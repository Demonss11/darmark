# Отчёт по реализации P1 прототипа Lua-плагинного хоста (v1.0)

**Дата:** 06.10.2026
**Проверяемый документ:** `tasks/TZ-proto-lua-host.md`, версия 1.0, фаза P1
**Ветка:** `proto/lua-plugin-host`
**Проверяемое:** крейт `crates/lua-proto` (bin), гейт P1

---

## 1. Общая оценка

P1 реализован в заявленном объёме. Гейт пройден: `cargo run -p lua-proto -- --plugin plugins/hello.lua`
печатает вывод плагина (`[info] hello` / `[info] bye`), код возврата 0, сборка под MSVC успешна
включая vendored Lua 5.5.1 (`lua-src 551.0.2`).

**Вердикт:** фаза P1 закрыта. Крейт пригоден как несущая конструкция для P2–P7.

| `plugins/hello.lua` | фикстура P1 | готово |

Отклонения от плана §3 ТЗ:

- **`permissions.rs` не создан.** По плану §3 он входит в структуру крейта, но по фазам
  относится к P5 (`apply_edit` + `document:write`). Пустой модуль в P1 дал бы dead-code.
- **`limits.rs` реализован раньше P3.** Причина: CLI из §3 уже содержит `--limit-mem`/`--limit-insns`,
  а `set_hook` — ключевая метрика M8. Код собран и работает, но методика замера N (M5/M6) —
  всё ещё предмет P3.

## 4. Ранние сигналы для FINDINGS (P2/P3/P8)

Это не полные замеры фаз, а подтверждения на уровне «собралось/запустилось», важные для §7 ТЗ:

1. **Vendored Lua 5.5.1 собирается под MSVC без правок** — риск из §7 (средняя вероятность) не
   подтвердился. Аварийный откат на `lua54` (D13) не требуется.
2. **`Lua::set_hook` компилируется под `lua55`** — код `limits.rs` собрался без `mlua::ffi`
   и без обхода через `lua_sethook`. Метрика M8 (ключевая) — положительна на уровне компиляции;
   поведенческий замер (`spin.lua`) — P3.
3. **`BASE` грузится неявно** при `Lua::new_with` — отдельного флага `StdLib::BASE` в mlua 0.12 нет;
   чистка `load`/`collectgarbage` реализована поверх. Это стоит зафиксировать в FINDINGS, т.к.
   в тексте §6.1 набор описан как «`BASE` да, с чисткой», что читается как явный флаг.
4. **`default-features = false`** даёт сборку без serde/async; прирост размера надо мерить в P2
   (без mlua vs с `lua55`), baseline для этого уже готов.

## 5. Замечания

### 5.1 Счётчик инструкций накапливается глобально (не блокирует P1)

`limits::install_instruction_limit` использует один `AtomicUsize` на всё время жизни состояния
(см. комментарий в коде). Для P1 (несколько инструкций в `hello.lua`) это неважно, но для P3
(`spin.lua`) лимит должен считаться **на вызов**, иначе `count.lua` упрётся в общий счётчик.
**Что делать в P3:** сбрасывать счётчик перед `on_activate`/вызовом host-функции.

### 5.2 Путь к фикстуре зависит от CWD

Гейт ТЗ `--plugin plugins/hello.lua` работает при запуске из `crates/lua-proto`; из корня нужен
`--plugin crates/lua-proto/plugins/hello.lua`. Cargo не меняет CWD на каталог пакета. Если в P2–P7
это начнёт мешать — задокументировать в FINDINGS или добавить дефолтный поиск относительно
`CARGO_MANIFEST_DIR`.

### 5.3 Сообщения хоста и плагина в один поток

`[xost]`-строки и вывод плагина идут в stderr без явного различия (кроме префикса `[level]` vs `[xost]`).
Для измерительного стенда приемлемо; при переносе в продукт — развести каналы.

## 6. Границы и что не входит

P2–P8 не реализовывались. Осознанно не созданы: `permissions.rs` (P5), событийная шина,
Document/View, манифест, `json`-модуль (D14), сравнение с `lua54` (D13). Код в `main` не мёржится.
