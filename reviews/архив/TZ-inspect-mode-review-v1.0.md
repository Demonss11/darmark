## 1. Общая оценка

Все три этапа из `TZ-inspect-mode-s1.md` реализованы: ядро `to_html_mapped`, IPC-параметр `mapped`,
модуль `inspector.ts`, UI (кнопка, хоткеи, стили, статус-бар) и интеграция в `main.ts`.
Проект собирается, автотесты ядра зелёные:

| Проверка | Результат |
|----------|-----------|
| `cargo test -p md-core` | ok — 45 passed, 0 failed |
| `npm run build` (tsc + vite) | ok — без ошибок типов |
| `cargo check -p mdedit` | ok |

**Вердикт:** каркас принят, но **ядро `to_html_mapped` нарушает инварианты T-3 (эквивалентность
обычному рендеру) и T-2.5 (запрет пустых блоков)**. Это блокирующие дефекты: в режиме инспектора
меняется содержимое предпросмотра (ссылки, сноски, `<hr>`) — то есть AC-9 не выполняется.
Требуется доработка ядра (раздел 3).

## 3. Замечания к устранению (блокирующие)

### 3.1 Ссылочные определения ломают ссылки и картинки (нарушены T-3, AC-9)

Где: `crates/md-core/src/lib.rs`, `to_html_mapped` (рендер блока из вырезанного среза).

Причина: `[foo]: /url` не порождает собственных `Event::Start/End`, поэтому диапазон определения
«прилипает» к следующему блоку и не попадает в парсер этого блока. Блок парсится изолированно
(`Parser::new_ext(trimmed, …)`), и ссылка остаётся неразрешённой.

Доказательство (сравнение с `to_html`):

```
вход:     "[foo]: /url\n\nUse [foo] here."
to_html:  "<p>Use <a href=\"/url\" rel=\"noopener noreferrer\">foo</a> here.</p>\n"
mapped:   "<div class=\"md-block\" data-md=\"21,36\"><p>Use [foo] here.</p>\n</div>"

вход:     "![img][logo]\n\n[logo]: /a.png"
to_html:  "<p><img src=\"/a.png\" alt=\"img\" /></p>\n"
mapped:   "<div class=\"md-block\" data-md=\"0,12\"><p>![img][logo]</p>\n</div>"
```

Существующий тест `mapped_matches_to_html_regression` использует вход без ссылочных определений,
поэтому дефект не пойман.

### 3.2 Сноски не разрешаются, метка определения портится (нарушены T-3, AC-9)

Где: там же.

Причина та же: определение `[^1]: …` рендерится в отдельном блоке, поэтому ссылка `[^1]` в
основном тексте не преобразуется, а метка определения теряет номер (внутренний счётчик парсера
начинается заново).

```
вход:     "Text[^1]\n\n[^1]: note"
to_html:  "<p>Text<sup class=\"footnote-reference\"><a href=\"#1\" rel=\"noopener noreferrer\">1</a></sup></p>\n<div class=\"footnote-definition\" id=\"1\">…<p>note</p>…"
mapped:   "<p>Text[^1]</p>\n<div class=\"footnote-definition\" id=\"1\"><sup class=\"footnote-definition-label\">1</sup>\n<p>note</p>…"
```

На многоблочном документе ломается и нумерация: у второго определения `[^2]` метка выводится как `1`.

Тест `footnote_definition_separate_block` проверяет лишь число блоков и наличие подстроки `footnote`,
поэтому дефект не пойман.

### 3.3 Пустые блоки создаются (нарушен T-2.5)

Где: там же, проверка `trimmed.is_empty()`.

Проверка непустоты делается по **исходному** срезу, а не по результату рендера. HTML-блок-комментарий
непуст по исходнику, но после санитайзера даёт пустую строку — и появляется пустая обёртка:

```
вход:   "before\n\n<!-- hidden -->\n\nafter"
mapped: "<div … data-md=\"0,6\"><p>before</p></div><div class=\"md-block\" data-md=\"8,23\"></div><div … data-md=\"25,30\"><p>after</p></div>"
```

### 3.4 `<hr>` не индексируется (нарушены T-4, AC-2; ослаблен property-тест T-5)

`Event::Rule` не даёт `Start/End`, поэтому строки `---`/`***` не входят ни в один `data-md`-диапазон,
хотя ТЗ требует индексировать `<hr>` (AC-2) и покрывать все непустые строки (T-5).

```
вход:   "text\n\n***\n\nmore"
mapped: data-md="0,4" (text)   data-md="11,15" (more)     ← "***" потерян
```

Property-тест `mapped_blocks_cover_nonempty_without_overlap` проходит только потому, что его вход
(`# A … table … list`) не содержит standalone `<hr>` и ссылочных определений. Инвариант T-5
не выполняется на реальных документах.

### 3.5 Рекомендуемое исправление (закрывает 3.1–3.4 одним изменением)

Парсить документ **один раз** и группировать уже готовые события по топ-блокам, а не перепарсивать
вырезанные срезы:

1. `Parser::new_ext(md, opts).into_offset_iter()` — пройти поток один раз, разрезая его на группы
   по границам топ-блоков (по `Event::Start`/`Event::End` при `depth == 0`).
2. Каждую группу прогнать через `html::push_html(&mut out, group_iter)` — ссылки и сноски уже
   разрешены исходным парсером (единый проход = единая таблица ссылок и сносок).
3. Диапазон блока брать из границ событий группы; `Event::Rule`/HTML-события при `depth == 0`
   включать в диапазон явно.
4. Пустоту блока проверять по итоговому HTML, а не по исходному срезу.

Это разом устраняет 3.1–3.4 и убирает N повторных парсингов (бонус к бюджету T-18).

## 4. Замечания (неблокирующие)

### 4.1 `INTERACTIVE_SELECTOR` отклоняется от T-12

В `inspector.ts` селектор — `"button, input, select, a, .col-filter-menu, th"`; в ТЗ T-12 —
`"button, input, select, a, .col-filter-menu"`. Добавление `th` разумно (клик по заголовку =
сортировка, а не inspect), но это отклонение от текста ТЗ — стоит либо согласовать, либо уточнить ТЗ.

### 4.2 Дублирование слушателей редактора (T-11)

T-11 просит переиспользовать единый хук `keyup/click` (уже навешанный в `main.ts` для `updateStatus`).
Инспектор вешает собственные `keyup`/`click` на `editor` — оба обработчика срабатывают на каждое
событие. Не критично, но расходится с ТЗ и плодит лишние вызовы.

### 4.3 Небезопасный fallback в конвертере единиц

`bytesToUnits`/`unitsToBytes` возвращают `maps.b2u[b] ?? 0`. Выход за границы `Int32Array` даёт
`undefined`, который молча превращается в `0` (начало документа) вместо ошибки/зажима. Стоит
ограничить индекс диапазоном (`Math.min/Math.max`) или явно обработать выход за границы.

### 4.4 Тесты T-4/T-5 не покрывают реальные ветки парсера

Все «пограничные» входы подобраны так, что дефекты 3.1–3.4 не проявляются. Рекомендуется добавить
в набор тестов: ссылочное определение (`[foo]: /url` + использование), `![img][logo]`, многострочную
сноску, standalone `<hr>`, HTML-комментарий (пустой после санитайзера). После исправления ядра эти
тесты должны быть красными на старой версии и зелёными на новой.

## 6. Итог

Реализация покрывает весь объём ТЗ и аккуратно интегрирована; сборка и автотесты зелёные.
Блокирует приёмку один узел — алгоритм `to_html_mapped`: изолированный парсинг блоков ломает
ссылочные определения и сноски, теряет `<hr>` и создаёт пустые обёртки, что противоречит
инвариантам T-3/T-5 и сценарию AC-9. Исправление локализовано в одной функции ядра и описано в 3.5;
после него пункты 4.1–4.3 закрываются как полировка.
