# Отчёт по ревизии v1.2 прототипа Lua-плагинного хоста и `FINDINGS.md`

**Дата:** 06.10.2026
**Заменяет:** ничего (первая ревизия v1.2 со стороны)
**Проверяемые документы:** `reviews/TZ-proto-lua-host-P1-review-v1.2.md`, `FINDINGS.md`
**Ветка:** `proto/lua-plugin-host`
**Повод:** внешний разбор результатов v1.2 с учётом нового ограничения — **Windows-only** как архитектурного решения.

---

## 1. Вердикт

**Windows-only снимает целый класс рисков и меняет статус варианта B с «жизнеспособен в теории» на «основной кандидат».** Но три пункта остаются критичными и **не зависят от платформы**:

1. host-функции с `Err` под `abort` всё ещё абортят — блокер варианта B;
2. оверхед hook ~×2 не лечится Windows-only — блокер UX;
3. `lua_State` после сработки лимита считается испорченным — правило, не риск.

Пункты v1.2 (F9–F14) подтверждены по существу. Формулировка §14/D6 меняется: **«+3.2 МБ под unwind» перестаёт быть «ценой за стабильность» и становится «блокером варианта A»** — не потому что цифра изменилась, а потому что без кросс-платформенной оговорки запас D6 нечем оправдать.

## 2. Что подтверждено фактически

| Проверка | Результат |
|---|---|
| F9: ошибка из Rust-callback под `abort` → abort процесса | подтверждено, механизм (SEH) корректен |
| F10: `unwind` на `mdedit` = +3.2 МБ | подтверждено; причина — landing-pad'ы всей Tauri-графы, не mlua |
| F11: C-hook под `abort` даёт лимит инструкций | подтверждено на MSVC/SEH |
| F12: голый hook проглатывается `pcall` | подтверждено |
| F13: scoped safe-`pcall` закрывает обход | подтверждено |
| F14: оверхед hook ~×2 | подтверждено; шаг 10k/100k/1M не влияет |
| Утечек нет (200k паник подряд) | подтверждено, состояние не деградирует |
| `MemoryError` под `abort` работает | подтверждено (F8) |
| Windows-only как решение | **новое ограничение**, требует фиксации в ADR |

Дополнительно: `lua-proto` под `abort` и `unwind` — **±0 байт**. Это значит, что выигрыш `abort` для прототипа нулевой; вся его ценность — в масштабе `mdedit`.

## 3. Что меняет Windows-only (существенно)

### 3.1. Снимается с очереди

- **Спайк C-hook на Linux (DWARF)** — не нужен. SEH-разворачивание проверено (F11), это единственный релевантный сценарий.
- **Кросс-компиляция mlua под разные таргеты** — не нужна. Vendored Lua под MSVC собирается без правок (F1).
- **Матрица CI под Linux/macOS** — не нужна для проверки panic-стратегии.

### 3.2. Что НЕ снимается

Windows-only **не помогает** с этими тремя пунктами:

| Пункт | Почему остаётся |
|---|---|
| Host-`Err` под `abort` | Свойство `abort` + Rust-фрейма, не ОС |
| Оверхед hook ×2 | Свойство `luaG_traceexec` (`lvm.c:1192`), не ОС |
| Пересоздание `lua_State` после лимита | Свойство `Drop` под `abort`, не ОС |

### 3.3. Что Windows-only позволяет зафиксировать

- Использовать WinAPI без абстракций, если понадобится (например, для file watching).
- Использовать MSVC-специфику в C-модуле (`__try`/`__except`, если потребуется).
- Дистрибуция — только MSI/NSIS + bootstrap WebView2.

**Оговорка:** ядро (`plugin-host`, `plugin-api`, Document/View/Pane) должно оставаться платформо-независимым. Windows-специфика — **только** в C-hook и сборке. Если через год понадобится macOS/Linux — переписывать придётся C-hook, не ядро.

## 4. Критические пункты, требующие решения

### 4.1. Host-функции с `Err` под `abort` — блокер варианта B

§8 DESIGN_DOC уже требует: «плагин без `document:write` получает `error { code = "permission_denied" }`, а не исключение Lua». В коде это **не реализовано**.

**Последствие:** пока `apply_edit` может вернуть `Err`, вариант B не является жизнеспособным — он «жизнеспособен в теории». Это не «вторая половина пути B», это **условие его работоспособности**.

**Решение:** все host-функции возвращают Lua-значение (`{ok, code, message}`), никогда `Err`. Это надо проверить спайком (P5) **до** перехода к P3.

### 4.2. Оверхед hook ~×2 — блокер UX

F14 подтверждает: `luaG_traceexec` вызывается каждую инструкцию, пока hook взведён. Шаг не помогает.

**Последствие:** preview, обновляющийся на каждое нажатие клавиши, будет вдвое медленнее. Для редактора это заметно.

**Варианты:**
- Проверять `lua_gethookcount` реже — но это требует модификации VM или отказа от точности.
- Принять ×2 как цену лимита и оптимизировать горячие пути (кэш на уровне Document, дебаунс).
- Пересмотреть механизм лимита (например, `LUA_MASKCOUNT` с адаптивным шагом).

**Решение за владельцем.** Но формулировка «принять или пересмотреть» в v1.2 недостаточна — нужно выбрать.

### 4.3. `Drop` под `abort` — это правило, не риск

v1.2 §3 отмечает «RAII-гвард вызывает Lua API в `Drop`; на пути разворачивания под `abort` `Drop` не выполняется». Это не «остаточный риск» — это **правило**.

**Правило:** после сработки лимита инструкций `lua_State` считается испорченным и пересоздаётся. Не пытаться восстановить.

**Плюс:** упрощает реализацию — не нужно защищать `Drop` от аборта.
**Минус:** теряется состояние плагина (что для preview/inspector неважно, они stateless).

### 4.4. Per-state счётчик C-модуля — архитектурное ограничение

v1.2 §3 относит это к «P3/P5». Я бы отнёс к **архитектуре**: если два плагина работают одновременно (preview + inspector), они должны иметь **разные `lua_State`**. Глобальный счётчик в C-модуле сломает это.

**Решение:** per-state реестр (через `LUA_REGISTRYINDEX`) — в P3, не позже.

## 5. Развилка после Windows-only

| Вариант | Лимит инструкций | Размер базы | Статус после Windows-only |
|---|---|---|---|
| A. `unwind` + `catch_unwind` | есть | 6.9 МБ | **закрыт**: D6 нарушается, кросс-платформенного оправдания нет |
| B. `abort` + C-hook + safe-pcall + Lua-ошибки значениями | есть | ~3.7 МБ | **основной кандидат**; блокеры — §4.1, §4.2 |
| C. `abort` + Lua в отдельном процессе | есть | 3.7 МБ + процесс | оставить как «аварийный люк» для H2/H3 (маркетплейс) |

**Вариант A** теперь можно закрыть одним предложением: «Технически доказан, экономически невозможен, кросс-платформенного сценария, где он оправдан, у проекта нет».

## 7. Что добавить в ADR (вход)

1. **Panic-стратегия:** `abort` для `mdedit`, C-hook для лимита инструкций, Lua-ошибки значениями. Вариант A — отклонён, вариант C — отложен.
2. **Windows-only:** осознанный выбор для H1/H2. Платформо-независимое ядро, Windows-специфика в C-hook.
3. **§10.2 DESIGN_DOC:** утверждение «Lua-ошибка не роняет приложение» ложно под `abort` — поправить на «Lua-ошибка, **возвращённая значением**, не роняет приложение; ошибка через `Err` из Rust-callback — роняет».

## 10. Итог

v1.2 — качественная работа: спайк C-hook, замеры F11–F14, честная таблица «гипотеза → замер → вывод». Windows-only **упрощает** развилку: вариант A закрывается, вариант B становится основным. Но три пункта — host-`Err`, оверхед ×2, пересоздание `lua_State` — **не лечатся платформой** и требуют решения.

Приоритет: сначала P5 (host-функции без `Err`) — без него вариант B не закрыт. Параллельно — ADR с фиксацией Windows-only и panic-стратегии. Оверхед ×2 — отдельным пунктом, не смешивать с остальными.

Ценность v1.2 выше фазы P1: она переводит обсуждение panic-стратегии из «теории» в «замеры» и снимает главный риск H2 (ошибка плагина убивает редактор). Это ровно тот тип находок, который оправдывает существование прототипа.
