## 2. Проблема 1 (AC-3): нет гранулярности вложенных элементов

**Наблюдение (ручной прогон):** при наведении на вложенный элемент (`<strong>` внутри `<p>`,
`<li>` внутри `<ul>`, `<td>` внутри `<table>`) инспектор всегда подсвечивает **родительский
топ-блок**, а не сам вложенный элемент. Переходы между разными топ-блоками работают.

**Причина:** это заявленное ограничение дизайна, а не дефект реализации. ТЗ §5.1:

> Гранулярность — **топ-блок**. Подсветка отдельных inline-элементов (`**bold**` внутри
> абзаца) — вне объёма v1 (требовало бы поуровневого маппинга всех Event'ов и
> сопоставления с HTML-DOM; сложность несопоставима).

Ядро (`to_html_mapped`) размечает `data-md` только на топ-обёртке `.md-block`; `inspector.ts`
делает `closest("[data-md]")`, что по построению даёт родителя.

**Формулировка AC-3 в ТЗ** («в т.ч. с вложенного элемента, например `<strong>` внутри `<p>`»)
описывает лишь переключение между блоками при движении по вложенным элементам — оно
работает. Подсветка «до уровня `<strong>`/`<li>`/`<td>`» текущим AC-3 не требуется, но
пользователь ожидает более глубокую гранулярность.

**Что нужно для закрытия (если расширяем объём):**
- поуровневый маппинг всех `Event`'ов (не только топ-блоков) в ядре → `data-md` на вложенных
  элементах (или карта «диапазон ↔ DOM-узел»);
- сопоставление inline-событий с HTML-DOM (проблема: один markdown-диапазон может
  соответствовать нескольким узлам и наоборот);
- правило интерактивности для `<td>`/`<th>` (сортировка таблиц) и `<a>` (открытие ссылок);
- переработка `INSPECT-ACTIVE` на несколько вложенных подсветок или «ближайший наименьший».

**Решение к принятию:** оставить top-block (как в ТЗ) либо расширить объём (v2).

## 3. Проблема 2 (AC-10): локальные изображения — **закрыто**

**Исходное наблюдение (ручной прогон):** `![Gramax logo](./logo.svg)` рендерился в
`<img src="./logo.svg" alt="Gramax logo" />`, но картинка не показывалась.

**Причина:** markdown рендерился корректно (санитайзер относительный `src` не трогает —
`url_is_safe("./logo.svg") === true`). Проблема была в загрузке ресурса:
1. Относительный `./logo.svg` резолвился относительно **origin приложения**
   (`tauri://localhost` / `http://tauri.localhost`), где файла нет; файл лежит рядом с
   открытым `.md` на диске.
2. Даже при корректном URL CSP (`tauri.conf.json`) не пропускал локальный ресурс:
   `img-src 'self' data: https:`.

**Важно:** к границам подсветки это отношения не имело — AC-10 (байты ↔ UTF-16) работал;
проблема относилась к **отображению** локальных картинок.

**Реализовано (отдельная фича, не расширение inspect-mode):**
- `tauri.conf.json`: включён `app.security.assetProtocol` (`enable: true`, пустой
  статический `scope`), CSP расширен до
  `img-src 'self' data: https: asset: http://asset.localhost`;
- `Cargo.toml` шелла: включена фича `tauri/protocol-asset`;
- `src-tauri/src/lib.rs`: `read_file`/`write_file` при успехе вызывают
  `app.asset_protocol_scope().allow_directory(parent, recursive = true)` — в scope попадает
  только каталог открытого/сохранённого файла (модель Notepad++, путь выбирает пользователь);
- `src/images.ts` (новый): после каждого рендера `resolveLocalImages(preview, currentPath)`
  заменяет относительные `src` на `convertFileSrc(абсолютный путь)`; поддерживаются
  `./x`, `sub/x`, `../x`, абсолютные пути Windows/Unix, `.`/`..` схлопываются;
- `main.ts`: вызов резолвера в `doRender` и после «Сохранить как» (смена каталога).

**Ограничения/замечания:**
- лимит 10 МБ применяется к самому `.md`; картинки через asset-протокол отдельным лимитом
  не ограничены (WebView грузит их штатно);
- `file://`-ссылки и `srcset` не обрабатываются (вне объёма);
- процесс резолва идемпотентен и не мешает режиму инспектора (DOM-обёртки не затрагиваются).

## 4. Проблема 3: нет синхронизации скролла редактора и предпросмотра — **закрыто**

**Наблюдение:** прокрутка окна редактора и окна предпросмотра независимы. При прокрутке
исходника предпросмотр остаётся на месте (и наоборот), поэтому в длинном документе
соответствующий фрагмент приходится искать вручную.

**Причина:** фича не реализована. Режим инспектора синхронизирует **выделение** (диапазон
markdown ↔ блок), но не позицию прокрутки: `inspector.ts` вызывает `scrollIntoViewIfNeeded`
только по hover/каретке. Двусторонней зависимости scrollTop ↔ scrollTop нет.

**Требование (новая фича, в объём inspect-mode не входит):**
- синхронизация вертикального скролла в обе стороны: редактор → предпросмотр и обратно;
- **переключатель** «синхронный / несинхронный скролл» (пользователь должен уметь выключить);
- защита от обратной связи (loop): флаг «программный скролл» либо сравнение источника
  события, иначе A скроллит B, B скроллит A;
- привязка позиций: ближайший `[data-md]`-блок к видимой строке редактора и наоборот.
  Для редактора нужен диапазон видимых строк (`scrollTop`, `clientHeight`, line-height);
  для предпросмотра — `offsetTop`/`getBoundingClientRect` блоков;
- поведение при разной длине исходника и HTML (источник «сжимается»/«растягивается»):
  пропорциональная привязка как fallback;
- не конфликтовать с инспектором (его `scrollIntoView` при hover/каретке) и таблицами.

**Открытые вопросы:**
- где размещать переключатель (тулбар / статус-бар / настройки) и каково состояние по умолчанию;
- опираться на `data-md` (тогда при несинхронном режиме разметку можно не запрашивать,
  а при синхронном — запрашивать mapped-рендер) или строить независимый маппинг по пропорции;
- сглаживание (`requestAnimationFrame`/throttle), чтобы прокрутка не дёргалась и не «дралась»
  с инерцией WebView.

**Статус:** реализован **MVP** отдельной фичей (не расширением inspect-mode):
пропорциональная синхронизация + переключатель «синхронно» в тулбаре
(`src/scrollsync.ts`, включена по умолчанию). Точная анкорная привязка через `data-md`
(неоднородные документы: таблицы, код-блоки, картинки) и сглаживание — v2.
С инспектором MVP специально не разводится: его `scrollIntoView` при hover может
потянуть вторую панель через sync (пропорционально).

---

## 5. Итог

Готовность режима инспектора к приёмке по AC-1…AC-10 — **функционально полная** в рамках
заявленной в ТЗ гранулярности (топ-блок).

- **AC-3 вложенность** — by design (ТЗ §5.1); остаётся как есть либо закрывается
  расширением ТЗ на поуровневый маппинг.
- **локальные картинки (AC-10)** — **закрыто** отдельной фичей (asset-protocol + резолв
  относительных `src`); см. §3.
- **синхронизация скролла** — **закрыто** реализован MVP отдельной фичей (пропорционально + тумблер);
  анкорная точность — v2; см. §4.

Итого открытым остаётся один вопрос объёма (AC-3), требующий решения владельца задачи.
