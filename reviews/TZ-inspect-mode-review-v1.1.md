## 1. Контекст

Блокирующие дефекты ядра из v1.0 устранены (один проход `into_offset_iter` + группировка
событий: ссылочные определения, сноски, `<hr>`, пустые блоки). Дополнительно при ручном
прогоне закрыты:

| Пункт | Симптом | Статус |
|---|---|---|
| Прочее | `Ctrl+P` открывал печать вместо переключения предпросмотра | исправлено (отключены браузерные акселераторы WebView2 через `ICoreWebView2Settings3`) |
| AC-6 | клик по блоку предпросмотра — выделение и фокус «пропадали» | исправлено (`applyBlock(..., force)` на клике) |
| AC-5 | протяжка выделения в редакторе вела подсветку только по якорю (первый блок) | исправлено (ориентир на активный край через `selectionDirection` + событие `select`) |
| AC-1…AC-4, AC-7…AC-9 | — | ок |

Ниже зафиксированы **два пункта, которые не закрываются кодом в рамках текущего объёма
ТЗ** и требуют отдельного решения (расширение ТЗ / новая фича).

## 2. Проблема 1 (AC-3): нет гранулярности вложенных элементов

**Наблюдение (ручной прогон):** при наведении на вложенный элемент (`<strong>` внутри `<p>`,
`<li>` внутри `<ul>`, `<td>` внутри `<table>`) инспектор всегда подсвечивает **родительский
топ-блок**, а не сам вложенный элемент. Переходы между разными топ-блоками работают.

**Причина:** это заявленное ограничение дизайна, а не дефект реализации. ТЗ §5.1:

> Гранулярность — **топ-блок**. Подсветка отдельных inline-элементов (`**bold**` внутри
> абзаца) — вне объёма v1 (требовало бы поуровневого маппинга всех Event'ов и
> сопоставления с HTML-DOM; сложность несопоставима).

Ядро (`to_html_mapped`) размечает `data-md` только на топ-обёртке `.md-block`; `inspector.ts`
делает `closest("[data-md]")`, что по построению даёт родителя.

**Формулировка AC-3 в ТЗ** («в т.ч. с вложенного элемента, например `<strong>` внутри `<p>`»)
описывает лишь переключение между блоками при движении по вложенным элементам — оно
работает. Подсветка «до уровня `<strong>`/`<li>`/`<td>`» текущим AC-3 не требуется, но
пользователь ожидает более глубокую гранулярность.

**Что нужно для закрытия (если расширяем объём):**
- поуровневый маппинг всех `Event`'ов (не только топ-блоков) в ядре → `data-md` на вложенных
  элементах (или карта «диапазон ↔ DOM-узел»);
- сопоставление inline-событий с HTML-DOM (проблема: один markdown-диапазон может
  соответствовать нескольким узлам и наоборот);
- правило интерактивности для `<td>`/`<th>` (сортировка таблиц) и `<a>` (открытие ссылок);
- переработка `INSPECT-ACTIVE` на несколько вложенных подсветок или «ближайший наименьший».

**Решение к принятию:** оставить top-block (как в ТЗ) либо расширить объём (v2).

## 3. Проблема 2 (AC-10): не отображаются локальные изображения

**Наблюдение (ручной прогон):** `![Gramax logo](./logo.svg)` рендерится в
`<img src="./logo.svg" alt="Gramax logo" />`, но картинка не показывается.

**Причина:** markdown рендерится корректно (санитайзер относительный `src` не трогает —
`url_is_safe("./logo.svg") === true`). Проблема в загрузке ресурса:
1. Относительный `./logo.svg` резолвится относительно **origin приложения**
   (`tauri://localhost` / `http://tauri.localhost`), где файла нет; файл лежит рядом с
   открытым `.md` на диске.
2. Даже при корректном URL CSP (`tauri.conf.json`) не пропустит локальный ресурс:
   ```
   img-src 'self' data: https:
   ```
   Нужно добавить `asset:` (Windows — `http://asset.localhost`).

**Важно:** к границам подсветки это отношения не имеет — AC-10 (байты ↔ UTF-16) работает;
проблема относится к **отображению** локальных картинок и к режиму инспектора прямого
отношения не имеет. ТЗ-inspect-mode её не покрывает.

**Что нужно для закрытия (если добавляем фичу «локальные картинки»):**
- включить asset-protocol и scope в `tauri.conf.json` (`app.security.assetProtocol`);
- на фронтенде после рендера резолвить относительные `src`/`href` картинок от каталога
  `currentPath` и заменять на `convertFileSrc(...)`;
- расширить CSP `img-src` (`asset:` / `http://asset.localhost`);
- учесть модель доступа Notepad++ (путь выбирает пользователь) и лимит 10 МБ.

**Решение к принятию:** вынести в отдельную задачу/ТЗ (не расширять inspect-mode).

---

## 4. Итог

Готовность режима инспектора к приёмке по AC-1…AC-10 — **функционально полная** в рамках
заявленной в ТЗ гранулярности (топ-блок). Оставшиеся два пункта — не дефекты реализации, а
вопросы объёма:

- **AC-3 вложенность** — by design (ТЗ §5.1); закрытие = расширение ТЗ на поуровневый маппинг.
- **локальные картинки** — вне объёма inspect-mode; закрытие = отдельная фича с asset-protocol.

Оба пункта требуют решения владельца задачи до перевода в реализацию.
