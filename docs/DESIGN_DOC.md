## 1. Назначение и рамки

### 1.1. Продукт
Лёгкий Markdown-редактор/вьюер (аналог Notepad++ для Markdown): слева редактор, справа HTML-предпросмотр, Excel-подобные таблицы, инспектор, синхронная прокрутка. Расширяется **пользовательскими Lua-плагинами без пересборки приложения**.

### 1.2. Плагинный UX (главная продуктовая фича)
> Пользователь кладёт `.lua` в `%APPDATA%/darmark/plugins/` — работает. Правит файл → «Перезагрузить плагин» — новая версия. **Без компилятора и пересборки.**

### 1.3. Вне рамок (не-цели)
- CodeMirror — отдельный ADR. CPU-тяжёлые плагины (парсер, LSP, mermaid) — не поддерживаем.

## 4. DocumentStore (Rust) — владение состоянием

### 4.1. Структуры
`Document { id, text, rev, undo, redo }`, `EditOp { start, removed, inserted }`, `UndoResult { text, rev, start, end }`.

### 4.2. Кто чем владеет
Rust владеет данными (текст, ревизии, кэш, undo/redo) — TS только проекция. Любая правка текста идёт через Rust.

### 4.3. Команды (IPC)
`new_document`, `open_document`, `update_document`, `render_document`, `undo_document`, `redo_document`.

`DocMeta { id, rev, dirty_hint }`, `RenderResult { html, rev, changed }`; `changed: false` при неизменной `rev` — TS не трогает DOM.

## 5. TS-слой: layout, pane, view

### 5.1. Идентификаторы
Строковые `Brand`-типы: `DocumentId`, `PaneId`, `ViewId` — единый формат с Rust и Lua.

### 5.2. Layout
Дерево: `Pane` (вкладки, D4) | `Split` (row/column). Операции — чистые функции без DOM.

### 5.3. ViewProvider и ViewContext
Два тира: plugin-safe (HTML) / built-in only (DOM) — **ADR-0022** §2. Preview — тир-1 на хосте (D2). ViewContext — единственная «песочница» для view.

### 5.5. Ограничения
D5, §11. Карта модулей — §2, `AGENTS.md`.

## 6. Плагинная система: Lua

### 6.1. Рантайм
`mlua` 0.12 + vendored Lua 5.5; LuaJIT запрещён (D1). Отдельный процесс и Lua-состояние на плагин (§10, §11.4). Обоснование — ADR-0021/0023; детали — `PLUGIN_API.md` §5.

### 6.2. Модель: плагин = код, инстанс = привязка
`plugin = манифест + .lua`; `instance = привязка к view/подписке`. Состояние хранит хост — плагины **stateless по коду** (упрощает `dispose()` и перезагрузку).

### 6.3. API плагина (host-функции)
Функции с permission возвращают `(value, err)`; `permission_denied` — значением, не исключением (§8). `host.log`, `md.*`, `json.*` без permission. Сигнатуры — `PLUGIN_API.md` §3.

### 6.4. Точки расширения (`contributes`)
Манифест: `views`, `commands`, `statusbar`, `toolbar`, `settings` (формат — `PLUGIN_API.md` §1–§2). `ui:toolbar` отложен (§8).

### 6.6. Жизненный цикл
Цикл: `scan → validate → load → on_activate → … → on_deactivate → unload`. Перезагрузка — `unload` → `load` с диска, без перезапуска. Ошибка загрузки → `failed`, приложение работает. Автоперезагрузка — off. Детали — ADR-0023 §2.4.

## 7. Протокол и транспорт

### 7.1. Уровни
Конверт `Request`/`Response`/`Error` (serde); транспорт — stdio. Dev-режим — тот же конверт. JSON-RPC не обязателен. Детали — ADR-0021/0023.

### 7.2. Версионирование
`api_version` в манифесте; хост отвергает `api_version > HOST_API_VERSION`. Удаление функций запрещено без мажора. Депрекация — ADR-0027.

---

## 8. Модель разрешений

По образцу Tauri ACL: deny-by-default; эффективный набор = **`manifest ∩ granted`**. Проверка — на хосте, до вызова; `permission_denied` — значением (§6.3).

- Поддержаны: `document:*`, `view:*`, `ui:statusbar`. `filesystem:*`/`network` — нет; `ui:menu`/`ui:sidebar`/`ui:toolbar` — отложены. Привязка — `PLUGIN_API.md` §1; версии — ADR-0027.
- **Согласие:** `%APPDATA%/darmark/config.json`; смена — перезапуском child'а. Предупреждения — ADR-0021 §3; магазин обязан показать (§11.4).

## 9. События

### 9.1. Каталог событий
| Ссобытие | Полезная нагрузка |
|---|---|
| `document:changed` | `doc_id`, `rev` |
| `document:opened`/`closed` | `doc_id`, `path` |
| `view:scroll`, `view:focus`, `command:invoked` | `view_id`/`command_id` |

> События фронт-шины (ADR-0029/0031) — вне контракта host↔child.

### 9.2. Модель доставки: notify-only + pull
Событие — только `doc_id` и `rev`; плагин вызывает `get_document_range`/`get_document_text` при необходимости.

### 9.3. Коалесинг и порядок
Коалесинг по `rev` (последняя ревизия за тик), FIFO внутри типа. `dispose()` отписывается. При рестарте хост переиздаёт `document:opened`.

### 9.4. Обратная маршрутизация
Клик по `data-p-<pluginid>-*` → Lua-хендлер → `host.set_view_content`/патч. `data-p-<pluginid>-*` переживает санитизацию (D7).

## 10. Ресурсные лимиты и отказоустойчивость

### 10.1. Лимиты
Плагин исполняется в отдельном дочернем процессе; лимиты задаёт ОС через Job Object.

| Лимит | Механизм |
|---|---|
| Память плагина | RSS-лимит Job Object |
| CPU/время | Job Object + **per-call watchdog** |
| Размер `.lua` | проверка перед загрузкой |

### 10.2. Отказоустойчивость и доверие
- Падение плагина → перезапуск child; 3 падения — карантин до ручного включения.
- Доверие: не сломает приложение, не съест ресурсы, не украдёт данные.

## 11. Санитайзер и границы безопасности

### 11.1. Единая точка
Санитизация — только на хосте, в конце конвейера. `preview.innerHTML` доверяет результату. HTML плагинов — тем же ядром (§11.2). Ответ AI рендерится как Markdown через общий хелпер `setSanitizedHtml` (`crates/app/src/safeHtml.ts`) и `md_core::to_html` как источник HTML ответа. Точки `innerHTML` на фронте исчерпывающе перечислены: `previewView.ts`, `safeHtml.ts` → `setSanitizedHtml()` (ADR-0038), `pluginViews.ts`; четвёртая точка запрещена.

### 11.2. Политика санитизации
Allowlist: безопасные теги/атрибуты/URL. `data-p-<pluginid>-*` — единственная правка. SVG — без событий и внешних ссылок.

### 11.3. CSP
`default-src 'self'; style-src 'self' 'unsafe-inline'`. Плагины — только HTML + инлайн-стили; `eval` запрещён.

### 11.4. Границы безопасности
- **Изоляция C-эксплойта:** эксплойт получает память child'а, не GUI-хоста. Полной sandbox-изоляции нет — осознанный отказ. Магазин обязан предупредить: `document`-permission = полный доступ к тексту.
