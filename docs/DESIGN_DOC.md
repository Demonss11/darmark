# DESIGN_DOC — darmark

> Целевая архитектура лёгкого Markdown-редактора с плагинным UX «открыл `.lua` — поправил — работает».
> Статус: **черновик v0.3**. Источник требований — `ideas/` (см. `ideas/darmark-ideas-review.md`).
> Документ описывает **целевое состояние**, а не текущее. Текущее — в `KODA.md`, `README.md`, `ideas/ОПИСАНИЕ_FRONT.md`, `ideas/ОПИСАНИЕ_BACK.md`.
> Порядок работ: **прототип (§15.0) → ADR (§16) → H1 (§15.1)**.

## 0. Принятые решения (краткая сводка)

| # | Решение | Мотив |
|---|---|---|
| D1 | **Плагинный рантайм: `mlua` 0.12 + vendored Lua 5.5** (не LuaJIT) | Один рантайм вместо двух (wasmi + Rhai); ~0.3–0.5 МБ вместо ~0.5–1 МБ + второй рантайм; текстовый скрипт правится без пересборки; CPU-тяжёлые плагины не в vision. Wasmi отклонён: платит размером и сложностью за экосистему языков, которая не нужна. Lua 5.5 (не 5.4) — см. §6.1.1: декларации глобалов, компактные массивы, внешние строки. |
| D2 | **Preview остаётся встроенным (тир-1) на хосте** | Горячий путь (каждый debounce) недопустимо гнать через интерпретатор. Плагинная система доказывается на холодных плагинах. Миграция preview в плагин — только за бенч-гейтом (не планируется). |

| D4 | **`Pane = { views: ViewId[], active: ViewId }`** закладывается сразу, даже если v1 всегда одно-вью | Иначе вкладки потребуют переделки модели данных, а не только UI. |

| D6 | **Размер базы ≤ 6 МБ**, «нулевая база»: ни одного встроенного `.lua`/`.wasm` в дистрибутиве; встроенные фичи (preview, inspector, таблицы) живут на хосте | Размер — продуктовая метрика. Плагины не уменьшают базу, они ограничивают её будущий рост. |

| D8 | **Имя продукта: `darmark`.** Tauri identifier `dev.darmark.app`, productName `darmark`, каталог `%APPDATA%/darmark/` | Принято. Требует миграции: сейчас в репозитории `dev.mdedit.app` / `mdedit` и стартовый текст «Добро пожаловать в mdedit» (замороженный e2e-контракт). |
| D9 | **Лимиты памяти — штатным `Lua::set_memory_limit`.** Кастомный аллокатор и `bumpalo` для песочницы **не применяются** | mlua 0.12 даёт лимит и метрику из коробки. `bumpalo` семантически несовместим с GC (нет `free`), лимита не даёт и дублировал бы существующий механизм. Подробно — §10.4. |
| D10 | **Язык документации — русский.** Код, комментарии, ТЗ, ADR — ru; публичный API-референс для авторов плагинов — ru (en-перевод отложен) | Принято. |

Сначала эксперимент, потом решение. |
| D12 | **Excel-таблицы не развиваем.** Существующая функциональность `tables.ts` (сортировка, фильтры, поиск) сохраняется и остаётся рабочей, но требования `TZ-excel-tables` (предикатные фильтры, мультисортировка, `sessionStorage`, sticky-столбец, TSV/CSV, печать, ресайз) **не реализуются**. ТЗ перенесено в `tasks/архив/` | Размер усилий не окупается: это отдельный продукт внутри редактора. Приоритет — плагинная платформа и Document/View/Pane. |

## 1. Назначение и рамки

### 1.1. Продукт
Лёгкий Markdown-редактор/вьюер (аналог Notepad++ для Markdown): слева редактор, справа HTML-предпросмотр, Excel-подобные таблицы, инспектор, синхронная прокрутка. Расширяется **пользовательскими Lua-плагинами без пересборки приложения**.

### 1.2. Плагинный UX (главная продуктовая фича)
> Пользователь кладёт `word-count.lua` в `%APPDATA%/darmark/plugins/`, приложение его видит, плагин работает. Пользователь правит файл в блокноте, сохраняет, нажимает «Перезагрузить плагин» — работает новая версия. **Никакого компилятора, никакого `wasm32`, никакой пересборки.**

### 1.3. Вне рамок (не-цели)
- Мобильные платформы. Windows — продукт, Linux — dev.
- Собственный редактор кода (CodeMirror) — отдельный ADR, не в H1–H2.
- CPU-тяжёлые плагины (собственный парсер, LSP-клиент, mermaid-рендер) — сознательно не поддерживаем; при необходимости это повод пересмотреть D1.
- Сетевой доступ плагинов по умолчанию запрещён.
- WIT / Component Model.
- Hard-isolation плагинов (процесс/WASM) — см. §11.4.

## 2. Слои системы

```
┌─────────────────────────────────────────────────────────────┐
│ TS-оболочка (crates/app/src)                                │
│  layout.ts · paneHost.ts · viewRegistry.ts · main.ts(корень) │
│  тир-2 провайдеры: editorView, tablesView                    │
│  previewView — тир-1 контракт, но встроен на хосте (D2)      │
├─────────────────────────────────────────────────────────────┤
│ IPC-граница (Tauri commands)                                 │
│  документы · рендер · плагины · настройки                    │
├─────────────────────────────────────────────────────────────┤
│ Rust-хост (crates/app/src-tauri/src)                         │
│  DocumentStore · RenderCache · PluginHost(mlua) · Sanitizer  │
│  EventBus · SettingsStore                                    │
├─────────────────────────────────────────────────────────────┤
│ Rust-ядро (crates/md-core) — чистые функции, без UI          │
│  to_html · to_html_with · to_html_mapped · sanitize_html     │
└─────────────────────────────────────────────────────────────┘
```

Правила слоёв:
1. `md-core` **не знает** про Tauri, Lua, плагины, состояние. Только `&str -> String`.
2. Rust-хост владеет **данными** (текст, ревизии, кэш рендера, конфиг, реестр плагинов).
3. TS владеет **представлением и взаимодействием** (dirty, selection, scroll, фокус, layout).
4. TS не парсит Markdown и не санитизирует HTML — только рендерит готовый HTML и украшает DOM.
5. Плагины не видят DOM. Единственный канал — host-функции.

## 3. Контракт ядра `md-core`

Публичный API остаётся неизменным (менять ядро в задачах рефакторинга запрещено):

```rust
pub const DEFAULT_OPTIONS: Options;
pub fn to_html(markdown: &str) -> String;
pub fn to_html_with(markdown: &str, options: Options) -> String;
pub fn to_html_mapped(markdown: &str) -> String;
```

`to_html_mapped` оборачивает топ-блоки в `<div class="md-block" data-md="start,end">` (байтовые смещения UTF-8). Это **замороженный контракт** — на нём держатся inspector и scrollsync.

**Единственное запланированное расширение ядра** (только под плагины, отдельной задачей):
```rust
pub fn to_html_mapped_with(markdown: &str, options: Options) -> String;
```
Причина: плагинам нужно управлять `Options` (например, отключить таблицы), не форкая ядро.

## 4. DocumentStore (Rust) — владение состоянием

### 4.1. Структуры
```rust
#[derive(Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize)]
#[serde(transparent)]
pub struct DocumentId(String);

pub struct DocumentStore {
    docs: HashMap<DocumentId, Document>,
    order: Vec<DocumentId>,
}

pub struct Document {
    pub id: DocumentId,
    pub path: Option<PathBuf>,
    pub text: String,
    pub rev: u64,
    pub cached: Option<RenderCache>,      // (mapped, rev) -> html
    pub undo: Vec<EditOp>,                 // H2+, см. D5
    pub redo: Vec<EditOp>,
}

pub struct EditOp { pub rev: u64, pub range: (usize, usize), pub text: String }
pub struct RenderCache { pub mapped: bool, pub rev: u64, pub html: String }
```

### 4.2. Кто чем владеет

| Данные | Владелец | Обоснование |
|---|---|---|
| текст документа | **Rust** | плагин не видит DOM; текст — единственный общий знаменатель |
| `rev` (ревизия) | **Rust** | ключ кэша рендера и инвалидации индексов |
| `id ↔ path` | **Rust** | сохранение, recent files, плагинные host-функции |
| кэш HTML | **Rust** | устранение дублирования `lastRenderedHtml`/`renderSeq` |
| undo/redo стек | **Rust** (цель) | единая точка правок для `apply_edit` |
| dirty-флаг | TS (проекция) | нужен синхронно на каждое нажатие |
| selection, scroll, фокус | TS | UI-состояние, IPC на клавишу недопустим |
| layout, panes, tabs | TS | UI-состояние |

**Правило:** TS-`docStore` — **проекция** Rust-стора, а не второй источник истины. Любая правка текста идёт через Rust.

### 4.3. Команды (IPC) — 1:1 к host-функциям плагинов

| Команда | Сигнатура | Заменяет (as-is) |
|---|---|---|
| `new_document` | `(text?) -> DocMeta` | `newFile()` |
| `open_document` | `(path) -> DocMeta` | `read_file` + `currentPath` |
| `update_document` | `(id, text, mapped) -> RenderResult` | `render_markdown` + `lastRenderedHtml` + `renderSeq` |
| `render_document` | `(id, mapped) -> RenderResult` | повторный рендер |
| `save_document` | `(id, path?) -> DocMeta` | `write_file` |
| `close_document` | `(id) -> ()` | — (появляется вместе с 2 панелями) |

```rust
pub struct DocMeta { pub id: DocumentId, pub path: Option<String>, pub rev: u64, pub dirty_hint: bool }
pub struct RenderResult { pub html: String, pub rev: u64, pub changed: bool }
```
`changed: false` при неизменной `rev` — переезд `lastRenderedHtml` в Rust. TS при `changed: false` **не трогает DOM**.

## 5. TS-слой: layout, pane, view

### 5.1. Идентификаторы
```ts
type Brand<T, K extends string> = T & { readonly __b: K };
export type DocumentId = Brand<string, "doc">;
export type PaneId     = Brand<string, "pane">;
export type ViewId     = Brand<string, "view">;
```
Строки, а не числа: единый формат с Rust (`#[serde(transparent)]`) и с Lua-плагинами (строковые ключи в таблицах).

### 5.2. Layout — дерево
```ts
export interface Pane {
  kind: "pane";
  id: PaneId;
  views: ViewId[];      // D4: модель под вкладки закладывается сразу
  active: ViewId;
}
export interface Split {
  kind: "split";
  id: string;
  dir: "row" | "column";
  children: [LayoutNode, LayoutNode];
}
export type LayoutNode = Pane | Split;
const MAX_PANES = 2;    // единственное ограничение v1
```
Операции — чистая функция без DOM: `(layout, op) => layout | ValidationError`. Операции: `splitPane`, `closePane`, `focusPane`, `addView`, `removeView`, `activateView`.

### 5.3. Двухтировый ViewProvider (центральная идея)

**Тир 1 — plugin-safe** (JSON на входе, HTML на выходе):
```ts
export interface HtmlViewProvider {
  readonly kind: ViewKind;
  readonly title: string;
  createView(ctx: ViewContext, opts: Json): HtmlView;
}
export interface HtmlView {
  render(doc: DocumentSnapshot): Promise<void>;
  dispose(): void;
}
```

**Тир 2 — built-in only** (полный DOM: редактор, Excel-таблицы, инспектор):
```ts
export interface DomViewProvider {
  readonly kind: ViewKind;
  readonly title: string;
  createView(ctx: ViewContext, host: HTMLElement, opts: Json): DomView;
}
export interface DomView { activate(): void; deactivate(): void; dispose(): void }
```

Preview реализуется как тир-1 провайдер, но **встроен на хосте** (D2). Это позволяет обкатать контракт тир-1 без плагинного рантайма.

### 5.4. ViewContext — единственная «песочница»
```ts
export interface ViewContext {
  readonly paneId: PaneId;
  readonly viewId: ViewId;
  document(): DocumentSnapshot | null;
  edit(text: string): void;
  render(text: string, mapped: boolean): Promise<RenderResult>;
  status(msg: string): void;
  openExternal(url: string): void;
  onDocument(cb: (d: DocumentSnapshot) => void): () => void;
}
```
Никакого доступа к `document`, `window`, `fetch`, файловой системе. Только этот фасад.

### 5.5. Модульная карта (цель H1)

| Модуль | Ответственность | Строк (оценка) |
|---|---|---|
| `main.ts` | композиционный корень: собрать всё, повесить тулбар | ~120 |
| `ids.ts` | брендированные id + генераторы | ~40 |
| `docStore.ts` | проекция Rust-стора, подписки, dirty | ~120 |
| `layout.ts` | дерево, операции, валидация | ~150 |
| `paneHost.ts` | монтирование панелей в DOM, фокус | ~120 |
| `viewRegistry.ts` | реестр провайдеров тир-1/тир-2 | ~80 |
| `editorView.ts` | тир-2 редактор (textarea) | ~130 |
| `previewView.ts` | тир-1 preview | ~100 |
| `linkController.ts` | inspector + scrollsync (общий `buildUnitMaps`) | ~200 |
| `mapping.ts` | без изменений | 145 |
| `tables.ts` | украшение таблиц; **сохраняется как есть** (D12), новый функционал не добавляется | 422 |
| `tauri.ts` | IPC-обёртки (расширяется) | ~70 |

Устранение дублирования: `inspector.ts` и `scrollsync.ts` сейчас **независимо** строят `buildUnitMaps`/`collectBlocks` из одного markdown. `linkController` строит **один** `RenderIndex` с `rev` и раздаёт обоим.

### 5.6. Риски TS-слоя
- **Нативный undo textarea**: программная смена `value` при переключении документа ломает undo-стек браузера. В H1 — принять как ограничение; в H2 — Rust-undo (D5).
- **Глобальный DOM-мусор**: меню фильтров таблиц сейчас вешается в `document.body` — при 2 панелях обязательны per-view подписка и `dispose()`.
- **E2E-контракты id**: `id="editor"`/`id="preview"` остаются на элементах **первичной** панели, добавляются `data-pane`/`data-view`.

## 6. Плагинная система: Lua

### 6.1. Рантайм
```toml
mlua = { version = "0.12", features = ["lua55", "vendored"] }
```
- `vendored` — Lua 5.5 компилируется из исходников. C-тулчейн уже требуется для Tauri на Windows, новых требований не появляется.
- **LuaJIT запрещён**: `ffi` даёт доступ к произвольному C — дыра в песочнице.
- Компиляция плагина: `lua.load(src).set_name(name)`; **отдельный `Lua` инстанс на плагин** (изоляция глобальных).

#### 6.1.1. Почему Lua 5.5, а не 5.4

Lua 5.5 вышла **22 декабря 2025**; `mlua` 0.11.6 (27.01.2026) добавил поддержку (`lua55` feature), в 0.12.1 (29.08.2026) поднята до 5.5.1. Мы на mlua 0.12.2 → доступна стабильно.

Три изменения 5.5, релевантных нам напрямую:

| Новшество 5.5 | Почему важно для darmark |
|---|---|
| **Декларации глобальных переменных** (`global x`) | В скопе с явной декларацией неявные глобалы **запрещены** — опечатка `host.show_mesage(...)` станет ошибкой компиляции, а не тихим `nil`. Для плагинов, которые пишут новички, это главный выигрыш. |
| **Компактные массивы** (крупные массивы ~60% меньше памяти) | Прямо улучшает работу лимита памяти: плагин, читающий большой документ в массив строк, укладывается в бюджет. |
| **Внешние строки** (память не управляется Lua) | Позволяет отдать плагину текст документа **без копирования** в Lua-кучу (см. §10.1 — Rust-аллокации не входят в лимит). Снимает главное ограничение лимита памяти. |

Плюс улучшена сборка мусора (major GC инкрементальный — меньше пауз) и добавлен `table.create`.

**Минус — один:** Lua 5.5 новее, чем большинство обучающих материалов и примеров в сети. Для нашей аудитории (пользователь правит скрипт в блокноте) это не критично, но API-референс плагинов обязан быть написан явно под 5.5, а не скопирован из туториалов под 5.1/5.4.

**Откат:** смена `lua55` → `lua54` в Cargo.toml — одна строка, при условии что плагины не используют `global` и `table.create`. **Планируем 5.5 как основную версию** (D13); откат — аварийный вариант, если сборка под MSVC не пойдёт.

**Набор стандартных библиотек** — задаётся явно через `Lua::new_with(StdLib, LuaOptions)`:

| Библиотека | Включаем | Причина |
|---|---|---|
| `BASE` | да, **с чисткой** | `pairs`, `ipairs`, `type`, `tostring`, `error`, `pcall`, метатаблица строк |
| `STRING`, `TABLE`, `MATH`, `UTF8` | да | базовые операции, `utf8` нужен для Markdown; `TABLE` также даёт `table.create` (5.5) |
| `COROUTINE` | **нет** | `Lua::set_hook` ставится **на поток**; корутина получила бы поток без hook и обошла лимит инструкций. Отказ от корутин убирает дыру |
| `OS`, `IO` | **нет** | файлы и время — только через host-функции с permission |
| `PACKAGE` | **нет** | нет `require`; модули подключает хост |
| `DEBUG` | **нет** | hook ставится через C API и без библиотеки `debug` |

**Чистка после загрузки `BASE`:** удалить `load`, `loadfile`, `dofile`, `collectgarbage`; `print` перенаправить в `host.log("info", ...)` (иначе вывод плагина уходит в stdout хоста).

### 6.2. Модель: плагин = код, инстанс = привязка
```
plugin (код)         = манифест + .lua файл(ы)
instance (состояние) = привязка к view/подписке; слот состояния хранит ХОСТ
```
Хост хранит таблицу `PluginState` и передаёт её плагину как аргумент — плагины остаются **stateless по коду**, состояние живёт в хосте. Это упрощает `dispose()` и перезагрузку.

### 6.3. API плагина (host-функции)
Начать с 8 функций — минимально достаточно и расширяемо:

**Документ:**
```lua
host.get_document_text(doc_id)   -> string
host.get_document_version(doc_id)-> integer
host.apply_edit(doc_id, start, stop, text)  -- только с permission document:write
```

**View:**
```lua
host.get_view_state(view_id)     -> table {scroll, cursor}
host.set_view_content(view_id, html)        -- только для тир-1 view
host.on_event(view_id, event_name, handler) -- подписка на события view
```

**Хост:**
```lua
host.log(level, message)         -- level: "debug"|"info"|"warn"|"error" -> stderr хоста
host.show_message(text)          -- уведомление в статусбар
```

**Плюс Lua-нативные удобства** (регистрируются хостом, не требуют JSON-прослойки):
```lua
md.to_html(text, opts?)          -> string   -- обёртка над md-core
md.to_html_mapped(text, opts?)   -> string
json.encode(value) / json.decode(s)
```

### 6.5. Пример плагина (эталон документации)
```lua
-- word-count/main.lua
local function count_words(text)
  local n = 0
  for _ in text:gmatch("%S+") do n = n + 1 end
  return n
end

function on_activate(ctx)
  ctx.subscribe("document:changed", function(doc_id)
    local text = host.get_document_text(doc_id)
    host.show_message("Слова: " .. count_words(text))
  end)
end

function on_deactivate(ctx) end
```

### 6.6. Жизненный цикл
```
scan(plugins_dir) -> validate(manifest) -> load(src) -> on_activate(ctx)
                                                   -> [события/команды]
                                                   -> on_deactivate(ctx) -> unload
```
- Перезагрузка: `unload` старого инстанса → `load` нового файла с диска. **Без перезапуска приложения.**
- Ошибка загрузки (синтаксис, отсутствует `on_activate`) → плагин помечается `failed`, показывается сообщение, приложение работает.
- Автоперезагрузка по изменению файла (fs-watch) — опционально, off by default.

## 7. Протокол и транспорт

### 7.1. Уровни
| Уровень | Формат | Транспорт |
|---|---|---|
| **Данные** | serde-структуры `Request`/`Response`/`Error` (JSON-совместимые) | — |
| **Основной** | прямые вызовы host-функций через `mlua` | in-process, без сериализации |
| **Dev** | тот же конверт как JSON-строки | stdio (внешний процесс `darmark --debug-plugin <path>`) |

**Важно:** JSON-RPC **не является** основным транспортом. Для Lua-плагинов это был бы лишний слой сериализации на каждый вызов. Конверт сохраняется как единый формат данных, чтобы dev-режим и будущий внешний протокол были совместимы.

### 7.2. Версионирование
Поле `api_version` в манифесте. Хост отвергает плагин с `api_version > HOST_API_VERSION`. Обратная совместимость host-функций — семантическое версионирование, удаление функций запрещено без мажора.

## 8. Модель разрешений

По образцу Tauri ACL: **всё запрещено по умолчанию**, плагин декларирует нужное, пользователь подтверждает при установке/первом запуске и может отозвать.

| Разрешение | Что даёт |
|---|---|
| `document:read` | `get_document_text`, `get_document_version` |
| `document:write` | `apply_edit` |
| `view:create` | регистрация тир-1 view |
| `view:modify` | `set_view_content`, `on_event` |
| `filesystem:read` | `host.read_file(path)` — со scope (какие пути) |
| `filesystem:write` | `host.write_file(path, data)` — со scope |
| `network` | `host.http_*` — по умолчанию **не предоставляется вообще** |
| `ui:menu` | пункт в меню |
| `ui:statusbar` | элемент статусбара |
| `ui:sidebar` | панель в сайдбаре |
| `ui:toolbar` | кнопка в тулбаре |

Проверка — **на стороне хоста, до вызова**. Плагин без `document:write` получает `error { code = "permission_denied", permission = "document:write" }`, а не исключение Lua.

## 9. События

### 9.1. Каталог событий
| Событие | Полезная нагрузка |
|---|---|
| `document:changed` | `doc_id`, `rev` |
| `document:opened` / `document:closed` | `doc_id`, `path` |
| `view:scroll` | `view_id`, `top` |
| `view:focus` | `view_id` |
| `pane:resized` | `pane_id`, `w`, `h` |
| `command:invoked` | `command_id` |

### 9.2. Модель доставки: notify-only + pull
Событие **не несёт содержимое документа**. Оно несёт `doc_id` и `rev`. Плагин, если ему нужен текст, вызывает `get_document_text`. Причины:
1. Не дублировать большие строки в каждый подписчик.
2. Плагин может пропустить события (backpressure) без потери данных.

### 9.3. Коалесинг и порядок
- События по одному `doc_id` **коалесцируются по `rev`**: доставляется только последняя ревизия за тик.
- Порядок доставки: FIFO внутри одного типа события.
- Подписка возвращает `unsubscribe`-функцию; `dispose()` view/плагина **обязан** отписаться (иначе — утечка на закрытой DOM-ноде).

### 9.4. Обратная маршрутизация из тир-1 view
Как клик/ввод внутри HTML-плагина возвращается в плагин:
```
клик по [data-p-<pluginid>-action="foo"]
  -> делегированный слушатель на контейнере view (один на view)
  -> сериализация {view_id, action, payload} (payload из data-p-*-payload)
  -> вызов Lua-хендлера плагина
  -> плагин возвращает новый HTML или патч
  -> host.set_view_content / точечный патч
```
`data-p-<pluginid>-*` — **единственный** класс атрибутов, который переживает санитизацию (D7).

## 10. Ресурсные лимиты и отказоустойчивость

### 10.1. Лимиты

| Лимит | Значение | Механизм |
|---|---|---|
| Память плагина | 64–128 МБ | **`Lua::set_memory_limit(limit)`** — штатный API mlua 0.12; превышение даёт `Error::MemoryError`, а не падение |
| Метрика памяти | — | `Lua::used_memory()` → в UI («плагин X: 12 МБ») |
| CPU (защита от `while true do end`) | ~5 млн инструкций на вызов | `Lua::set_hook(HookTriggers::every_nth_instruction(N), cb)`; `cb` возвращает `Err` при превышении → вызов прерывается |
| Время инициализации | 1 с | таймаут на `load` + `on_activate` |
| Размер `.lua` | 1 МБ | проверка перед загрузкой |
| Корутины | запрещены | библиотека `COROUTINE` не загружается — иначе hook (per-thread) обходится |

Документация mlua прямо описывает наш сценарий: hook «can be used to implement a limited form of execution limits by setting `HookTriggers::every_nth_instruction` and erroring once an instruction limit has been reached».

**Доступность hook:** `Lua::set_hook` в mlua 0.12.2 помечен `Available on non-crate feature luau only`, то есть доступен для **всех Lua-версий, кроме Luau** — включая 5.5. Никакого обхода через `mlua::ffi::lua_sethook` не требуется. (Проверено в прототипе, см. §15.0.)

**Ограничение, которое надо знать:** `set_memory_limit` покрывает **только Lua-кучу**. Rust-аллокации внутри host-функций (например, `String` с текстом документа) в лимит не входят. Для наших объёмов (документ ≤ 10 МБ, ограничение `MAX_FILE_SIZE` уже есть) это приемлемо. Lua 5.5 **внешние строки** (см. §6.1.1) позволяют отдать текст документа без копирования в Lua-кучу — это снимает и вторую половину проблемы; проверить в прототипе.

### 10.2. Отказоустойчивость
- Lua-ошибка (`error`, `MemoryError`, stack overflow) → плагин **не роняет приложение**; хост ловит `mlua::Error`, логирует, показывает сообщение в статусбаре.
- **Карантин:** после N=3 падений подряд плагин автоматически отключается до ручного включения.
- Паника внутри host-функции не должна пробиваться в UI: host-функции возвращают `Result`.

### 10.3. Три уровня доверия (для трезвости ожиданий)

| Уровень | Что даёт | Чем обеспечен |
|---|---|---|
| **Не сломает приложение** | ошибка/лимит → сообщение, а не краш | `pcall` + `Result` + карантин |
| **Не съест ресурсы** | лимит памяти и инструкций | `set_memory_limit` + `set_hook` |
| **Не украдёт данные** | нет ФС/сети без permission, нет `os`/`io`/`require` | allowlist библиотек + проверка permission в host-функции |

### 10.4. Почему `bumpalo` для песочницы не подходит

Рассматривался вариант «изолировать память плагина arena-аллокатором (`bumpalo`)». **Отклонено:**

1. **Семантика несовместима с GC.** Bump-аллокатор освобождает только всё сразу (`reset()`); поштучного `dealloc` нет. Lua — GC-язык: сборщик постоянно освобождает и переиспользует строки/таблицы. С bump-ареной память будет **только расти** до лимита, и единственное «лечение» — `reset()`, то есть уничтожение Lua-состояния целиком.
2. **Лимита не даёт.** `bumpalo` не умеет «стоп на 64 МБ». Чтобы получить лимит, надо обернуть его в собственный `GlobalAlloc` со счётчиком — но тогда счётчик можно повесить прямо на `allocf`, и `bumpalo` становится лишним слоем.
3. **Дублирование существующего.** `Lua::set_memory_limit` уже реализован внутри mlua ровно через этот механизм (собственный allocator функции Lua). Писать своё = делать то же, но хуже.
4. **Скорости не выиграет.** Bump быстр на множестве мелких аллокаций с одинаковым временем жизни. Lua-куча — противоположный паттерн (разное время жизни + GC).

**Вердикт:** для песочницы — штатный `set_memory_limit` (D9). `bumpalo` в зависимости **не добавляем**.

### 10.5. Где арена (`bumpalo`) была бы уместна (не сейчас)

| Место | Пригодность | Вердикт |
|---|---|---|
| Временные структуры одного host-вызова (разбор аргументов) | подходит по паттерну | выигрыш недоказан, значения всё равно копируются в Lua-кучу → **отложить** |
| `md-core::to_html_mapped` (сборка `StructRange`) | подходит, но ядро трогать запрещено | **отложить** |
| Плагинный парсер/AST/граф | классический кейс | вне vision (§1.3) |

Правило: арена добавляется **только за бенчмарком** и отдельным ADR. Сейчас — YAGNI: `+размер бинарника`, `−ничего`.

## 11. Санитайзер и границы безопасности

### 11.1. Единая точка
Санитизация — **только на хосте**, ровно один раз, в конце конвейера рендера. Фронтенд `preview.innerHTML = html` доверяет результату.

### 11.2. Текущие ограничения (as-is) и что меняем
| Ограничение | Следствие | Решение |
|---|---|---|
| `DROP_CONTENT_TAGS` включает `svg` | диаграммные/графические плагины невозможны | allowlist-подмножество SVG (`svg`, `g`, `path`, `rect`, `circle`, `line`, `polyline`, `text`, `defs`, `use`) без событий и внешних ссылок; иначе растровый fallback |
| Все `data-*` срезаются | интерактивный HTML плагина не работает | `data-p-<pluginid>-*` — allowlist-префикс |
| Нет политики для кастомных классов | плагинные стили невозможны | классы с префиксом `p-<pluginid>-` переживают санитизацию |
| `ALLOWED_SCHEMES = ["http","https","mailto","tel"]` | — | сохранить; для плагинов **дополнительно** запретить `http` в `src`/`href` без permission `network` |

### 11.3. CSP
`default-src 'self'; style-src 'self' 'unsafe-inline'` — сохраняется. Плагины **не могут** внедрять скрипты: только HTML + инлайн-стили. Внешние библиотеки/`eval` запрещены.

### 11.4. Честная граница: софт-песочница, не hard-isolation
Lua выполняется **в процессе приложения**. Это значит:
- Защита — от **багов и случайного вреда** (бесконечный цикл, утечка памяти, чтение файла без permission).
- Защиты от **намеренного обхода** (эксплойт в интерпретаторе Lua, шелл-код) — нет. Hard-isolation потребовала бы отдельного процесса или WASM (это и был единственный настоящий аргумент за wasmi, отклонённый в D1).

Для модели угроз darmark это адекватно: плагины ставит сам пользователь для себя, в отличие от расширений браузера, скачиваемых из чужого стора. **Магазин плагинов (H3) обязан** явно предупредить об этом в UI установки.

**Риски прототипа:**
- Сборка vendored Lua 5.5 под MSVC может потребовать правок — тогда fallback на `lua54` (аварийный, D13) и запись в FINDINGS.

## 17. Глоссарий

| Термин | Значение |
|---|---|
| **Document** | Данные файла: текст, `rev`, путь, кэш рендера, undo-стек. Владелец — Rust. |
| **View** | Способ отображения документа. Два тира: HtmlView (JSON→HTML) и DomView (полный DOM). |
| **Pane** | Слот в layout. Содержит `views[]` и активный `ViewId`. |
| **Layout** | Бинарное дерево разбиений. `MAX_PANES = 2` в v1. |
| **ViewContext** | Единственный фасад доступа view/плагина к хосту. |
| **rev** | Ревизия документа, инкремент на каждую правку. Ключ кэша и инвалидации. |
| **RenderIndex** | Карты «байты ↔ code units» + блоки. Строится один раз на `rev`. |
| **Плагин** | Код: манифест + `.lua`. |
| **Инстанс** | Привязка плагина к view/подписке; состояние хранит хост. |
| **Карантин** | Автоотключение плагина после 3 падений подряд. |
| **notify-only + pull** | Событие несёт `doc_id`+`rev`, содержимое плагин запрашивает сам. |
| **Софт-песочница** | Изоляция средствами рантайма (allowlist, лимиты) в одном процессе; не защищает от эксплойта интерпретатора. |
