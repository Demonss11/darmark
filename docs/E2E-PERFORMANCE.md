# E2E: замеры времени и статуса сценариев

> **Назначение:** следить за скоростью и стабильностью GUI E2E-набора
> (`cd crates/app && npm run test:e2e`; Cucumber + WebdriverIO поверх release-бинарника).
> **Метод:** время — wall-clock каждого сценария (хуки `Before`/`After`), а не
> `result.duration` cucumber (он показывает лишь последний шаг). WDIO запускает
> каждую `.feature` отдельной сессией, поэтому в первый сценарий сессии входит старт приложения.
> **Обновление:** файл — снимок последних значений (без дельт); перегенерировать
> `node e2e/timing-report.mjs <timing.jsonl> ../../docs/E2E-PERFORMANCE.md` (см. шапку скрипта).

Платформа: Windows x86_64; приложение — release-сборка; WebView2.

## Контекст: устранённые источники накладных расходов

### WebDriver-команды элементов (`$`/`$$`, `waitForExist`, `getValue`, `elementClick`, `getTitle`)

Их перехватывает `ensureActiveWindowFocus()` из `@wdio/tauri-service` и на каждую команду
запрашивает состояние окна через `browser.tauri.execute`. В приложении darmark нет guest-JS
`@wdio/tauri-plugin`, поэтому проба готовности плагина крутится полный бюджет (~100×50 мс ≈ 5 с)
и падает («Failed to get window states»). Общая точка входа была — шаг `приложение darmark запущено`
(`smoke.steps.js`) с `$("#editor").waitForExist()` / `$("#preview").waitForExist()`; отсюда до 374 с
на сессию у дровера, вкладок, smoke и a11y.

**Исправлено:** в `smoke.steps.js` ожидание/чтение DOM переведено на `browser.execute`; в `a11y.steps.js`
реальный клик по тумблеру — на W3C pointer-actions (`browser.action`). Элементных WebDriver-команд в
шагах больше нет (0 `findElement` / 0 «Failed to get window states» за прогон).

### Дубликат определения шага

Шаг `предпросмотр виден` был определён и в `logs.steps.js`, и в `plugins.steps.js` → «Multiple step
definitions match». `logs.feature` помечена `@wip`, но файлы шагов загружаются всегда, поэтому
регистрация дублировалась.

**Исправлено:** вариант в `logs.steps.js` переименован в `предпросмотр виден в рабочей области`
(проверка по геометрии; у глобального шага — по атрибуту `hidden`), Gherkin `logs.feature` обновлён.

### Остаточные расходы (норма)

- Новое приложение на каждый spec-файл: время старта входит в первый сценарий сессии, холодный старт —
  в самый первый сценарий прогона.
- Фиксированные паузы шагов (`browser.pause`) — сотни миллисекунд на сценарий.
