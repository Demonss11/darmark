# Бэклог идей

> **Статус:** non-normative, живой бэклог идей проекта (не только UI).
> **Нормативно:** `docs/DESIGN_DOC.md` (layout/контракты, + ADR в `docs/adr/`); визуальная идентичность и дизайн-концепции — `DESIGN.md`.
> **Как идея продвигается:** идея → спайк → ADR → TZ → код.

## Статусы

- `идея` — сырое, не оценено;
- `research` — нужен спайк;
- `adr` — нужно архитектурное решение;
- `tz` — готово к реализации;
- `done` — реализовано (ссылка на TZ);
- `dropped` — отклонено (кратко почему).

## Шаблон идеи

```
### IDEA-NNN — <название>
- **Статус:** идея | research | adr | tz | done | dropped
- **Зачем:** <продуктовая ценность>
- **Суть:** <что делаем>
- **Затрагивает:** DESIGN_DOC §…, ADR-…, замороженные контракты §13.2 (да/нет)
- **Артефакты:** спайк / ADR / TZ
- **Открытые вопросы:** …
- **Критерий успеха:** …
```

## Бэклог

### IDEA-002 — Разделение Host / Engine (универсальный редактор)

- **Статус:** research (спайки) → adr
- **Зачем:** продуктовый pivot — от «Markdown-редактора» к универсальному редактору с подключаемыми движками. Host работает с файлом, не зная про Markdown.
- **Суть:**
  - **Host** — оболочка/файлы/UI: открывает файл, отдаёт текст движку.
  - **Engine** — абстракция `text → данные отрисовки`; реализации: `md-core`, WASM, IPC, плагин.
- **Затрагивает:** `DESIGN_DOC` §2 (слои), §3 (контракт ядра), §5.3/§5.4 (тир-1 ViewProvider как «движок-представление»), §6–§12 (плагины), §13.2 (id/селекторы) (бюджет). **Нужен отдельный ADR.**
- **Артефакты:**
  - спайки: `crates/*-spike` + замеры в `docs/FINDINGS.md` (латентность IPC, размер/запуск WASM, стоимость сериализации render-data);
  - ADR с границей Host/Engine и формальным контрактом;
  - обновление `DESIGN_DOC` §2/§3.
- **Открытые вопросы (гипотезы для спайков):**
  1. Что отдаёт Engine: HTML или структурные данные (AST/токены/патч)? Инкрементальность?
  2. Выдержит ли дебаунс рендера 120 мс (§13.2) проход через WASM/IPC?
  3. Где живёт mapping байты↔UTF-16 и `data-md` — в Engine или Host?
  4. WASM: размер, бюджет (GUI ≤ 6 МБ).
  5. Плагины H2 и «плагины-движки» — общий механизм или разные?
  6. Совместимость: `md-core` остаётся эталонным Engine.
- **Критерий успеха спайка:** Host отображает Markdown через Engine; замеры IPC/WASM приемлемы; e2e §13.2 не сломаны.

### IDEA-003 — Деградация tool-loop у провайдеров без поддержки `tools`

- **Статус:** adr
- **Зачем:** часть OpenAI-совместимых шлюзов отвергает поле `tools` (400) или молча игнорирует его. Сейчас `ai_chat` объявляет инструменты в каждом чате (реестр MCP непуст), и такой провайдер отдаёт `ai:error` вместо обычного ответа — регрессия против прежнего поведения.
- **Суть:** зафиксировать поведение по `tasks/MCP-TOOLLOOP.md` §3.3: (а) 400 на `tools` → один авто-повтор без `tools`; (б) 200 без `tool_calls` → повтор без `tools`; (в) нестандартная форма `tool_calls` → считать пустыми. Решить: тихий `warn` vs карточка в чате; кэш «провайдер не умеет tools» на сессию; эвристика отличия 400 «из-за tools». Реализован только минимум «пустой реестр → нет поля `tools`» (`ai/commands/mod.rs::provider_tools`).
- **Затрагивает:** `ai/commands/mod.rs`, `ai/tool_loop.rs`, ADR-0036; замороженные контракты §13.2 — нет.
- **Артефакты:** решение (ADR или дополнение к ADR-0036), тесты деградации.
- **Открытые вопросы:** §3.3 ТЗ (Q1–Q4).
- **Критерий успеха:** зафиксировано поведение для (а)/(б)/(в); чат не ломается у провайдера без `tools`.

### IDEA-004 — Единый статус валидации: карточка вызова vs запись журнала

- **Статус:** idea
- **Зачем:** `plugin_validate` на невалидном плагине возвращает `Ok(result)` с `result.ok = false` без `isError`, поэтому tool-loop считает вызов успешным (`ok = !isError`) и рисует карточку «готово», а журнал MCP пишет «ошибка». Два наблюдательных канала показывают противоположное — AC-MCP-4 подтверждён лишь частично.
- **Суть:** адаптер `plugin_validate`/`plugin_test` должен отдавать `isError: true` при провале валидации (или карточка обязана брать статус из результата, а не из `isError`). Затрагивает `mcp/adapters/tools.rs`, `ai/tool_loop.rs`.
- **Затрагивает:** `crates/app/src-tauri/src/mcp/adapters/tools.rs`, `crates/app/src-tauri/src/ai/tool_loop.rs`; ADR-0036; замороженные контракты §13.2 — нет.
- **Артефакты:** решение (правка адаптера + ADR), тест контракта `mcp`.
- **Критерий успеха:** карточка и журнал согласованы по статусу для всех исходов валидации.

### IDEA-005 — Красный `npm run lint` (oxlint) пре-существующий

- **Статус:** idea
- **Зачем:** `npm run lint` (`oxlint --deny-warnings src e2e scripts`) падает на `src/panels/aiPanel/pluginCard.ts:239` — `unicorn(no-useless-spread)`: `for (const card of [...state.pluginCards])`. Правило ложно-положительное: спред делает снимок `Set` перед удалением элементов в цикле (`card.remove()` → `state.pluginCards.delete(...)`); без снимка итерация по мутируемому `Set` пропускала бы элементы. Ошибка пре-существующая (пришла из `de36eec`, эпик MCP файл не трогал), но CI-джоб линта на ветке красный.
- **Суть:** безопасная правка — `Array.from(state.pluginCards)` вместо спреда (эквивалентно, правило не срабатывает), либо точечный `oxlint-disable` с обоснованием.
- **Затрагивает:** `crates/app/src/panels/aiPanel/pluginCard.ts`; замороженные контракты §13.2 — нет.
- **Артефакты:** зелёный `npm run lint`.
- **Критерий успеха:** `cd crates/app; npm run lint` возвращает exit 0 без изменения поведения очистки карточек.
