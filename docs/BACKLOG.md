# Бэклог идей

> **Статус:** non-normative, живой бэклог идей проекта (не только UI).
> **Нормативно:** `docs/DESIGN_DOC.md` (layout/контракты, + ADR в `docs/adr/`); визуальная идентичность и дизайн-концепции — `DESIGN.md`.
> **Как идея продвигается:** идея → спайк → ADR → TZ → код.

## Статусы

- `идея` — сырое, не оценено;
- `research` — нужен спайк;
- `adr` — нужно архитектурное решение;
- `tz` — готово к реализации;
- `done` — реализовано (ссылка на TZ);
- `dropped` — отклонено (кратко почему).

## Шаблон идеи

```
### IDEA-NNN — <название>
- **Статус:** идея | research | adr | tz | done | dropped
- **Зачем:** <продуктовая ценность>
- **Суть:** <что делаем>
- **Затрагивает:** DESIGN_DOC §…, ADR-…, замороженные контракты §13.2 (да/нет)
- **Артефакты:** спайк / ADR / TZ
- **Открытые вопросы:** …
- **Критерий успеха:** …
```

## Бэклог

### IDEA-002 — Разделение Host / Engine (универсальный редактор)

- **Статус:** research (спайки) → adr
- **Зачем:** продуктовый pivot — от «Markdown-редактора» к универсальному редактору с подключаемыми движками. Host работает с файлом, не зная про Markdown.
- **Суть:**
  - **Host** — оболочка/файлы/UI: открывает файл, отдаёт текст движку.
  - **Engine** — абстракция `text → данные отрисовки`; реализации: `md-core`, WASM, IPC, плагин.
- **Затрагивает:** `DESIGN_DOC` §2 (слои), §3 (контракт ядра), §5.3/§5.4 (тир-1 ViewProvider как «движок-представление»), §6–§12 (плагины), §13.2 (id/селекторы) (бюджет). **Нужен отдельный ADR.**
- **Артефакты:**
  - спайки: `crates/*-spike` + замеры в `docs/FINDINGS.md` (латентность IPC, размер/запуск WASM, стоимость сериализации render-data);
  - ADR с границей Host/Engine и формальным контрактом;
  - обновление `DESIGN_DOC` §2/§3.
- **Открытые вопросы (гипотезы для спайков):**
  1. Что отдаёт Engine: HTML или структурные данные (AST/токены/патч)? Инкрементальность?
  2. Выдержит ли дебаунс рендера 120 мс (§13.2) проход через WASM/IPC?
  3. Где живёт mapping байты↔UTF-16 и `data-md` — в Engine или Host?
  4. WASM: размер, бюджет (GUI ≤ 6 МБ).
  5. Плагины H2 и «плагины-движки» — общий механизм или разные?
  6. Совместимость: `md-core` остаётся эталонным Engine.
- **Критерий успеха спайка:** Host отображает Markdown через Engine; замеры IPC/WASM приемлемы; e2e §13.2 не сломаны.

### IDEA-003 — Деградация tool-loop у провайдеров без поддержки `tools`

- **Статус:** done (реализовано `5b6b740`; ADR-0040 — `docs/adr/0040-ai-tools-capability-degradation.md`; ТЗ не заводилось — решение целиком ADR)
- **Зачем:** часть OpenAI-совместимых шлюзов отвергает поле `tools` (400) или молча игнорирует его. Сейчас `ai_chat` объявляет инструменты в каждом чате (реестр MCP непуст), и такой провайдер отдаёт `ai:error` вместо обычного ответа — регрессия против прежнего поведения.
- **Суть:** зафиксировать поведение по `tasks/MCP-TOOLLOOP.md` §3.3: (а) 400 на `tools` → один авто-повтор без `tools`; (б) 200 без `tool_calls` → обычный финальный ответ, повтор не выполняется (ADR-0040 §2.4); (в) нестандартная форма `tool_calls` → считать пустыми. Решено: тихий `warn` вместо карточки в чате; кэш «провайдер не умеет tools» по `(base_url, model)` в `AiState`; эвристика отличия 400 «из-за tools» — по статусу, без разбора тела (ADR-0040 §2.6, §2.5, §2.3).
- **Затрагивает:** `ai/commands/mod.rs`, `ai/tool_loop.rs`, ADR-0036; замороженные контракты §13.2 — нет.
- **Артефакты:** ADR-0040 (дополнение к ADR-0036); тесты деградации в `ai/tests/` (`tool_loop.rs`, `commands.rs`, `errors.rs`, `state.rs`) + контракт сериализации `CommandError` в `error.rs`.
- **Ограничения (ADR-0040 §3):** деградация срабатывает только на 400 (шлюз, отвечающий на отказ `tools` статусом 422/501, не покрывается); `CONTEXT_MARKERS` неполны — нераспознанная формулировка превышения контекста даёт один лишний повтор без `tools`.
- **Открытые вопросы:** нет — Q1–Q4 закрыты ADR-0040 §2.6, §2.5, §2.3, §2.8.
- **Критерий успеха:** зафиксировано поведение для (а)/(б)/(в); чат не ломается у провайдера без `tools`.

### IDEA-004 — Единый статус валидации: карточка вызова vs запись журнала

- **Статус:** tz (ADR-0041 — `docs/adr/0041-mcp-tool-verifier-status.md`; ТЗ не заводилось — решение целиком ADR)
- **Зачем:** `plugin_validate` на невалидном плагине возвращает `Ok(result)` с `result.ok = false` без `isError`, поэтому tool-loop считает вызов успешным (`ok = !isError`) и рисует карточку «готово», а журнал MCP пишет «ошибка». Два наблюдательных канала показывают противоположное — AC-MCP-4 подтверждён лишь частично.
- **Суть (ADR-0041):** инструмент-верификатор объявляет свой вердикт полем `isError` в payload, транспорт `mcp-core` копирует его в конверт `tools/call`; структурированный payload сохраняется целиком, журнал и карточка читают один `result.ok`. Три класса исходов: проверка не прошла → `isError: true` + журнал «ошибка» (правится); проверка прошла → без `isError` (не меняется); вызов отсечён до исполнения → `ToolError`, карточка `is-error`, записи журнала нет (не меняется — фиксирует ADR-0040 §2.6 п.29).
- **Уточнение формулировки (было неверно):** «адаптер должен отдавать `isError: true`» в текущем коде **невыполнимо** — ветка `Ok(result)` в `mcp-core/src/server.rs:93-107` жёстко собирает конверт без `isError` и пробрасывать поле обработчику нечем; это слепое зрение транспорта, а не только адаптера. Вариант «карточка берёт статус из `payload.ok`» отклонён: лечит симптом на одном клиенте, оставляет слепым агента и вносит вертикальный хардкод в общий крейт. Вариант A (`ToolError` при `!result.ok`) отклонён: теряет структуру и ломает AC-MCP-6 (паритет payload с ядром в `tests/mcp_contract.rs`).
- **Уточнение диагноза (было неточно):** дефект ловится не тем, что тесты обходят JSON-RPC-слой. `tests/mcp_contract.rs` **ходит через `server.handle`** и содержит невалидную фикстуру (`plugin_validate_reports_nonempty_errors_matching_static_validation`), но не утверждает `is_error(&envelope)` для этого случая — не смотрит на сломанный признак. Плюс E2E закрывает классы «прошло» и «отказ до исполнения», но **провал проверки на невалидном плагине в UI не покрыт вообще**.
- **Затрагивает:** `crates/mcp-core/src/server.rs` (чтение `isError` в ветке `Ok`), `crates/mcp-core/src/handlers.rs` и `registry.rs` (док-комментарии конвенции), `crates/mcp-core/tests/server_tests.rs`; `crates/app/src-tauri/src/mcp/adapters/tools.rs` (merge `isError`, общий хелпер); `crates/app/src-tauri/tests/mcp_contract.rs`; `crates/app/src-tauri/src/ai/plugin_harness/tests/mcp.rs` (док-комментарий); `crates/app/e2e/` (фикстура `e2e-invalid`, третий вызов). ADR-0036 §2.2 дополняется; ADR-0036 §2.4, ADR-0038 §2.3, ADR-0040 — без изменений. **Фронт не меняется:** `tool_loop.rs:131-134` уже читает `isError`, `toolCard.ts:74-81` уже рисует по `ok`. **Панель плагинов не меняется:** `pluginCard.ts:131-135` читает `res.ok` из прямой команды и корректна; тип `AiValidationResult` обслуживает и MCP, и `ai_validate_plugin`, поэтому `isError` добавляется merge на уровне `Value` в адаптере, а не полем в структуре. Замороженные контракты §13.2 — нет; `HOST_API_VERSION` не поднимается.
- **Артефакты:** ADR-0041; правки кода — `mcp-core` (2 теста), адаптер MCP (merge), контракт-тест (утверждение о конверте), E2E (третий вызов). Проверки: `cargo test -p mcp-core`, `cargo test -p darmark`, `cd crates/app; npm run test:e2e`.
- **Критерий успеха:** карточка и журнал согласованы по статусу для всех исходов валидации — инвариант сформулирован **по классам** (ADR-0041 §2.4 п.14): если инструмент исполнился, журнал и карточка не могут показывать разное; если не исполнился — карточка `is-error` без записи журнала.

### IDEA-005 — Красный `npm run lint` (oxlint) пре-существующий

- **Статус:** done (исправлено `d375147`: `Array.from(state.pluginCards)` вместо спреда; `npm run lint` → exit 0)
- **Зачем:** `npm run lint` (`oxlint --deny-warnings src e2e scripts`) падает на `src/panels/aiPanel/pluginCard.ts:239` — `unicorn(no-useless-spread)`: `for (const card of [...state.pluginCards])`. Правило ложно-положительное: спред делает снимок `Set` перед удалением элементов в цикле (`card.remove()` → `state.pluginCards.delete(...)`); без снимка итерация по мутируемому `Set` пропускала бы элементы. Ошибка пре-существующая (пришла из `de36eec`, эпик MCP файл не трогал), но CI-джоб линта на ветке красный.
- **Суть:** безопасная правка — `Array.from(state.pluginCards)` вместо спреда (эквивалентно, правило не срабатывает), либо точечный `oxlint-disable` с обоснованием.
- **Затрагивает:** `crates/app/src/panels/aiPanel/pluginCard.ts`; замороженные контракты §13.2 — нет.
- **Артефакты:** зелёный `npm run lint`.
- **Критерий успеха:** `cd crates/app; npm run lint` возвращает exit 0 без изменения поведения очистки карточек.
