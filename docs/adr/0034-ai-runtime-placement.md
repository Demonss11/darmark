# ADR-0034. Размещение AI-рантайма: в процессе GUI (шов `AiBackend`/`AiTransport`); сайдкар отложен

- **Статус:** **Принят**
- **Дата:** 11.10.2026

---

## 1. Контекст

### 1.1. Проблема

AI-ассистент — сетевой функционал в лёгком редакторе под жёстким D6. При обсуждении провайдера и клиента (ADR-0032/0033) возникло предложение разместить AI-рантайм **вне процесса GUI** — отдельным бинарником `darmark-ai.exe` «как плагины»: чтобы (а) не раздувать `darmark.exe` и (б) сделать фичу включаемой/отключаемой на уровне дистрибутива. Нужно зафиксировать **место исполнения** AI и последствия этого выбора.

### 1.2. Что уже зафиксировано (не пересматривается)

- **HTTP-клиент** — `reqwest` (`native-tls`/SChannel) + **SSE** (ADR-0033).
- **Провайдер** — OpenAI-совместимый API (`routerai.ru`) (ADR-0032).
- **D6 (release-exe ≤6 МБ, size-gate)**; ориентир AI-клиента — маргинальный прирост ≤1.0 МиБ (ADR-0033).
- **Сайдкар у плагинов обязателен технически**: `mlua`/Lua под `panic="abort"` недопустим в GUI (D6/ADR-0021), поэтому `darmark-plugin-host.exe` — отдельный child. Это техническая причина, а не универсальный паттерн «всё внешнее — в child».

### 1.3. Коллегиальная оценка

Предложение «вынести AI в `darmark-ai.exe` сейчас» рассмотрено тремя ролями; результат: бюджет укладывается (`darmark.exe` 3.94 МиБ, gate 6 МиБ, AI ≤1.0 МиБ); сайдкар не уменьшает поставку (`externalBin` пакует всегда); security-минус (инверсия привилегий, подмена бинарника) — подробности в §4.

---

## 2. Решение

**AI-рантайм — в процессе GUI (`crates/app/src-tauri/src/ai/`), сеть — на Rust-стороне (ADR-0032/0033). Сайдкар `darmark-ai.exe` отложен; фича делается включаемой без отдельного бинарника. Закладывается шов `AiBackend`/`AiTransport`, чтобы будущий сайдкар стал drop-in без переделки UI/IPC. MCP — вне MVP.**

### 2.1. Место исполнения

1. AI-модуль размещается **в процессе GUI** — `crates/app/src-tauri/src/ai/`: HTTP-клиент, SSE-парсер, хранение ключа. Отдельный бинарник/child **не вводится**.
2. Сеть AI остаётся **только на Rust-стороне**; CSP не ослабляется (§2.7).
3. Модуль локализован: смена клиента/TLS/провайдера и потенциальное выделение в child не трогают замороженные контракты §13.2 и контракт плагинов (ADR-0021).

### 2.2. Шов под будущий сайдкар

4. Вызов провайдера и передача текста инкапсулируются за **трейтом `AiBackend`/`AiTransport`**: реализация в процессе GUI — первый и единственный в MVP вариант за трейтом.
5. Шов проектируется так, чтобы **сайдкар стал drop-in** — замена реализации трейта **без переделки UI и IPC-контрактов** фронта.
6. Шов **не вводит неиспользуемых сущностей**: минимальная абстракция — один трейт и одна реализация; расширение — по триггерам §2.6, отдельным ADR.

### 2.3. Включаемость без бинарника

7. Фича включается **флагом `ai.enabled`** в `config.json` — без отдельного бинарника. Инициализация AI-модуля — **ленивая** (сеть/клиент не поднимаются, пока фича не востребована).
8. Пользователю показываются **понятные состояния**: «**выкл**», «**нет ключа**», «**нет согласия**», «**офлайн**» (ADR-0030).
9. Отключение `ai.enabled` **не требует** пересборки/переустановки — фича гасится конфигом, не удалением файла из дистрибутива (в отличие от сайдкар-варианта).

### 2.4. `plugin-cli` — инструмент, не рантайм

10. Harness плагинов — **инструмент разработчика**, а **не** AI-рантайм: он **делегирует** существующему CLI `darmark-plugin`, **переиспользуя** валидацию манифеста и изоляцию `mlua` (прогон в песочнице — только в child, D6/ADR-0021).
11. Отчёт harness — **версионированный JSON**; **fallback** при недоступности CLI — прямая валидация + прогон `plugin-host` (тот же контракт проверки).
12. Сеть в `plugin-cli` **не вводится**: CLI остаётся dev-инструментом, AI-рантайм — отдельно (§2.1). Смешение «dev-инструмент + AI-рантайм» запрещено (см. §4).

> **Обновление (14.10.2026).** Версия схемы версионированного отчёта (п. 11) вынесена в
> `plugin-core::REPORT_SCHEMA_VERSION`: писатель поля (`plugin-cli`) и читатель
> (`ai::plugin_harness`) обязаны сверяться с **одной** константой. Два независимых литерала `1`
> означали бы тихую рассинхронизацию контракта, при которой расхождение выглядело бы как
> «малоизвестный формат» и молча уводило harness в fallback. Политика версий не меняется:
> аддитивные поля не повышают мажор, неизвестная версия → fallback.

### 2.5. MCP

13. **MCP — вне MVP.** MCP — **отделённая граница доверия** (**inbound**: внешние клиенты вызывают нас), качественно иная, чем outbound-запрос к провайдеру. При появлении кейса внешних клиентов — **отдельный ADR**.

> **Обновление (12.10.2026).** Пункт 13 **замещён** **ADR-0036**: рамка MCP пересмотрена — это **внутренний** контрактный tool-слой (клиент — только встроенный AI), транспорт **in-memory**, трек — `tasks/TZ-MCP.md`. Внешние клиенты/inbound по-прежнему вне рамки.

### 2.6. Триггеры перехода к сайдкару (пересмотр настоящего ADR)

14. Настоящее решение **пересматривается** (новый ADR / правка этого) при любом из триггеров:
    - требование дистрибутива **без AI** (поставка, физически не содержащая сетевой AI-код);
    - **тяжёлый AI** (tool-loop, локальная модель, эмбеддинги), несовместимый с бюджетом/архитектурой in-process;
    - гейт `darmark.exe` **станет тесным** (прирост AI перестанет укладываться в остаток ≤6 МБ);
    - желание **CI-инварианта** `cargo tree -p darmark` **без `reqwest`** (жёсткое разделение сетевого слоя на уровне сборки).
15. До наступления триггеров сайдкар **не вводится**; шов §2.2 держит выделение в child **рефактором за трейтом**, без правок UI/IPC.

### 2.7. Инварианты, которые не меняются

16. Сеть — **только Rust-сторона**; CSP не ослабляется (ADR-0032/0033).
17. Согласие на отправку содержимого — **обязательно**; ответ рендерится через Rust-санитайзер (ADR-0030 §2.4, D7/§11).
18. События/контракты AI — **аддитивны**; мажор `HOST_API_VERSION` не поднимается (ADR-0027 §2.4); контракты §13.2 и контракт плагинов **не меняются** (AI — не плагин, ADR-0021).
19. **`mlua` остаётся вне GUI-хоста** (D6/ADR-0021, guard `cargo tree -p darmark`); `plugin-cli` — dev-инструмент, не AI-рантайм (§2.4).

## 3. Последствия

**Положительные:**

- **Нет нового бинарника, протокола и супервизора:** меньше движущихся частей, нет `AI_PROTOCOL_VERSION`/конверта/Job Object для AI.
- **Сайдкар не уменьшает поставку** (`externalBin` пакует всегда) — вынос был бы переносом веса без выгоды; размер укладывается: `darmark.exe` 3.94 МиБ, AI ≤1.0 МиБ, gate 6 МиБ (§4).
- **Меньше поверхность атаки:** нет child с сетью+ключом, нет риска подмены AI-бинарника; секрет и egress остаются в единственном процессе с уже действующими митигациями (ADR-0032 §2.4).
- **Включаемость решена конфигом:** `ai.enabled` + ленивая инициализация + состояния «выкл/нет ключа/нет согласия/офлайн» — без отдельного бинарника (§2.3).
- **Обратимость:** выделение в child — **рефактор за трейтом** `AiBackend`/`AiTransport`, UI/IPC не переделываются (§2.2, §2.6).
- **Переиспользование плагинной инфраструктуры:** harness делегирует `darmark-plugin`, изоляция `mlua` сохраняется (§2.4).

**Отрицательные / ограничения:**

- **AI-код (и `reqwest`) остаётся в дереве `darmark`:** `cargo tree -p darmark` содержит сетевой стек; CI-инвариант «без `reqwest`» **не достигается** сейчас (это триггер §2.6).
- **Дистрибутив физически содержит AI** (код + сетевой стек), даже если `ai.enabled=false`; «поставка без AI» возможна только через сайдкар-выделение (§2.6).
- **Тяжёлый AI** (локальная модель, эмбеддинги, tool-loop) не вписывается в in-process-модель — потребует пересмотра (§2.6).
- **Шов надо держать честным:** абстракция `AiBackend`/`AiTransport` без переусложнения; одна реализация в MVP (риск «преждевременной» абстракции принят сознательно ради обратимости).
- **`plugin-cli` — граница ответственности:** harness обязан оставаться dev-инструментом, сеть в CLI не вводится; иначе — смешение ролей (§2.4).

## 4. Отклонённые альтернативы

- **Сайдкар `darmark-ai.exe` сейчас (AI в отдельном child-процессе).** Отклонён:
  - **не уменьшает поставку** — `bundle.externalBin` (Tauri) пакует сайдкар в установщик **всегда**; вынос лишь переносит вес между файлами;
  - **инверсия привилегий** — child получает **сеть + API-ключ**, которых у GUI-части для этого не требуется; граница процесса — **изоляция отказов**, **не** защита данных (ADR-0021/§11.4);
  - **новый риск подмены бинарника** — `darmark-ai.exe` с egress+ключом+текстом можно подменить в обход согласия;
  - **watchdog не переиспользуется** — бюджеты watchdog (ADR-0023) убьют запрос с ориентиром 30 с (ADR-0032 §10.1);
  - **нужна новая подсистема** — отдельный протокол (ADR-0027), свой супервизор;
  - **нет технической причины** (в отличие от `mlua`-плагинов): `reqwest`+`timeout` process-isolation не требует.
  Не отклонён **навсегда** — оставлен как цель триггеров §2.6.
- **AI-агент на базе `plugin-cli` (harness как рантайм).** Отклонён: **утащит сеть в dev-CLI** и смешает **dev-инструмент** и **AI-рантайм** в одном бинарнике; нарушает изоляцию `mlua` (D6/ADR-0021) и размывает границу ответственности (§2.4).
- **MCP сейчас (inbound-сервер внешних клиентов).** Отклонён: **отделённая граница доверия** (**inbound** против outbound-запроса), вне MVP; при появлении кейса — отдельный ADR (§2.5).
- **`ai.enabled` через отдельный флаг сборки (compile-time feature) вместо конфига.** Отклонён: включаемость нужна **пользователю без пересборки**; compile-time feature не даёт «гашения из конфига» и усложняет поставку одной сборкой (§2.3).
- **Вынести AI в child ради CI-инварианта «`cargo tree -p darmark` без `reqwest`».** Отклонён **сейчас**: инвариант ценный, но не оправдывает инверсию привилегий и подмену бинарника; отложен как один из триггеров §2.6.
