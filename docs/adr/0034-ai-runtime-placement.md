# ADR-0034. Размещение AI-рантайма: в процессе GUI (шов `AiBackend`/`AiTransport`); сайдкар отложен

- **Статус:** **Принят**
- **Дата:** 11.10.2026
- **Основание:** коллегиальная оценка предложения «вынести AI в отдельный бинарник как плагины»
  (архитектор + системный аналитик + security-reviewer, 11.10.2026); продуктовый выбор
  пользователя — **остаться в процессе GUI + заложить шов, сайдкар отложить**; MCP — вне MVP;
  `tasks/TZ-AI-ASSISTANT.md` (IDEA-013) §2, §9, §12–14; порядок «проверочный стенд → ADR →
  реализация» (`DESIGN_DOC` §0, D11/ADR-18)
- **Связанные:** `docs/DESIGN_DOC.md` §5.5 (модульная карта — `aiPanel.ts`), §10 (лимиты/Job Object),
  §13.2 (замороженные контракты), §14 (бюджет D6), §16 (реестр ADR);
  `docs/adr/0032-ai-provider-openai.md` (провайдер/сетевой слой), `docs/adr/0033-ai-http-client-streaming.md`

  `crates/plugin-core/`, `crates/plugin-host/`

## 1. Контекст

### 1.1. Проблема

AI-ассистент (IDEA-013, `TZ-AI-ASSISTANT`) — сетевой функционал в лёгком редакторе под жёстким D6.
При обсуждении провайдера и клиента (ADR-0032/0033) возникло предложение разместить AI-рантайм **вне
процесса GUI** — отдельным бинарником `darmark-ai.exe` «как плагины»: чтобы (а) не раздувать
`darmark.exe` и (б) сделать фичу включаемой/отключаемой на уровне дистрибутива. Нужно зафиксировать
**место исполнения** AI и последствия этого выбора.

### 1.2. Что уже зафиксировано (не пересматривается)

- **Сеть AI — только Rust-сторона**; CSP `default-src 'self'` не ослабляется (ADR-0032 §1.2, §2.5 п. 11).
- **HTTP-клиент** — `reqwest` (`native-tls`/SChannel) + **SSE** (ADR-0033).
- **Провайдер** — OpenAI-совместимый API (`routerai.ru`) (ADR-0032).
- **Согласие обязательно**: содержимое документа уходит в облако только после явного согласия
  (ADR-0030 §2.4, ADR-0032 §2.3); ответ рендерится через **Rust-санитайзер** (D7/§11).
- **AI — не плагин** (ADR-0021): плагину недоступны сеть и Rust-сетевой слой.
- **D6 (release-exe ≤6 МБ, size-gate §14)**; ориентир AI-клиента — маргинальный прирост ≤1.0 МиБ (ADR-0033).
- **Сайдкар у плагинов обязателен технически**: `mlua`/Lua под `panic="abort"` недопустим в GUI
  (D6/ADR-0021), поэтому `darmark-plugin-host.exe` — отдельный child. Это техническая причина, а не
  универсальный паттерн «всё внешнее — в child».

### 1.3. Коллегиальная оценка (что проверяли)

Предложение «вынести AI в `darmark-ai.exe` сейчас» рассмотрено тремя ролями; результат:

- **Факты бюджета:** `darmark.exe` — **3.94 МиБ** при гейте **6 МиБ** (запас ≈**2.06 МиБ**);
  ориентир AI-клиента **≤1.0 МиБ** (ADR-0033) укладывается в остаток с запасом.
- **Сайдкар не уменьшает поставку:** Tauri `bundle.externalBin` пакует сайдкар в установщик
  **всегда**; вынос AI в отдельный бинарник **переносит** вес между файлами, но **не убирает** его
  из дистрибутива.
- **Process-isolation не требуется:** `reqwest`+`timeout` — обычный async-I/O; в отличие от Lua
  под `panic="abort"`, падение/утечка сетевого клиента не мотивирует выносить его в child.
- **Security-разбор сайдкара даёт минус:** child получает **сеть + API-ключ** (инверсия привилегий
  относительно GUI); граница процесса — **изоляция отказов**, **не** защита данных; появляется новый
  вектор **подмены бинарника** (egress+ключ+текст в обход согласия).
- **Watchdog не переиспользуется:** бюджеты плагинов (400/1500 мс, ADR-0023) убьют запрос с
  ориентиром таймаута **30 с** (ADR-0032 §10.1); сайдкару нужен отдельный конверт и своя версия
  протокола (`AI_PROTOCOL_VERSION` ≠ `HOST_API_VERSION`, ADR-0027) — это новая подсистема, а не
  «переиспользование».

Итог оценки: у плагинов вынос в child **обязателен технически**, у AI такой причины **нет**;
вынос сейчас даёт **отрицательный security-профиль** без выгоды по размеру поставки.

## 2. Решение

**AI-рантайм — в процессе GUI (`crates/app/src-tauri/src/ai/`), сеть — на Rust-стороне (ADR-0032/0033).
Сайдкар `darmark-ai.exe` отложен; фича делается включаемой без отдельного бинарника. Закладывается
шов `AiBackend`/`AiTransport`, чтобы будущий сайдкар стал drop-in без переделки UI/IPC. MCP — вне MVP.**

### 2.1. Место исполнения

1. AI-модуль размещается **в процессе GUI** — `crates/app/src-tauri/src/ai/`: HTTP-клиент
   (`reqwest`+SChannel), SSE-парсер, хранение ключа, маппинг ошибок. Отдельный бинарник/child
   **не вводится**.
2. Сеть AI остаётся **только на Rust-стороне**; CSP `default-src 'self'` не ослабляется
   (ADR-0032 §2.5 п. 11, ADR-0033).
3. Модуль локализован: смена клиента/TLS/провайдера и потенциальное выделение в child не трогают
   замороженные контракты §13.2 и контракт плагинов (ADR-0021).

### 2.2. Шов под будущий сайдкар

4. Вызов провайдера и передача текста инкапсулируются за **трейтом `AiBackend`/`AiTransport`**
   (точка «вызов провайдера + передача текста»): реализация в процессе GUI — первый и единственный
   в MVP вариант за трейтом.
5. Шов проектируется так, чтобы **сайдкар стал drop-in** — замена реализации трейта **без переделки
   UI и IPC-контрактов** фронта (id `#ai-*` и команды/события не меняются).
6. Шов **не вводит неиспользуемых сущностей** (строгий TS, `noUnusedLocals`): минимальная абстракция —
   один трейт и одна реализация; расширение — по триггерам §2.6, отдельным ADR.

### 2.3. Включаемость без бинарника

7. Фича включается **флагом `ai.enabled`** в `config.json` (секция `ai`, settings-store D11) — без
   отдельного бинарника. Инициализация AI-модуля — **ленивая** (сеть/клиент не поднимаются, пока
   фича не востребована).
8. Пользователю показываются **понятные состояния**: «**выкл**» (фича отключена), «**нет ключа**»,
   «**нет согласия**», «**офлайн**» (нет сети/недоступен провайдер). Индикатор — `#ai-dot`
   (`TZ-AI-ASSISTANT` §12; ADR-0030).
9. Отключение `ai.enabled` **не требует** пересборки/переустановки — фича гасится конфигом, не
   удалением файла из дистрибутива (в отличие от сайдкар-варианта).

### 2.4. `plugin-cli` — инструмент, не рантайм

10. Harness плагинов (скилл «Создать плагин», `TZ-AI-ASSISTANT` §9) — **инструмент разработчика**, а
    **не** AI-рантайм: он **делегирует** существующему CLI `darmark-plugin` (`init`/`test <dir>
    --json`), **переиспользуя** валидацию манифеста (`plugin_core::manifest`) и изоляцию `mlua`
    (прогон в песочнице — только в child, D6/ADR-0021).
11. Отчёт harness — **версионированный JSON**; **fallback** при недоступности CLI — прямая валидация
    через `plugin_core::manifest` + прогон `plugin-host --self-test` (тот же контракт проверки).
12. Сеть в `plugin-cli` **не вводится**: CLI остаётся dev-инструментом, AI-рантайм — отдельно
    (§2.1). Смешение «dev-инструмент + AI-рантайм» запрещено (см. §4).

### 2.5. MCP

13. **MCP — вне MVP.** MCP — **отделённая граница доверия** (**inbound**: внешние клиенты вызывают
    нас), качественно иная, чем outbound-запрос к провайдеру. При появлении кейса внешних клиентов —
    **отдельный ADR**.

### 2.6. Триггеры перехода к сайдкару (пересмотр настоящего ADR)

14. Настоящее решение **пересматривается** (новый ADR / правка этого) при любом из триггеров:
    - требование дистрибутива **без AI** (поставка, физически не содержащая сетевой AI-код);
    - **тяжёлый AI** (tool-loop, локальная модель, эмбеддинги), несовместимый с бюджетом/архитектурой
      in-process;
    - гейт `darmark.exe` **станет тесным** (прирост AI перестанет укладываться в остаток ≤6 МБ);
    - желание **CI-инварианта** `cargo tree -p darmark` **без `reqwest`** (жёсткое разделение сетевого
      слоя на уровне сборки).
15. До наступления триггеров сайдкар **не вводится**; шов §2.2 держит выделение в child **рефактором
    за трейтом**, без правок UI/IPC.

### 2.7. Инварианты, которые не меняются

16. Сеть — **только Rust-сторона**; CSP не ослабляется (ADR-0032/0033).
17. Согласие на отправку содержимого — **обязательно**; ответ рендерится через Rust-санитайзер
    (ADR-0030 §2.4, D7/§11).
18. События/контракты AI — **аддитивны**; мажор `HOST_API_VERSION` не поднимается (ADR-0027 §2.4);
    контракты §13.2 и контракт плагинов **не меняются** (AI — не плагин, ADR-0021).
19. **`mlua` остаётся вне GUI-хоста** (D6/ADR-0021, guard `cargo tree -p darmark`); `plugin-cli` —
    dev-инструмент, не AI-рантайм (§2.4).

## 3. Последствия

**Положительные:**

- **Нет нового бинарника, протокола и супервизора:** меньше движущихся частей, нет
  `AI_PROTOCOL_VERSION`/конверта/Job Object для AI.
- **Сайдкар всё равно не уменьшил бы поставку** (`externalBin` пакует всегда) — вынос был бы переносом
  веса без выгоды; размер при этом укладывается: `darmark.exe` 3.94 МиБ, AI ≤1.0 МиБ, gate 6 МиБ.
- **Меньше поверхность атаки:** нет child с сетью+ключом, нет риска подмены AI-бинарника; секрет и
  egress остаются в единственном процессе с уже действующими митигациями (ADR-0032 §2.4).
- **Включаемость решена конфигом:** `ai.enabled` + ленивая инициализация + состояния
  «выкл/нет ключа/нет согласия/офлайн» — без отдельного бинарника (§2.3).
- **Обратимость:** выделение в child — **рефактор за трейтом `AiBackend`/`AiTransport`**, UI/IPC не
  переделываются (§2.2, §2.6).
- **Переиспользование плагинной инфраструктуры:** harness делегирует `darmark-plugin`, изоляция
  `mlua` сохраняется (§2.4).

**Отрицательные / ограничения:**

- **AI-код (и `reqwest`) остаётся в дереве `darmark`:** `cargo tree -p darmark` содержит сетевой стек;
  CI-инвариант «без `reqwest`» **не достигается** сейчас (это триггер §2.6).
- **Дистрибутив физически содержит AI** (код + сетевой стек), даже если `ai.enabled=false`;
  «поставка без AI» возможна только через сайдкар-выделение (§2.6).
- **Тяжёлый AI** (локальная модель, эмбеддинги, tool-loop) не вписывается в in-process-модель —
  потребует пересмотра (§2.6).
- **Шов надо держать честным:** абстракция `AiBackend`/`AiTransport` без переусложнения; одна
  реализация в MVP (риск «преждевременной» абстракции принят сознательно ради обратимости).
- **`plugin-cli` — граница ответственности:** harness обязан оставаться dev-инструментом, сеть в CLI
  не вводится; иначе — смешение ролей (§2.4).

**Обратимость:** AI-модуль локализован (`src-tauri/src/ai/`) и спрятан за трейтом; выделение в
`darmark-ai.exe` — рефактор за швом **без правок UI и замороженных контрактов §13.2**. Пересмотр —
по триггерам §2.6 отдельным ADR.

## 4. Отклонённые альтернативы

- **Сайдкар `darmark-ai.exe` сейчас (AI в отдельном child-процессе).** Отклонён:
  - **не уменьшает поставку** — `bundle.externalBin` (Tauri) пакует сайдкар в установщик **всегда**;
    вынос лишь переносит вес между файлами;
  - **инверсия привилегий** — child получает **сеть + API-ключ**, которых у GUI-части для этого не
    требуется; граница процесса — **изоляция отказов**, **не** защита данных (ADR-0021/§11.4);
  - **новый риск подмены бинарника** — `darmark-ai.exe` с egress+ключом+текстом можно подменить в
    обход согласия;
  - **watchdog не переиспользуется** — бюджеты плагинов (400/1500 мс, ADR-0023) убьют запрос с
    ориентиром 30 с (ADR-0032 §10.1);
  - **нужна новая подсистема** — отдельный конверт и `AI_PROTOCOL_VERSION` (≠ `HOST_API_VERSION`,
    ADR-0027), свой супервизор;
  - **нет технической причины** (в отличие от `mlua`-плагинов): `reqwest`+`timeout` process-isolation
    не требует.
  Не отклонён **навсегда** — оставлен как цель триггеров §2.6.
- **AI-агент на базе `plugin-cli` (harness как рантайм).** Отклонён: **утащит сеть в dev-CLI** и
  смешает **dev-инструмент** и **AI-рантайм** в одном бинарнике; нарушает изоляцию `mlua`
  (D6/ADR-0021) и размывает границу ответственности (§2.4).
- **MCP сейчас (inbound-сервер внешних клиентов).** Отклонён: **отделённая граница доверия**
  (**inbound** против outbound-запроса), вне MVP; при появлении кейса — отдельный ADR (§2.5).
- **`ai.enabled` через отдельный флаг сборки (compile-time feature) вместо конфига.** Отклонён:
  включаемость нужна **пользователю без пересборки**; compile-time feature не даёт «гашения из
  конфига» и усложняет поставку одной сборкой (§2.3).
- **Вынести AI в child ради CI-инварианта «`cargo tree -p darmark` без `reqwest`».** Отклонён
  **сейчас**: инвариант ценный, но не оправдывает инверсию привилегий и подмену бинарника; отложен
  как один из триггеров §2.6.
