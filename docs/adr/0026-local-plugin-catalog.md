# ADR-0026. Локальный каталог плагинов (Фаза 2a экосистемы H3)

- **Статус:** **Принят**
- **Дата:** 10.10.2026
- **Основание:** веха H3 «экосистема» (Фаза 2 «Реестр плагинов»); Фаза 1 — `crates/plugin-cli`
- **Связанные:** `docs/DESIGN_DOC.md` §7.1, §10; `docs/adr/0021-*`; `docs/adr/0023-*`;
  `docs/PLUGIN_API.md` §6

---

## 1. Контекст

Фаза 2 H3 сформулирована «в лоб»: git-репозиторий + `index.json` + подпись Ed25519 +
`install/update/remove`. Это тяжёлая инфраструктура — сеть, ротация ключей, доверие
реестру, CI/CD — которая заблокировала бы разработчиков плагинов. Продукт ещё
стабилизируется (релизный workflow и бандлинг сайдкаров в работе), поэтому делать её
первой — значит поставить discoverability в зависимость от несуществующей инфраструктуры.

При этом механизм discoverability и установки нужен уже сейчас: разработчики копируют
каталоги руками, а UI-каталог (ADR-0024) должен опираться на работающий контракт. Поэтому
Фаза 2 разбивается: **2a — локальный каталог без сети и подписи** (этот ADR), **2b —
удалённый подписанный реестр** (отдельный ADR, отложен).

---

## 2. Решение

**Локальный каталог внутри репозитория darmark + CLI-команды поверх него; сеть,
Ed25519-подпись и доверие реестру — вне этого ADR.**

### 2.1. Структура каталога

- Каталог — `plugins/` (после 16.10.2026 — `crates/plugin-catalog/examples/plugins/`), индекс — `plugins/index.json`.
- Плагины — подкаталогами с `plugin.json` + `main.lua`. Каталог и примеры — один репозиторий.

### 2.2. Формат `index.json`

- Индекс содержит `schema_version` и записи `{ id, path, description }` — **минимальный**.
- **Метаданные не дублируются:** `name`/`version`/`api_version`/`permissions` берутся только
  из `plugin.json` плагина; индекс — навигация, а не второй источник правды.
- **Каждая запись валидируется** через `plugin-core::manifest` (`Manifest::from_json`) —
  те же правила, что GUI-сканирование; невалидная запись не публикуется.

### 2.3. Команды CLI

Все команды — в существующем бинарнике `darmark-plugin` (`crates/plugin-cli`):

- **`list`** — читает `index.json`, валидирует записи, печатает информацию о плагинах.
- **`install <id>`** — копирует каталог плагина из `--repo` в `--dest`.
- **`link <id>`** — ставит junction/симлинк для разработки «на лету».
- **`remove <id>`** — удаляет плагин из `--dest`.
- **`update <id>`** — переустанавливает из репозитория поверх `--dest`.

**Семантика установки:** рантайм **не меняется** — установка идёт в `plugins_dir()`,
который он сканирует.

### 2.4. Дефолты путей

- `--repo`: автопоиск по предкам текущего каталога (содержит `plugins/index.json`);
  терпит обе формы — каталог с индексом и корень репозитория.
- `--dest`: env `DARMARK_PLUGINS_DIR` → `%APPDATA%/darmark/plugins` — совпадает с `plugins_dir()` рантайма.

### 2.5. Интерфейс

Только CLI. UI-каталог в правом дровере (ADR-0024) — позже, **поверх тех же команд**,
без второго источника данных.

### 2.6. Безопасность путей

- `path` записи и `id` **ограничены границами** репозитория: относительный путь без `..`,
  без абсолютных путей, без выхода за пределы `plugins/`.
- `link` на Windows — **junction** (`mklink /J`): не требует прав администратора, в отличие
  от симлинка; источник канонизируется.
- `update`/`remove` **не затирают** junction: `update` пропускает ссылки, `remove` удаляет
  только точку монтирования; `remove` идемпотентен.

## 3. Последствия

**Положительные:**

- Нет сети, ключей и модели доверия — не блокирует разработчиков инфраструктурой.
- `link` даёт «правил исходник — видно рантайму» без пересборки.
- Единый формат `index.json` — прямой путь к Фазе 2b (те же записи, расширяемые полями).
- Переиспользование валидации `plugin-core::manifest` — те же правила, что у GUI-скана.
- CLI-контракт готов стать бэкендом UI-каталога (ADR-0024).

**Отрицательные / ограничения:**

- **Нет доверия и подписи** — каталог доверенный по факту (репозиторий darmark); защиты
  от подмены источника нет — до Фазы 2b.
- **Каталог локальный** — нет публикации/обновления из сети.
- **UI отсутствует** — только CLI.
- Платформенная специфика `link` (junction) — привязана к Windows (целевая платформа).
- Копирование при `install` не даёт автообновления — `update` запускается явно.

**Обратимость:** затрагивает только `crates/plugin-cli` и содержимое `plugins/`; рантайм
и контракт плагина не меняются.

---

## 4. Отклонённые альтернативы

- **Сразу удалённый подписанный реестр** — отклонён: тяжёлая инфраструктура (сеть,
  Ed25519, доверие, CI/CD), блокирующая разработчиков; переносится в Фазу 2b (§1).
- **`bundle.resources` в `tauri.conf.json`** — не подходит: кладёт файлы в resource-каталог
  инсталлятора, а не в `plugins_dir()` рантайма; зашивает плагины в GUI-установщик.
- **Ставить `<path>` вручную** — отклонён: нет discoverability и команд install/update/remove.
- **Vendoring/git-submodule** — отклонён: не даёт команд установки, неудобно для отдельных
  Lua-плагинов, не решает вопрос каталога установки рантайма.

---

## 5. Путь к Фазе 2b

- Записи `index.json` расширяются полями источника и подписи; `schema_version` — точка
  версионирования формата.
- Проверка подписи Ed25519 и модель доверия к реестру — **отдельный ADR**.
- CLI получает удалённое получение индекса; `install`/`update` добавляют верификацию подписи.
  Локальный каталог остаётся офлайн-режимом.

> **Статус (10.10.2026):** Фаза 2b отложена на неопределённый срок (продукт стабилизируется,
> удалённый реестр преждевременен). Фаза 2 закрыта без активных работ. Возобновление — только
> при реальной потребности и с отдельным ADR.

> **Обновление (16.10.2026):** индекс и примеры перенесены в `crates/plugin-catalog/examples/plugins/`.
> Упрощено разрешение путей: убран env `DARMARK_PLUGIN_REPO` и автопоиск `examples/plugins`;
> `--repo` ищет только `plugins/index.json`, MCP-адаптер использует явный `%APPDATA%/ПЕНАЛ/plugins/`.
