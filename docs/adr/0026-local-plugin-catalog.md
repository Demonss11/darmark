# ADR-0026. Локальный каталог плагинов (Фаза 2a экосистемы H3)

- **Статус:** **Принят**
- **Дата:** 10.10.2026
- **Основание:** `docs/ROADMAP.md` (H3, Фаза 2 «Реестр плагинов»);
  `docs/ROADMAP.md` (H3 — экосистема, отложена до стабилизации); Фаза 1 H3 —
  `crates/plugin-cli` (`darmark-plugin test`/`init`)
- **Связанные:** `docs/DESIGN_DOC.md` §7.1, §10, §16; `docs/adr/0021-*` (изоляция процесса),
  `docs/adr/0023-*` (плагинный runtime); `docs/PLUGIN_API.md` §6; `crates/plugin-cli`,
  `crates/plugin-core` (`manifest`)

---

## 1. Контекст

Фаза 2 H3 в плане сформулирована «в лоб»: **git-репозиторий + `index.json` + подпись Ed25519 +
команды `install/update/remove`**. Это тяжёлая инфраструктурная задача: сеть, хранение и ротация
ключей, модель доверия к реестру, публикация и CI/CD. Риски (Ed25519-ключи, доверие, CI/CD)
зафиксированы в истории H3 (`docs/ROADMAP.md`). Делать её первой —
значит поставить доступность плагинов в зависимость от ещё не построенной инфраструктуры.

Продукт в этот момент **не стабилизирован** по части поставки:

- **нет релизного workflow** — в репозитории только `.github/workflows/ci.yml`; канала публикации
  артефактов, на который опирался бы подписанный реестр, нет;
- **бандлинг сайдкаров только что переработан и ещё в работе** — `bundle.externalBin`
  (`darmark-plugin-host`, `darmark-plugin`) и `crates/app/scripts/prepare-sidecars.mjs` менялись
  в текущей рабочей копии; кладётся рядом с `darmark.exe` вручную;
- **CLI плагина только появился** (Фаза 1: `crates/plugin-cli`, бинарник `darmark-plugin`,
  `test`/`init`), а в `plugins/` лежат эталонные примеры (`word-count`, `todo-lens`,
  `format-selection`, `export-html`) без какого-либо «каталога».

При этом **нужно уже сейчас** дать механизм discoverability и установки плагинов, чтобы
разработчики не копировали каталоги руками и чтобы интерфейс будущего UI-каталога опирался на
уже работающий контракт. Поэтому Фаза 2 разбивается: **2a — локальный каталог без сети и подписи**
(этот ADR), **2b — удалённый подписанный реестр** (отдельный ADR, тот же формат `index.json`).

---

## 2. Решение

**Вводится локальный каталог плагинов внутри репозитория darmark и CLI-команды поверх него;
это Фаза 2a. Сеть, Ed25519-подпись и доверие реестру — вне этого ADR.**

### 2.1. Структура каталога

1. Каталог — `plugins/` в репозитории darmark; индекс — `plugins/index.json`.
2. Плагины — подкаталогами (`plugins/<dir>/plugin.json`, `plugins/<dir>/main.lua`, …). Эталонные
   примеры лежат там же, что и индекс, — каталог и примеры — один репозиторий.

### 2.2. Формат `index.json`

3. Индекс содержит `schema_version` и список записей; запись — **минимальна**:
   `{ id, path, description }`:

   ```json
   {
     "schema_version": 1,
     "plugins": [
       { "id": "word-count", "path": "word-count", "description": "Считает слова в документе" }
     ]
   }
   ```

4. **Метаданные не дублируются.** `name`/`version`/`api_version`/`permissions` берутся только из
   `plugin.json` соответствующего каталога. Индекс — лишь навигация, а не второй источник правды.
5. **Каждая запись валидируется.** Каталог по `path` разбирается `plugin-core::manifest`
   (`Manifest::from_json`), как при GUI-сканировании: те же правила `id` (`is_safe_id`),
   `api_version ≤ HOST_API_VERSION`, разрешения из §8, `entry`. Индекс с записью, не прошедшей
   валидацию, считается недействительным для этой записи (команда сообщает и продолжает/падает —
   по решению реализации, но **не** публикует невалидную запись).

### 2.3. Команды CLI

6. Все команды — в существующем бинарнике `darmark-plugin` (крейт `crates/plugin-cli`), тем же
   ручным разбором аргументов, без `clap`:
   - **`list`** — читает `index.json`, валидирует записи, печатает `id` + описание (и `name`/`version`
     из `plugin.json`).
   - **`install <id>`** — копирует каталог плагина из репозитория (`--repo`) в каталог установки
     (`--dest`).
   - **`link <id>`** — ставит **junction/симлинк** каталога-источника в `--dest` для разработки
     «на лету» (правка исходников сразу видна рантайму).
   - **`remove <id>`** — удаляет плагин из `--dest`.
   - **`update <id>`** (или без аргумента — все) — переустанавливает из репозитория поверх `--dest`.
7. **Семантика установки.** Установка = копирование (`install`/`update`) либо линк (`link`) в
   каталог, который сканирует рантайм (`plugins_dir()` в `crates/app/src-tauri/src/lib.rs`).
   Рантайм при этом **не меняется** — он по-прежнему читает `%APPDATA%/darmark/plugins`.

### 2.4. Дефолты путей

8. **Источник каталога** `--repo`: env `DARMARK_PLUGIN_REPO` → ближайший предок текущего каталога,
   содержащий `plugins/index.json`. Явный `--repo`/env **терпит обе формы** — каталог с `index.json`
   и корень репозитория (`<dir>/plugins/index.json`) — и нормализуется до каталога плагинов. Ошибка,
   если ничего не разрешается.
9. **Каталог установки** `--dest`: env `DARMARK_PLUGINS_DIR` → `%APPDATA%/darmark/plugins`.
   Это **совпадает** с `plugins_dir()` рантайма, включая override `DARMARK_PLUGINS_DIR`
   (используется тестами/E2E для изоляции профиля).

### 2.5. Интерфейс

10. Сейчас — **только CLI**. UI-каталог в правом дровере (ADR-0024) — позже, **поверх тех же
    команд** (`list`/`install`/`link`/`remove`/`update`), без второго источника данных.

### 2.6. Безопасность путей

11. `path` записи и `id` **должны** оставаться в границах репозитория: относительный путь без
    `..`, без абсолютных путей и без разделителей за пределами `plugins/`; фактический источник
    канонизируется и проверяется на принадлежность `--repo`.
12. Запись в `--dest` **должна** ограничиваться каталогом установки (та же проверка границ);
    `id` — безопасный идентификатор (те же правила, что `plugin-core::manifest::is_safe_id`).
13. `link` на Windows использует **junction** (`mklink /J`) для каталогов: не требует режима
    разработчика/прав администратора, в отличие от симлинка; ошибка при отсутствии прав
    сообщается явно. Источник **канонизируется** (`canonicalize`) — junction указывает на
    канонический путь (корректно и при симлинках в репозитории).
14. `update`/`remove` **не должны** молча затирать/удалять каталог, пришедший из `link`
    (junction): `update` пропускает ссылки, `remove` удаляет только точку монтирования. `remove`
    **идемпотентен** (нет плагина → «нечего удалять», код `0`).

## 3. Последствия

**Положительные:**

- Нет сети, ключей и модели доверия — Фаза 2a не блокирует разработчиков инфраструктурой.
- Разработка быстрее: `link` даёт «правил исходник — видно рантайму» без пересборки.
- Единый формат `index.json` — **прямой путь к Фазе 2b**: те же записи, расширяемые полями
  источника и подписи.
- Переиспользование готовой валидации (`plugin-core::manifest`) — те же правила, что у GUI-скана.
- CLI-контракт сразу готов стать бэкендом UI-каталога (ADR-0024), не изобретая второй API.

**Отрицательные / ограничения:**

- **Нет доверия и подписи.** Каталог доверенный по факту (это репозиторий darmark); защиты от
  подмены источника нет — до Фазы 2b.
- **Каталог локальный.** Нет публикации/обновления из сети; `update` работает только из `--repo`.
- **UI отсутствует.** Пользователю доступен только CLI; установка через интерфейс — позже.
- Платформенная специфика `link` (junction) — привязана к Windows (целевая платформа, §1.3).
- Копирование при `install` не даёт автообновления: запускать `update` нужно явно.

**Обратимость:** решение затрагивает только `crates/plugin-cli` и содержимое `plugins/`; рантайм
и контракт плагина не меняются, объём — в один коммит.

## 4. Отклонённые альтернативы

- **Сразу удалённый подписанный реестр (Фаза 2 «в лоб»).** Отклонён: сеть + Ed25519 + ротация
  ключей + доверие + CI/CD — тяжёлая инфраструктура, блокирующая разработчиков; продукт ещё
  стабилизируется (нет релизного workflow, бандлинг сайдкаров в работе). Переносится в Фазу 2b.
- **`bundle.resources` в `tauri.conf.json`.** Не подходит: кладёт файлы в resource-каталог
  инсталлятора, а не рядом с exe и не в `%APPDATA%/darmark/plugins`, который сканирует рантайм;
  при этом зашивает плагины в GUI-установщик и раздувает его.
- **Игнорировать каталог (ставить `<path>` вручную).** Отклонён: нет discoverability и команд
  install/update/remove; разработчики копируют каталоги руками, как до этого ADR.
- **Vendoring/git-submodule плагинов.** Отклонён: не даёт команд установки, неудобно для
  отдельных Lua-плагинов и не решает вопрос каталога установки рантайма.

---

## 5. Путь к Фазе 2b

- Записи `index.json` расширяются полями источника и подписи (`source`/`url`/`signature`);
  `schema_version` остаётся точкой версионирования формата.
- Проверка подписи Ed25519 и **модель доверия к реестру** (кто владеет ключом, где он лежит,
  как ротируется) — **отдельный ADR**, а не этот.
- CLI получает удалённое получение индекса; `install`/`update` добавляют шаг верификации подписи
  до копирования. Локальный каталог остаётся офлайн-режимом.

> **Обновление (10.10.2026).** **Фаза 2b отложена на неопределённый срок** (решение заказчика):
> продукт ещё стабилизируется, удалённый реестр с Ed25519 преждевременен. Фаза 2a закрыта, Фаза 2
> закрыта без активных работ; общий статус — `docs/ROADMAP.md` (раздел H3). Возобновление 2b — только
> при реальной потребности и с отдельным ADR.
