# ADR-0021. Изоляция плагинов: Lua в отдельном процессе (D16)

- **Статус:** **Принят**
- **Дата:** 06.10.2026
- **Основание:** прототип `proto/lua-plugin-host`; факты — `docs/FINDINGS.md` (F1–F36)
- **Связанные:** `docs/DESIGN_DOC.md` §7.1, §10, §11.4;
  `reviews/TZ-proto-lua-host-P1-review-v1.4.md` (C-спайк), `reviews/TZ-proto-lua-host-P9-review-v1.0.md` (M10–M12)

---

## 1. Контекст

In-process хостинг Lua под `panic="abort"` критичен: ошибка из Rust-функции не ловится
и абортит процесс (F9). Обходы (C-hook F11, safe-`pcall` F13) не ловят панику host-кода
и дают оверхед ×2 (F14); `unwind` недопустим (+3.2 МБ, ломает D6, F10).

Вынос Lua в дочерний процесс (C, F16–F32) подтвердил: жёсткая изоляция отказов,
приемлемая латентность, транспорт в GUI-конфигурации и управляемые лимиты.

---

## 2. Решение

**Выбирается вариант C — Lua-плагин исполняется в отдельном дочернем процессе; GUI-хост не
линкует `mlua` и может оставаться на `panic="abort"`.**

1. **Рантайм.** Отдельный процесс (`child`) на Lua 5.5 (mlua `lua55`+`vendored`). Host и Lua
   разделены границей процесса. В базе GUI-хоста `mlua` отсутствует (F20).
2. **Транспорт.** stdio, подтверждён в GUI-конфигурации без консоли; кадр 10 МБ, обрывы
   детектируются без блокировки (F26/F27).
3. **Модель процессов — «child на плагин»** (изоляция отказов; цена ≈0.6 МиБ и ≈2 мс на плагин,
   F30). «Общий child» отвергнут (F31).
4. **Лимиты — Job Object** (RSS — жёсткий, CPU/время — backstop) + watchdog (прогресс-таймаут
   и абсолютный дедлайн, F33/F35). Детали — §3.
5. **API host-функций — range/delta** (обязательно по памяти при «child на плагин», F22/F30).
   Детали — §3.
6. **Изоляция — только изоляция отказов.** Краш/зависание/перерасход плагина не трогают
   GUI-хост (F18/F25). Это **не** защита от намеренного обхода Lua VM: скомпрометированный
   плагин получает процесс с правами пользователя (§11.4, F25).

---

## 3. Обязательные требования до H2

- [x] **Watchdog** — прогресс-таймаут + абсолютный дедлайн на invocation (F33/F35).
- [x] **Range/delta host-API** — обязательно по памяти (F22/F30/F34).
- [x] **Устойчивость протокола** — вывод child'а как hostile, лимиты кадров (F36).
- [x] **Job Object + карантин** — лимиты, `KILL_ON_JOB_CLOSE`, N=3 падений → отключение (F28/F29/F37).
- [x] **Изоляция отказов** — формулировка в UI/магазине (F38).

---

## 4. Отклонённые альтернативы

| Вариант | Причина отказа |
|---|---|
| A: `unwind` + `catch_unwind` | +3.2 МБ, ломает D6 (F10) |
| B: `abort` + C-hook + safe-`pcall` | Не ловит панику host-кода, оверхед ×2, ABI-хрупкость (F11/F13/F14, W5/W6). Fallback только если процессная модель неприемлема. |

---

## 5. Последствия

**Цена:** RPC-модель (нужен watchdog), N процессов (≈0.6 МиБ и ≈2 мс каждый), сложность
жизненного цикла. **Плюсы:** риск F9 снят, GUI-хост без `mlua`, лимиты на ОС.

**Правки DESIGN_DOC:** §7.1 (stdio — основной), §10.1/§10.2 (Job Object + watchdog).
