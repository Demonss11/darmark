## 1. Контекст

### 1.1. Проблема

AI-ассистент (IDEA-013, `TZ-AI-ASSISTANT`) — встроенная подсистема хоста, снижающая порог входа в
Markdown и создание Lua-плагинов. Ему нужен **провайдер LLM**. Провайдер — единственная часть AI,
которой требуется сетевой доступ, а сеть в продукте ограничена жёстко.

### 1.2. Что уже зафиксировано (не пересматривается)

- **CSP `default-src 'self'`** (`tauri.conf.json`): WebView не ходит в сеть. Сетевой доступ возможен
  **только с Rust-стороны** (`DESIGN_DOC` §11; ADR-0030 §2.3). Это граница, а не деталь реализации.
- **Приватность документов:** содержимое документа не покидает машину без явного согласия
  пользователя (`TZ-AI-ASSISTANT` §4, §10.2; ADR-0030 §2.4 — модальный диалог согласия).
- **Рендер ответа — на Rust-стороне** через единый санитайзер (`md-core::sanitize_html`, D7/§11);
  сырой вывод LLM в `innerHTML` не попадает (ADR-0030 §2.2 п. 16).
- **AI — не плагин** (`TZ-AI-ASSISTANT` §2, вне scope): плагину недоступны сеть и Rust-сетевой слой
  (ADR-0021). AI нужен Rust-клиент вне песочницы.
- **D6 (≤6 МБ):** тяжёлых зависимостей не вводим; AI-клиент — малая часть бюджета
  (`DESIGN_DOC` §14).

### 1.3. Почему решение пересматривается

`TZ-AI-ASSISTANT` §3.2 проектировало **гибрид**: локальная модель (Ollama) по умолчанию, облачный
API — расширение (открытый вопрос №1 IDEA-013). Продуктовое решение 11.10.2026 пересматривает это:

- локальная LLM требует **внешнего сервера** (Ollama) и загрузки больших моделей — пользователь не
  получает ассистента «из коробки»;
- на CPU генерация **медленная**, что ухудшает UX сильнее сетевого round-trip;
- локальный провайдер **усложняет онбординг** (установи сервер, скачай модель, держи её запущенной);
- выгода локальной модели (приватность) перекрывается уже существующим требованием явного согласия
  и возможностью отказаться от отправки.

Локальный провайдер **не реализуется сейчас** и откладывается на неопределённый срок (вне scope, без
обязательства вернуться; при возврате — отдельный ADR/спайк).

## 2. Решение

**В MVP единственный реализуемый провайдер LLM — OpenAI-совместимый API (сторонний роутер
`routerai.ru`). Локальная LLM (Ollama) и гибрид — вне scope. Сетевой слой — Rust
(`src-tauri/src/ai/`); интерфейс провайдера держим расширяемым, но реализуется только
OpenAI-совместимый провайдер.**

### 2.1. Провайдер и протокол

1. Провайдер — **OpenAI-совместимый API** (сторонний роутер, **не** `api.openai.com`): базовый URL
   по умолчанию — `https://routerai.ru/api/v1`, эндпоинт `POST /chat/completions`, авторизация —
   **Bearer-токен** (заголовок `Authorization`). Протокол — официальный OpenAI Chat Completions
   (`messages` → `choices[].message.content`), поэтому клиент может быть **любым
   OpenAI-совместимым**; выбор Rust-клиента — **спайк** (§2.7 п. 17).
2. Модель по умолчанию — **`deepseek/deepseek-v4.1-flash`**; `base_url` и `model`
   **конфигурируемы**. Прочие параметры (`max_tokens`, `temperature`) — тоже (значения по
   умолчанию — открытый вопрос PM, §4 ТЗ).
3. Сетевой слой — **Rust** (`crates/app/src-tauri/src/ai/`): HTTP-клиент, сериализация запроса,
   парсинг ответа и `usage`. В TS-слое сетевых вызовов нет (CSP).

### 2.2. Расширяемость интерфейса провайдера

4. Провайдер за абстракцией (trait/`enum`), допускающей добавление провайдеров **без ломки
   контрактов** IPC и замороженных контрактов §13.2. В MVP вариант ровно один —
   OpenAI-совместимый (`routerai.ru`); прочие (Anthropic, локальный) — возможное расширение позже.
5. Абстракция **не вводит** неиспользуемых сущностей в MVP (строгий TS, `noUnusedLocals`): «швы»
   минимальны — точка выбора провайдера и параметры запроса.

### 2.3. Согласие (обязательно)

6. **Согласие обязательно.** Содержимое документа уходит в **облако** → перед **первой** отправкой
   показывается **диалог согласия** (модальный, транзиентный; ADR-0030 §2.4, `dialog.ts`).
7. Формулировка согласия — явно про **облачный сервис `routerai.ru`** (сторонний роутер; данные
   покидают машину и уходят в его облако). Пользователь может **не разрешать**; без согласия
   запросы **не уходят** (ошибка в чате, не отправка).

### 2.4. Секреты

8. API-ключ **хранится локально** в каталоге `%APPDATA%/darmark/` (там же, где настройки и плагины)
   через **существующий settings-store (D11)**: файл `config.json`, секция `ai`. Ключ **не попадает**
   в TS-код и **не логируется**.
9. **Windows Credential Manager / DPAPI отклонены** (11.10.2026) как избыточные для локального лёгкого
   редактора (§4). Trade-off: секрет лежит на диске **в открытом виде**; митигации — **маскирование
   в UI**, **запрет логирования**, **права каталога** `%APPDATA%/darmark/`.
10. Ключ не сериализуется в снапшоты/события и не выходит за пределы Rust-стороны.

### 2.5. Сеть и TLS

11. Сеть — **только Rust-сторона**; **TLS — системный SChannel** (`native-tls` на Windows),
    **без OpenSSL** (Windows-only §1.3; D6). HTTP-клиент — **`reqwest`**
    (`default-features = false`, фичи `native-tls`/`json`/`stream`); стриминг — **SSE**. Выбор
    клиента/стриминга зафиксирован в **ADR-0033** (было: «TLS через rustls, кроссплатформенная
    сборка без системных зависимостей» — **пересмотрено** по F55/F56).
12. **Таймаут** запроса (значение — §10.1 ТЗ; ориентир 30 с) и клиентский **rate limit**
    (ориентир 1 запрос/с, §10.1 ТЗ).
13. **Маппинг ошибок OpenAI-совместимого API** в понятные пользователю сообщения чата:
    - `401` — неверный/отсутствующий ключ;
    - `429` — лимит/quota; учитывать `Retry-After`;
    - `400` (context length) — запрос длиннее контекста модели → предложить фрагмент/сокращение;
    - `5xx` — транзиентные; **ретрай** с backoff (ограниченное число попыток);
    - сетевые ошибки/таймаут — офлайн-сообщение, без падения приложения.
    У стороннего роутера возможны **свои коды/квоты**; маппинг должен быть **устойчив** к ним
    (неизвестный код → общее сообщение с текстом ответа, без падения).
14. **Логирование — только метаданные** (timestamp, model, tokens/usage); **содержимое не логируется**.

### 2.6. Стоимость и лимиты

15. Контроль стоимости: `max_tokens`, выбор модели, клиентский rate limit, оценка/показ токенов
    (`usage`).
16. Зависимость от доступности роутера (`routerai.ru`) и выбранной модели — осознанное ограничение:
    при недоступности/отсутствии сети показывается **понятное состояние ошибки** с действием
    **«Повторить»**, а не «пустой ответ». **Fallback отсутствует** (11.10.2026, §4): резервная
    модель/резервная точка доступа **не вводится** — только ошибка и повтор.

### 2.7. Бюджет D6

17. Лёгкий HTTP+TLS стек; **AI-клиент — ориентир ≤1.0 МБ** маргинально в продукте (**пересмотрено**
    с ≤0.5 МБ по F55: прежний ориентир недостижим; `TZ-AI-ASSISTANT` AC-13/§10.3 правит аналитик).
    Выбор HTTP-клиента (**`ureq` vs `reqwest`**) и способа **стриминга (SSE)** зафиксирован в
    **ADR-0033** по результатам спайка: **`reqwest`+SChannel (native-tls) + SSE**. Решение подчиняется
    D6/size-gate (`DESIGN_DOC` §14; общий gate ≤6 МБ не меняется).

### 2.8. Инвариант приватности документов

18. Инвариант «документ не покидает машину без согласия» (ADR-0030 §2.3; `TZ` §4) **сохраняется**:
    отправка — только с согласия; ответ рендерится через **Rust-санитайзер** (D7/§11).

### 2.9. Принцип баланса MVP

19. AI-ассистент — **дополнительный** функционал лёгкого редактора, а не его ядро. MVP **не
    перенагружаем**, но оставляем **информативным**: понятные состояния провайдера, показ `usage`/
    токенов, читаемые ошибки (§2.5 п. 13, §2.6 п. 15). Зафиксировано 11.10.2026:
    - **скиллов ровно 2** — «Объяснить файл» и «Создать плагин»;
    - **история чата — в памяти на сессию** (не персистится);
    - **телеметрия — вне MVP**;
    - **диффы — на Rust-стороне** (в TS не вычисляются);
    - **формат скиллов — JSON**.

### 2.10. Открытые вопросы

20. **Закрыты 11.10.2026:** модель по умолчанию (`deepseek/deepseek-v4.1-flash`, §2.1 п. 2);
    хранилище ключа (`config.json`, секция `ai`; §2.4); поведение при недоступности роутера (ошибка +
    «Повторить», без fallback; §2.6 п. 16); **выбор HTTP-клиента и стриминга** — **ADR-0033**
    (`reqwest`+SChannel + SSE; §2.5 п. 11, §2.7 п. 17). Остаётся открытым (в ТЗ, §4):
    - значения по умолчанию `max_tokens`/`temperature` (§2.1 п. 2);
    - **включение стриминга** в MVP или Фазу 3 (механизм SSE зафиксирован в ADR-0033; факт — за PM).

## 3. Последствия

**Положительные:**

- **Ассистент работает «из коробки»** — без установки сервера и загрузки моделей; онбординг сводится
  к вводу ключа.
- **Быстрый отклик** относительно локальной CPU-генерации; качество выбранной модели
  (`deepseek/deepseek-v4.1-flash`) выше типовых локальных.
- **Сеть остаётся в одной точке** (Rust), CSP не ослабляется; TS-слой чист от секретов и сети.
- **Расширяемость без ломки контрактов:** интерфейс провайдера допускает Anthropic/локальный позже.
- **Явная модель согласия и отказ** — отправка управляема пользователем.
- **MVP не перенагружается** (принцип баланса, §2.9): 2 скилла, история в памяти на сессию, без
  телеметрии; при этом ассистент **информативен** (понятные состояния, `usage`/токены, читаемые ошибки).

**Отрицательные / ограничения:**

- **Данные уходят в облако стороннего роутера** — путь данных: **darmark → `routerai.ru` → выбранная
  модель**; приватность опирается на **явное согласие** (с именованием `routerai.ru`), **отключаемость**
  отправки и **отсутствие логирования содержимого**; локальной альтернативы в MVP нет.
- **Зависимость от роутера (`routerai.ru`) и выбранной модели** — доступность, лимиты, стоимость,
  коды/квоты роутера и изменения API вне нашего контроля; нужен **устойчивый маппинг ошибок**
  (§2.5 п. 13) и понятное состояние ошибки; **fallback нет** — только ошибка + **«Повторить»**
  (§2.6 п. 16).
- **Секреты** — ключ лежит **на диске в открытом виде** (`%APPDATA%/darmark/config.json`, секция `ai`);
  компенсируется **маскированием в UI**, **запретом логирования** и **правами каталога** (Credential
  Manager/DPAPI отклонены, §2.4 п. 9, §4).
- **D6 под наблюдением** — HTTP+TLS стек добавляет вес; контроль через size-gate (ориентир
  AI-клиента **≤1.0 МБ**, пересмотрен с ≤0.5 МБ по F55; ADR-0033).
- **ТЗ требует правок** — `TZ-AI-ASSISTANT` (§2, §3.1–3.2, §4, §8.6, §9, §10, §11, §12–14)
  переписывает аналитик отдельной правкой (открытые вопросы — §4 ТЗ).

### 3.3. Влияние и трассировка

- **ТЗ:** `tasks/TZ-AI-ASSISTANT.md` — §2 (scope: облачный OpenAI-совместимый провайдер
  (`routerai.ru`) вместо локального),
  §3.1–3.2 (провайдер), §4 (согласие/сеть/секреты), §8.6 (состояния провайдера),
  §9 (команды/события), §10 (лимиты/бюджет), §11 (AC), §12–14 (план/риски/открытые вопросы).
  Правит **аналитик** (отдельная правка).
- **Идеи:** `ideas/UI-IDEAS.md` IDEA-013 — правит **аналитик** (этот ADR файл не трогает).
- **Прототип (удалён после реализации):** источник UI; провайдер в UI не виден.
- **Дизайн-документ:** §5.5 (`aiPanel.ts`), §12 (настройки/`config.json` — владелец `SettingsStore`),
  §13.2 (AI-контракты), §14 (D6), §16 (реестр ADR).
- **ADR-0030:** режим AI дока и диалог согласия; ссылка на этот ADR — провайдер/сетевой слой.
- **ADR-0021/0030 §2.3:** обоснование «AI — не плагин» (нужен Rust-сетевой слой).

**Обратимость:** провайдер за абстракцией + отдельный модуль `src-tauri/src/ai/`; добавление
локального/иного провайдера — без правок замороженных контрактов §13.2 и контракта плагинов. Смена
`base_url`/`model` (в т.ч. уход от `routerai.ru`) не меняет код клиента (OpenAI-совместимый протокол).
Отказ от облачного провайдера в пользу локальной LLM потребует нового ADR/спайка.

## 4. Отклонённые альтернативы

- **Локальная LLM (Ollama/llama.cpp) как базовый провайдер.** **Отложена на неопределённый срок**
  (вне scope, без обязательства вернуться): внешний сервер + большие модели (онбординг), медленная
  CPU-генерация, дублирование уже имеющегося согласия ради приватности. При возврате — отдельный
  ADR/спайк.
- **Гибрид (локальный + облачный выбор).** Отклонён **сейчас**: локальной реализации нет, гибрид
  усложняет конфигурацию и UI без работающей локальной ветки.
- **Прямой `api.openai.com` как точка доступа.** Отклонён в пользу стороннего роутера `routerai.ru`
  (тот же OpenAI-совместимый протокол): роутер даёт доступ к выбранной модели
  (`deepseek/deepseek-v4.1-flash`) и роутингу; протокол совместим, поэтому смена базового URL не
  меняет код клиента.
- **Anthropic API как провайдер MVP.** Отклонён как MVP-провайдер: возможно **расширение** позже за
  той же абстракцией; в MVP реализуется только OpenAI-совместимый провайдер (`routerai.ru`).
- **AI как плагин (Lua).** Отклонён: плагину недоступны сеть и Rust-сетевой слой (ADR-0021); AI
  нужен Rust-клиент вне песочницы. Совпадает с «вне scope» `TZ-AI-ASSISTANT` §2.
- **Сетевые вызовы из TS (fetch/WebView).** Отклонён: нарушает CSP `default-src 'self'` и инвариант
  «сеть — на Rust-стороне».
- **Windows Credential Manager / DPAPI как хранилище ключа.** **Отклонены** (11.10.2026): избыточны
  для локального лёгкого редактора — отдельная интеграция и API ради секрета, который и так лежит в
  пользовательском каталоге `%APPDATA%/darmark/`. Выбрано: **`config.json` (секция `ai`)** через
  settings-store D11; trade-off — секрет на диске **в открытом виде**, митигации — маскирование в UI,
  запрет логирования, права каталога (§2.4).
- **Fallback при недоступности `routerai.ru` (резервная модель/точка).** **Отклонён** (11.10.2026):
  MVP не перенагружаем; пользователю показывается **понятная ошибка** с действием **«Повторить»**
  (§2.6 п. 16).
- **HTTP-клиент с OpenSSL.** Отклонён: тянет системные зависимости и вес; выбран **системный
  SChannel** (`native-tls`), без OpenSSL (ADR-0033; пересмотрено с rustls по F55/F56).
