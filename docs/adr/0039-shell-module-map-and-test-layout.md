# ADR-0039. Карта модулей Rust-шелла и раскладка тестов по доменам

- **Статус:** Принят
- **Дата:** 15.10.2026
- **Затрагивает:** `crates/app/src-tauri/src/` — раскладка модулей, порог размера файла,
  размещение тестов домена, видимость Tauri-команд

## 1. Контекст

Шелл `darmark` (`crates/app/src-tauri`, крейт `darmark`) вырос в god-файлы: `lib.rs` — 1065
строк на шесть доменов, `ai/plugin_harness.rs` — 1380, `plugins/tests.rs` — 2985 на весь домен,
`plugins/host.rs` — 888, `state.rs` — 815. Три следствия:

- **Навигация.** Имя файла не говорило, что внутри; домен «плагины» жил вперемешку с рантаймом,
  настройками и тестами.
- **Разбор.** Правка одного домена требовала держать в голове весь файл.
- **Рецензирование.** Диффы на сотни строк не различались по смыслу.

Проект при этом Windows-only (ADR-0021, коммит `b892464` снял все `cfg(windows)`), поэтому ряд
обоснований в коде — «должно компилироваться и на не-Windows» — стал неверным, но сохранился.

Отдельная находка при разбиении: перенос Tauri-команд из корня крейта в подмодуль ломает
сборку неочевидным образом (§2.2). Ни один существующий ADR этого не фиксировал.

## 2. Решение

### 2.1. Карта модулей

`DESIGN_DOC.md` §2 отсылает карту модулей к `AGENTS.md` — карта живёт там.

| Модуль | Содержимое |
|---|---|
| `lib.rs` | только сборка: `mod`-декларации, `pub use` наружу, `run()`, `generate_handler!` |
| `contract.rs` | контрактные типы IPC: `PluginViewInfo`, `PluginStatus`, `CommandInfo`, `PluginInfo` |
| `fs.rs` | `MAX_FILE_SIZE`, чтение/запись, asset-scope, имя файла для журнала |
| `commands/documents.rs` | 11 команд документов + `lock_store` |
| `commands/plugins.rs` | 9 команд менеджера плагинов + `open_devtools` |
| `setup/plugins.rs` | `PluginState`, sinks плагинной подсистемы, `setup_plugins` |
| `setup/env.rs` | каталог настроек, отключение WebView2-акселераторов |
| `dev_plugin.rs` | dev-режим `--debug-plugin` |
| `state/` | владение документами: `types` / `store` / `history` / `tests` |
| `ai/` | ассистент: `commands`, `doc_harness`, `plugin_harness`, `history`, `skills`, `settings`, `backend` |
| `mcp/` | MCP-сервер: `adapters` (tools/privacy/journal/tests), `resources` |
| `plugins/` | плагинная подсистема: `manager`, `host`, `supervisor`, `services`, `views`, `scan`, `bus`, настройки |

**Порог размера файла: 400 строк.** Файл выше — повод разбить по домену. Исключения
обосновываются в этом ADR; на момент принятия их нет.

**Правило раскладки:** структура с полями объявляется в модуле-родителе, её `impl`-блоки
разводятся по подмодулям. Приватность поля действует на модуль объявления и его потомков,
а не на соседей, — поэтому объявление обязано быть **выше** всех, кто это поле читает.
Отсюда `struct PluginHost` и `struct DocumentStore` живут в `host/mod.rs` и `state/mod.rs`,
а не в одноимённых подмодулях.

### 2.2. Видимость Tauri-команд вне корня крейта

**Правило: команда Tauri вне корня крейта обязана быть `pub(crate) fn` или `pub fn`.**

Макрос `#[tauri::command]` для функции с видимостью `Inherited` (то есть `fn cmd()`)
генерирует `macro_rules! __cmd__X` **без** `#[macro_export]` и реэкспортирует его с
унаследованной видимостью. `generate_handler!`, находящийся в `lib.rs`, адресует этот макрос по
пути — и получает `E0603 «macro import is private»`. Для `pub(crate) fn` и `pub fn` макрос
получает `#[macro_export]`, и всё компилируется.

Проверено на `tauri` 2.12.1 (`Cargo.lock`). Все 21 команда шелла — `pub(crate) fn`; публичный
API библиотеки это не меняет, команда и так адресовалась из `generate_handler!`.

Второе следствие того же правила: при переносе команды в подмодуль реэкспортировать нужно
**и сами макросы** (`pub use commands::{__cmd__ai_diff, __tauri_command_name_ai_diff};`),
иначе `E0433` — `generate_handler!` ищет их по пути модуля объявления.

### 2.3. Тесты домена — отдельным деревом

Тесты домена лежат в `plugins/tests/` и `ai/plugin_harness/tests/`, а не внутри
модулей-владельцев. Общие хелперы — в `common.rs`.

**Видимость: приватные детали, нужные тестам, расширяются до `pub(super)`, не до `pub(crate)`.**
`pub(super)` не выходит за пределы домена; `pub(crate)` на элементах рантайма плагинов
(`PluginHost`, `ensure_plugin_path_allowed`) расширял бы границу доверия без нужды.

## 3. Последствия

**Положительные**

- `lib.rs` — 108 строк вместо 1065; ни один файл шелла не превышает 400.
- Домен читается по имени файла; правка одного домена не открывает соседние.
- Тесты домена собираются в одном месте и следуют за доменом при его перемещении.

**Отрицательные**

- Публичные пути требуют `pub use` при каждом переносе символа. Ошибка проявляется сразу на
  `cargo check`, но требует ручной сверки потребителей (`ripgrep` по `crates/`, включая
  интеграционные тесты в `crates/app/src-tauri/tests/`, которые видят наружную поверхность крейта).
- Правило §2.2 добавляет `pub(crate)` всем командам. Это не изменило и не может изменить
  публичный API: команда не входит в наружную поверхность `darmark_lib`.
- Перенос разрывает intra-doc ссылки (`[`SettingsStore`]` → `` [`SettingsStore`](super::settings::SettingsStore) ``).
  `cargo doc` не входит в гейт CI, поэтому такие ссылки ловятся только вручную.

**Нейтральные**

- Порядок объявления `mod` задаёт `rustfmt` (`reorder_modules`); комментарии между декларациями
  его не отключают, а `#[rustfmt::skip]` подавлять не стоит.

## 4. Рассмотренные альтернативы

- **Тесты внутри модулей-владельцев** (`#[cfg(test)] mod tests` рядом с кодом). Отклонено:
  владелец проекта выбрал отдельное дерево; плюс оно всё равно упирается в приватность —
  соседние подмодули потребовали бы `pub(super)` в тех же местах.
- **`pub(crate)` вместо `pub(super)` для тестовых нужд.** Отклонено: расширяет видимость
  production-элементов за пределы домена без необходимости.
- **Порог 250 вместо 400 строк.** Отклонено: `plugins/supervisor/mod.rs` (392) — связный
  автомат состояния (spawn → чтение кадров → watchdog → activate → invoke); деление разорвёт
  последовательность чтения и таймаутов. Порог 400 даёт запас, не поощряя накопления.
- **Оставить god-файлы.** Отклонено: см. §1.

## 5. Побочные правки

- Удалены все обычные `//`-комментарии: пересказ кода, подписи фаз разработки, разделители.
  Doc-комментарии `///` и `//!` сохранены полностью — это контракт API и носитель ссылок на ADR.
- **Инварианты, записанные обычными `//`, перенесены в `///`/`//!`, а не удалены.** Сплошная
  зачистка снесла вместе с шумом обоснования, которые защищают от регрессий при рефакторинге:
  дедлок `blocking_save_file` при экспорте HTML, «guard стора отпущен до уведомлений»,
  «sink не берёт лок повторно», эхо-защита по неизменной `rev`, запрет редиректов у HTTP-клиента AI
  (тело-документ не должно уходить на хост вне согласия), приватность текста serde-ошибки,
  инвариант «сохранённый файл всегда загружаем», порядок «view в реестре до старта child».
  Правило на будущее: `//`-комментарий, объясняющий **почему** (а не **что**), при вычистке
  переводится в `///` на ближайший элемент или `//!` в шапку модуля.
- Исправлены фактически неверные обоснования «объявлено платформенно-нейтрально, должно
  компилироваться на не-Windows» (`contract.rs`, `plugins/views.rs`, `ai/mod.rs`,
  `ai/settings.rs`): после `b892464` в шелле нет ни одного `cfg(windows)`, `target_os` или
  `target_family`. Обоснование заменено на честное: типы лежат отдельно, потому что это контракт
  IPC, а не внутреннее состояние плагинов.
