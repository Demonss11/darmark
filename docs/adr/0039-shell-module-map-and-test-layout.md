# ADR-0039. Карта модулей Rust-шелла и раскладка тестов по доменам

- **Статус:** Принят
- **Дата:** 15.10.2026
- **Затрагивает:** `crates/app/src-tauri/src/` — раскладка модулей, порог размера файла,
  размещение тестов домена, видимость Tauri-команд

## 1. Контекст

Шелл `darmark` (`crates/app/src-tauri`, крейт `darmark`) вырос в god-файлы: `lib.rs` —
~1000 строк на шесть доменов, остальные файлы доменов — сопоставимого размера.
Имя файла не говорило, что внутри; домен «плагины» жил вперемешку с рантаймом,
настройками и тестами, диффы не различались по смыслу.

Отдельная находка при разбиении: перенос Tauri-команд из корня крейта в подмодуль ломает
сборку неочевидным образом (§2.2). Ни один существующий ADR этого не фиксировал.

## 2. Решение

### 2.1. Карта модулей

Карта модулей шелла — `AGENTS.md` («Модули шелла»). ADR фиксирует только правила:

**Порог размера файла: 400 строк.** Файл выше — повод разбить по домену. Исключения
обосновываются в этом ADR (перечень и обоснование — §4).

**Правило раскладки:** структура с полями объявляется в модуле-родителе; объявление
обязано быть выше всех читателей поля (`PluginHost` → `host/mod.rs`,
`DocumentStore` → `state/mod.rs`). Подробности — в `AGENTS.md`.

### 2.2. Видимость Tauri-команд вне корня крейта

**Правило: команда Tauri вне корня крейта обязана быть `pub(crate) fn` или `pub fn`.**
Иначе `generate_handler!` из `lib.rs` не видит макрос. Причина — видимость
`macro_rules!`, подробности в `AGENTS.md`. При переносе команды реэкспортируется
и её `__cmd__*`-макрос.

### 2.3. Тесты домена — отдельным деревом

Тесты домена лежат в `plugins/tests/` и `ai/plugin_harness/tests/` (подробности —
в `AGENTS.md`). **Видимость: приватные детали для тестов расширяются до `pub(super)`,
не до `pub(crate)`.** `pub(super)` не выходит за пределы домена; `pub(crate)` на
элементах рантайма расширял бы границу доверия без нужды.

## 3. Последствия

**Положительные**

- `lib.rs` сжался до ~100 строк; ни один файл `src` не превышает 400 (исключения для файлов
  тестов — §4).
- Домен читается по имени файла; правка одного домена не открывает соседние.
- Тесты домена собираются в одном месте и следуют за доменом при его перемещении.

**Отрицательные**

- Публичные пути требуют `pub use` при переносе символа; ошибка всплывает на `cargo check`.
- Правило §2.2 добавляет `pub(crate)` всем командам. Публичный API это не меняет.
- Перенос разрывает intra-doc ссылки — они ловятся вручную.

**Нейтральные**

- Порядок объявления `mod` задаёт `rustfmt`.

## 4. Рассмотренные альтернативы

- **Тесты внутри модулей-владельцев.** Отклонено: отдельное дерево не хуже по
  приватности (см. §2.3) и следует за доменом при перемещении.
- **`pub(crate)` вместо `pub(super)` для тестовых нужд.** Отклонено: расширяет
  видимость production-элементов за пределы домена без необходимости.
- **Порог 250 вместо 400 строк.** Отклонено: `plugins/supervisor/mod.rs` (~380 строк) —
  связный автомат (spawn → кадры → watchdog → activate → invoke); деление разорвёт
  последовательность и таймауты. Порог 400 даёт запас, не поощряя накопления.
- **Файлы тестов домена `ai` выше порога: исключение (принято 16.10.2026, ADR-0040).**
  `ai/tests/tool_loop.rs` (~726), `ai/tests/state.rs` (~765), `ai/tests/commands.rs` (~477).
  Обоснование: §2.3 требует группировки **по модулям-владельцам**, а двойники (транспорт,
  MCP-серверы, эмиттер, кэш возможностей) уже вынесены в общий `ai/tests/support.rs` — то есть
  единственное, что раздувает файл теста, — это сами проверки, разложить которые больше некуда.
  Рассмотренный перенос блока деградации в `ai/tests/commands.rs` отклонён: сквозные проверки
  деградации там уже есть (дублирование), а файл вырос бы до ~800 строк, и проверки
  `tool_loop::run` оказались бы у другого владельца. Триггер пересмотра: файл теста одного
  владельца перерастает ~900 строк — `tool_loop.rs` уже дошёл до ~726 — тогда делить по парам
  «сценарий + ожидание» внутри одного владельца, а не по фиче.
