# ADR-0025. Ре-дизайн палитры и типографики

> **Частично заменён ADR-0037** (13.10.2026): введён ручной тумблер Dark/Light.

- **Статус:** **Предложен**
- **Дата:** 10.10.2026
- **Основание:** проблемы доступности и поддерживаемости текущей палитры.

---

## 1. Контекст

Текущая палитра функциональна, но имеет четыре системных проблемы:

1. **Нет семантической системы.** Цвета используются напрямую (`--green`, `--amber`, `--red`),
   без абстракции намерения. Статусы привязаны к конкретным значениям, а не к роли.
2. **Нет масштабирования.** Фиксированные `px` ограничивают доступность: пользователь не может
   увеличить интерфейс без потери читаемости. Нет резиновой типографики.
3. **Дублирование тем.** `previewView.ts` содержит отдельную светлую тему (`COPY_CSS`) для
   буфера обмена — это вторая палитра, которая не синхронизируется с основной.
4. **Плагинные цвета не гарантируют контраст.** `pluginColor.ts` генерирует цвет без проверки контраста на фонах приложения.

**Ограничения:**
- Общие проектные ограничения (CSP, размер базы ≤ 6 МБ) — см. `DESIGN.md`.

---

## 2. Решение

### 2.1. Новая палитра

**Фоны** — холодные, глубокие, с синим подтоном:

| Токен | Значение | Роль |
|-------|----------|------|
| `--bg-0` | `#111318` | базовый фон приложения |
| `--bg-1` | `#161920` | панели, тулбар, вкладки |
| `--bg-2` | `#1c1f28` | карточки, строки списков |
| `--bg-3` | `#242836` | hover-состояния, кнопки |
| `--line` | `#2e3348` | границы, разделители |
| `--line-soft` | `#232736` | тонкие границы, подложки |

**Текст** — светлые холодные тона с гарантированным контрастом:

| Токен | Значение | Контраст на `--bg-0` | Уровень |
|-------|----------|---------------------|---------|
| `--fg` | `#e8eaf0` | 9.2:1 | AAA |
| `--fg-dim` | `#a0a6bd` | 5.8:1 | AA |
| `--fg-mute` | `#6b7194` | 4.6:1 | AA (large text) |

**Акцент** — приглушённый индиго:

| Токен | Значение | Контраст на `--bg-0` | Уровень |
|-------|----------|---------------------|---------|
| `--accent` | `#8b7cf6` | 6.2:1 | AA |
| `--accent-2` | `#6ea8fe` | 5.1:1 | AA |

Статусные цвета (`--green`, `--amber`, `--red`, `--teal`) остаются базовыми значениями.

### 2.2. Семантические токены

| Токен | Значение | Использование |
|-------|----------|---------------|
| `--success` | `var(--green)` | успешные операции, активные плагины |
| `--warning` | `var(--amber)` | предупреждения, несохранённые изменения |
| `--error` | `var(--red)` | ошибки, карантин, удаление |
| `--info` | `var(--teal)` | информационные сообщения |
| `--disabled` | `var(--fg-mute)` | отключённые элементы |
| `--link` | `var(--accent-2)` | гиперссылки в предпросмотре |

### 2.3. Новая типографика

| Токен | Было | Стало |
|-------|------|-------|
| `--ed-fs` | 13.5px | 14.5px |
| `--ed-lh` | 23px (1.70) | 26px (1.8) |
| `--ed-pad-y` | 16px | 20px |

### 2.4. Унификация `previewView.ts`

`COPY_CSS` в `previewView.ts` заменяется на токены приложения; для буфера обмена — отдельный блок `:root.copy-theme` в `style.css`.

### 2.5. Проверка контраста плагинных цветов

`pluginColor.ts` корректирует светлоту цвета, если контраст < 4.5:1 на `--bg-0` или `--bg-1`.

---

## 3. Обязательные требования

- [ ] Семантические токены и контрасты реализованы согласно §2.1–2.2.
- [ ] E2E-тесты не падают (`npm run build` + визуальная проверка).

---

## 4. Отклонённые альтернативы

- **Полная переработка UI.** Отклонено: сломает замороженные контракты и E2E-тесты.
- **Итеративные улучшения без ADR.** Отклонено: объём L, затрагивает несколько подсистем.
- **Светлая тема.** Отклонено: одна тёмная тема — замороженный контракт (см. ADR-0037).

---

## 5. Последствия

**Положительные:**
- Гарантированная доступность (WCAG AA).
- Единая семантическая система упрощает поддержку.
- Устранение дублирования тем.

**Отрицательные / цена:**
- Возможны проблемы обратной совместимости пользовательских стилей.
- Необходимость визуальной проверки всех экранов.
