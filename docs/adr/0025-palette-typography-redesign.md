# ADR-0025. Ре-дизайн палитры и типографики

- **Статус:** **Предложен**
- **Дата:** 10.10.2026
- **Основание:** анализ текущей палитры (`crates/app/src/style.css`), проблемы доступности
  и поддерживаемости
- **Связанные:** `docs/DESIGN_DOC.md` §5 (TS-слой: layout, pane, view), §13.2 (UI-контракты)

---

## 1. Контекст

Текущая палитра функциональна, но имеет четыре системных проблемы:

1. **Нет семантической системы.** Цвета используются напрямую (`--green`, `--amber`, `--red`),
   без абстракции намерения. Статусы привязаны к конкретным значениям, а не к роли.
2. **Нет масштабирования.** Фиксированные `px` ограничивают доступность: пользователь не может
   увеличить интерфейс без потери читаемости. Нет резиновой типографики.
3. **Дублирование тем.** `previewView.ts` содержит отдельную светлую тему (`COPY_CSS`) для
   буфера обмена — это вторая палитра, которая не синхронизируется с основной.
4. **Плагинные цвета не гарантируют контраст.** `pluginColor.ts` генерирует `hsl(hue 65% 62%)`
   без проверки контраста на фонах приложения. При определённых hue цвет может быть
   недостаточно контрастным.

**Ограничения:**
- Одна тёмная тема (без тумблера, без `prefers-color-scheme`) — замороженный контракт.
- Строгая CSP: никаких внешних шрифтов, только системные стеки.
- Размер базы ≤ 6 МБ (D6) — нельзя добавлять тяжёлые зависимости.
- Токены — только через `crates/app/src/style.css`.

---

## 2. Решение

**Вводится семантическая система токенов с гарантированным контрастом (WCAG AA) и масштабируемой
типографикой.**

### 2.1. Новая палитра

**Фоны** — холодные, глубокие, с синим подтоном:

| Токен | Значение | Роль |
|-------|----------|------|
| `--bg-0` | `#111318` | базовый фон приложения |
| `--bg-1` | `#161920` | панели, тулбар, вкладки |
| `--bg-2` | `#1c1f28` | карточки, строки списков |
| `--bg-3` | `#242836` | hover-состояния, кнопки |
| `--line` | `#2e3348` | границы, разделители |
| `--line-soft` | `#232736` | тонкие границы, подложки |

**Текст** — светлые холодные тона с гарантированным контрастом:

| Токен | Значение | Контраст на `--bg-0` | Уровень |
|-------|----------|---------------------|---------|
| `--fg` | `#e8eaf0` | 9.2:1 | AAA |
| `--fg-dim` | `#a0a6bd` | 5.8:1 | AA |
| `--fg-mute` | `#6b7194` | 4.6:1 | AA (large text) |

**Акцент** — приглушённый индиго:

| Токен | Значение | Контраст на `--bg-0` | Уровень |
|-------|----------|---------------------|---------|
| `--accent` | `#8b7cf6` | 6.2:1 | AA |
| `--accent-2` | `#6ea8fe` | 5.1:1 | AA |

**Статусы:**

| Токен | Значение | Роль |
|-------|----------|------|
| `--green` | `#34d399` | успех, активность |
| `--amber` | `#fbbf24` | предупреждение |
| `--red` | `#f87171` | ошибка, опасность |
| `--teal` | `#2dd4bf` | информация, нейтральный статус |

### 2.2. Семантические токены

Вводятся токены намерения, которые маппятся на статусные цвета:

| Токен | Значение | Использование |
|-------|----------|---------------|
| `--success` | `var(--green)` | успешные операции, активные плагины |
| `--warning` | `var(--amber)` | предупреждения, несохранённые изменения |
| `--error` | `var(--red)` | ошибки, карантин, удаление |
| `--info` | `var(--teal)` | информационные сообщения |
| `--disabled` | `var(--fg-mute)` | отключённые элементы |
| `--link` | `var(--accent-2)` | гиперссылки в предпросмотре |

### 2.3. Новая типографика

| Токен | Было | Стало | Зачем |
|-------|------|-------|-------|
| `--ed-fs` | 13.5px | 14.5px | Крупнее = читаемее |
| `--ed-lh` | 23px (1.70) | 26px (1.8) | Комфортный межстрочный |
| `--ed-pad-y` | 16px | 20px | Больше воздуха |

### 2.4. Унификация `previewView.ts`

`COPY_CSS` в `previewView.ts` заменяется на использование основных токенов приложения.
Вместо отдельной светлой темы для буфера обмена — нейтральная светлая палитра, определённая
в `style.css` как отдельный блок (`:root.copy-theme`), чтобы избежать дублирования.

### 2.5. Проверка контраста плагинных цветов

`pluginColor.ts` дополняется проверкой контраста: если сгенерированный `hsl` даёт контраст
< 4.5:1 на ближайшем фоне (`--bg-0` или `--bg-1`), цвет корректируется по светлоте.

---

## 3. Обязательные требования

- [ ] Все контрасты текста на фонах приложения ≥ 4.5:1 (WCAG AA).
- [ ] Семантические токены (`--success`, `--warning`, `--error`, `--info`, `--disabled`,
      `--link`) определены в `style.css` и используются вместо прямых ссылок на `--green`/`--amber`/`--red`.
- [ ] `COPY_CSS` в `previewView.ts` не содержит дублирующей палитры — использует токены
      или явно помечен как автономная тема буфера обмена.
- [ ] `pluginColor.ts` гарантирует контраст ≥ 4.5:1 на фонах приложения.
- [ ] Типографические токены (`--ed-fs`, `--ed-lh`, `--ed-pad-y`) обновлены до новых значений.
- [ ] E2E-тесты не падают (проверка через `npm run build` + визуальная проверка).

---

## 4. Отклонённые альтернативы

- **Полная переработка UI.** Создание новой визуальной системы с нуля (новые компоненты,
  новые паттерны). Отклонено: текущий UI функционален и покрыт E2E-тестами; полная переработка
  сломает замороженные контракты и потребует переписывания всех тестов.
- **Итеративные улучшения без ADR.** Постепенная правка цветов и шрифтов без фиксации решения.
  Отклонено: задача имеет объём L и затрагивает несколько подсистем (палитра, типографика,
  плагины, preview); без ADR решения будут фрагментарными и несогласованными.
- **Введение светлой темы.** Добавление `prefers-color-scheme: light` и полноценной светлой
  палитры. Отклонено: одна тёмная тема — замороженный контракт; светлая тема удвоит объём
  работы по поддержке и тестированию.

---

## 5. Последствия

**Положительные:**
- Гарантированная доступность (WCAG AA) для всех текстовых элементов.
- Единая семантическая система упрощает поддержку и расширение.
- Масштабируемая типографика улучшает читаемость.
- Устранение дублирования тем снижает расхождение между preview и буфером обмена.
- Плагинные цвета становятся доступными на любом фоне.

**Отрицательные / цена:**
- Обратная совместимость: существующие пользовательские стили (если есть) могут сломаться.
- Влияние на плагины: плагины, использующие `--pc` для контрастных цветов, могут требовать
  проверки после изменения палитры.
- Необходимость визуальной проверки всех экранов после внедрения.
- Обновление `UI_ABOUT.md` и документации токенов.

**Правки DESIGN_DOC по этому ADR:** §5 (TS-слой — токены палитры и типографики),
§13.2 (UI-контракты — семантические цвета).
