## 1. Контекст

D5 принят и зафиксирован в §4.1/§4.2: **владелец текста и undo-стека — Rust `Document`**.
В `state.rs` уже стоят заглушки: `undo`/`redo: Vec<EditOp>` и `EditOp { rev, range, text }`
(под `#[allow(dead_code)]`), стек наполняется не был.

Правки текста идут двумя путями, и оба — через Rust:

- **Ввод редактора:** фронт шлёт **весь текст** дебаунсом (`update_document`, `DEBOUNCE_MS = 120`
  в `crates/app/src/docStore.ts`); `rev` растёт только при реальной смене текста (эхо-защита).
- **Программные правки:** `formatActions.ts` и Lua-плагины меняют текст через `apply_edit`
  (байтовые диапазоны UTF-8, `DocumentStore::apply_edit`).

**Нативный undo `<textarea>` непригоден.** Любая программная смена `value` (переключение
документа, `formatActions`, плагинные правки) сбрасывает историю браузера — известное
ограничение (§13, `crates/app/src/formatActions.ts`). Нативный undo несовместим с `apply_edit`
и не даёт единой истории для ввода и правок плагинов.

Кэш рендера и `rev` живут в Rust (§4.2); `rev` — ключ кэша `(mapped, rev)` и инвалидации
индексов. S16 — **gate перед реализацией**: зафиксировать
rev-семантику и контракт undo до кодинга.

---

## 2. Решение

**Выбирается diff-модель undo в Rust: единый стек для ввода и `apply_edit`, операция — замена
байтового диапазона, отдельные `undo`/`redo`, лимит по числу операций, только в памяти.**

### 2.1. Модель diff-undo

1. Единица истории — **операция замены диапазона**: `[start, start + removed.len())` → `inserted`,
   смещения — **байтовые UTF-8** (как `data-md` в `md-core`).
2. `EditOp` **переопределяется**: `{ start: usize, removed: String, inserted: String }` — заменяет
   прежнюю заглушку `{ rev, range, text }`. `removed` — что было в диапазоне, `inserted` — что
   вставлено вместо него. Поле `rev` из `EditOp` уходит.
3. **`undo`** применяет обратную замену (`inserted` → `removed` по тем же смещениям), **`redo`** —
   прямую.

### 2.2. Единый стек

4. Все правки текста документа идут через **один** undo-стек: ввод редактора (`update_document`)
   и программные правки (`apply_edit` — `formatActions`, плагины).
5. `update(id, text, mapped)` — **сигнатуру не меняем**: внутри фиксирует **diff-оп** (минимальный
   общий префикс/суффикс между старым и новым текстом) в `undo` и очищает `redo`.
6. `apply_edit(id, start, stop, text)` — **сигнатуру не меняем**: фиксирует **точную** оп
   (`start`, `removed = старый [start, stop)`, `inserted = text`) в `undo` и очищает `redo`.
7. Правка, **не меняющая текст** (`start == stop` и `text` пуст; либо `update` тем же текстом),
   оп не пишет и `redo` не очищает — эхо-защита не портит историю.

### 2.3. `undo` / `redo`

8. Новые операции стора: `undo(id) -> Option<UndoResult>`, `redo(id) -> Option<UndoResult>`.
9. `UndoResult { text, rev, start, end }` — текст **после** операции и диапазон результата
   (байтовые UTF-8) для восстановления выделения во фронте.
10. `undo` снимает верх `undo`, применяет обратную замену, кладёт оп в `redo`; `redo` — наоборот.
    Пустой стек → `None` (no-op).

### 2.4. Команды IPC

11. Новые команды: `undo_document(id)`, `redo_document(id) -> UndoResult`; обёртки — в
    `crates/app/src/tauri.ts`.
12. Сигнатуры `update_document`/`apply_edit` **не меняются** — фронт и плагины продолжают
    работать без правок транспорта.

### 2.5. `rev`, кэш, события

13. `rev` растёт на **любой** реальной смене текста, **включая** undo/redo → инвалидация кэша
    рендера `(mapped, rev)` и событие `document:changed` для плагинов (та же семантика, что у
    обычной правки).
14. `undo`/`redo` рендерят документ как обычную правку — кэш и `changed` переиспользуются.

### 2.6. Лимит стека

15. Стек ограничен по числу операций: **`UNDO_LIMIT = 500`**; при переполнении отбрасываются
    **самые старые** оп-ы (дно стека).

### 2.7. Персистентность

16. Стек undo/redo — **только в памяти**, на диск не персистится; закрытие документа освобождает
    историю. Соответствует §4.2 (undo/redo — владелец Rust, но не персистируемое состояние).

### 2.8. Перехват нативного undo на фронте

17. Фронт перехватывает `Ctrl+Z` / `Ctrl+Y` / `Ctrl+Shift+Z` и событие `beforeinput`
    с `inputType` `historyUndo`/`historyRedo`, вызывает `undo_document`/`redo_document` и
    применяет `UndoResult` (текст + выделение `start..end`) в редактор.

## 3. Последствия

**Положительные:**

- Единая точка правок (D5): ввод редактора и плагинный `apply_edit` отменяются одним стеком.
- Нативный undo заменяется предсказуемым: программные правки (переключение документа,
  `formatActions`, плагины) больше не рвут историю.
- **Транспорт не меняется**: `update_document` по-прежнему шлёт весь текст — diff считается на
  Rust из уже отправленного текста, переписывать IPC не нужно.
- `rev`/кэш/события переиспользуются: undo/redo автоматически инвалидируют рендер и уведомляют
  плагины.

**Отрицательные / ограничения:**

- **Coalescing грубый.** Границей оп-а служит дебаунс ~120 мс: несколько быстрых нажатий могут
  схлопнуться в одну оп-у (или наоборот) — тонкой группировки по паузам нет.
- **Память.** `removed`/`inserted` дублируют фрагменты текста в стеке; при `UNDO_LIMIT = 500` и
  крупных вставках объём заметен.
- **`dirty` остаётся на TS** (§4.2): Rust-undo его не трогает. Фронт **выводит**
  `dirty = text !== savedText` (пересчёт на set/undo/redo/host-update/save) — undo к сохранённому
  тексту корректно сбрасывает флаг.
- **Selection возвращается во фронт** через `UndoResult` (`start`/`end`, байты): Rust не владеет
  выделением (UI-состояние, §4.2). Перевод в UTF-16 — однопроходный `byteToUtf16` (O(offset),
  без построения полных карт) — достаточно для редкого undo/redo.
- **Стек не персистится**: перезапуск приложения историю теряет.

## 4. Отклонённые альтернативы

- **Delta-транспорт (правки текста дельтами).** Отклонён: дороже и ломает текущий конвейер
  (`update_document` шлёт весь текст, D5); не требуется, т.к. diff вычисляется на Rust из уже
  отправленного текста.
- **Оставить нативный undo `<textarea>`.** Отклонён: несовместим с `apply_edit` — программная
  смена `value` рвёт историю браузера (§13, `formatActions.ts`).
- **Персистентный undo (на диск).** Отклонён: не нужен — undo-история эфемерна и не переживает
  перезапуск.
- **Хранить `rev` в `EditOp` / привязывать историю к ревизиям.** Отклонён: усложняет без пользы —
  отмена есть операция над текстом, а не над `rev`.
