# ADR-0035. Пользовательски настраиваемые провайдеры LLM: map провайдеров/моделей в `config.json` (идея opencode.json)

> Идея конфигурации — из `opencode.json` (`providers` как map, раздел **Custom**:
> <https://opencode.ai/v2/docs/providers/#custom>). Адаптируется под darmark (Rust, без npm-пакетов):
> провайдер описывается **данными** (точка, ключ, заголовки, модели), а не кодом.

- **Статус:** **Принят**
- **Дата:** 12.10.2026
- **Основание:** продуктовое решение 12.10.2026 — пользователь **сам указывает провайдеров** LLM
  (разные точки доступа, модели и ключи), вместо единственного жёстко заданного `routerai.ru`;
  модель провайдеров из `opencode.json` (раздел **Custom**);
  `docs/adr/0032-ai-provider-openai.md` (**обобщается** настоящим ADR: одиночный провайдер → map);
  ТЗ AI-ассистента (Ф1/Ф2 реализованы; IDEA-013);
  порядок «проверочный стенд → ADR → реализация» (`DESIGN_DOC` §0, D11/ADR-0018)
- **Связанные:** `docs/adr/0032-ai-provider-openai.md` (**заменяет** фиксированного провайдера;
  секрет/сеть/согласие — сохраняются), `docs/adr/0033-ai-http-client-streaming.md`
  (`reqwest`+SChannel + SSE; протокол-клиент не меняется), `docs/adr/0034-ai-runtime-placement.md`
  (AI в процессе GUI за швом `AiBackend`/`AiTransport`; включаемость `ai.enabled`),
  `docs/adr/0030-bottom-dock-two-modes.md` (режим AI дока, диалог согласия),
  `docs/adr/0011`-класс (настройки: Rust-store + JSON в appdata, §12),
  `docs/DESIGN_DOC.md` §5.5 (модульная карта — `aiPanel.ts`), §12 (настройки/`config.json`),
  §13.2 (замороженные контракты) (бюджет D6) (реестр ADR);
  `crates/app/src-tauri/src/ai/`, `crates/app/src/aiPanel.ts`

## 1. Контекст

### 1.1. Проблема

ADR-0032 зафиксировал в MVP **один** провайдер — OpenAI-совместимый API стороннего роутера
`routerai.ru` с моделью `deepseek/deepseek-v4.1-flash` и **жёстко заданной** точкой доступа.
Пользователю нужен выбор: разные точки доступа, разные модели и **свои** ключи (корпоративный
шлюз, локальный OpenAI-совместимый сервер, иной роутер). Текущая схема `ai` (`base_url`/`model`/
`api_key` — по одному значению) этого не выражает и не масштабируется на несколько провайдеров.

### 1.2. Что уже зафиксировано (не пересматривается)

- **Сеть — только Rust-сторона**; CSP `default-src 'self'` не ослабляется (ADR-0032 §2.5 п. 11,
  ADR-0033, ADR-0034 §2.2 п. 2).
- **Протокол** — OpenAI-совместимый Chat Completions (`POST /chat/completions`,
  `Authorization: Bearer <key>`, `messages` → `choices[].message.content`), `base_url` и `model`
  уже конфигурируемы (ADR-0032 §2.1 п. 2). Смена точки/модели **не меняет код клиента**.
- **HTTP-клиент** — `reqwest` (`native-tls`/SChannel) + SSE (ADR-0033).
- **Размещение** — в процессе GUI за швом `AiBackend`/`AiTransport` (ADR-0034); включаемость —
  `ai.enabled` + ленивая инициализация (ADR-0034 §2.3).
- **Согласие обязательно**: содержимое документа уходит в облако **только после явного согласия**
  (ADR-0030 §2.4, ADR-0032 §2.3); ответ рендерится через **Rust-санитайзер** (D7/§11).
- **Секреты** — локально в `%APPDATA%/darmark/config.json`, секция `ai`, через settings-store
  (D11); **не** в TS-коде и **не** в логах; Credential Manager/DPAPI отклонены (ADR-0032 §2.4).
- **D6 (release-exe ≤6 МБ, size-gate)**; AI-клиент — маргинальный прирост ≤1.0 МиБ (ADR-0033).

### 1.3. Почему решение пересматривается

ADR-0032 §2.2 п. 4 уже требовал держать интерфейс провайдера расширяемым «без ломки контрактов»,
но оставлял в MVP **ровно один** провайдер. Продуктовое решение 12.10.2026 снимает это
ограничение: список провайдеров задаёт **пользователь**, а не сборка. Источник модели — конфиг
`opencode.json` (раздел **Custom**, <https://opencode.ai/v2/docs/providers/#custom>): провайдеры как
map, ключ — id, поля `name`/`env`/`package`/`settings` (там же `baseURL`/`apiKey`/`timeout`)/
`headers`/`body`/`models`. Переносим **структуру данных**, не runtime: в darmark нет npm-пакетов
провайдеров, поэтому `package` переосмыслен из npm-runtime в **маркер протокола**
(`openai-compatible`; зарезервирован `anthropic-compatible`), а `canonical` (наследование каталога
`models.dev`) **не переносится** — каталога моделей нет, модели перечисляются явно.

---

## 2. Решение

**Провайдеры LLM задаются пользователем в `config.json` (секция `ai`) как map `providers`
(ключ — id провайдера) плюс `active_provider`/`active_model`; структура — по разделу **Custom**
`opencode.json`. Секреты — локально, credential-by-config (`settings.apiKey` либо `env`);
`settings.baseURL`, `settings.timeout`, `headers`, `body` и `models` — на провайдера; `package` —
**маркер протокола**. Протокол остаётся OpenAI-совместимым (Chat Completions); клиент, шов
`AiBackend`/`AiTransport`, CSP, санитайзер и D6 — без изменений.**

### 2.1. Схема конфигурации (map провайдеров)

1. Секция `ai` в `%APPDATA%/darmark/config.json` получает **map провайдеров** `ai.providers`
   (ключ — **id провайдера**) и выбор активной пары `ai.active_provider` + `ai.active_model`:

   ```jsonc
   "ai": {
     "enabled": true,
     "active_provider": "routerai",
     "active_model": "deepseek/deepseek-v4.1-flash",
     "consent_document_send": false,
     "providers": {
       "routerai": {
         "name": "RouterAI",
         "env": ["ROUTERAI_API_KEY"],           // упорядоченные env-переменные для ключа (как в Custom)
         "package": "openai-compatible",        // маркер протокола (в MVP один; зарезервирован anthropic-compatible)
         "settings": {                          // «typed controls» Custom
           "baseURL": "https://routerai.ru/api/v1",
           "apiKey": "",                        // локальный секрет (необязательно; приоритет над env)
           "timeout": 30000                     // мс; провайдер-wide (settings.timeout в Custom)
         },
         "headers": {},                         // доп. HTTP-заголовки на каждый запрос
         "body": {},                            // JSON-поля, вливаемые в тело запроса
         "models": {
           "deepseek/deepseek-v4.1-flash": { "name": "DeepSeek V4.1 Flash" }
         }
       }
       // ... ещё провайдеры: openai, корпоративный шлюз, локальный OpenAI-совместимый (http loopback)
     }
   }
   ```

2. Поля провайдера: `name` (отображаемое имя), `env` (упорядоченный список env-переменных для
   ключа), `package` (маркер протокола, `openai-compatible`), `settings` (`baseURL` — точка доступа,
   **обязательна**; `apiKey`; `timeout`), `headers`/`body` (по умолчанию пусты), `models`
   (map id → `{ name }`).
3. `settings.baseURL` — **точка**; протокол к ней — **OpenAI-совместимый Chat Completions** (как
   сейчас). Провайдер описывается **данными**; отдельного кода на провайдера **не вводится**.
4. Из `opencode.json` (раздел Custom) переносится **структура**, но не npm-runtime: `package`
   переосмыслен как **маркер протокола** (значение `openai-compatible` — единственное в MVP;
   зарезервировано `anthropic-compatible`), а `canonical` (наследование каталога `models.dev`) **не
   переносится** — каталога моделей нет, модели перечисляются явно. Модель — объект `{ name }`
   (Custom также знает `modelID`/`disabled`, опц. `limit`/`cost` — см. таблицу ниже); в MVP
   достаточно `name`. Если позже понадобится не-OpenAI протокол (Anthropic-compatible) — **отдельный
   ADR** (ср. ADR-0032 §4).

   Соответствие полям Custom (`opencode.json` → darmark `ai.providers[id]`):

   | Custom (`opencode.json`) | darmark (`config.json` → `ai.providers[id]`) | Примечание |
   |---|---|---|
   | `name` | `name` | отображаемое имя |
   | `env` | `env` | упорядоченные имена env-переменных для ключа |
   | `package` | `package` | переосмыслен: маркер протокола `openai-compatible` (не npm-пакет) |
   | `canonical` | — | **не переносится** (нет каталога `models.dev`) |
   | `settings` | `settings` | типизированные контролы; в darmark — `baseURL`/`apiKey`/`timeout` |
   | `settings.baseURL` | `settings.baseURL` | точка доступа (**обязательна**) |
   | `settings.apiKey` | `settings.apiKey` | локальный секрет; приоритет над `env` |
   | `settings.timeout` | `settings.timeout` | мс, провайдер-wide |
   | `settings.headerTimeout`/`chunkTimeout` | — | **не вводятся** в MVP (§2.5 п. 13) |
   | `headers` | `headers` | доп. HTTP-заголовки |
   | `body` | `body` | доп. JSON-поля тела запроса |
   | `models` (у модели `name`/`modelID`/`disabled`, опц. `limit`/`cost`) | `models` (в MVP — `{ name }`) | id модели — ключ map |
   | корневой `model: "provider/model"` | `active_provider` + `active_model` | резолв по полям, не разбором строки (§2.2) |

### 2.2. Ссылка на модель

5. В UI модель показывается как **`provider/model`** (как в opencode): `active_provider` +
   `active_model`. Резолв идёт по **полям** `active_provider`/`active_model` (ключ в `providers` и
   ключ в `providers[id].models`), а **не** разбором строки по `/`: id модели **сам может содержать
   `/`** (напр. `deepseek/deepseek-v4.1-flash` у `routerai.ru`) — деление по первому `/` ломало бы
   резолв. Это осознанное ограничение формата отображения.
6. `active_model` **обязан** существовать в `providers[active_provider].models`; иначе — понятная
   ошибка настроек (не отправка запроса).

### 2.3. Секреты (credential-by-config)

7. Ключ задаётся **на провайдера**: `settings.apiKey` (локально, в `config.json`) **либо** `env`
   (упорядоченный список имён переменных окружения; берётся первая заданная, значение читается в
   момент запроса). Если заданы оба источника — приоритет за `settings.apiKey` (значение из конфига
   перекрывает env). Порядок `env` соответствует Custom.
8. Секреты остаются **локальными** и следуют правилам ADR-0032 §2.4: маскирование в UI,
   **запрет логирования** ключа и содержимого, права каталога `%APPDATA%/darmark/`. Credential
   Manager/DPAPI **по-прежнему отклонены** (§4).
9. Наружу (в TS-слой/события/`Debug`) уходит **только** признак наличия ключа (`has_key` на
   провайдера) — ключ не сериализуется в DTO и не логируется (сохраняется инвариант ADR-0032
   §2.4 п. 10).

### 2.4. Надстройка запроса: `headers` и `body`

10. `headers` — **дополнительные** HTTP-заголовки на каждый запрос к провайдеру; `body` —
    JSON-поля, вливаемые в тело запроса (напр. корпоративный tenant-заголовок или `metadata`).
    Идея — из `opencode.json` (`headers`/`body`).
11. `Authorization: Bearer <key>` формируется **из ключа** (§2.3) и **не** задаётся через
    `headers` — чтобы источник авторизации был однозначен. `headers`/`body` **не должны** ломать
    протокол Chat Completions (`model`/`messages`/`stream` формирует клиент; пользовательский
    `body` — надстройка, а не замена обязательных полей).

### 2.5. Таймауты

12. `settings.timeout` — **провайдер-wide** ограничение запроса (отправка → завершение ответа), как
    `settings.timeout` в Custom; по умолчанию — ориентир ADR-0032 §2.5 п. 12 (≈30 с);
    `0`/отсутствие — значение по умолчанию. Провайдер может переопределить глобальное значение
    AI-модуля.
13. Раздельные `settings.headerTimeout`/`settings.chunkTimeout` из Custom **не вводятся** в MVP:
    SSE-парсер (ADR-0033) уже устойчив к паузам между чанками; при необходимости — открытый вопрос
    (§5, §2.10).

### 2.6. Валидация и граница доверия

14. **`settings.baseURL` валидируется на каждого провайдера** при сохранении/использовании:
    допускается **`https`**; **`http`** — **только** для loopback (`127.0.0.1`/`::1`/`localhost`) —
    локальный OpenAI-совместимый рантайм. Иные схемы/хосты — ошибка настроек (код `CommandError`),
    запрос не уходит. Инвариант совпадает с текущим (см. `error.rs`: «`base_url` не `https://` и не
    loopback»).
15. **Согласие называет активный хост** (§2.7) — пользователь видит **фактическую** точку отправки,
    а не хардкод `routerai.ru`. Это ключевое следствие для границы доверия: адресат данных
    определяется конфигом, поэтому согласие обязано быть **привязано к текущему активному хосту**
    и **перезапрашиваться** при его смене (пользователь не должен отправлять данные новому хосту
    «по старому согласию»).
16. `headers`/`body`/`env` — пользовательские данные локального конфига; их значения
    **не логируются** (содержимое/секреты). `settings.baseURL` (хост) — метаданные, допустимы в
    диагностике.

### 2.7. Согласие

17. Диалог согласия (ADR-0030 §2.4) формулируется **про активного провайдера**: показывается
    `name` + **хост `settings.baseURL`** активного провайдера. Смена `active_provider`/
    `settings.baseURL` → согласие **перезапрашивается** (ср. §2.6 п. 15). Инвариант «документ не
    покидает машину без согласия» (ADR-0030 §2.3) сохраняется.
18. Согласие остаётся полем `consent_document_send` в секции `ai` (как сейчас) — без
    отдельных команд; при смене активного хоста значение **сбрасывается**.

### 2.8. Миграция текущей секции `ai`

19. Старая схема (`provider`/`base_url`/`model`/`api_key` — по одному значению) **мигрирует** в
    первый провайдер без потери данных: `base_url` → `settings.baseURL`, `api_key` →
    `settings.apiKey`, `model` → ключ в `models`; id провайдера — из `provider` или дефолтный
    `routerai`, `active_provider`/`active_model` указывают на неё. Миграция **идемпотентна** и
    совместима с `#[serde(default)]`: старый конфиг **разбирается** и не роняет приложение (как
    сейчас).
20. Значения по умолчанию сохраняют поведение ADR-0032: провайдер по умолчанию —
    OpenAI-совместимый `routerai.ru`, модель `deepseek/deepseek-v4.1-flash`, `enabled = false`
    (opt-in, ADR-0034 §2.3).

### 2.9. Discovery моделей (опционально)

21. `GET /models` у провайдера — **опциональный** источник списка моделей (эндпоинт уже
    используется лёгкой проверкой соединения). Провайдер без discovery использует **явный** map
    `models`. Discovery **не обязателен** для работы и не блокирует MVP; включать ли авто-подтяжку —
    открытый вопрос (§5, §2.10).

### 2.10. Что не меняется и что вне scope

22. **Протокол** — OpenAI-совместимый Chat Completions; **клиент** (`reqwest`+SChannel), **SSE**
    (ADR-0033), **шов** `AiBackend`/`AiTransport` и включаемость `ai.enabled` (ADR-0034) — без
    изменений. Конфигурация провайдеров потребляется **за швом** (внутренняя сборка `AiRequest`),
    IPC-контракты фронта и замороженные id `#ai-*` (ADR-0030, §13.2) **не ломаются** (изменение
    DTO настроек — согласованное, см. §3).
23. **CSP** `default-src 'self'` и инвариант «сеть — только Rust» — без изменений.
24. **D6** — без изменений: конфигурация — данные, новых зависимостей не вводится; size-gate и
    ориентир AI-клиента ≤1.0 МиБ (ADR-0033) сохраняются.
25. **MCP** — **вне scope** (ср. ADR-0034 §2.5); при реализации — отдельный ADR. Настоящий ADR MCP
    **не затрагивает**.

## 3. Последствия

**Положительные:**

- **Пользователь выбирает провайдера и модель** — разные точки доступа/ключи/модели без пересборки;
  онбординг сводится к добавлению провайдера и вводу ключа.
- **Расширяемость данными, а не кодом** — новый OpenAI-совместимый провайдер = запись в
  `config.json`; интерфейс провайдера из ADR-0032 §2.2 п. 4 реализован буквально.
- **Секреты остаются локальными**; credential-by-config (`settings.apiKey`/`env`) покрывает и
  «ключ в конфиге», и «ключ в окружении» (CI/корпоративный сценарий).
- **Надстройка запроса** (`headers`/`body`) — без правок кода клиента (корпоративные шлюзы).
- **CSP/D6/санитайзер/шов — без изменений**: конфигурация не добавляет веса и не ослабляет границы.

**Отрицательные / ограничения:**

- **DTO настроек меняются** (список провайдеров вместо одиночных полей) — согласованная правка
  фронта (`aiPanel.ts`) и Rust; id `#ai-*`/замороженные контракты §13.2 сохраняются, но
  `AiSettingsView`/`AiSettingsInput` перерабатываются.
- **Согласие усложняется**: привязка к активному хосту и перезапрос при смене провайдера/точки
  (§2.6 п. 15, §2.7 п. 17) — пользователь должен подтверждать нового адресата.
- **Риск неверной конфигурации**: пользователь может указать недоступную точку/модель — нужны
  понятные состояния/ошибки (сохраняется маппинг ошибок ADR-0032 §2.5 п. 13).
- **`http` только loopback** — осознанное сужение (иначе данные уходят в открытом виде); корпоративный
  шлюз обязан быть `https`.
- **Формат `provider/model` неоднозначен** при id модели со `/` (§2.2 п. 5): резолв — по полям, не
  разбором строки; отображение может выглядеть как `routerai/deepseek/deepseek-v4.1-flash`.
- **ТЗ Ф3** (`tasks/TZ-AI-PHASE3.md`) описывает провайдеров/настройки/согласие на ТЗ-уровне;
  `docs/BACKLOG.md` (IDEA-013) — обновлены аналитиком.

**Обратимость:** конфигурация локализована в секции `ai` и в модуле `crates/app/src-tauri/src/ai/`;
возврат к одиночному провайдеру — чтение одного элемента map. Замороженные контракты §13.2 и
контракт плагинов не затронуты (AI — не плагин, ADR-0021).

## 4. Отклонённые альтернативы

- **Оставить один фиксированный провайдер (`routerai.ru`).** Отклонён: продуктовое решение
  12.10.2026 требует пользовательских провайдеров; фиксированная точка не покрывает корпоративные
  шлюзы и локальные OpenAI-совместимые рантаймы.
- **npm-пакеты провайдеров (runtime `package` как в `opencode.json`).** Отклонён: в darmark нет
  JS-runtime и npm-экосистемы; `package` переосмыслен как **маркер протокола** (`openai-compatible`),
  а не npm-пакет. `canonical` (наследование каталога `models.dev`) **не переносится** — каталога нет,
  модели перечисляются явно.
- **Конфигурация только через переменные окружения (env-only).** Отклонён: лёгкому локальному
  редактору нужен **UI-редактор провайдеров** и персистентность в `config.json` (D11); `env` —
  **дополнительный** источник ключа, а не единственный.
- **Жёсткий хардкод `routerai.ru` в согласии и валидации.** Отклонён: согласие обязано называть
  **фактический** активный хост (§2.6 п. 15, §2.7 п. 17); иначе граница доверия вводит в
  заблуждение при пользовательских провайдерах.
- **Раздельные `settings.headerTimeout`/`settings.chunkTimeout` (как в `opencode.json`) сейчас.**
  Отклонён в MVP: SSE-парсер (ADR-0033) уже переживает паузы между чанками; одного
  `settings.timeout` достаточно, детали — открытый вопрос (§5).
- **Не-OpenAI протокол (Anthropic-compatible) в этой же схеме.** Отклонён **сейчас**: смешал бы
  протоколы за одним `settings.baseURL`; при появлении — **отдельный ADR** (ср. ADR-0032 §4).
- **Хранилище ключей в Windows Credential Manager/DPAPI.** **Отклонено** (сохраняется решение
  ADR-0032 §2.4 п. 9): избыточно для лёгкого редактора; ключи остаются в `config.json` с
  митигациями (маскирование, запрет логирования, права каталога).
- **Сетевые вызовы из TS.** Отклонён: нарушает CSP `default-src 'self'` (ADR-0032 §2.5 п. 11).
