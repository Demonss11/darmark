# ADR-0036. MCP-сервер darmark: in-memory транспорт, внутренний клиент, контрактный tool-слой

- **Дата:** 12.10.2026

## 1. Контекст

### 1.1. Проблема

ADR-0034 §2.5 фиксировал MCP как **inbound** (внешние клиенты, auth/consent/аудит) и выводил из MVP.
Продуктовое решение 12.10.2026 пересматривает рамку: MCP — **внутренний контрактный tool-слой**
для встроенного AI-ассистента (IDEA-016), клиент — только внутренний.

Нужно зафиксировать **транспорт/размещение** MCP-сервера и его контрактные рамки: что сервер
реализует (протокол по букве), где он исполняется (в процессе GUI), как связан с существующими
командами и песочницей, и что именно он даёт агенту (R1/R2 из ТЗ).

### 1.2. Что уже зафиксировано (не пересматривается)

- AI-рантайм — в процессе GUI, `ai.enabled` (ADR-0034 §2.1/§2.3).
- Сеть — только Rust-сторона; CSP `default-src 'self'` (ADR-0032 §2.5, ADR-0033).
- Согласие обязательно; санитайзер — на хосте (ADR-0030 §2.4, D7/§11).
- Провайдеры LLM — map в `config.json` (ADR-0035).
- Плагинная система: child-per-plugin, `mlua` вне GUI, `HOST_API_VERSION` (ADR-0021/0023/0027).
- D6 (≤6 МБ, size-gate); бюджет AI-клиента ≤1.0 МиБ (ADR-0033 §2.4).
- Замороженные контракты §13.2 — не меняются.

### 1.3. Почему решение пересматривается

TZ-MCP §2 фиксирует пересмотр рамки ADR-0034 §2.5: MCP — **внутренний tool-слой** для встроенного
ассистента. Модель доверия простая: единственный клиент, доверенный, в процессе.

---

## 2. Решение

**MCP-сервер реализуется как встроенная подсистема хоста (in-memory транспорт): протокол MCP по букве
(JSON-RPC 2.0 + семантика MCP) поверх внутрипроцессного канала. Сервер исполняется в процессе GUI
(`crates/app/src-tauri/src/mcp/`), состояние документов/плагинов живёт там же. Клиент — только
внутренний (встроенный AI-ассистент). MCP — контракт и сужение поверхности, не механизм принуждение.**

### 2.1. Транспорт и размещение

1. **Транспорт — in-memory (embedded):** JSON-RPC 2.0 + семантика MCP поверх внутрипроцессного
   канала. Нулевая OS-поверхность: не слушается порт, не создаётся child, не вводится новый
   бинарник. MCP-спека отделяет транспорт от протокола — протокол остаётся «настоящим».
2. **Размещение — в процессе GUI:** MCP-сервер — модуль `crates/app/src-tauri/src/mcp/`, как
   `DocumentStore` или `RenderCache`. Состояние документов, плагинов, настроек — общее с хостом;
   IPC-прокси не требуется.
3. **Клиент — только внутренний:** встроенный AI-ассистент (`aiPanel.ts` + `crates/app/src-tauri/src/ai/`)
   вызывает MCP-инструменты через tool-loop. Внешних клиентов, inbound-auth и аудита внешних
   вызовов — нет. MCP-клиент darmark к чужим MCP-серверам (outbound) — **не входит** (ср. ADR-0034 §4.3).
4. **Сетевые вызовы из TS запрещены:** in-memory канал не покидает процесс.

### 2.2. Контракт и сужение поверхности

5. **Протокол — по букве:** сервер реализует стандартные методы MCP (см. TZ-MCP §3.1). Ответы —
   по спецификации MCP.
6. **Первый срез — read-only контракты плагинов** (§3): 6 resources + 4 tools. Мутаций нет.
7. **MCP — контракт, не принуждение:** права/rev-guard/безопасность путей остаются в существующих
   командах (permissions, `Manifest::validate`, белый список директорий). MCP не создаёт второго
   источника истины для безопасности.
8. **Tool = тонкая обёртка** над существующей командой/CLI; никакой бизнес-логики в MCP (R4).
   Результат совпадает с прямым вызовом `plugin-cli`/`md-core` (AC-MCP-6).

### 2.3. Цель: результат, а не сервер

9. **Цель — результат, а не сервер:** контрактная ясность для агента (R1), наблюдаемость
   в журнале (R2), tool-loop (R6) — требования TZ-MCP §5.

### 2.4. Что не меняется

10. **Что не меняется:** сеть/HTTP-клиент/провайдеры (ADR-0032/0033/0035), CSP (ADR-0032),
    D6 (ADR-0033), инварианты ADR-0027, триггеры пересмотра ADR-0034 §2.6.

## 3. Первый срез: инвентарь

**Первый срез:** 6 resources + 4 tools (read-only контракты плагинов). Полный инвентарь — TZ-MCP §4.1–§4.2.

## 4. Отклонённые альтернативы

- **Внутренний tool-слой без сервера («MCP-подобный» слой, YAGNI).** Отклонён **заказчиком**:
  продуктовое решение 12.10.2026 требует **настоящий MCP-сервер** (протокол по букве), а не
  внутренний слой с похожим API. MCP — открытый стандарт; реализация «по букве» даёт совместимость
  с экосистемой инструментов и честную границу: клиент может быть заменён на внешний (при
  появлении кейса) без переписывания сервера. YAGNI-аргумент («клиент один, сервер не нужен»)
  отклонён как ограничивающий обратимость.
- **Loopback Streamable HTTP (сервер слушает `127.0.0.1`).** Отклонён: вводит OS-поверхность
  (открытый порт, хотя loopback), новый inbound-listener в процессе GUI, риск конфликта портов
  и вопросы firewall/антивируса на Windows. При этом состояние документов/плагинов всё равно
  живёт в GUI-процессе (TZ-MCP §1, п.6), поэтому транспорт не даёт реального преимущества
  размещения — только усложнение. Внутренний клиент не требует HTTP-рукопожатия.
- **stdio/headless (отдельный процесс без GUI, состояние через IPC-прокси).** Отклонён: тяжёл
  (второй процесс, прокси состояния, синхронизация), не нужен при единственном внутреннем клиенте
  и состоянии в GUI. Выделение в child — только по триггерам ADR-0034 §2.6 (тяжёлый AI, бюджет,
  «поставка без AI»).
- **Внешние клиенты / inbound.** Отклонён **рамкой 12.10.2026**: клиент — только внутренний.
  При появлении кейса — отдельный ADR (ADR-0034 §2.5, §4).

## 5. Последствия

**Положительные:**

- Нулевая OS-поверхность; минимальный прирост размера (≤0.1 МиБ).
- Состояние общее с хостом; нет IPC-прокси.
- Протокол остаётся «настоящим» — перенос на loopback/stdio без переписывания протокольного слоя.
- Контрактная ясность для агента (R1/R2, §2.3).
- CSP/D6/санитайзер/плагинные контракты — без изменений.

**Отрицательные / ограничения:**

- **MCP-код остаётся в дереве `darmark`:** `cargo tree -p darmark` содержит MCP-модуль; CI-инвариант
  «без MCP» не достигается (аналогично `reqwest`, ADR-0034 §3).
- **Внутрипроцессный канал — не граница доверия:** MCP-сервер не изолирован от GUI-хоста; при
  компрометации MCP-модуля (или клиента) злоумышленник получает доступ к состоянию хоста. Это
  осознанно: клиент внутренний и доверенный; граница доверия — на уровне процесса, а не модуля.
- **Инвариант «сервер в процессе GUI» держит обратимость:** при выделении в child появится
  прокси состояния — цена, зафиксированная как триггер ADR-0034 §2.6.
- **Инструменты — тонкие обёртки:** при ошибке адаптер (например, `plugin_test`) результат должен
  совпадать с прямым вызовом CLI (AC-MCP-6); дрейф схем и сигнатур контролируется контракт-тестом.

**Обратимость:** MCP-модуль локализован; перенос транспорта — рефактор модуля (§2.4).
