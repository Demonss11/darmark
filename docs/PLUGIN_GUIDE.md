# Как подключить свой Lua-плагин в darmark

Это пошаговое руководство для пользователя: как положить свой `.lua`-плагин, включить его,
править и перезагружать без пересборки приложения. Полный референс функций — `docs/PLUGIN_API.md`;
архитектура — `docs/adr/0023-plugin-runtime.md`, нормативная спецификация — `docs/DESIGN_DOC.md`.

Плагин исполняется в **отдельном процессе** (не внутри редактора): его сбой или зависание не
роняют приложение, но и доступа к DOM у плагина нет — только host-функции и события.

---

## 1. Куда класть плагин

Плагин — это **каталог** в папке плагинов:

```text
%APPDATA%\darmark\plugins\my-plugin\
├── plugin.json      # манифест: id, имя, версия, точка входа, разрешения
└── main.lua         # код плагина
```

Откройте папку плагинов: `Win+R` → вставьте `%APPDATA%\darmark\plugins` → Enter.
(Если папки нет — создайте её или просто запустите darmark один раз.)

> Каталог плагинов можно переопределить переменной окружения `DARMARK_PLUGINS_DIR`
> (полезно для переносимой установки/тестов).

Затем откройте в darmark **боковую панель «Плагины»** (иконка плагина на левой панели-rail).
Плагин появится в списке при следующем запуске приложения (автопересканирование каталога «на лету»
в текущей версии не выполняется) и включён по умолчанию.

---

## 2. Минимальный плагин за 2 файла

`%APPDATA%\darmark\plugins\hello\plugin.json`:

```json
{
  "id": "hello",
  "name": "Hello",
  "version": "1.0.0",
  "api_version": 1,
  "entry": "main.lua",
  "permissions": ["ui:statusbar"]
}
```

`%APPDATA%\darmark\plugins\hello\main.lua`:

```lua
function on_activate(ctx)
  host.show_message("Привет из плагина hello!")
end

function on_deactivate(ctx) end
```

Сохраните файлы, откройте панель **Плагины** — увидите `hello` со статусом «активен».
Сообщение плагина появится в статусбаре внизу окна.

**Правила манифеста** (полный контракт — `docs/PLUGIN_API.md` §1):
- `id` — только строчные латинские буквы, цифры, `-` и `_`; совпадает с именем каталога (рекомендуется);
- `entry` — имя `.lua`-файла **без путей** (`main.lua`); размер исходника ≤ 1 МиБ;
- `api_version` — сейчас `1`; большее значение хост отклонит;
- `permissions` — список разрешений (см. §5), `"[]"` — если ничего не нужно.

---

## 3. Правка и перезагрузка без перезапуска

1. Откройте `main.lua` в любом редакторе, измените, сохраните.
2. В панели **Плагины** нажмите **«Перезагрузить»** рядом с плагином.
3. Плагин запустится заново с новым кодом — перезапускать darmark не нужно.

Если в коде ошибка, статус станет «ошибка» с текстом; исправьте и нажмите «Перезагрузить» снова.
После **3 падений подряд** плагин уходит в **карантин** (автоотключён) — включите его вручную
тумблером, когда исправите.

## 4. Пример: события + статусбар (кратко)

Плагин подписывается на изменение документа и показывает число слов:

```json
{
  "id": "my-word-count",
  "name": "Мой счётчик слов",
  "version": "1.0.0",
  "api_version": 1,
  "entry": "main.lua",
  "permissions": ["document:read", "ui:statusbar"]
}
```

```lua
function on_activate(ctx)
  ctx.subscribe("document:changed", function(name, payload)
    local len = host.get_document_len(payload.doc_id)
    if len then
      -- читаем документ циклом окон (лимит одного вызова — 1 МиБ)
      local text = host.get_document_range(payload.doc_id, 0, len)
      local n = 0
      for _ in text:gmatch("%S+") do n = n + 1 end
      host.show_message("Слова: " .. n)
    end
  end)
end
```

**Полный листинг с чтением больших документов циклом окон — `docs/PLUGIN_API.md` §7.**

Что здесь важно:
- `document:changed` **не несёт текст** — только `doc_id` и `rev`; текст плагин читает сам
  (`get_document_range`), чтобы не гонять большие строки;
- `ctx.subscribe` возвращает функцию-отписку; при деактивации от подписок нужно избавляться.

---

## 5. Разрешения

| Разрешение | Что открывает |
|---|---|
| `document:read` | чтение текста (`get_document_len/range/version/text`) |
| `document:write` | правка документа (`apply_edit`) |
| `view:create` | регистрация своего представления |
| `view:modify` | запись HTML представления (`set_view_content`) |
| `ui:statusbar` | сообщения в статусбар (`show_message`) |

**Полная таблица с привязкой к функциям — `docs/PLUGIN_API.md` §1.**

- `filesystem:*` и `network` **не поддерживаются** — плагин не имеет доступа к файлам напрямую
  и к сети. Экспорт HTML делается через `host.export_html` (открывается системный диалог
  сохранения — согласие даёт сам пользователь).
- Панель **Плагины** показывает, какие разрешения запрашивает плагин, и предупреждения о
  границе безопасности.

## 6. Свой собственный «предпросмотр» (плагинное представление)

Плагин может добавить свою вкладку в панель предпросмотра (тир-1 представление).

`plugin.json` — объявляем view и разрешения:

```json
{
  "id": "my-preview",
  "name": "Моё представление",
  "version": "1.0.0",
  "api_version": 1,
  "entry": "main.lua",
  "permissions": ["document:read", "view:create", "view:modify"],
  "contributes": {
    "views": [{ "kind": "my-preview", "title": "Моё представление", "tier": 1 }]
  }
}
```

`main.lua`:

```lua
-- view_id всегда "<id_плагина>:<kind>"
local VIEW = host.plugin_id .. ":my-preview"

function on_activate(ctx)
  ctx.subscribe("document:changed", function(name, payload)
    local id = payload.doc_id
    local len = host.get_document_len(id)
    local text = host.get_document_range(id, 0, len)
    -- HTML санитизируется хостом; кнопка с data-p-<id>-action вернёт клик в on_action
    local html = "<p>Символов: " .. #text .. "</p>"
      .. '<span data-p-my-preview-action="ping">нажми меня</span>'
    host.set_view_content(VIEW, html)
  end)
end

function on_action(view_id, action, payload)
  if action == "ping" then
    host.set_view_content(view_id, "<p>Поймал клик!</p>")
  end
end
```

- Клик по элементу с `data-p-<plugin_id>-action="..."` (и необязательным
  `data-p-<plugin_id>-payload`) возвращается в `on_action`.
- HTML плагина проходит **ту же санитизацию**, что и предпросмотр: теги/атрибуты по allowlist,
  сохраняются только атрибуты `data-p-<plugin_id>-*`; скрипты, `onerror`, `javascript:` вырезаются.
- Нативный предпросмотр остаётся вкладкой по умолчанию; ваша появляется рядом.

## 7. Отладка

```text
darmark-plugin-host --self-test <plugin.lua>   # загрузить+активировать, лог в stderr
darmark --debug-plugin <path>                  # запуск плагина без %APPDATA% (debug-сборка)
```

`--debug-plugin` не требует копировать плагин в `%APPDATA%` — путь может быть любым.

**Подробности про stdio-конверт и режимы `--serve-plugin` — `docs/PLUGIN_API.md` §6.**

Статусы в панели «Плагины»: «активен», «остановлен», «ошибка» (с текстом), «карантин».
Ошибка не роняет приложение.

---

## 8. Частые ошибки

| Симптом | Причина / что делать |
|---|---|
| Плагина нет в списке | Ошибка манифеста: неверный `id` (не строчные/есть пробелы), отсутствует `entry` или `.lua`-файл, `api_version` > 1, размер исходника > 1 МиБ. Проверьте имена файлов и каталог. |
| Статус «ошибка»: `permission_denied` | Не хватает разрешения — добавьте его в `permissions` и перезагрузите. |
| `set_view_content` не работает | Нет `view:modify`, либо `view_id` не совпадает с `<id_плагина>:<kind>` из `contributes.views`. |
| Клик по кнопке в view ничего не делает | Атрибут должен быть `data-p-<plugin_id>-action`, а `on_action` — объявлен. |
| Сообщение не видно | Для `show_message` нужно разрешение `ui:statusbar`. |
| Плагин «зависает» | Долгие вывы снимаются watchdog'ом; не делайте бесконечных циклов в обработчиках. |
| Карантин после правок | Было 3 падения подряд — включите плагин тумблером вручную после исправления. |

---

## 9. Границы системы

**Можно:** читать и править документ, показывать сообщения, строить своё представление,
подписываться на события, исполнять команды, экспортировать HTML через нативный диалог,
хранить свои настройки, писать логи.

**Нельзя:** работать с сетью, напрямую читать/писать файлы, рисовать в DOM редактора,
менять нативные панели/меню/тулбар, пользоваться `os`/`io`/`require`/`load`/`coroutine`
(песочница). Данные приложения и плагина разделены границей процесса.

Настройки плагина (`host.get_setting`/`host.set_setting`) **не реализованы**: вызов возвращает
`(nil, { code = "not_implemented" })`. Пока храните состояние прямо в Lua (локальная таблица живёт,
пока плагин запущен) или в константах файла.
