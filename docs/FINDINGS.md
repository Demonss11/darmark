# FINDINGS — замеры прототипов и спайков darmark

> **Назначение.** Источник чисел (размеры, память, латентность, стоимость) для решений проекта.
> Нормативная спецификация чисел не содержит: трассировка решений — `docs/DESIGN_DOC.md` §16 и
> ADR в `docs/adr/`; **источник чисел — этот файл** (D15).
> **Происхождение замеров.** Windows x86_64-msvc, rustc 1.99, релизный профиль
> `[profile.release]` (`opt-level="s"`, LTO, strip, `panic="abort"`); где нужен `unwind` —
> `[profile.proto]`. Стенды (`crates/*-spike`) и прототип `proto/lua-plugin-host` в продукт не
> входили и **удалены после реализации**; их блоки перенесены в продуктовые `plugin-host`/
> `plugin-core`, упоминания их файлов ниже — исторические.
> **Форма записей.** «гипотеза → замер → вывод» (D15); нумерация фактов `F1–F58` сквозная.
> **Статус.** Реализованные замеры свёрнуты в «Индекс закрытых фактов» (для трассируемости
> `F`-номеров); открытые оговорки — ниже.

---

## 1. Что не проверено (предел прототипа)

Пункты прототипной очереди, оставшиеся непроверенными (на принятые решения не влияют):

- range/delta-API против N1 (латентность) — проверено только по **памяти** (F34), не по латентности.
- P3: `MemoryError` на `hog.lua`; `spin.lua` под лимитом; M6 на `count.lua`; M7 (два инстанса в одном процессе).
- P5: host-функции на заглушке + permissions; возврат ошибок Lua-значением.
- P6: внешние строки 5.5 (M9).
- P2: полный M1 (`strip`, baseline именно прототипа).
- API-референс 5.5: `global`, `table.create`, отличия C API (в т.ч. `LUA_REGISTRYINDEX`).

## 2. Открытые вопросы и ограничения

### 2.1. Источник метрик ОЗУ/CPU (спайк, ADR-0031)

**Что не проверено стендом (оговорки):**

1. **WebView2/event-loop** напрямую не тестировался — стенд мерил только стоимость WinAPI/`sysinfo`,
   а не влияние на отзывчивость UI главного процесса (AC-19 остаётся на ручную проверку в GUI
   при реализации).
2. Замеры — на **idle** child'ах: реальные плагины с активным RSS/Lua дадут другие значения самих
   метрик, но не стоимости вызова.
3. CPU-время процесса **квантуется планировщиком** (~15.6 мс), поэтому прямой `[POLL]` — верхняя
   граница, а рабочая оценка — производная от F49.
4. `GetProcessHandleCount` требует `PROCESS_QUERY_INFORMATION` (для наших child'ов доступно; для
   чужих процессов может потребоваться повышенное право) — в UI хендлы только при превышении порога.

**Независимая проверка стенда (оговорки, 11.10.2026):**

- **F49 — «порядок величины», не точный p50.** Числа WinAPI нестабильны от прогона к прогону
  (разброс ~×2); подтверждён порядок «µs против мс» (≥×100), абсолют «×375» — оптимистичная граница.
- **F50 завышено для `sysinfo`.** Прямой квантованный замер для `sysinfo` даёт 0.31–1.09% (на n=5
  в 5 из 6 прогонов > AC-17 0.5%); производная от F49 указывает, что реальный CPU, вероятно, всё же
  проходит AC-17, но **прямой замер этого не доказывает**. Для WinAPI AC-17 — с большим запасом.
- **F52 усилена оговорка (PID reuse).** Открытие по «голому» PID может **молча** вернуть метрики
  **чужого** процесса (не `Err`, значит обработка ошибок F51 не спасает). Риск снят владением
  процессом (PID из живого `Supervisor`) и низкой частотой спавнов; для произвольных чужих PID
  нужен `start_time`/guard.

### 2.2. AI-клиент (спайк, ADR-0032/ADR-0033)

**Что не проверено стендом (оговорки):**

1. **Живой запрос к `routerai.ru`** — не выполнялся (нет `ROUTERAI_API_KEY`); проверены только
   парсер и mock-сервер. Реальный роутер может отличаться форматом чанков (`usage` в последнем
   чанке, `reasoning_content`, собственные коды/квоты).
2. **Маргинальный размер в продукте** — не измерен: замеры standalone; в `darmark` уже присутствуют
   `tokio`, `url`, `http`, `serde_json`, поэтому реальный прирост `reqwest` **меньше** дельты стенда,
   а вклад `rustls`-стека (новый целиком) — близок к дельте. Точный размер требует сборки `darmark`
   с AI-модулем (отдельная задача).
3. **30-секундный таймаут / rate-limit / маппинг ошибок** — заданы номинально; поведение под
   `429`/`5xx`/офлайн не измерялось.
4. **Интеграция с UI Tauri** — не проверялась: blocking-`ureq` требует выноса с UI-потока
   (`async_runtime::spawn_blocking`) и доставки чанков событиями; `reqwest` — async-нативно.

## 3. Индекс закрытых фактов

Свёрнутые (реализованные) замеры — по диапазонам, чтобы любой цитируемый `F`-номер оставался
разрешимым. Границы уточнены по фактическому составу файла.

- **F1–F15** — прототип Lua-хоста, in-process (`panic="abort"`/`unwind`, C-hook, safe-`pcall`,
  транспорт) → ADR-0021 (изоляция процесса).
- **F16–F38** — вынос Lua в процесс: C-транспорт, P9 (M10–M12), закрытие D16 (per-call watchdog,
  range/delta, устойчивость протокола, карантин, граница изоляции) → ADR-0021/0023.
- **F39–F44** — продуктовая плагинная система H2 (рантайм, permissions, события, настройки,
  `view:create`, мёртвый код) → ADR-0022/0023.
- **F45–F48** — локальный каталог плагинов H3, Фаза 2a (`--repo`, `remove`, `link`, целостность/
  подпись отложена в Фазу 2b) → ADR-0026.
- **F49–F54** — источник метрик ОЗУ/CPU → ADR-0031 (WinAPI, `windows`-crate).
- **F55–F58** — AI-клиент (HTTP+TLS, SSE) → ADR-0032/0033 (`reqwest`+SChannel, SSE).
