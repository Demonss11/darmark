# FINDINGS — замеры прототипов и спайков darmark

> **Назначение.** Источник чисел (размеры, память, латентность, стоимость) для решений проекта.
> Нормативная спецификация чисел не содержит: трассировка решений — `docs/DESIGN_DOC.md` и
> ADR в `docs/adr/`; **источник чисел — этот файл** (D15).
> **Происхождение замеров.** Windows x86_64-msvc, rustc 1.99, релизный профиль
> `[profile.release]` (`opt-level="s"`, LTO, strip, `panic="abort"`); где нужен `unwind` —
> `[profile.proto]`. Стенды (`crates/*-spike`) и прототип `proto/lua-plugin-host` в продукт не
> входили и **удалены после реализации**; их блоки перенесены в продуктовые `plugin-host`/
> `plugin-core`, упоминания их файлов ниже — исторические.
> **Форма записей.** «гипотеза → замер → вывод» (D15); нумерация фактов `F1–F60` сквозная.
> **Статус.** Реализованные замеры свёрнуты в «Индекс закрытых фактов» (для трассируемости
> `F`-номеров); открытые оговорки — ниже.

## 1. Открытые вопросы и ограничения


### 1.5. MCP-сервер

**Контекст.** MCP переосмыслен из inbound-сервера внешних клиентов (ADR-0034 §2.5) во **внутренний
контрактный tool-слой** (ADR-0036: in-memory транспорт, клиент — встроенный AI). Реализован **План 1**:
крейт `mcp-core` (JSON-RPC 2.0 + семантика MCP), чистый крейт `plugin-catalog`, модуль `mcp` в
`src-tauri` (4 tools + 6 resources, журнал вызовов, белый список путей). Tool-loop ассистента — **План 2**
(зависит от поддержки tool-calling провайдером).

**Подтверждённые структурные факты (без `F`-номеров — это не замеры):**

- **`mlua` вне GUI сохранён:** `cargo tree -p darmark | Select-String mlua` пусто и после подключения
  MCP. Каталог плагинов вынесен из `plugin-cli` в чистый крейт `plugin-catalog` (deps: `plugin-core`,
  `serde_json`), чтобы не сломать guard ADR-0021/D6 через транзитивную зависимость `plugin-host` → `mlua`.
- **Тесты после Плана 1:** `md-core`, `mcp-core` (26), `plugin-catalog` (21), `darmark` (268 lib +
  13 контрактных `mcp_contract`, 1 `debug_plugin`); `cargo fmt --check` и `clippy -D warnings` — чисто;
  `npm run build` (tsc strict) — зелено.

**Открытые оговорки и не-блокеры (заведены; для MVP не критичны):**

1. **Tool-loop не реализован (План 2).** AC-MCP-5/14 (ассистент сам вызывает tools; результат —
   «данные, не инструкции») не закрыты: зависят от tools/function-calling провайдера.
2. **Белый список путей: разрешён весь системный temp** (TZ-MCP R3) — сужение до `darmark-ai-validate-*`
   сломало бы валидацию плагинов из произвольных temp-каталогов. Клиент доверенный, изоляция
   (`canonicalize` + `starts_with` + отказ на reparse) сохранена.
3. **JSON-RPC-упрощения:** поле `jsonrpc` не валидируется; notification получает ответ с `id: null`;
   `"arguments": null` не нормализуется в `{}`. Для внутреннего клиента не критично.
4. **Шаблонный ресурс `darmark://plugins/{id}/manifest`** читается через `resources/read`; отдельный
   `resources/templates/list` (есть в спеке MCP) не вводится.
5. **Гигиена/мелочи:** `manifest_errors` стало `#[cfg(test)]`; `sanitize_text` — prefix-replace без границ
   пути; тесты мутируют глобальные env без лока; цикл `AppHandle` в managed state (осознан); дублирование
   `ToolError`/`ResourceError`; часть тестов `mcp-core` тавтологичны.
6. **HIGH — `create_link` (plugin-catalog): небезопасная передача путей в `cmd /c mklink`.**
   `Command::new("cmd").arg("/c").arg("mklink")…` идёт через `cmd.exe`, который разбирает аргументы
   как командную строку, поэтому `&`, `|`, `^`, `%` в пути к каталогу плагина будут интерпретированы
   как операторы оболочки. `target` безопасен (`is_safe_id`: `[a-z0-9-_]`), но `source` — это
   `canonicalize(repo.join(&raw.path))`, где `is_safe_relative` отклоняет только пустое значение, `:`,
   абсолютность и не-`Normal` компоненты. Имя вида `x&calc.exe` — валидный `Component::Normal`,
   проходит проверку; если в нём лежит валидный `plugin.json`, `read_manifest` его примет.
   **Эксплуатация:** из CLI (`darmark-plugin link`) при наличии такого каталога в репозитории —
   выполнение произвольной команды в неизолированном процессе CLI (вне песочницы плагинов и Job Object).
   **Направления исправления:**
   1. Перейти на `CommandExt::raw_arg` (убирает передачу через командную строку целиком);
   2. Либо сузить `is_safe_relative` белым списком символов `[A-Za-z0-9._/-]` (ломает юникодные/пробельные
      пути и дублирует модель безопасности путей из `plugin_core`);
   3. В модульный doc вернуть **правдивую** формулировку: «Единственное место, где крейт запускает
      процесс, — `create_link`; пути к нему обязаны быть провалидированы `is_safe_id`/`is_safe_relative`».
   **Статус:** задача на исправление (вне рамок чистки комментариев).

## 2. Индекс закрытых фактов

Свёрнутые (реализованные) замеры — по диапазонам, чтобы любой цитируемый `F`-номер оставался
разрешимым. Границы уточнены по фактическому составу файла.

- **F1–F15** — прототип Lua-хоста, in-process (`panic="abort"`/`unwind`, C-hook, safe-`pcall`,
  транспорт) → ADR-0021 (изоляция процесса).
- **F16–F38** — вынос Lua в процесс: C-транспорт, P9 (M10–M12), закрытие D16 (per-call watchdog,
  range/delta, устойчивость протокола, карантин, граница изоляции) → ADR-0021/0023.
- **F39–F44** — продуктовая плагинная система H2 (рантайм, permissions, события, настройки,
  `view:create`, мёртвый код) → ADR-0022/0023.
- **F45–F48** — локальный каталог плагинов H3, Фаза 2a (`--repo`, `remove`, `link`, целостность/
  подпись отложена в Фазу 2b) → ADR-0026.
- **F49–F54** — источник метрик ОЗУ/CPU → ADR-0031.
- **F55–F58** — AI-клиент (HTTP+TLS, SSE) → ADR-0032/0033.

**F59 — латентность range/delta-API против N1** (закрытие пункта 2.1 прототипной очереди).
Гипотеза: чтение окнами дороже одного полного чтения из-за N round-trip'ов через границу процесса.
Замер (`crates/plugin-host/tests/latency_bench.rs`, реальный child-процесс, документ ровно 1 МиБ,
release, медиана 5 прогонов):

- N1 (`get_document_text`, один ответ ~1 МиБ): **≈2.3–2.5 мс**;
- range/delta (`get_document_range`, 16 окон по 64 КиБ, как `WINDOW` в примерах плагинов):
  **≈2.9–3.1 мс**;
- отношение range/N1: **≈1.2** (стабильно между прогонами).

Вывод: оверхед RPC при чтении окнами существует, но мал (≈1.2×); на документе ≤ фрейма обе модели
сопоставимы, и выбор range/delta оправдан **памятью**, а не скоростью — полное чтение копировало бы
документ в каждый child-процесс (F30). Проверено по латентности, а не только по памяти (F34). →
ADR-0021/0023.

**F60 — сценарии песочницы P3** (закрытие пункта 2.2 прототипной очереди).
Гипотеза: продуктовый runtime (Job Object + watchdog, ADR-0021/0023) воспроизводит сценарии
прототипа `proto/lua-plugin-host` (hog/spin/count/M6/M7).
Замер (`crates/app/src-tauri/src/plugins/tests/supervisor.rs`, реальный child-процесс, debug):

| Сценарий | Фикстура | Ожидание | Результат |
|---|---|---|---|
| hog.lua (1 МиБ в цикле) | `tests/plugins/hog.lua` | Job Object RSS-лимит (64 МиБ) срабатывает, child снят, GUI жив | `activate()` → `crashed`/`timeout` (код зависит от того, кто раньше — Job или watchdog) |
| spin.lua (`while true do end`) | `tests/plugins/spin.lua` | watchdog снимает child по прогресс-таймауту (нет кадров от child) | `activate()` → `timeout` |
| count.lua (M6: оверхед hook) | `tests/plugins/count.lua` | host-call `get_document_text` работает, результат корректный | `activate()` → `Ok` |
| M7 (два инстанса в одном процессе) | — | изоляция глобалов между инстансами | **неактуально**: продуктовая 模型 child-на-плагин (ADR-0021) исключает общий процесс; изоляция глобалов обеспечена процессной границей |

Вывод: P3 закрыт. hog/spin/count воспроизведены в продуктовом runtime (Job Object + watchdog
вместо `set_memory_limit`/`set_hook` прототипа); M6 (оверхед instruction-hook) неактуален —
hook не переносился (ADR-0021 §2.4), оверхед RPC измерен в F59 (≈1.2×); M7 неактуален —
модель child-на-плагин. → ADR-0021/0023.

**F61 — прогон песочницы через MCP `plugin_test`** (закрытие оговорки о покрытии песочницы через MCP).
Гипотеза: `plugin_test` через MCP покрыт только схемой (`tests/mcp_contract.rs`), а исполнение
Lua в песочнице Rust-тестом не проверяется.
Замер (`crates/app/src-tauri/src/ai/plugin_harness/tests/mcp.rs`, реальный child-процесс, debug):

| Сценарий | Фикстура | Ожидание | Результат |
|---|---|---|---|
| Валидный плагин | `plugin.json` + `main.lua` с `on_activate` → `print("ok")` | Песочница исполняет Lua, `ok: true`, `errors: []` | `plugin_test` → `ok: true`, `errors: []` |
| Невалидный манифест | `plugin.json` с пустым `id` | Валидация отсекает до песочницы, `ok: false`, непустой `errors` | `plugin_test` → `ok: false`, `errors: ["manifest: …"]` |

Вывод: `plugin_test` через MCP покрыт Rust-тестом с реальным прогоном песочницы (child-хост
собирается внутри теста, env не мутируется). → ADR-0034/ADR-0036.

**F62 — конверт события `log-entry` прод-стока MCP** (закрытие оговорки о непокрытом `app_log_sink`).
Гипотеза: конверт `log-entry {level,category,message}` проверяется лишь до границы стока;
`AppHandle` без Tauri-runtime не создать, поэтому прод-сток не покрыт Rust-тестом.
Замер (`crates/app/src-tauri/src/mcp/tests.rs`, mock `LogEmitter`, без Tauri):

| Проверка | Ожидание | Результат |
|---|---|---|
| Имя события | `log-entry` | `log-entry` |
| Поле `level` | строка `"info"` | строка `"info"` |
| Поле `category` | строка `"system"` | строка `"system"` |
| Поле `message` | строка, дословно равная тексту стока | совпадает |

Вывод: `app_log_sink` параметризован трейтом `LogEmitter` (прод — `AppHandle`, тест — mock);
конверт `log-entry` покрыт без Tauri-runtime, прод-поведение не изменилось. → ADR-0036.

**F63 — источник каталога плагинов не зависит от CWD** (закрытие оговорки о `catalog_repo()`).
Гипотеза: `catalog_repo()` разрешался от рабочего каталога процесса, поэтому в упакованном
приложении tool/resource возвращали ошибку (CWD произволен).
Изменение (`crates/app/src-tauri/src/mcp/mod.rs`): `catalog_repo(data_dir: &Path)`;
приоритет env `DARMARK_PLUGIN_REPO` → `discover_repo(data_dir)` → `data_dir/plugins`.
`build_registry` берёт `SettingsStore::data_dir()` — единый каталог данных приложения
(`%APPDATA%/darmark`, DESIGN_DOC D8); каталог «запекается» в обработчики при
сборке реестра, на пути чтения CWD не используется.

**Обоснование (Вариант B):** `app.path().app_data_dir()` возвращает `%APPDATA%/dev.darmark.app`
(по Tauri-identifier) — второй, нигде не используемый корень. `SettingsStore::data_dir()`
возвращает `%APPDATA%/darmark` — тот же каталог, который сканирует рантайм (`plugins_root()` /
`plugins_dir()`), куда ставит `--dest` (ADR-0026), и где живут настройки (ADR-0032/0035).
Вариант B сводит MCP к той же области, что и остальное приложение, и устраняет разрыв:
`plugin_catalog_list` / `darmark://plugins/*` указывают на каталог, чьи плагины
`plugin_test` / `plugin_validate` могут протестировать через `ensure_plugin_path_allowed`.

**Dev-следствие:** автопоиск репозиторного `examples/plugins/` через CWD более недоступен —
`discover_repo` от `%APPDATA%/darmark` репозиторий не находит. Штатный механизм dev —
env `DARMARK_PLUGIN_REPO` (приоритетнее автопоиска, ADR-0026 §2.4); он уже используется
тестами (`mcp/tests.rs`, `mcp_contract.rs`).

Замер (`mcp/tests.rs`, debug):

| Проверка | Ожидание | Результат |
|---|---|---|
| env задан | env-путь важнее `data_dir` | env-путь |
| env нет, есть `<data_dir>/plugins/index.json` | автопоиск находит каталог | `<data_dir>/plugins` |
| env нет, каталога нет, CWD содержит свой `plugins/index.json` | fallback `<data_dir>/plugins`, CWD игнорируется | `<data_dir>/plugins` |

Вывод: `catalog_repo()` не зависит от CWD (ни один prod-путь не читает `current_dir`);
приоритет env > автопоиск > fallback подтверждён тестом, включая смену CWD;
источник — единый каталог данных приложения, согласованный с рантаймом. → ADR-0026, ADR-0036.
