# Frontend mdedit (vanilla TS + Tauri v2)

Определяющее свойство проекта: **фреймворка нет**. Никаких React/Vue/Svelte, никаких
React Query / Zustand / Tailwind / styled-components, никаких хуков и компонентов —
это тупики, в которые этот код нельзя тащить. Модель прямая: один HTML-файл, ES-модули,
состояние — обычные переменные модуля и стейт-фабрики (`createDocStore`, `createEditorView`).

Второе определяющее свойство: «API» проекта — не HTTP, а Tauri IPC. Локальные вызовы
`#[tauri::command]`, которые возвращают значение или отклоняют промис. **Нет сети, нет
задержки, нет серверного состояния.** React Query / SWR / TanStack, axios-интерцепторы,
retry с экспоненциальной задержкой, дедупликация in-flight-запросов, optimistic-обновления
с откатом — всё это решает проблемы ненадёжного канала, которого здесь нет. Не приносить в код.

Перед правкой прочитай цель в `tasks/TZ-*.md` (порядок чтения — в `.kodarules`).
Если задача только про фронтенд — `md-core` и `src-tauri` не трогай.

## 1. Жёсткие рамки

| Рамка | Следствие для кода |
|---|---|
| CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https: asset: http://asset.localhost` (`tauri.conf.json`) | нет CDN-скриптов, нет `eval`/`new Function`, нет инлайн-`<script>`. Инлайн-`style` разрешён. Внешних HTTP-вызовов нет и не будет |
| Зависимости — только с явного согласия пользователя | npm-пакет не ставится «чтобы было удобнее». Нет пакета — пиши на API браузера |
| `strict` + `noUnusedLocals` + `noUnusedParameters` + `noEmit` (`tsconfig.json`) | неиспользуемая переменная валит сборку; удаляй, а не подавляй |
| Тяжёлые вычисления и владение документом — на Rust (`md-core` + `DocumentStore`) | парсинг Markdown во фронтенде не появляется; фронтенд рендерит и украшает |
| WebView2 (Chromium), target `es2021` | современные API браузера доступны, полифилы не нужны; фичи только-только из свежих Chrome — не использовать |

## 2. Карта кода (`crates/app/src/`)

- **`main.ts`** — композиционный корень: собирает `docStore` + `editorView` и связывает их с
  предпросмотром, инспектором, тулбаром, статус-строкой и заголовком окна. Команды файла,
  горячие клавиши, `onCloseRequested`, стартовый документ.
- **`docStore.ts`** — TS-проекция Rust-стора (D5): текст, ревизия, путь, dirty. Чистый модуль
  без DOM: ввод приходит из `editorView`, HTML уходит в `onRender`. Дебаунс IPC-рендера,
  защита от гонки ответов, подписки.
- **`editorView.ts`** — тир-2 представление `textarea`. `editor.value` — отображение проекции,
  не источник истины.
- **`tables.ts`** — Excel-подобные сортировка/фильтры поверх `<table>`. Публичный контракт:
  `enhanceTables(root)`, `attachMenuAutoClose(scroller)`.
- **`tauri.ts`** — все обращения в Rust: тонкие типизированные обёртки над `invoke`. Ни один
  другой модуль `invoke` напрямую не импортирует.
- **`style.css`** — все стили, один файл, переменные в `:root` + `prefers-color-scheme`.
- **`index.html`** — каркас `#app` → `#toolbar` / `#panes` (`#editor`, `#preview`) / `#statusbar`.

## 3. IPC с Rust: слой запросов

`tauri.ts` — единственное место, где импортируется `invoke`. Новый вызов — функция здесь,
иначе контракт IPC перестаёт быть видимым в одном месте:

```ts
export function updateDocument(id, text, mapped = false): Promise<RenderResult> {
  return invoke<RenderResult>("update_document", { id, text, mapped });
}
```

- `invoke<T>(cmd, args)` — из `@tauri-apps/api/core`; `T` и имя команды обязаны совпадать
  с `#[tauri::command]` в `src-tauri/src/lib.rs`.
- Имена аргументов Tauri приводит из camelCase (`defaultPath` → `default_path`). Расхождение
  проявляется не ошибкой типов, а пустым значением в Rust — сверять с Rust-сигнатурой.
- Возврат `Option<T>` на Rust-стороне = `T | null` в TS. Отмена диалога — это `null`,
  а не ошибка: `if (typeof selected !== "string") return`.
- Тип `T` задавай по факту сериализации (`serde`-представление enum/`Option` = объявление в TS).
- Различай контракты. `open_document`/`save_document` — async-команды с `Result<_, CommandError>`:
  отклонённый промис = реальная отказка, текст сформулирован на Rust-стороне.
  `update_document`/`render_document` возвращают `Result<RenderResult, CommandError>` — ошибка
  только при неизвестном `id` или сбое IPC-канала; «markdown не распарсился» ошибкой не бывает.
- Файловые диалоги живут на Rust-стороне/плагине dialog: выбранный каталог «запоминается»
  разрешённым (asset-scope), не доверяя фронтенду. Не обходи это подстановкой пути строкой.

### Что заменят собой обычные паттерны

| Обычный паттерн | В mdedit |
|---|---|
| axios/fetch-обёртка с интерцепторами | `tauri.ts`: тонкие функции без логики |
| Retry + backoff для транзиентных сбоев | нет транзиентности сети. Сбой FS (файл заблокирован, нет прав) повторять бессмысленно — показать причину в статус-строке |
| Дедупликация in-flight-запросов | не нужна: вызовы локальные. Дорогой рендер ограничен debounce 120 мс |
| SWR / кэш серверного состояния | кэш рендера `(mapped, rev)` и флаг `RenderResult.changed` — на Rust-стороне; TS своего `lastRenderedHtml` не ведёт |
| `AbortController` для отмены | у `invoke` нет `signal`: отменить нельзя, только проигнорировать. Страж порядка — `rev` и сверка `id` (см. §4) |
| Optimistic update с откатом | буфер `docStore.text` обновляется синхронно вводу; «откатывать» нечего, `dirty` — производный флаг |
| Global error boundary, тосты | `flash()` в статус-строке (самоочищается через 4 с) |
| Loading-спиннер | не нужен при локальном IPC; длинных операций нет |
| Пагинация / infinite scroll | документ целиком в памяти |

## 4. Рендер предпросмотра — инварианты

Ломать нельзя; каждый пункт закрыл реальный баг:

1. **Дебаунс 120 мс** (`schedule` в `docStore`) — иначе IPC на каждое нажатие клавиши.
2. **`flush()` перед save** — гасит таймер и отправляет текст в Rust до записи; ошибка пробрасывается.
3. **Защита от гонки** — `applyRes` отбрасывает ответ со `rev < lastRev`; `pushText`/`reload`
   сверяют `id !== st.id` после await (документ сменился, пока ждали).
4. **`RenderResult.changed`** — HTML не изменился → DOM не трогается. Иначе на каждом дебаунсе
   сбрасывались бы сортировка, фильтры и фокус внутри таблиц.
5. **`enhanceTables` в `try/catch`** (`onRender`) — украшение таблиц не роняет рендер: при
   исключении остаётся читаемый HTML, причина уходит в `flash()`.
6. **Ошибка рендера** — обнулить `lastRev = -1` (иначе следующий идентичный HTML даст
   `changed:false` и ошибка «прилипнет» к экрану) и сообщить через `onStatus`.
7. `preview.innerHTML = res.html` — единственный источник HTML это `md-core`
   (CommonMark+GFM + санитайзер). Свою сборку HTML из сырого текста во фронтенде не делать.
8. Внешние ссылки: делегированный `click` на `#preview`, `https?:` → `preventDefault()` +
   `openUrl(href)` из `@tauri-apps/plugin-opener` (не `window.open` — обходит CSP).

## 5. Обработка ошибок

Три уровня, у каждого свой способ показать проблему:

1. **Команда файла** (`openFile`, `saveFile`, `saveAs`) — `try/catch` вокруг вызова, текст в
   `flash()` через `errorMessage(e)`. Отказку формирует Rust (`CommandError { code, message }`):
   файл не найден, не-UTF-8, больше `MAX_FILE_SIZE` (10 МБ). Текст уже точный и человекочитаемый
   — показывать как есть, не подменяя своим «не удалось открыть». Прерванный `openFile` не должен
   оставить `path` указывающим на непрочитавшийся файл: стор применяет снапшот только после
   успешного чтения.
2. **Рендер** (`renderCurrent`) — `catch` + `lastRev = -1` + `onStatus` (см. §4.6).
3. **Украшение таблиц** — собственный `try/catch` вокруг `enhanceTables`: сбой украшений не
   отменяет уже полученный читаемый HTML.

«Тихий» `catch {}` запрещён: пользователь должен видеть, что действие не выполнилось, иначе
потеряет правки, решив, что файл сохранён.

## 6. UI-код: конвенции

- Элементы берутся один раз в начале модуля: `document.getElementById("x") as HTMLElement`
  (для гарантированных из `index.html` — через `!`). Внутри функций не искать заново.
- Состояние, привязанное к DOM-узлу, — в `WeakMap` (образец: `registry` в `tables.ts`).
  Свойств узлу не навешивать, JSON в `data-*` вместо состояния не использовать.
- Обработчики — делегирование на контейнере (`#preview`), а не на каждой строке/ячейке:
  содержимое предпросмотра полностью заменяется при рендере.
- Глобальное состояние «единственный открытый поповер» снимается при закрытии; при прокрутке
  контейнера поповер закрывается (`attachMenuAutoClose`).
- Горячие клавиши: один `keydown` на `window`, фильтр `e.ctrlKey || e.metaKey`,
  `e.preventDefault()` на каждом совпадении.
- Текст интерфейса — русский, прямо в коде/разметке. i18n-библиотеки нет, не предлагать.
- Комментарии — только про «зачем», на русском, как в существующем коде; шум не добавлять.

## 7. Стили

- Цвета и акценты — через переменные `:root` (`--bg`, `--fg`, `--border`, `--toolbar-bg`,
  `--accent`, `--code-bg`); тёмная тема — переопределение в `@media (prefers-color-scheme: dark)`.
  Хардкод цвета в правиле ломает тёмную тему.
- Визуальный язык — «системный шрифт UI + моноширинный редактор», плотный notepad++-лейаут.
- Липкие заголовки таблиц требуют `border-collapse: separate` и явного `z-index`: при `collapse`
  границы перекрывают `sticky`.
- Один `style.css` пока мал; при росте дробить по модулям таблиц, а не вводить CSS-in-JS.
- Детали визуального языка, токены и компонентные рецепты — см. скилл `frontend-design`.

## 8. Проверка изменений

Команды и их условия запуска — в `.kodarules` и `AGENTS.md`, здесь только порядок:

1. Типы — первое узкое место: `tsc` идёт в составе сборки и валит её на пропущенном `null`,
   неиспользуемой переменной или лишнем параметре. Правки TS не считают законченными, пока
   сборка (`npm run build`) не прошла.
2. Сборку гонять после каждой связки «новый модуль + его потребитель»: `noUnusedLocals` ловит
   рассинхрон контрактов.
3. Юнит-тестов фронтенда сейчас нет (`vitest` не установлен). Логика проверяется сборкой;
   GUI поднимается (`npx tauri dev`) только по явному запросу пользователя.
4. Изменения, затрагивающие поведение Rust-команд, требуют и проверки ядра/шелла
   (`.kodarules`), иначе фронтовая часть «починится» за счёт сломанного бэкенда.

## 9. Типичные ошибки

- Писать компонентную/хуковую абстракцию поверх `main.ts`. Состояние здесь — стейт-фабрики и
  переменные модуля.
- Ставить React/Tailwind «для скорости»: ломает CSP-модель и запрет на зависимости.
- Ставить TanStack Query или свой `useQuery` «для кэша»: кэш рендера на Rust-стороне, а
  библиотека нарушает запрет на зависимости.
- Трогать `preview.innerHTML` вне `onRender` — сбрасывает сортировку и фильтры таблиц.
- Делать `innerHTML` из пользовательского текста в обход `md-core`.
- Звать `invoke` напрямую из `main.ts`/`tables.ts`, минуя `tauri.ts`.
- Ждать отмены вызова через `AbortController`: его нет, есть `rev`/сверка `id`.
- Терять `lastRev = -1` в обработчике ошибки рендера — ошибка «прилипает» к экрану.
- Присваивать путь документа до успешного чтения.
- Показывать ошибку через `innerHTML` (текст ошибки IPC — недоверенные данные, только `textContent`).
- Повторять неудачную запись файла в цикле: причина обычно в блокировке, повтор её не уберёт.
- Ставить npm-пакет без согласия пользователя.
- Хардкод цвета вместо переменной — светлая тема починена, тёмная сломана.
