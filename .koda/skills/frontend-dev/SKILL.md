# Frontend mdedit (vanilla TS + Tauri v2)

Определяющее свойство проекта: **фреймворка нет**. Никаких React/Vue/Svelte, никаких
React Query / Zustand / Tailwind / styled-components, никаких хуков и компонентов —
это тупики, в которые этот код нельзя тащить. Модель прямая: один HTML-файл, ES-модули,
состояние — обычные переменные модуля.

Перед правкой прочитай цель в `tasks/TZ-*.md` (порядок чтения — в `.kodarules`).
Если задача только про фронтенд — `md-core` и `src-tauri` не трогай.

## 1. Жёсткие рамки

| Рамка | Следствие для кода |
|---|---|
| CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:` (`crates/app/src-tauri/tauri.conf.json`) | нет CDN-скриптов, нет `eval`/`new Function`, нет инлайн-`<script>`. Инлайн-`style` разрешён |
| Зависимости — только с явного согласия пользователя | npm-пакет не ставится «чтобы было удобнее». Нет пакета — пиши на API браузера |
| `strict` + `noUnusedLocals` + `noUnusedParameters` + `noEmit` (`crates/app/tsconfig.json`) | неиспользуемая переменная валит сборку; удаляй, а не подавляй |
| Тяжёлые вычисления — на Rust (`md-core`) | парсинг Markdown во фронтенде не появляется; фронтенд рендерит и украшает |
| WebView2 (Chromium), target `es2021` | современные API браузера доступны, полифилы не нужны; фичи, доступные только в самых свежих сборках Chrome, не использовать |

## 2. Карта кода (`crates/app/src/`)

- **`main.ts`** (~250 строк) — состояние документа (`currentPath`, `dirty`), предпросмотр
  (debounce + `renderSeq` + `lastRenderedHtml`), статус-строка и заголовок окна, команды
  файла, горячие клавиши, `onCloseRequested`.
- **`tables.ts`** (~420 строк) — Excel-подобные сортировка/фильтры поверх `<table>` из
  предпросмотра. Публичный контракт: `enhanceTables(root)`, `attachMenuAutoClose(scroller)`.
- **`tauri.ts`** (~25 строк) — все обращения в Rust: тонкие типизированные обёртки над
  `invoke`. Ни один другой модуль `invoke` напрямую не импортирует.
- **`style.css`** — все стили, один файл, переменные в `:root` + `prefers-color-scheme`.
- **`index.html`** — каркас `#app` → `#toolbar` / `#panes` (`#editor`, `#preview`) / `#statusbar`.

Планируемое дробление `tables.ts` (`TZ-excel-tables.md`, T-17): чистая логика →
`tables-core.ts`, персистентность → `tables-state.ts`, работа с DOM → адаптер. Критерий
переноса: функция не трогает `document`/`HTMLElement` и детерминирована по входным данным.
Кандидаты: `parseNumber`, `parseDate`, `toCellValue`, `detectColumnKind`, `compareCells`,
`rowMatches`.

## 3. IPC с Rust

Новый вызов = функция в `tauri.ts`, больше нигде:

```ts
export function renderMarkdown(markdown: string): Promise<string> {
  return invoke<string>("render_markdown", { markdown });
}
```

- `invoke<T>(cmd, args)` — из `@tauri-apps/api/core`; `T` и имя команды обязаны совпадать
  с `#[tauri::command]` в `src-tauri`. Имена аргументов Tauri приводит из camelCase
  (`defaultPath` → `default_path`) — сверяйся с Rust-сигнатурой.
- Ошибку не глотай: `try/catch` + `flash()` (статус-строка), либо давай всплыть к
  обработчику команды. «Тихий» `catch {}` = баг.
- Файловые диалоги живут на Rust-стороне (`pick_open_file`, `pick_save_file`): только так
  выбранный каталог «запоминается» разрешённым, не доверяя фронтенду. Не обходи это
  вызовами `@tauri-apps/plugin-dialog` для путей.
- `fetch` и внешние HTTP-запросы во фронтенде не появляются (CSP + смысл приложения).

## 4. Рендер предпросмотра — инварианты

Ломать нельзя; каждый пункт закрыл реальный баг:

1. **Debounce 120 мс** (`scheduleRender`) — иначе IPC на каждое нажатие клавиши.
2. **`renderSeq`** — монотонный счётчик; ответ старого `renderMarkdown` отбрасывается
   (`if (seq !== renderSeq) return`). Без него гонка рендеров показывает старый HTML.
3. **`lastRenderedHtml`** — HTML не изменился → DOM не трогается. Иначе на каждом дебаунсе
   сбрасывались бы сортировка, фильтры и фокус внутри таблиц.
4. **`resetRenderState()` при смене/создании документа** — гасит таймер и обесценивает
   ответы в полёте; старый ввод не «эхает» в новый файл.
5. **`enhanceTables` в `try/catch`** — украшение таблиц не роняет рендер: при исключении
   остаётся читаемый HTML, причина уходит в `flash()`.
6. `preview.innerHTML = html` — единственный источник HTML это `md-core` (CommonMark+GFM).
   Экранирование исходника делает Rust; свою сборку HTML из сырого текста во фронтенде
   не делать.
7. Внешние ссылки: делегированный `click` на `#preview`, `https?:` → `preventDefault()` +
   `window.open(href, "_blank", "noopener,noreferrer")`. Навигации внутри WebView нет.

## 5. UI-код: конвенции

- Элементы берутся один раз в начале модуля: `document.getElementById("x") as HTMLElement`
  (для гарантированных из `index.html` — через `!`). Внутри функций не искать заново.
- Состояние, привязанное к DOM-узлу, — в `WeakMap` (образец: `registry` в `tables.ts`,
  `WeakMap<HTMLTableElement, TableEntry>`). Свойств узлу не навешивать, JSON в `data-*`
  вместо состояния не использовать.
- Обработчики — делегирование на контейнере (`#preview`), а не на каждой строке/ячейке:
  содержимое предпросмотра полностью заменяется при рендере.
- Глобальное состояние «единственный открытый поповер» (`openMenu`, `outsideHandler`)
  обязательно снимается при закрытии; при прокрутке контейнера поповер закрывается
  (`attachMenuAutoClose`).
- Горячие клавиши: один `keydown` на `window`, фильтр `e.ctrlKey || e.metaKey`,
  `e.preventDefault()` на каждом совпадении.
- Текст интерфейса — русский, прямо в коде/разметке. i18n-библиотеки нет, не предлагать.
- Комментарии — только про «зачем», на русском, как в существующем коде; шум не добавлять.

## 6. Стили

- Цвета и акценты — через переменные `:root` (`--bg`, `--fg`, `--border`, `--toolbar-bg`,
  `--accent`, `--code-bg`); тёмная тема — переопределение в
  `@media (prefers-color-scheme: dark)`. Хардкод цвета в правиле ломает тёмную тему.
- Визуальный язык — «системный шрифт UI + моноширинный редактор», плотный notepad++-лейаут;
  новые элементы должны выглядеть как часть Windows-приложения.
- Липкие заголовки таблиц требуют `border-collapse: separate` (`style.css:116`) и явного
  `z-index`: при `collapse` границы перекрывают `sticky`.
- Один `style.css` пока мал; при росте дробить по модулям таблиц, а не вводить CSS-in-JS
  или препроцессор.

## 7. Проверка изменений

Команды и их условия запуска — в `.kodarules`, здесь только порядок действий:

1. Типы — первое узкое место: `tsc` идёт в составе сборки и валит её на пропущенном
   `null`, неиспользуемой переменной или лишнем параметре. Правки TS не считают
   законченными, пока сборка не прошла.
2. Сборку гонять после каждой связки «новый модуль + его потребитель»: `noUnusedLocals`
   ловит рассинхрон контрактов (например, перенёс функцию в `tables-core.ts`, а `tables.ts`
   всё ещё ждёт старый импорт).
3. Тестового контура во фронтенде сейчас нет. Логика таблиц проверяется ручным прогоком на
   тестовом документе в `main.ts`; GUI поднимается только по явному запросу пользователя.
4. Когда контур появится (`TZ-excel-tables.md`, T-18: `vitest` + `jsdom`, каталог
   `crates/app/tests/`) — красным-зелёным для `tables-core.ts`: сначала падающий тест на
   конкретном значении (`parseNumber`, `detectColumnKind`, `compareCells`), затем перенос
   функции. Тесты DOM-слоя — только для чистой части state-флоу, layout-поведение
   (sticky, клиппинг) автотестами не проверяется, оно в ручном чек-листе.
5. Изменения, затрагивающие поведение Rust-команд, требуют и быстрой проверки ядра
   (`.kodarules`), иначе фронтовая часть «починится» за счёт сломанного бэкенда.

## 8. Типичные ошибки

- Писать компонентную/хуковую абстракцию поверх `main.ts`. Состояние здесь — переменные
  модуля; это работает ровно до момента, пока не появляется второй документ.
- Ставить React/Tailwind «для скорости»: ломает CSP-модель и запрет на зависимости.
- Трогать `preview.innerHTML` вне `doRender` — сбрасывает сортировку и фильтры таблиц.
- Делать `innerHTML` из пользовательского текста в обход `md-core`.
- Звать `invoke` напрямую из `main.ts`/`tables.ts`, минуя `tauri.ts`: контракт IPC
  перестаёт быть видимым в одном месте.
- Ставить npm-пакет без согласия пользователя.
- Хардкод цвета вместо переменной — светлая тема починена, тёмная сломана.
- Оставлять `dirty = true` после программной вставки текста: заголовок окна врёт о
  несохранённых изменениях.
