# Интеграция фронтенда с Rust-бэкендом (mdedit)

«API» в этом проекте — не HTTP. Это Tauri IPC: локальные вызовы `#[tauri::command]`,
которые возвращают значение или отклоняют промис. Отсюда следует главное отличие от
обычных паттернов фронтенда: **нет сети, нет задержки, нет серверного состояния**.
React Query / SWR / TanStack, axios-интерцепторы, retry с экспоненциальной задержкой,
дедупликация in-flight-запросов, optimistic-обновления с откатом — всё это решает
проблемы ненадёжного канала, которого здесь нет. Не приносить их в код.

## 1. Слой запросов: один модуль

`crates/app/src/tauri.ts` — единственное место, где импортируется `invoke`. Новый вызов —
функция здесь, иначе контракт IPC перестаёт быть видимым в одном месте.

```ts
export function renderMarkdown(markdown: string): Promise<string> {
  return invoke<string>("render_markdown", { markdown });
}
```

- `invoke<T>(cmd, args)`: `T` и имя команды обязаны совпадать с Rust-сигнатурой
  `#[tauri::command]` в `crates/app/src-tauri/src/lib.rs`.
- Аргументы Tauri приводит из camelCase в snake_case (`defaultPath` → `default_path`).
  Расхождение имён проявляется не ошибкой типов, а пустым значением в Rust — сверять руками.
- Возврат `Option<T>` на Rust-стороне = `T | null` в TS. Отмена диалога — это `null`,
  а не ошибка; проверять `if (!path) return`, не бросать исключение.
- Тип `T` задавать по факту сериализации, а не по желанию: `serde`-представление enum
  и `Option` должно совпадать с тем, что объявлено в TS.
- Различать два контракта. `read_file`/`write_file` — async-команды с `Result<_, String>`:
  отклонённый промис означает реальную отказку, а текст сформулирован на Rust-стороне.
  `render_markdown` — синхронная команда, возвращающая `String` без `Result`: она всегда
  отдаёт HTML, и её промис отклоняется только при сбое IPC-канала. «Markdown не
  распарсился» ошибкой не бывает — CommonMark парсит любой вход.

## 2. Что заменят собой обычные паттерны

| Обычный паттерн | В mdedit |
|---|---|
| axios/fetch-обёртка с интерцепторами | `tauri.ts`: тонкие функции без логики |
| Инъекция токена, auth-заголовки | нечего инжектировать; доступ к файлам проверяет Rust |
| Retry + backoff для транзиентных сбоев | нет транзиентности сети. Сбой FS (файл открыт в другом процессе, нет прав) повторять бессмысленно — показать причину в статус-строке |
| Дедупликация in-flight-запросов | не нужна: вызовы локальные и быстрые. Дорогой `render_markdown` уже ограничен debounce 120 мс |
| SWR / кэш серверного состояния | `lastRenderedHtml` в `main.ts` — кэш последнего результата, чтобы не перетирать DOM |
| `AbortController` для отмены устаревших запросов | монотонный счётчик `renderSeq`: ответ старше текущего отбрасывается. У `invoke` нет `signal`, отменить отправленный вызов нельзя — только проигнорировать результат |
| Optimistic update с откатом | флаг `dirty` + маркер `●` в заголовке окна. Данные уже в `editor.value`, «откатывать» нечего |
| Global error boundary, тосты | `flash()` в статус-строке (самоочищается через 4 с) либо `preview.textContent` при отказе рендера |
| Loading-спиннер | не нужен при локальном IPC; длинных операций нет |
| Пагинация / infinite scroll | документ целиком в памяти |

## 3. Обработка ошибок

Три уровня, и у каждого свой способ показать проблему:

1. **Команда файла** (`openFile`, `saveFile`, `saveAs`) — `try/catch` вокруг вызова,
   текст в `flash()`. Отказку формирует Rust (`validate_path`): путь вне разрешённых
   каталогов, выход по symlink за их пределы, расширение вне `ALLOWED_EXTS`, файл больше
   `MAX_FILE_SIZE` (10 МиБ). Текст уже точный и человекочитаемый — показывать его как есть,
   не подменяя своим «не удалось открыть». Прерванный `openFile` не должен оставить
   `currentPath` указывающим на файл, который не прочитался: присваивать путь только
   после успешного чтения.
2. **Рендер** (`doRender`) — отказ маловероятен (см. контракты выше), но обработан:
   обнулить `lastRenderedHtml` (иначе следующий идентичный HTML решит «ничего не
   изменилось» и ошибка останется на экране) и вывести текст в `preview.textContent`,
   не в `innerHTML`. Паника в `md-core` — не способ обработки ошибок: при panic=abort она
   забирает процесс, поэтому подозрительный вход лечится тестом в ядре, а не `catch`
   во фронтенде.
3. **Украшение таблиц** — собственный `try/catch` вокруг `enhanceTables`: сбой украшений
   не имеет права отменять уже полученный читаемый HTML.

«Тихий» `catch {}` запрещён: пользователь должен видеть, что действие не выполнилось,
иначе он потеряет правки, решив, что файл сохранён.

## 4. Гонки и порядок ответов

Единственная реальная гонка — быстрые правки, каждая из которых запускает `render_markdown`:

```ts
const seq = ++renderSeq;
const html = await renderMarkdown(editor.value);
if (seq !== renderSeq) return; // более новый рендер уже в полёте
```

Дополнительно при смене или создании документа `resetRenderState()` гасит таймер дебаунса
и увеличивает `renderSeq`, чтобы ответ по старому содержимому не «эхнулся» в новый файл.
Любой новый асинхронный вызов, чей результат попадает в DOM, обязан нести такой же
страж порядка — иначе появится мерцание и рассинхрон редактора с предпросмотром.

## 5. Границы доверия

- Фронтенд не проверяет расширение и не «чинит» путь: это делает Rust (`ALLOWED_EXTS`,
  выбор каталога через нативный диалог). Обходить диалог и подставлять путь строкой нельзя.
- `writeFile` принимает содержимое как есть; решение о перезаписи принято во фронтенде
  через подтверждение, а не молча.
- Ответ Rust считается доверенным только в части разметки: HTML приходит из `md-core`,
  и вставлять его в `preview` можно. Текст ошибки IPC — недоверенные данные, для него
  `textContent`/`flash()`, но не `innerHTML`.
- Внешних HTTP-вызовов нет и не будет: CSP (`default-src 'self'`) их запрещает.

## 6. Проверка

- Типы и сборка — по правилам проекта (`.kodarules`); `tsc` валится на расхождении `T`
  в `invoke<T>` с реальным использованием результата.
- Поведение IPC проверить на реальном файле: открыть, изменить, сохранить, сохранить как,
  отменить диалог, открыть файл с запрещённым расширением, открыть файл, заблокированный
  другим процессом. Каждый отказ должен дать читаемое сообщение в статус-строке.
- Правки, задевшие Rust-команды, требуют и проверки ядра (`.kodarules`).
- GUI (`npx tauri dev`) поднимать только по явному запросу пользователя.

## 7. Типичные ошибки

- Ставить TanStack Query или свой хук `useQuery` «для кэша»: кэш здесь — одна строковая
  переменная, а библиотека нарушает запрет на зависимости.
- Звать `invoke` из `main.ts`/`tables.ts`, минуя `tauri.ts`.
- Ждать отмены вызова через `AbortController`: его нет, есть `renderSeq`.
- Терять `lastRenderedHtml = ""` в обработчике ошибки рендера — ошибка «прилипает» к экрану.
- Присваивать `currentPath` до успешного чтения.
- Показывать ошибку через `innerHTML`.
- Повторять неудачную запись файла в цикле: причина обычно в блокировке процесса, повтор её не уберёт.
