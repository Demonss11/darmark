# Чистый текст (mdedit)

Проза проекта пишется по-русски: `tasks/TZ-*.md`, `KODA.md`, `README.md`, комментарии в коде,
UI-строки (`tables.ts`, `main.ts`), сообщения коммитов. Убирай предсказуемые AI- и бюрократические
штампы. Действует и на английские вкрапления (имена, технический жаргон — не трогай).

## Главные правила

1. **Вырезай вводные-костыли.** «Важно отметить», «стоит подчеркнуть», «нельзя не заметить»,
   «в целом», «по сути», «достаточно сказать», «фактически», «по сути дела», «при этом важно».
   См. [references/phrases.md](references/phrases.md).
2. **Ломай шаблонные конструкции.** «Не X, а Y» → скажи Y прямо. «Это не значит, что…» → скажи,
   что это значит. «Во-первых / во-вторых / в-третьих» → нумерованный список или убери.
   Три однородных пункта подряд → оставь два. См. [references/structures.md](references/structures.md).
3. **Действующее лицо в подлежащем.** Вместо «было реализовано», «осуществляется рендер»,
   «является результатом» — «рендер делает…», `main.ts` вызывает…", "агент запускает…".
   Неодушевлённые предметы не совершают человеческих действий («таблица запоминает сортировку» →
   «состояние таблицы хранится в…»).
4. **Конкретика вместо деклараций.** «Проблемы структурные» → назови проблему и файл со строкой.
   «Много мест» → посчитай. «Всегда», «никогда», «любой» без проверки — убери или докажи.
5. **Помещай читателя в сцену.** В ТЗ и README: «открываешь предпросмотр, сортируешь колонку»
   вместо «пользователь имеет возможность отсортировать». «Ты» вместо «разработчики».
6. **Разнообразь ритм.** Чередуй короткие и длинные предложения. Не заканчивай каждый абзац
   той же конструкцией. Не начинай предложения с «Данный», «Этот», «Также», «Кроме того».
7. **Доверяй читателю.** Не смягчай и не оправдывайся: не «возможно, стоит рассмотреть вариант…»,
   а «сделай X». Не объясняй очевидное для того, кто читает ТЗ проекта.
8. **Вырезай афоризмы.** Фраза, годящаяся в заголовок-цитату («Состояние — главная боль таблиц»),
   переписать по делу.

## Поверхности проекта (специфика)

| Артефакт | Требование |
|---|---|
| `tasks/TZ-*.md` | AC формулируй проверяемо: «`npm run build` проходит», а не «код качественный». Без обещаний «в будущем планируется» — только объём работы |
| `KODA.md`, `README.md` | Факт и команда, а не рассуждение. Разделы короткие, без вводных абзацев «В этом документе описывается…» |
| Комментарии в коде | Объясняют **зачем**, 1–2 строки. Без пересказа кода и без «// здесь мы…» |
| UI-строки (`tables.ts`, `main.ts`) | Повелительное наклонение, минимум слов: «Сортировать», «Сбросить фильтр». Без «Пожалуйста», «Вы уверены, что хотите…?» длиннее одной строки |
| Commit message | Повелительное наклонение, до 50 символов, «почему» в теле (см. скилл `git-commit`) |

## Быстрая проверка

Перед выдачей текста:

- Есть вводные-костыли из п. 1? Вырезай.
- Пассив без действующего лица («было добавлено»)? Найди того, кто добавил, поставь в подлежащее.
- Неодушевлённый предмет делает человеческое действие? Назови человека или опиши механизм.
- Предложение начинается с «Этот», «Данный», «Также»? Перестрой.
- «Не X, а Y»? Скажи Y.
- Три предложения одной длины подряд? Разбей одно.
- Абзац заканчивается «ударной» строкой в 3 слова? Разнообразь.
- Вводная «Важно отметить»? Убирай — если важно, это видно по делу.
- Отвлечённая декларация («Последствия серьёзные»)? Назови последствие.
- Канцелярит: «осуществляет», «является», «в рамках», «в части», «по мере возможности»,
  «на данный момент», «в текущей реализации»? Заменить нормальным словом или вырезать.
- Номинализация («выполнение сортировки», «осуществление рендера»)? → глагол: «сортирует», «рендерит».
- Список из трёх пунктов, где хватает двух? Сократи.
- В AC и критериях нет способа проверки? Добавь команду или наблюдаемый факт.
- Мета-связки («Далее будет показано», «В начале документа…»)? Убирай — текст идёт дальше.

## Оценка

Ставь 1–10 по каждому измерению:

| Измерение | Вопрос |
|---|---|
| Прямолинейность | Утверждения или объявления о них? |
| Ритм | Длина предложений разная? |
| Доверие | Уважает ли интеллект читателя? |
| Естественность | Похоже на человеческий текст? |
| Плотность | Осталось ли что вырезать? |

## Границы

- Технические термины, имена файлов, идентификаторы, команды, markdown/GFM-разметку не «улучшать».
- Не менять смысл ТЗ и AC: сокращение не должно убрать требование или критерий.
- Русскую орфографию и пунктуацию не ломать; тире как связка вместо глагола — вырезай,
  обычное тире остаётся.
- Форматирование артефакта (таблицы, чекбоксы, нумерация T-xx) сохраняй.
