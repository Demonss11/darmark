# Rust-код в md-core (процедура)

Рабочий метод для подзадачи по Rust в `crates/md-core` (edition 2021).
Ядро — чистые функции без состояния: вход → выход, без побочек и без I/O.
Цель — минимальная правка, которая проходит гейт и не ломает потребителей.

## Порядок работы
1. **Прочитай контекст.** Целевой модуль + 2–3 соседа + его `#[cfg(test)]`. Переняй
   конвенции модуля (имена, как разбит парсер, как возвращают `enum`-ошибку).
   Не выдумывай новый стиль и не тяни сюда состояние/UI/IPC — это вне ядра.
2. **Зафиксируй контракт.** Что на входе/выходе, какие `pub`-сигнатуры нельзя менять.
   Если задача требует смены публичного API ядра или новой архитектуры — остановись
   и верни пункт в блок «Блокеры» отчёта, не переделывай сверх задания.
3. **Правь точечно.** Без side-effect рефакторинга чужих участков парсера/рендера.
4. **Прогони гейт** (ниже) и чини до зелёного.

## Ошибки — ручные enum
- Возврат — `Result<T, E>`, где `E` — локальный `enum` с кодами, как в существующем
  модуле. **Без** `thiserror`/`anyhow`/`std::error::Error`-обёрток сверх текущих.
- Новая ошибка → новая варианта в существующий enum ядра + `///`-комментарий с кодом
  и смыслом; не плоди отдельный crate-овертайп на каждый случай.
- В production-путях **нет** `unwrap()`/`expect()` (в `#[cfg(test)]` — можно).
- `?` для проброса; явные `match` на ветках ошибок, без «магических» `_ =>`.

## Паттерны Rust
- Чистые функции: без `static`/`Mutex`/глобального состояния в ядре.
- Итераторы + `match` вместо индексации и «магических» веток; ранние возвраты.
- Публичные `fn`/`struct`/`enum` — с `///` doc-комментарием (что делает, коды ошибок).
- `unsafe` — только с `// SAFETY:` и обоснованием; по умолчанию запрещено.
- Границы лимитов (`max_size`, `rev`) — проверяй на входе, не «надейся» на вызывающего.

## Тесты
- Unit — `#[cfg(test)] mod tests` рядом с кодом; интеграция — в `crates/md-core/tests/`.
- Один сценарий на `#[test]`; имя описывает поведение (`renders_gfm_table`, `rejects_oversized_input`).
- Граничные обязательны: пустая строка, Unicode, лимиты (`max_size`, `rev`).
- Повторяющийся сценарий на табличных данных — `for` по кортежам внутри одного теста.
- Менять ожидание теста ради зелёного **запрещено** — чинится код.

## Гейт приёмки (в конце, по crate md-core)
```bash
cargo fmt --all -- --check
cargo clippy -p md-core --all-targets -- -D warnings
cargo test  -p md-core
```
- `fmt` падает → `cargo fmt --all`, перечитать диф.
- `clippy` (`-D warnings`) → править предупреждение, не глушить; `#[allow]` только
  с обоснованием в комментарии.
- `test` → чинить код ядра.

## Не трогать
`Cargo.lock`/`Cargo.toml` (зависимости) без явного запроса · `tauri.conf.json` ·
публичные сигнатуры парсера/рендера сверх задания · чужие crate/модули · `.mdcc/` ·
`git push`/история.

## Отчёт (в конце)
1. Что сделано (2–5 пунктов). 2. Затронутые файлы. 3. Гейт: fmt/clippy/test — что чинил.
4. Блокеры/риски для основного агента (напр. требует смены публичного API ядра).
