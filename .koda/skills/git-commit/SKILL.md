# Git Commit Messages

## Purpose

Создание сообщений коммитов в стандарте Conventional Commits.

## When to use

Когда пользователь просит сгенерировать commit message или использует команду `/commit`.

## Instructions

### 1. Формат сообщения

    ```
    <type>(<scope>): <description>

    [optional body]

    [optional footer]
    ```

### 2. Типы коммитов

- **feat**: Новая функциональность
- **fix**: Исправление бага
- **docs**: Изменения в документации
- **style**: Форматирование, отступы (без изменений кода)
- **refactor**: Рефакторинг кода
- **test**: Добавление тестов
- **chore**: Изменения в сборке, зависимостях
- **perf**: Улучшение производительности
- **ci**: Изменения в CI/CD
- **build**: Изменения в системе сборки

### 3. Правила

- Заголовок до 50 символов
- Тело до 72 символов на строку
- Используй повелительное наклонение: "add", не "added"
- Не заканчивай точкой
- Указывай breaking changes в footer

### 4. Примеры

✅ **Хорошо**:
    ```
    feat(auth): добавить OAuth2 аутентификацию

    - Интеграция с Google OAuth
    - Добавлены эндпоинты /auth/google
    - Обновлены типы User

    Closes #123
    ```

❌ **Плохо**: `fix: исправил баги и добавил фичи`

## Examples

### Пример для исправления бага

    ```
    fix(api): исправить утечку памяти в WebSocket

    Закрытие соединения не освобождало ресурсы.
    Добавлен явный вызов cleanup() при отключении.

    Fixes #456
    ```

### Пример для новой фичи

    ```
    feat(ui): добавить тёмную тему

    - Реализовано переключение тем
    - Сохранение выбора в localStorage
    - Обновлены цветовые переменные CSS

    BREAKING CHANGE: Изменены названия цветовых переменных
    ```
