# Verification Before Completion

## Overview

**Core principle:** Evidence before claims, always.

**Violating the letter of this rule is violating the spirit of this rule.**

## The Iron Law

```
NO COMPLETION CLAIMS WITHOUT FRESH VERIFICATION EVIDENCE
```

If you haven't run the verification command in this message, you cannot claim it passes.

## The Gate Function

```
BEFORE claiming any status or expressing satisfaction:

1. IDENTIFY: What command proves this claim?
2. RUN: Execute the FULL command (fresh, complete)
3. READ: Full output, check exit code, count failures
4. VERIFY: Does output confirm the claim?
   - If NO: State actual status with evidence
   - If YES: State claim WITH the command and its result
5. ONLY THEN: Make the claim

Skip any step = lying, not verifying
```

## Проектный контур верификации

Команды, границы модулей и условия их запуска — **единственный источник истины**: `AGENTS.md`
(раздел «Команды») и `.kodarules` (раздел «Команды и сборка»). Здесь — только принцип
сопоставления, без пересказа конкретных путей.

Сопоставь затронутый слой с проверкой, которая его реально покрывает:

| Затронут слой | Что обязано пройти |
|---------------|--------------------|
| Чистое ядро (Rust-логика вне GUI) | тесты ядра (`cargo test -p <core>`) |
| Фронтенд (TypeScript) | сборка фронта (`npm run build` = `tsc && vite build`) — `tsc` валит её на любой ошибке типов |
| IPC-контракт (обе стороны вызова) | сборка фронта (типы) **и** тесты шелла — частичной проверки недостаточно |
| GUI-поведение | E2E на **пересобранном** релизном бинаре |
| Кодировки / границы строк | E2E на Unicode-входе (кириллица / эмодзи / CRLF), не только на ASCII |
| Финальный exe / установщик | релизная сборка (`tauri build`), а не обычный `cargo build` |
| Требования ТЗ | перечитать `tasks/TZ-*.md` целиком → построчный чеклист → проверка каждого пункта |

> ⚠️ Обычный `cargo build`/`cargo run` НЕ собирает единый exe с вшитым фронтом — он
> компилирует только Rust. Встраивание `dist/` делает именно `tauri build`. Утверждать
> «сборка прошла» после `cargo build` — ложь.
>
> ⚠️ E2E работают с собранным релизным бинарём. После правок фронта его **нужно
> пересобрать**, иначе E2E проверяют старый код — это ложная верификация.

## Common Failures

| Claim | Requires | Not Sufficient |
|-------|----------|----------------|
| Тесты проходят | свежий прогон: 0 failures | прошлый запуск, «должно пройти» |
| Код компилируется | сборка: exit 0 | файл «выглядит правильно» |
| Контракт согласован | проверки обеих сторон | только одна сторона |
| GUI-фича работает | E2E на пересобранном бинаре: сценарий пройден | сборка прошла |
| Кодировки корректны | Unicode-сценарий пройден | тест на ASCII-документе |
| Санитайзер/XSS безопасен | сценарий с вредоносным вводом | «я же удаляю опасное» |
| Bug fixed | воспроизвести исходный симптом → он не проявляется | код изменён, «предположительно исправлено» |
| Regression test работает | red-green цикл проверен | тест прошёл один раз |
| Требования ТЗ выполнены | ТЗ перечитан целиком → чеклист | тесты проходят |
| Релиз собирается | артефакты сборки реально существуют | скомпилировался Rust |
| Агент завершил | diff показывает изменения | агент рапортует «успешно» |

## Red Flags — STOP

- «Должно», «вероятно», «кажется», «по идее работает»
- Удовлетворение до верификации («Отлично!», «Готово!», «Работает!»)
- Коммит/PR без свежего прогона команд
- Доверие рапортам субагента («agent said success»)
- Утверждение о GUI/сборке/кодировках без соответствующей проверки
- Утверждение «требования ТЗ выполнены» без перечитывания ТЗ целиком
- Частичная верификация при контракте из нескольких слоёв
- Усталость и желание закончить
- **Любая формулировка об успехе без запуска проверки**

## Rationalization Prevention

| Excuse | Reality |
|--------|---------|
| «Должно работать» | ЗАПУСТИ верификацию |
| «Я уверен» | Уверенность ≠ доказательства |
| «Только в этот раз» | Исключений нет |
| «Сборка прошла» | Компиляция ≠ поведение GUI |
| «Тесты ядра прошли» | Ядро ≠ фронт ≠ шелл; проверяй затронутый слой |
| «Агент сказал успех» | Проверяй diff независимо |
| «Я устал» | Истощение ≠ оправдание |
| «Частичной проверки хватит» | Частичное ничего не доказывает |
| «Другими словами — правило не про это» | Дух важнее буквы |

## Manual-Only Checks

Автотесты не покрывают всё, что зависит от ОС и нативных диалогов (выбор каталога,
внешний браузер, лимиты размера, экзотичный битый HTML, диалог закрытия с
несохранёнными изменениями). Такие пункты помечай отдельно и прогоняй руками —
«E2E зелёные» НЕ означает, что они закрыты.

## When To Apply

**Всегда перед:**
- любой вариацией утверждений об успехе/завершённости;
- любым выражением удовлетворения или позитивным высказыванием о состоянии работы;
- коммитом, PR, завершением задачи, переходом к следующей задаче;
- делегированием агентам и приёмкой их результата;
- утверждением о GUI, сборке, кодировках, безопасности, соответствии ТЗ.

**Правило применяется к:** точным фразам, пересказу и синонимам, подразумеванию успеха —
к любой коммуникации, намекающей на завершённость или корректность.
