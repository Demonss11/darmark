# Аудит инструментария OpenCode

## Назначение

Конфиги `.opencode/` дрейфуют при каждом добавлении агента или навыка: появляются
невалидные модели, несуществующие permission-ключи, устаревшие `tools`/`permissions`,
дубли абзацев, висячие ссылки. Этот навык превращает ручную ловлю таких дефектов в
повторяемую процедуру: **детерминированные проверки — скриптом, качественные
суждения — по этой инструкции**.

Навык ничего не редактирует и не является обязательным гейтом. Найденные дефекты
исправляются **отдельными задачами через `code-reviewer`**.

## Как запускается

Скрипт лежит рядом с навыком и не требует сети или внешних зависимостей:

```bash
node .opencode/skills/tooling-audit/scripts/audit.mjs
```

По умолчанию он берёт каталог `.opencode/` относительно своего расположения.
Можно передать другой каталог первым аргументом:

```bash
node .opencode/skills/tooling-audit/scripts/audit.mjs path/to/.opencode
```

Скрипт печатает механический отчёт и **всегда завершается с кодом 0** — находки не
должны ронять пайплайн.

## Механические проверки (что делает скрипт)

1. **Frontmatter** агентов (`.opencode/agents/*.md`) и навыков
   (`.opencode/skills/*/SKILL.md`): блок `--- … ---` присутствует и закрыт; разбор
   без внешнего YAML; набор ключей допустим; `permission` — в единственном числе;
   нет устаревших `tools`/`permissions`; нет дублирующихся ключей.
2. **Ключи `permission`** входят в актуальный набор: `read`, `edit`, `glob`, `grep`,
   `list`, `bash`, `task`, `webfetch`, `websearch`, `lsp`, `skill`, `question`,
   `external_directory`, `todowrite`, `doom_loop`.
3. **Соответствие имени**: `name` агента ↔ имя файла; `name` навыка ↔ имя каталога.
4. **Висячие ссылки**: `@упоминания` и backtick-имена против фактического списка
   `.opencode/` и известных глобальных навыков. Отдельно помечается «навык упомянут
   как агент».
5. **Дубли абзацев** между файлами (нормализованный хеш) и внутри одного файла.
6. **Хардкод путей и имён проекта** в телах агентов (эвристика по списку токенов:
   пути крейтов, `md-core`, `plugin-proto`, `plugin-host`, `src-tauri`, `DESIGN_DOC`,
   `docs/adr`, имя проекта).
7. **Модель**: поле `model` присутствует и имеет формат `провайдер/модель`.

## Суждение (что оценивает LLM по этой процедуре)

Механику скрипт закрывает; ниже — то, что он не может:

- **Качество описаний**: отвечает ли `description` на «что + когда», «настойчиво»
  ли оно (перечислены триггеры и близкие формулировки), не размыто ли.
- **Перекрытие ролей и границы**: developer ↔ tester, `security-reviewer` ↔
  `code-reviewer`, `architect` ↔ `senior-system-analyst`; у каждой пары должна быть
  явная граница, а не дублирование обязанностей.
- **Дублирование с глобальными скиллами**: проект не должен переписывать то, что уже
  покрыто (`writing-plans`, `systematic-debugging`, `test-driven-development`,
  `review` и т.п.) — только дополнять.
- **Ясность и структура**: объясняет ли текст «почему», русский ли язык, единообразна
  ли структура разделов, нет ли противоречий между frontmatter и телом.
- **Факт-точность относительно репозитория**: команды, стек, ссылки на документы и
  ADR существуют и названы верно.
- **Сверка доступности `model`** с реальным списком моделей: скрипт её не делает —
  подтверди вручную или пометь ⚠️.

## Формат вывода

Скрипт печатает:

1. Таблицу «**файл → проверка → OK / FAIL / ⚠️**» (механическая часть).
2. Список находок с уровнями **Critical / Important / Minor**.
3. Итог по файлам.

К механическому отчёту добавь раздел **«Суждение»** с выводами по пунктам выше и
расставь приоритеты. Дефекты Critical блокируют сдачу; Important требует исправления
отдельной задачей; Minor допустим и перечисляется.

## Ограничения

- **Не редактирует файлы.** Исправления — отдельными задачами через `code-reviewer`.
- **Доступность `model` офлайн не проверяется** — если подтвердить нельзя, помечай
  ⚠️, а не FAIL. Сужденческую сверку с реальным списком моделей делает LLM.
- **Сам навык и скрипт — тоже артефакт**: держи их в синхроне при изменении схемы
  агентов/навыков (набор ключей, список permission, перечень глобальных навыков).
- **Не блокирующий CI-гейт.** Скрипт выходит с кодом 0 при любых находках.
- **Хардкод путей — эвристика**: умышленные ссылки на проектные документы у
  проектно-специфичных агентов помечаются как ⚠️ и требуют суждения, а не слепого
  исправления.
