# md-core-domain: домен ядра Markdown

## Зачем этот навык

`md-core` — единственный крейт, который знает, как превратить Markdown в HTML для всего
приложения: предпросмотра, инспектора, будущего CLI. Он не должен знать о окнах, IPC и
состоянии редактора. Это навык о границах и контрактах внутри ядра: где заканчивается
pulldown-cmark, как санитизируется вывод, почему нельзя «быстро добавить» зависимость
от Tauri.

## pulldown-cmark 0.13: три входа

Ядро рендерит через pulldown-cmark 0.13 (CommonMark + GFM-расширения). Три публичных
функции — это не три реализации, а один конвейер с разной глубиной интеграции:

| Вход | Когда использовать | Что делает |
|------|-------------------|------------|
| `to_html()` | Предпросмотр и любой простой рендер | Рендер с `DEFAULT_OPTIONS` + санитизация |
| `to_html_with()` | Тесты, будущий CLI, нестандартные наборы опций | То же, но с произвольным `Options` |
| `to_html_mapped()` | Двусторонняя подсветка и scrollsync | Добавляет `data-md="{start},{end}"` в каждый топ-блок и структурные теги таблиц |

`DEFAULT_OPTIONS` включает: Tables, Strikethrough, Tasklists, Footnotes,
Heading Attributes. Не выключай их молча — фронт и плагины рассчитывают на эти
расширения.

Инвариант рендера: содержимое блоков без обёрток `md-block` и атрибутов `md`
побайтово совпадает с `to_html()`. Это значит, что отрендеренный HTML не зависит
от того, включён ли маппинг.

## XSS-санитайзер: белые списки, не чёрные

pulldown-cmark не санитизирует выход: сырой HTML из документа проходит как есть.
Санитайзер (`sanitize_html`) — вторая половина рендера, без неё ядро небезопасно.

Принципы:
- **Allowlist тегов** вместо чёрного: неизвестный тег «разворачивается» (тег убран,
  содержимое сохранено). `ALLOWED_TAGS` — полный список разрешённых.
- **Allowlist атрибутов**: глобальные (`class`, `id`, `title`, `lang`, `dir`,
  `role`) + по тегу. `on*`, `srcdoc`, `formaction` удаляются автоматически.
- **`data-*` атрибуты** разрешены только в одном виде: `data-p-<pluginid>-<suffix>`
  (плагинная маршрутизация, D7). Остальные `data-*` срежаются — не расширяй allowlist
  без необходимости.
- **URL по белому списку схем** (`http`, `https`, `mailto`, `tel`). `javascript:`,
  `data:text/html`, обфускация через `&#58;` и `java\tscript:` нейтрализуются.
  Значения декодируются от сущностей и заново экранируются, чтобы `&#34;` не мог
  «разорвать» атрибут.
- **`style`** оставляется только для выравнивания ячеек (`text-align: left|right|
  center|justify`) — то, что генерирует сам pulldown для таблиц.
- **Опасные контейнеры** (`script`, `style`, `iframe`, `object`, `form`, `template`,
  `svg`, `math`, `noscript`, `textarea`, `select`, `button`, `xmp`, `title`) удаляются
  вместе с содержимым.
- **Комментарии** `<!-- ... -->` вырезаются целиком.
- На ссылках проставляется `rel="noopener noreferrer"`.

Зачем так строго: предпросмотр рендерит произвольный пользовательский Markdown и HTML,
а CSP приложения (`default-src 'self'`) — не панацея, если в документе уже есть
`<script>` или `javascript:`-ссылка. Санитайзер — последний рубеж защиты до того,
как HTML попадёт в WebView.

**Важно про плагины:** если плагин передаёт HTML через `host.set_view_content`,
он обязан пройти `sanitize_fragment()` — ту же политику, что и предпросмотр.
Расширенный `data-p-*` работает и там.

## YAML-шапка: не украшается tables.ts

Ведущий блок `---…---` рендерится отдельно в HTML-таблицу «ключ → значение»
через `frontmatter::render_frontmatter`. Это не GFM-таблица: её не нужно и нельзя
обрабатывать `tables.ts` — состояние Excel-подобных таблиц не должно зависеть от
рендера шапки.

Детекция шапки своя, а не `Options::ENABLE_YAML_STYLE_METADATA_BLOCKS`: опция
pulldown распознаёт metadata-блок в любом месте столбца 0 и тогда обычные пары
`---` съедали бы содержимое. Нужна только шапка в начале документа.

BOM обрабатывается: если файл начинается с `\u{FEFF}`, он пропускается перед
проверкой первой строки.

## Mapping байтов↔UTF-16

Текст документа в Rust — байты UTF-8, в JavaScript — строки UTF-16. Инспектор и
scrollsync должны переводить диапазоны между этими мирами.

На фронте — `mapping.ts` (`bytesToUtf16`, `utf16ToBytes`), в ядре — диапазоны
`OffsetIter` в байтах. Границы блоков от `OffsetIter` гарантированно попадают
в UTF-8 char-boundary, поэтому маппинг на стороне JS не может «разрезать» символ.

Зачем: подсветка в редакторе и предпросмотре должна совпадать даже с многобайтовыми
символами (кириллица, эмодзи, CJK). Если диапазон в байтах перевести в UTF-16
с ошибкой, подсветка уедет или сломается.

## Горячие пути рендера

Предпросмотр перерисовывается на каждый документ целиком, но инспектор должен быть
отзывчивым. Узкие места и их обработка:

1. **Санитайзер — по символам, не по байтам.** Кириллица в `title`/`alt` не должна
   уводить индекс в середину символа. Парсинг идёт по `Vec<char>`, только вывод
   собирается в байты.
2. **Структурная разметка таблиц — после санитайзера.** `data-md` на `<tr>`, `<th>`,
   <td>` вставляется в уже санитизированный HTML, иначе `data-*` был бы срезан.
   `<tr>` в `<thead>` не размечается — у шапки интерактивны только `<th>`.
3. **Один проход парсера.** Документ парсится один раз через `OffsetIter`.
   События группируются по топ-блокам, каждая группа прогоняется через
   `html::push_html`. Ссылочные определения и сноски разрешаются единым парсером
   на весь документ — нельзя рендерить срезы блоков отдельно, иначе ссылки
   потеряются.
4. **Промежутки между блоками.** Байты ссылочных определений не порождают событий
   и оказываются «между» блоками. Такие промежутки приклеиваются к следующему
   блоку, чтобы подсветка не рвалась.
5. **Хвостовые пробелы.** `trim_end_ws` убирает «воздух» между абзацами, чтобы
   подсветка не захватывала пустоту.
6. **Предаллокация.** `String::with_capacity(markdown.len() + 64)` — грубая, но
   достаточная оценка, чтобы избежать повторных реаллокаций на каждом блоке.

## Правило: без GUI/Tauri-зависимостей

`md-core` не линкует Tauri и не знает о GUI. Это не ограничение, а контракт:
ядро должно оставаться переиспользуемым в CLI, TUI, тестах и плагинном хосте.

**Нельзя:**
- Добавлять `tauri`, `serde` (если не через feature-glob), `std::net`, `std::fs`
  без feature-флага.
- Возвращать `Result` с Tauri-специфичными ошибками.
- Зависеть от состояния приложения (путь файла, dirty-флаг, ревизия).

**Можно и нужно:**
- Чистые функции над `&str` → `String`.
- Константы и параметры через `Options`.
- Собственные ошибки, если нужны, но без привязки к Tauri.

CI проверяет: `cargo tree -p darmark | Select-String mlua` — пусто (плагинный
хост не должен протекать в GUI-хост). Аналогично, `md-core` не должен протекать
в Tauri.

## Тесты и проверка

- `cargo test -p md-core` — юнит-тесты ядра; быстро, без GUI.
- Санитайзер покрыт табличными тестами (`table_no_event_handler_survives_any_context`,
  `table_no_dangerous_uri_survives_any_context`) — расширяй именно их при добавлении
  новых правил.
- Инварианты маппинга проверяются тестами на совпадение с `to_html()`.
