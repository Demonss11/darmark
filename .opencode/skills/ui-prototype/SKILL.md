# ui-prototype

## Механика прототипирования

Прототипы — однофайловые HTML-документы (`front_ideaN.html`) в каталоге идей проекта. Каждый файл самодостаточен: все стили в `<style>`, весь размет в теле, JS (если нужен) инлайновый в `<script>`. Никаких внешних зависимостей.

**Зачем так:** прототип открывается двойным кликом без сервера и сборки, легко расшаривается, не загрязняет продуктовую сборку и не требует отдельной инфраструктуры.

**Нумерация:** следующий свободный `N` в имени файла; при обновлении существующего прототипа версия не накапливается — правится тот же файл.

## CSS-токены и темы

Токены прототипа **зеркалят** канонический набор из продуктового `style.css`:

- Фоны: `--bg-0…--bg-4`, границы `--line`, `--line-soft`.
- Текст: `--fg`, `--fg-dim`, `--fg-mute`, `--head`, `--body`.
- Акцент: `--accent`, `--accent-2`, `--accent-soft`, `--accent-rgb`.
- Семантика: `--green`, `--amber`, `--red`, `--teal`.
- Метрики: высоты `--h-toolbar/--h-tabs/--h-status`, ширины `--w-rail/--w-sidebar/--w-infopanel`, радиусы `--r-sm/--r-md/--r-lg`.
- Редактор: `--ed-fs`, `--ed-lh`, `--ed-pad-y`, `--gutter`.
- Цвет плагина: `--pc` (переопределяется inline).

**Зачем:** прототип, использующий те же токены, не требует перевода палитры при хендоффе — цвета и метрики уже совпадают с продуктом.

**Тема:** по умолчанию тёмная (`color-scheme: dark`). Светлая палитра добавляется только по явному запросу. Используйте `prefers-color-scheme` для переключения в самом прототипе — для референса это дешевле, чем держать два файла.

## Self-contained / CSP-safe

Прототип обязан проходить под строгую CSP продукта (`default-src 'self'`):

- Без CDN, внешних шрифтов, внешних картинок.
- Без `eval`, `new Function`, inline-обработчиков `onclick=` (используйте `addEventListener`).
- Без фреймворков и сборщиков — чистый HTML/CSS/JS.

**Зачем:** продукт живёт под этой CSP; прототип, нарушающий её, потребует переделки на этапе переноса.

## Чек-лист «референс → ТЗ/DESIGN_DOC → реализация»

Перед хендоффом прототип проверяется по чек-листу:

1. **Токены и тема** соответствуют продуктовому набору.
2. **`<html lang="ru">`** — обязательно.
3. **CSP-safe** — нет внешних ресурсов, `eval`, обработчиков в атрибутах.
4. **Замороженные контракты** — если прототип отображает поверхности, общие с продуктом, используются существующие брендированные id и селекторы (сверка с дизайн-документом, раздел замороженных контрактов).
5. **Направление выбрано** — из 2–3 вариантов определён один с пояснением почему.
6. **Бэклог идей обновлён** — если прототип закрывает идею, статус в бэклоге изменён; если породил новую — добавлена запись.
7. **Хендофф готов** — описание направления, что в ТЗ, что остаётся открытым, ссылка на файл прототипа.

## Связь с UI-IDEAS.md / ADR

Прототипы — инструмент продвижения бэклога:

- Идея из бэклога, получившая прототип, переводится из `идея` в `tz` при готовности хендоффа, либо в `adr`, если нужно архитектурное решение.
- Прототип, меняющий нормативный дизайн-документ, требует ADR — направление согласовывается с `@architect` до записи в DESIGN_DOC.
- Принятое решение уходит из бэклога в DESIGN_DOC/ADR; в бэклоге остаётся ссылка и статус.

## a11y-ориентиры

Доступность оценивается по глобальному навыку `web-design-guidelines` — контраст, фокус, ARIA-роли, клавиатурная навигация. Здесь не дублируется: прототип должен следовать тем же ориентирам, что и продукт, а проверка соответствия — через указанный навык.

## Что этот навык не покрывает

Реализацию продукта — навык описывает только прототип-референс. Перенос в `crates/app/src` — зона `frontend-developer` по ТЗ, подготовленному из этого прототипа.
