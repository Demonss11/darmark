# UI-BUGS — баг-бэклог интерфейса

> **Статус:** non-normative, живой список наблюдённых дефектов/UX-проблем UI.
> Нормативная спецификация — `docs/DESIGN_DOC.md` (+ ADR в `docs/adr/`); идеи — `ideas/UI-IDEAS.md`.
> **Как запись продвигается:** `new` → `triaged` (есть причина/план) → `fixing` (TZ/ветка) → `fixed`.
> Сюда же попадают UX-проблемы, требующие решения дизайнера (помечаются `design`).

## Статусы

- `new` — сообщено, не разобрано;
- `triaged` — причина/область установлены, есть направление;
- `fixing` — в работе (ссылка на ветку/TZ);
- `fixed` — исправлено (ссылка на коммит/TZ);
- `wontfix` / `dropped` — отклонено (кратко почему).

## Severity

- `P0` — ломает данные/блокирует работу;
- `P1` — мешает частому действию или даёт неверный результат;
- `P2` — полировка/удобство.

## Шаблон записи

```
### BUG-NNN — <название>
- **Статус:** new | triaged | fixing | fixed | wontfix
- **Severity:** P0 | P1 | P2
- **Область:** <файл/модуль/поверхность>
- **Симптом:** <что видит пользователь>
- **Воспроизведение:** <шаги>
- **Гипотеза/причина:** <если есть>
- **Затрагивает:** <файлы, замороженные контракты §13.2 — да/нет>
- **Направление:** <как чинить>
- **Открытые вопросы:** …
```

## Бэклог

### BUG-001 — Выделение мышью захватывает слово вместе с пробелом

- **Статус:** fixed
- **Severity:** P1
- **Область:** `crates/app/src/formatActions.ts` (`wrap` — общий для `bold`/`italic`/`code`; `link`).
- **Симптом:** при выделении слова мышью в выделение попадает замыкающий пробел; после `Ctrl+B` получается `**слово **` вместо `**слово**`. Мешает быстрым командам форматирования.
- **Воспроизведение:** открыть документ → выделить `"hello "` (0..6) → `Ctrl+B` (или кнопка «Жирный»).
- **Причина (подтверждена):** `wrap()` оборачивал выделение как есть, без нормализации краёв. Кастомных обработчиков выделения в коде нет — краевой пробел приходит из нативного выделения WebView2.
- **Исправлено:** `wrap()` выносит краевые whitespace-символы (пробелы, табы, `\n`/`\r`, NBSP) **наружу** маркеров, оборачивая только непробельное ядро; выделение после вставки ставится на ядро. Пустое выделение — по-прежнему курсор между маркерами; выделение из одних whitespace — оборачивается как есть. bold/italic/code (общий `wrap`) исправлены.
- **Follow-up закрыт:** `link()` тоже нормализует края — `"hello " + Ссылка → [hello](url) world` (текст ссылки — непробельное ядро, краевые whitespace снаружи; для пустого/whitespace-выделения — плейсхолдер «текст»).
- **Тесты:** E2E `crates/app/e2e/features/format.feature` — 6 сценариев (Жирный: замыкающий, ведущий, без пробелов, whitespace-only; Ссылка: замыкающий, без пробелов). На старом коде падало (`**hello **world`); после фиксов — зелёный, полный E2E 9/9.
- **Осталось (вне кода):** реальный двойной клик мышью проверяется вручную (WebDriver задаёт диапазон через `setSelectionRange`).

### BUG-002 — Вкладка «Плагины»: кнопка «Выполнить» и её действие расходятся

- **Статус:** fixed (частично: A + D разобраны и исправлены; C/B выделены отдельно)
- **Severity:** P1
- **Область:** `crates/app/src/pluginManager.ts`, `crates/app/src/docStore.ts`, `crates/app/src-tauri/src/plugins/{manager,bus,host,services}.rs`, `crates/app/src/style.css`, эталонные плагины `plugins/`.
- **Симптом:** в панели 3 плагина. У третьего нет кнопки «Выполнить»; у второго она есть, но при нажатии, по ощущению, выполняется действие третьего. Также заявлена некорректная раскладка блоков.
- **Воспроизведение:** открыть панель «Плагины» (`plugins/word-count`, `format-selection`, `export-html`) → нажать «Выполнить» у `format-selection`.
- **Разбор (systematic-debugging, доказано):** это **НЕ ошибка маршрутизации**. Фронт кладёт `command.id` в `data-command` кнопки и читает его из неё (`pluginManager.ts:134,198`); `run_plugin_command` публикует `command:invoked`, а `pump` доставляет событие **всем активным** плагинам (`host.rs:227-234`) — фильтрация по `command_id` внутри плагина. Порядок `[export-html, format-selection, word-count]` — сортировка по id (`manager.rs:276`); у `word-count` нет `contributes.commands`, поэтому у него нет кнопки (ожидаемо). «Действие третьего плагина» — это `word-count`, который подписан на `document:changed` и печатает «Слова: N» в статусбар после `format-selection.bold` (тот применяет `**…**` ко **всему** документу, т.к. H2 не даёт плагину текущее выделение). Усугубляло то, что плагинная правка **не была видна** в UI (см. A), поэтому единственным откликом на клик оставалось чужое сообщение.
- **Исправлено (A + D, коммит см. ниже):**
  - **A — внешние правки документа доходят до UI.** Новый `DocumentSink` в `DocumentServices` → событие `document-updated{doc_id,rev}` (только для плагинного `apply_edit`, не для фронтового `update_document`); фронт тянет текст командой `document_snapshot(id)` и `docStore.applyHostUpdate` обновляет `#editor`/`#preview`. Правка плагина больше не теряется и видна.
  - **D — группировка панели.** `.pl-actions` пристёгнуты к своему `.pl-item` (hairline сверху), разделитель плагинов усилен (`--line`).
- **Осталось (вынесено, не блокирует):**
  1. **C** — `format-selection` правит весь документ вместо выделения (ограничение H2: `ViewContext` без selection). Решение — в плагинном API/H3, не в этом фиксе.
  2. **B** — `word-count` печатает сообщение после чужой команды (broadcast `document:changed`). Продуктовый вопрос: глушить ли фоновые реакции или ввести в статусбаре различие «команда» vs «событие».
  3. Потеря непушнутого локального ввода при внешней правке — семантика выбрана осознанно (внешняя правка авторитетнее), задокументирована в `docStore.applyHostUpdate`.
- **Тесты:** Rust `plugins::tests` (broadcast `command:invoked`, каскад `document:changed`, вызов `document_sink`) — `cargo test -p darmark` 80 passed; E2E `plugins.feature` — сценарий «Плагинная правка документа доходит до редактора и предпросмотра» (фикстура `e2e-edit`), 8/8 спеков.

### BUG-003 — Инспектор: клик по Предпросмотру не закрепляет выделение

- **Статус:** new
- **Severity:** P2 (новая функциональность, не регресс)
- **Область:** `crates/app/src/inspector.ts`, `crates/app/src/linkController.ts`, поверхность `#btn-inspect`/`Ctrl+I`.
- **Симптом:** при включённом инспекторе клик по области в Предпросмотре выделяет соответствующий диапазон в редакторе, но выделение не «фиксируется»: нет режима «первый клик — закрепить выделение в обеих панелях, следующий клик по любой области — снять закрепление».
- **Воспроизведение:** `Ctrl+I` → клик по блоку в предпросмотре → ожидание закрепления (сейчас отсутствует).
- **Гипотеза/причина:** механизм закрепления не реализован; инспектор лишь программно выставляет выделение.
- **Затрагивает:** `inspector.ts`; **важно:** режим подсветки (`#btn-inspect`, `Ctrl+I`, `#stat-inspect`, `.inspect-*`) менять нельзя/аккуратно — см. UX-spec §2.1.
- **Направление:** состояние «pinned selection» в инспекторе: клик закрепляет (запоминаем диапазон, не сбрасываем на `selectionchange`), повторный клик вне закреплённой области снимает. Не переиспользовать эту фичу под инфо-панель `#infopanel` (UX-spec §11.1 шаг 3).
- **Открытые вопросы:**
  1. Точные правила снятия: любой клик по предпросмотру или только по другой области?
  2. Сохранять ли закрепление при правках текста/перерендере (сдвиг байт↔UTF-16)?
  3. Esc — должен снимать закрепление (сейчас Esc выключает режим инспектора)?

### BUG-004 — Полоса плагинов `#plugin-strip` разрастается (design)

- **Статус:** fixed (решение A — полоса удалена)
- **Severity:** P2
- **Область:** `#plugin-strip` в тулбаре (`index.html`), `crates/app/src/pluginStrip.ts`, `style.css` (`.pbtn`).
- **Симптом:** с ростом числа плагинов (пример: E, F, W…) контекст-бар забивается монограммами; поверхность превращается в «мусор».
- **Воспроизведение:** установить/включить несколько плагинов → тулбар заполняется `.pbtn`.
- **Гипотеза/причина:** шаг 2 §11.1 (`ideas/UX-spec.md`) добавил по одной кнопке на каждый плагин, без лимита/группировки/переполнения.
- **Затрагивает:** `pluginStrip.ts`, `#plugin-strip`, `.pbtn`; замороженные контракты §13.2 — нет.
- **Решение (bounded, согласовано):** полосу **убрали** — тулбар O(1) и не растёт с числом плагинов. Плагинные view остаются доступны вкладками `#view-switch` (их клик полностью покрывает прежнее действие полосы), команды/enable/reload — в панели «Плагины». Изменения: удалены `pluginStrip.ts`, `#plugin-strip`/`.pbtn*` (CSS) и подключение в `main.ts`; откат аддитивного `pluginViews.activatePlugin` и E2E-сценария полосы. Шаг 2 §11.1 в исходном виде **отменён**.
- **Отложено:** вариант B (один триггер «Плагины» с попап-меню, `--pc`/статусы/действия) — зафиксирован как `IDEA-005` в `ideas/UI-IDEAS.md`; тянуть только вместе с инфраструктурой меню/шага 3.
- **Открытые вопросы (на будущее):**
  1. Нужна ли идентичность плагина в тулбаре вообще (или достаточно `view-switch`)?
  2. Переполнение меню при большом числе плагинов (скролл/поиск/группировка).

### BUG-005 — Команда в начале длинного файла прокручивает предпросмотр вниз

- **Статус:** fixed
- **Severity:** P2
- **Область:** `crates/app/src/scrollsync.ts` (`alignEditorToPreview`); проявляется при включённом инспекторе (mapped-рендер/анкоры), в т.ч. после `Ctrl+B`/кнопки «Жирный».
- **Симптом:** с включённым инспектором при команде в начале длинного файла предпросмотр уезжает вниз (~14px), «съедая» верхний отступ первого блока; редактор остаётся на месте. Воспроизводится и просто при включении инспектора с длинным документом, прокрученным в начало.
- **Причина (systematic-debugging, воспроизведено E2E):** `alignEditorToPreview` считает `delta = block.top − preview.top` и вычитает только `padding-top` предпросмотра (10px), но не верхний `margin` блока `.md-block` (14px). У самого верха документа цель = 14 вместо 0. Шина/инспектор/`scrollIntoView` не при чём (трассировка `scrollIntoView` пустая; отключение синхронизации сдвиг убирает).
- **Исправлено:** у самого верха документа (`topLine === 0`) предпросмотр ставится в естественное начало (`scrollTop = 0`); для остальных строк сохранено прежнее анкорное выравнивание (попытка вычитать `margin` блока ломала эвристику «верхний блок», т.к. зазор `.md-block` намеренно больше `padding-top` #preview).
- **Тесты:** `crates/app/e2e/features/format.feature` — сценарии «в начале длинного файла … не сдвигает скролл» (кнопка, `Ctrl+B`, `Ctrl+B` с инспектором) проверяют, что скролл редактора и предпросмотра остаётся в начале; полный E2E 9/9.
- **Открытые вопросы:** нет.
