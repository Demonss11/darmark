# UI-BUGS — баг-бэклог интерфейса

> **Статус:** non-normative, живой список наблюдённых дефектов/UX-проблем UI.
> Нормативная спецификация — `docs/DESIGN_DOC.md` (+ ADR в `docs/adr/`); идеи — `ideas/UI-IDEAS.md`.
> **Как запись продвигается:** `new` → `triaged` (есть причина/план) → `fixing` (TZ/ветка) → `fixed`.
> Сюда же попадают UX-проблемы, требующие решения дизайнера (помечаются `design`).

## Статусы

- `new` — сообщено, не разобрано;
- `triaged` — причина/область установлены, есть направление;
- `fixing` — в работе (ссылка на ветку/TZ);
- `fixed` — исправлено (ссылка на коммит/TZ);
- `wontfix` / `dropped` — отклонено (кратко почему).

## Severity

- `P0` — ломает данные/блокирует работу;
- `P1` — мешает частому действию или даёт неверный результат;
- `P2` — полировка/удобство.

## Шаблон записи

```
### BUG-NNN — <название>
- **Статус:** new | triaged | fixing | fixed | wontfix
- **Severity:** P0 | P1 | P2
- **Область:** <файл/модуль/поверхность>

- **Гипотеза/причина:** <если есть>

- **Направление:** <как чинить>
- **Открытые вопросы:** …
```

### BUG-001 — Выделение мышью захватывает слово вместе с пробелом

- **Статус:** fixed
- **Severity:** P1
- **Область:** `crates/app/src/formatActions.ts` (`wrap` — общий для `bold`/`italic`/`code`; `link`).
- **Симптом:** при выделении слова мышью в выделение попадает замыкающий пробел; после `Ctrl+B` получается `**слово **` вместо `**слово**`. Мешает быстрым командам форматирования.
- **Воспроизведение:** открыть документ → выделить `"hello "` (0..6) → `Ctrl+B` (или кнопка «Жирный»).
- **Причина (подтверждена):** `wrap()` оборачивал выделение как есть, без нормализации краёв. Кастомных обработчиков выделения в коде нет — краевой пробел приходит из нативного выделения WebView2.
- **Исправлено:** `wrap()` выносит краевые whitespace-символы (пробелы, табы, `\n`/`\r`, NBSP) **наружу** маркеров, оборачивая только непробельное ядро; выделение после вставки ставится на ядро. Пустое выделение — по-прежнему курсор между маркерами; выделение из одних whitespace — оборачивается как есть. bold/italic/code (общий `wrap`) исправлены.
- **Follow-up закрыт:** `link()` тоже нормализует края — `"hello " + Ссылка → [hello](url) world` (текст ссылки — непробельное ядро, краевые whitespace снаружи; для пустого/whitespace-выделения — плейсхолдер «текст»).
- **Тесты:** E2E `crates/app/e2e/features/format.feature` — 6 сценариев (Жирный: замыкающий, ведущий, без пробелов, whitespace-only; Ссылка: замыкающий, без пробелов). На старом коде падало (`**hello **world`); после фиксов — зелёный, полный E2E 9/9.
- **Осталось (вне кода):** реальный двойной клик мышью проверяется вручную (WebDriver задаёт диапазон через `setSelectionRange`).

### BUG-002 — Вкладка «Плагины»: кнопка «Выполнить» и её действие расходятся

- **Статус:** fixed (частично: A + D разобраны и исправлены; C/B выделены отдельно)
- **Severity:** P1
- **Область:** `crates/app/src/pluginManager.ts`, `crates/app/src/docStore.ts`, `crates/app/src-tauri/src/plugins/{manager,bus,host,services}.rs`, `crates/app/src/style.css`, эталонные плагины `plugins/`.
- **Симптом:** в панели 3 плагина. У третьего нет кнопки «Выполнить»; у второго она есть, но при нажатии, по ощущению, выполняется действие третьего. Также заявлена некорректная раскладка блоков.
- **Воспроизведение:** открыть панель «Плагины» (`plugins/word-count`, `format-selection`, `export-html`) → нажать «Выполнить» у `format-selection`.
- **Разбор (systematic-debugging, доказано):** это **НЕ ошибка маршрутизации**. Фронт кладёт `command.id` в `data-command` кнопки и читает его из неё (`pluginManager.ts:134,198`); `run_plugin_command` публикует `command:invoked`, а `pump` доставляет событие **всем активным** плагинам (`host.rs:227-234`) — фильтрация по `command_id` внутри плагина. Порядок `[export-html, format-selection, word-count]` — сортировка по id (`manager.rs:276`); у `word-count` нет `contributes.commands`, поэтому у него нет кнопки (ожидаемо). «Действие третьего плагина» — это `word-count`, который подписан на `document:changed` и печатает «Слова: N» в статусбар после `format-selection.bold` (тот применяет `**…**` ко **всему** документу, т.к. H2 не даёт плагину текущее выделение). Усугубляло то, что плагинная правка **не была видна** в UI (см. A), поэтому единственным откликом на клик оставалось чужое сообщение.
- **Исправлено (A + D, коммит см. ниже):**
  - **A — внешние правки документа доходят до UI.** Новый `DocumentSink` в `DocumentServices` → событие `document-updated{doc_id,rev}` (только для плагинного `apply_edit`, не для фронтового `update_document`); фронт тянет текст командой `document_snapshot(id)` и `docStore.applyHostUpdate` обновляет `#editor`/`#preview`. Правка плагина больше не теряется и видна.
  - **D — группировка панели.** `.pl-actions` пристёгнуты к своему `.pl-item` (hairline сверху), разделитель плагинов усилен (`--line`).
- **Осталось (вынесено, не блокирует):**
  1. **C** — `format-selection` правит весь документ вместо выделения (ограничение H2: `ViewContext` без selection). Решение — в плагинном API/H3, не в этом фиксе.
  2. **B** — `word-count` печатает сообщение после чужой команды (broadcast `document:changed`). Продуктовый вопрос: глушить ли фоновые реакции или ввести в статусбаре различие «команда» vs «событие».
  3. Потеря непушнутого локального ввода при внешней правке — семантика выбрана осознанно (внешняя правка авторитетнее), задокументирована в `docStore.applyHostUpdate`.
- **Тесты:** Rust `plugins::tests` (broadcast `command:invoked`, каскад `document:changed`, вызов `document_sink`) — `cargo test -p darmark` 80 passed; E2E `plugins.feature` — сценарий «Плагинная правка документа доходит до редактора и предпросмотра» (фикстура `e2e-edit`), 8/8 спеков.

### BUG-003 — Инспектор: клик по Предпросмотру не закрепляет выделение

- **Статус:** fixed
- **Severity:** P2 (новая функциональность, не регресс)
- **Область:** `crates/app/src/inspector.ts` (состояние `pinned`), поверхность `#btn-inspect`/`Ctrl+I`.
- **Затрагивает:** `crates/app/src/inspector.ts`; замороженные контракты §13.2 — нет. Режим подсветки (`#btn-inspect`, `Ctrl+I`, `#stat-inspect`, `data-md`, `.inspect-*`) не переименовывался/не перевязывался (UX-spec §2.1).
- **Симптом:** при включённом инспекторе клик по области в Предпросмотре выделяет соответствующий диапазон в редакторе, но выделение не «фиксируется»: нет режима, где клик закрепляет выделение в обеих панелях, а повторный клик снимает закрепление.
- **Воспроизведение:** `Ctrl+I` → клик по блоку в предпросмотре → ожидание закрепления.
- **Причина (подтверждена):** механизм закрепления не был реализован; инспектор реагировал на `mouseover`/`mouseout` и программно выставлял выделение, снимая подсветку при уходе курсора.
- **Исправлено:** в `inspector.ts` добавлено состояние `pinned`.
  - **Закрепление:** клик по блоку/ячейке (`onClickCapture`) применяет цель (`applyTarget(..., force)`) и ставит `pinned = true`. Пока закреплено, `onMouseOver`/`onMouseOut`/`onEditorSelection`/`onShiftKey` игнорируются — подсветка и выделение не меняются при наведении, уходе курсора и движении каретки.
  - **Перенос:** клик по **другому** блоку/ячейке переносит закрепление на него (событие поглощается, выделение и фокус — в редакторе).
  - **Снятие:** повторный клик по **тому же** блоку или клик по **пустой области** снимает закрепление, гасит подсветку/бэнды и возвращает сохранённый фокус. Клик по интерактивному элементу (`th`/ссылка/меню фильтра) тоже снимает закрепление, но событие отдаётся дальше (сортировка/переход).
  - **Сброс:** закрепление также снимается при перестройке индекса (`onIndexChanged` — правка/перерендер, смещения устарели) и при выходе из режима (`disable`).
- **Направление (реализовано):** состояние «pinned selection» локально в инспекторе; режим подсветки (`#btn-inspect`, `Ctrl+I`, `#stat-inspect`, `.inspect-*`) и его контракты не менялись. Инфо-панель `#infopanel` (UX-spec §11.1) не переиспользована.
- **Открытые вопросы (закрыты):**
  1. Снятие — **повторный клик по тому же блоку или клик по пустой области**; клик по другому блоку переносит закрепление. Клик по интерактивному элементу (`th`/ссылка/меню) снимает закрепление, событие отдаётся дальше.
  2. При правке текста/перерендере закрепление **сбрасывается** (байтовые смещения блока после правки недействительны).
  3. `Esc` по-прежнему **полностью выключает режим инспектора** (закрепление снимается как следствие); отдельного «Esc — сначала снять закрепление, второй Esc — выйти» не вводили.
- **Тесты:** E2E `crates/app/e2e/features/inspector-pin.feature` (без `@wip`) — три сценария: «Клик по блоку закрепляет подсветку и выделение», «Клик по другому блоку переносит закрепление», «Повторный клик по тому же блоку снимает закрепление»; регрессия `inspector.feature`/`inspect-tables.feature` (клик/наведение/`mouseout`) зелёная. Полный E2E — **10 passed, 10 total**.
- **Коммит:** `da92a9a` (реализация), `e9f1a33` (уточнение семантики: перенос закрепления); ветка `ui/ux-11.1-style-tokens`.

### BUG-004 — Полоса плагинов `#plugin-strip` разрастается (design)

- **Статус:** fixed (решение A — полоса удалена)
- **Severity:** P2
- **Область:** `#plugin-strip` в тулбаре (`index.html`), `crates/app/src/pluginStrip.ts`, `style.css` (`.pbtn`).
- **Симптом:** с ростом числа плагинов (пример: E, F, W…) контекст-бар забивается монограммами; поверхность превращается в «мусор».
- **Воспроизведение:** установить/включить несколько плагинов → тулбар заполняется `.pbtn`.
- **Гипотеза/причина:** шаг 2 §11.1 (`ideas/UX-spec.md`) добавил по одной кнопке на каждый плагин, без лимита/группировки/переполнения.
- **Затрагивает:** `pluginStrip.ts`, `#plugin-strip`, `.pbtn`; замороженные контракты §13.2 — нет.
- **Решение (bounded, согласовано):** полосу **убрали** — тулбар O(1) и не растёт с числом плагинов. Плагинные view остаются доступны вкладками `#view-switch` (их клик полностью покрывает прежнее действие полосы), команды/enable/reload — в панели «Плагины». Изменения: удалены `pluginStrip.ts`, `#plugin-strip`/`.pbtn*` (CSS) и подключение в `main.ts`; откат аддитивного `pluginViews.activatePlugin` и E2E-сценария полосы. Шаг 2 §11.1 в исходном виде **отменён**.
- **Отложено:** вариант B (один триггер «Плагины» с попап-меню, `--pc`/статусы/действия) — зафиксирован как `IDEA-005` в `ideas/UI-IDEAS.md`; тянуть только вместе с инфраструктурой меню/шага 3.
- **Открытые вопросы (на будущее):**
  1. Нужна ли идентичность плагина в тулбаре вообще (или достаточно `view-switch`)?
  2. Переполнение меню при большом числе плагинов (скролл/поиск/группировка).

### BUG-005 — Команда в начале длинного файла прокручивает панели вниз

- **Статус:** fixed
- **Severity:** P2
- **Область:** `crates/app/src/formatActions.ts` (`commit`) + `crates/app/src/scrollsync.ts` (`alignEditorToPreview`); проявляется при `Ctrl+B` и особенно при клике по кнопке тулбара «Жирный».
- **Симптом:** при команде в начале длинного файла прокрутка уезжает вниз. При `Ctrl+B` (редактор в фокусе) — небольшой сдвиг предпросмотра (~14px) с включённым инспектором; **при клике по кнопке** — редактор уезжает почти к концу документа (~5000px), предпросмотр следует за ним.
- **Причина (systematic-debugging, воспроизведено E2E, две независимые):**
  1. **Кнопочный путь.** Реальный клик по кнопке снимает фокус с редактора. Затем `formatActions.commit` присваивает `host.value`, зовёт `host.focus()` (без `preventScroll`) — браузер прокручивает редактор к каретке/концу; `setSelectionRange` в WebView2 позицию не возвращает. При `Ctrl+B` редактор уже в фокусе, поэтому не воспроизводилось.
  2. **Анкорный путь при инспекторе.** `scrollsync.alignEditorToPreview` вычитал только `padding-top` #preview (10px), но не верхний `margin` первого `.md-block` (14px): у самого верха документа цель = 14 вместо 0.
- **Исправлено:**
  1. `commit` сохраняет `scrollTop`/`scrollLeft`, использует `focus({ preventScroll: true })` и возвращает позицию после `setSelectionRange` — формат-команда больше не двигает прокрутку редактора.
  2. `alignEditorToPreview` при верхней логической строке (`topLine === 0`) ставит предпросмотр в `scrollTop = 0`; остальное выравнивание сохранено (попытка вычитать `margin` блока ломала эвристику «верхний блок», т.к. зазор `.md-block` намеренно больше `padding-top`).
- **Тесты:** `crates/app/e2e/features/format.feature` — сценарии «в начале длинного файла … не сдвигает скролл» (кнопка с реалистичным снятием фокуса, `Ctrl+B` с курсором, `Ctrl+B`, кнопка+C инспектор) проверяют, что `#editor` и `#preview` остаются в начале; полный E2E 9/9.
- **Открытые вопросы:** нет.

### BUG-006 — UI-ревью: доступность базовых контролов (B1/M2/M3/M4/M5/M6/M7/M8/M9)

- **Статус:** fixed (обе итерации; остался только необязательный nit по анимации sidebar)
- **Severity:** P1 (B1 — блокер клавиатурной навигации)
- **Область:** `crates/app/index.html`, `crates/app/src/style.css`, `crates/app/src/tables.ts`,
  `crates/app/src/shell.ts`, `crates/app/src/inspector.ts`, `crates/app/e2e/**`.
- **Источник:** UI-ревью по Web Interface Guidelines (скилл `web-design-guidelines`), read-only.
- **Симптом (по ревью):**
  - **B1** — тумблеры `#toggle-sync`/`#toggle-preview`: скрытый `input` (`0×0`, `opacity:0`) без доступного имени; фокус при Tab не виден (у `label.tbtn` нет `:focus-within`).
  - **M2** — icon-only кнопки rail (`#rail-explorer`/`-plugins`/`-logs`) имели только `title`.
  - **M8** — `#editor { outline: none }` (id-селектор) глушил глобальный `:focus-visible` — у редактора не было фокус-ринга.
  - **M1** — нет `prefers-reduced-motion`; **M3** — `th` терял роль `columnheader` (`role="button"`), воронка вложена в `role=button`, не было `aria-sort`; **M4** — поисковые поля таблиц без меток; **M5** — popup-фильтр без `role`, не закрывался по Escape и не возвращал фокус; **M6** — статусбар не объявлялся скринридеру; **M7** — `#editor` без доступного имени; **M9** — `--fg-mute` ≈3.1:1.
- **Исправлено (приоритет-1, коммит `8f04857`):**
  1. **B1** — `input` тумблеров получили `role="switch"` + `aria-label` («Синхронная прокрутка» / «Предпросмотр»), декоративные `svg` — `aria-hidden="true" focusable="false"`; добавлено `label.tbtn:focus-within { outline: 2px solid var(--accent); outline-offset: 1px; }`.
  2. **M2** — rail-кнопкам добавлены `aria-label` («Файлы» / «Плагины» / «Журнал»).
  3. **M8** — добавлено `#editor:focus-visible { outline: 2px solid var(--accent); outline-offset: -2px; }`. **Отменено** (см. BUG-007): рамка оказалась навязчивой (редактор почти всегда в фокусе), убрана по замечанию пользователя.
- **Исправлено (вторая итерация, коммит см. ниже):**
  - **M1** — в `style.css` добавлен `@media (prefers-reduced-motion: reduce)`, гасящий `animation`/`transition` и `scroll-behavior` (в т.ч. анимацию `width` sidebar).
  - **M3** — сам `th` сохраняет нативную роль `columnheader`; сортировка вынесена в кнопку `.col-sort-btn` (доступное имя «Сортировать по столбцу «…»», Enter/Space «из коробки», inline-разметка заголовка сохранена); `apply()` выставляет `aria-sort` (`ascending`/`descending`/`none`); воронка `.col-filter-btn` получила `aria-label` и `aria-expanded`. Заголовок с интерактивом (ссылка/контрол) не оборачивается в `<button>` (без невалидной вложенности) — кнопка сортировки ставится рядом значком «↕».
  - **M4** — у поиска по таблице и мини-поиска фильтра — `aria-label` + `autocomplete="off"`.
  - **M5** — popup-фильтр: `role="dialog"` + `aria-label` (без `aria-modal`: фокус не запирается, фон не инертен — ложная модальность не заявляется); закрытие по Escape (capture-слушатель, событие не уходит в shell), возврат фокуса на воронку; `aria-expanded` воронки отражает состояние; флип поповера у нижней границы окна; поповер закрывается при перерисовке предпросмотра (не остаётся «осиротевшим»).
  - **M6** — `#stat-msg` → `role="status"` + `aria-live="polite"`; `#stat-inspect` → `role="status"` + `aria-live="polite"`, текст выставляется/сбрасывается в `enable`/`disable` (live-region объявляет именно мутацию содержимого).

### BUG-007 — Ручная проверка после BUG-006: рамка редактора, белый угол, favicon и set_title

- **Статус:** fixed
- **Severity:** P1 (шумные ошибки в консоли + заметный визуальный дефект)
- **Область:** `crates/app/src/style.css`, `crates/app/src/statusBar.ts`, `crates/app/index.html`, `crates/app/public/favicon.ico`, `crates/app/src-tauri/capabilities/default.json`.
- **Симптом (замечено при ручном запуске `npx tauri dev`):**
  1. `#editor` обведён фиолетовой рамкой — focus-ring из M8 (`#editor:focus-visible`); редактор почти всегда в фокусе, поэтому рамка постоянная и навязчивая.
  2. В правом нижнем углу редактора — белый квадрат: неоформленный стык скроллбаров `::-webkit-scrollbar-corner` на тёмной теме.
  3. `GET /favicon.ico 404` — значка нет в раздаче.
  4. `Uncaught (in promise) window.set_title not allowed … core:window:allow-set-title` — в capability не было разрешения на `set_title`.
- **Исправлено:**
  1. Убрано правило `#editor:focus-visible`; индикатор фокуса редактора — каретка (**M8 отменён осознанно**, см. BUG-006).
  2. Добавлено `::-webkit-scrollbar-corner { background: transparent; }`.
  3. Добавлен `crates/app/public/favicon.ico` (копия `src-tauri/icons/icon.ico`) и `<link rel="icon" href="/favicon.ico">`; Vite отдаёт из `public/`.
  4. В `capabilities/default.json` добавлено `core:window:allow-set-title`; `updateTitle` гасит возможный reject (`.catch`), чтобы не плодить unhandled rejection.
- **Тесты:** E2E `a11y.feature` — сценарий «У редактора виден фокус-ринг» удалён; остальные зелёные. Полный E2E — **11 passed, 11 total**.
