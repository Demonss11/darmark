# UI_CONCEPT v3 — «Плагины как первоклассные граждане интерфейса»

> Документ усиления интерфейса к `DESIGN_DOC.md` (нормативная спецификация) и прототипу
> `front_idea3.html` (интерактивная демонстрация, полностью автономная — без CDN и сети).
> Предыдущая итерация — `front_idea2.html`. Нумерация § — ссылки на DESIGN_DOC.

---

## 0. Тезис усиления

**idea2** показывала «ещё один тёмный Markdown-редактор»: плагинная система — главная продуктовая
фича (§1.2) — была в UI почти невидима (строка в статусбаре и файл `word-count.lua` в дереве).

**idea3** строит интерфейс вокруг обещания продукта: *пользователь должен за 10 секунд увидеть,
почему «открыл `.lua` — поправил — работает» — это не слоган, а механика.* Каждый слой UI делает
плагинную систему **видимой, осязаемой и заслуживающей доверия**:

| Принцип | Что означает в UI |
|---|---|
| **Видимость** | У каждого плагина есть цвет; все его вклады (view, статусбар, тулбар, команды) помечены этим цветом и подписаны именем плагина |
| **Осязаемость** | Главный цикл §1.2 воспроизведён буквально: `main.lua` открывается как документ, над редактором появляется pill «⟳ Перезагрузить плагин (Ctrl+R)» — правка подхватывается без перезапуска |
| **Доверие** | Разрешения (§8) — не скрытая настройка, а интерфейс: чипы на карточках, диалог установки с предупреждением §11.4, живая демонстрация `permission_denied` |
| **Честность отказов** | Карантин (§10.2) и падения child-процесса показаны как состояния UI, а не как тишина: счётчик «2/3 до карантина», снятие вкладов, журнал с exit-кодами |
| **Соответствие модели** | Pane/View/тиры (§5.2–5.3) не спрятаны в коде, а предъявлены: вкладки-view в шапках панелей с бейджами T1/T2 и точкой происхождения (core/плагин) |

## 1. Семь усилений интерфейса

### 1.1. Панель плагинов — «центр управления» (activity bar → sidebar)
Activity bar (иконки слева) переключает контексты сайдбара: **Проводник** и **Плагины** (с бейджем
количества; бейдж желтеет, если хоть один плагин не в состоянии `active`).

Карточка плагина показывает всё, что о нём знает хост:
- статус: `активен / failed / карантин / отключён` (цвета состояний закреплены в дизайн-системе, §3 ниже);
- **permissions как чипы** (§8): выданные — зелёные; опциональные — пунктирные, клик = выдать/отозвать
  с записью в журнал («проверка — на стороне хоста, до вызова»);
- **contributes одной строкой** (§6.4): views (с тиром), команды (с кейбиндами), статусбар, тулбар;
- действия: ⟳ Перезагрузить · ‹/› Открыть `.lua` · Открыть view · ⏻ Отключить;
- для нестабильного плагина — счётчик падений «N/3 до карантина» и кнопка демонстрации отказа.

Трассировка: §6.2 (плагин=код, инстанс=привязка), §6.6 (жизненный цикл), §8, §10.2.

### 1.2. Цикл «правлю `.lua` → перезагрузил → работает» (§1.2) — буквально в UI
Открытие `plugins/word-count/main.lua` из дерева или с карточки плагина:
1. редактор переключается на файл плагина (превью честно сообщает «файл не Markdown, `to_html` не вызывался»);
2. над редактором появляется **lua-pill**: «Файл плагина word-count · v1.0.1 · есть несохранённые правки» + кнопка ⟳;
3. перезагрузка (кнопка или Ctrl+R) выполняет полный цикл §6.6 в журнале:
   `unload → on_deactivate → child остановлен` → `load → lua.load(src).set_name(...) → новый child` → `on_activate`;
4. **версия подхватывается из текста**: плагин в демо declares `local VERSION = "…"` — изменил строку,
   перезагрузил, карточка и все вклады показывают новую версию. Это и есть продуктовое обещание, доведённое до интерактива.

### 1.3. Модель Pane/View видна пользователю (§5.2–5.3, D4)
- Две панели (`pane-a`, `pane-b`) с resize-ручкой; в шапке каждой — **вкладки-view**, а не только имя файла.
- На вкладке-view: цветная точка происхождения (core = акцент, плагин = его цвет), название, бейдж **T1/T2**
  (тир провайдера), у плагинных view — кнопка «убрать из панели».
- Вкладки документов (files) и вкладки views (способы показа) разделены — это ровно граница
  `Document` (Rust, §4) vs `View` (TS, §5.3).
- Инспектор показывает текущие `pane / view / тир` — модель данных прозрачна.
- Кнопка «Разделить» честно отвечает: `MAX_PANES = 2 (§5.2) — уже достигнуто`.

### 1.4. Вклады плагинов с атрибуцией (§6.4)
| Поверхность | Как усилена |
|---|---|
| **Статусбар** (`ui:statusbar`) | элементы плагинов с цветной точкой и tooltip «contributes.statusbar (§6.4)»; клик открывает view плагина или запускает его команду; при карантине/отключении элемент **исчезает** — связь «состояние плагина ↔ поверхность UI» наглядна |
| **Тулбар** (`ui:toolbar`) | отделён сепаратором от ядровых кнопок; у плагинной кнопки цветная точка-маркер в углу |
| **Палитра команд** | у каждой команды бейдж происхождения: `core` (нейтральный) или `word-count` / `todo-lens` (цвет плагина); команды неактивных плагинов пропадают из выдачи |
| **View** (`view:create`) | тир-1 view плагина («Статистика», «Задачи») — отдельные вкладки в pane-b рядом со встроенным «Предпросмотром» (тоже T1, но «встроен на хосте», D2) |

`host.show_message` (§6.3) маршрутизируется в `stat-msg` статусбара — как в спецификации.

### 1.5. Разрешения и отказы как интерфейс (§8, §10, §11.4)
Три сценария доверия, которые пользователь может **прожить руками**:
1. **Установка**: диалог с чекбоксами permissions, обязательным предупреждением
   «плагин с permission `document` видит содержимое документа полностью (§11.4)», кнопки
   «Отклонить / Разрешить и установить». Установка пишет в журнал весь конвейер:
   `scan → validate manifest (api_version ≤ HOST) → подтверждение прав → spawn child (Job Object) → on_activate`.
2. **`permission_denied` вживую**: в view «Статистика» кнопка «Вставить сводку в курсор» без
   `document:write` даёт ровно то, что предписывает §8 — `error { code: "permission_denied" }`
   (в журнале + toast), а **не** исключение Lua и не тихий отказ. Выдал permission чипом на карточке —
   та же кнопка теперь выполняет `apply_edit` (журнал показывает диапазон и новую `rev`; undo — в Rust, D5).
3. **Карантин**: кнопка «☠ Уронить (демо)» на карточке `csv-peek` роняет child: журнал показывает
   Lua-ошибку, exit-код, перезапуск; счётчик «N/3»; на третьем — статус «карантин», вклады сняты,
   выход только вручную (§10.2). Приложение живо — уровень доверия «не сломает приложение» (§10.3) продемонстрирован.

### 1.6. Журнал хоста и лента событий (нижняя панель)
- **Журнал**: строки `время · источник · сообщение`; источники-плагины подсвечены своими цветами;
  фильтр по источнику; счётчик ошибок на иконке activity bar. Это визуализация `host.log → stderr` (§6.3)
  и окно наблюдения за child-процессами (§10).
- **События**: лента `document:changed / document:opened / view:focus / command:invoked / pane:resized`
  с **коалесингом по rev** (§9.3): частый ввод схлопывается в одну запись «×N коалесцировано», а сама
  запись честно подписана «notify-only: содержимое плагин тянет сам (§9.2)».
- **Обратная маршрутизация (§9.4)** показана в журнале: клик по элементу плагинного view логируется как
  `← on_action {view, action, payload} · data-p-<id>-*`, затем — решение хоста (apply_edit или permission_denied).

### 1.7. Данные вместо декораций
Прототип v2 показывал «rev 42» и «12 мс» как наклейки. В v3 всё настоящее:
- собственный мини-рендерер Markdown, воспроизводящий **замороженный контракт §3**: топ-блоки
  обёрнуты в `<div class="md-block" data-md="start,end">` с реальными **байтовыми смещениями UTF-8**
  (проверяется roundtrip-срезом источника);
- `rev` инкрементируется на каждую правку, дебаунс рендера — **120 мс** (константа §13.2), время рендера измеряется;
- инспектор: позиция/смещение курсора в байтах, блок под курсором (тип + диапазон из `data-md`),
  RenderIndex («N байт ↔ M code units»), подписчики `document:changed`;
- блок под курсором подсвечивается в превью (cursor-block), скролл-синхро — по ratio с throttle 100 мс (§13.2);
- таблицы (D12) украшены по замороженным селекторам: `.table-enhanced`, `.table-count`, `.table-scroll`,
  `.col-filter-btn` + меню фильтров `.col-filter-menu`/`.col-filter-item`, инспекция ячейки
  `.inspect-active`/`.inspect-col`/`tr.inspect-row`;
- санитизация: весь пользовательский/плагинный вывод экранируется, `window.__xss === false`,
  `window.__errors`/`__errorCapture` присутствуют (§13.2).

## 3. Дизайн-система (добавления к idea2)

| Токен/правило | Значение |
|---|---|
| Цвет плагина | у каждого плагина свой `--pc`; используется ЕДИНООБРАЗНО: точка карточки, точка вкладки-view, точка статусбара, бейдж в палитре, источник в журнале, подсветка cursor-block у его правок. Правило: «глаз должен находить плагин по цвету за один проход» |
| Статусы | `active` — зелёный, `failed/quarantined` — красный, `off` — приглушённый + opacity карточки, `warn/crash` — янтарный |
| Бейдж тира | `T1` (HtmlView, JSON→HTML) / `T2` (DomView, built-in) — на каждой вкладке-view; обучает модели §5.3 без документации |
| Чип permission | выдан — зелёная рамка; опциональный — пунктир «+ document:write» (клик выдать); отозванный — исчезает |
| Анимации | только функциональные: flash карточки при reload/install (подтверждение), slide-down lua-pill, toast-in/out; ≤ 300 мс |
| Тема | тёмная (дефолт) + светлая; переключение — `data-theme` на `<html>`, все цвета через токены |
| Шрифты | системные (без CDN): UI — system stack, код/журнал — Cascadia/JetBrains/mono fallback |

## 4. Ключевые сценарии (что кликать в прототипе)

1. **Главная фича (§1.2)**: Проводник → `plugins/word-count/main.lua` → изменить `local VERSION = "1.1.0"` → pill «⟳ Перезагрузить» → карточка и журнал показывают v1.1.0. Без перезапуска.
2. **Доверие (§8)**: pane-b → view «Статистика» → «🔒 Вставить сводку» → toast+журнал `permission_denied` → панель Плагины → чип «+ document:write» → повторить → `apply_edit` вставляет текст, `rev` растёт.
3. **Отказоустойчивость (§10.2)**: карточка `csv-peek` → «☠ Уронить» ×3 → карантин: элемент «CSV: N табл.» исчезает из статусбара, команды нет в палитре, выход — кнопкой.
4. **Установка (§8, §11.4)**: «+ Установить» → reading-time → диалог permissions с предупреждением → разрешить → новый элемент в статусбаре и команда в палитре появляются мгновенно.
5. **Обратная маршрутизация (§9.4)**: view «Задачи» → клик по чекбоксу → в журнале: `← on_action {…}` → `apply_edit(todo-lens)` → текст и превью обновились, undo-стек — за хостом (D5).
6. **Модель событий (§9.2–9.3)**: открыть bottom-панель (Ctrl+\`) → вкладка «События» → быстро печатать в редакторе → записи `document:changed` схлопываются «×N коалесцировано».
7. **Палитра**: Ctrl+Shift+P → «слова» → команда `Word Count: Посчитать слова` с бейджем плагина; Ctrl+P — файлы.

## 6. Что намеренно НЕ добавлено (рамки)

- CodeMirror-подсветка в textarea — отдельный ADR (§15, ADR-6); pill и gutter не претендуют на редактор кода.
- Excel-таблицы не развиваются сверх замороженного `tables.ts` (D12) — в v3 они лишь приведены к замороженным селекторам.
- Реальный child-процесс/Job Object/stdio-RPC в HTML-прототипе симулируются журналом; контракт сообщений соответствует §7.
- Сетевой доступ плагинов не имитируется вообще (§1.3, §8).
