## Что есть сейчас (сжатая карта)

**Rust — полностью stateless.** `md-core`: 1867 строк, чистые `to_html` / `to_html_with` / `to_html_mapped`, serde вообще нет, контракт с JS — голый `String` HTML + атрибут `data-md="start,end"` (байты UTF-8). `src-tauri/lib.rs`: 179 строк, ровно 3 команды (`read_file`, `write_file`, `render_markdown`), **ни `app.manage`, ни `State<..>`, ни `emit`**. serde/serde_json в Cargo.toml объявлены, но не используются. Ошибка — `String` с префиксом пути.

**TS — состояние документа живёт в top-level `let` файла `main.ts`:** `currentPath`, `dirty`, `renderSeq`, `lastRenderedHtml`, `debounceTimer` рядом с DOM-хуками (`editor`, `preview`, `statPos`…). `editor.value` — это и есть «документ». `doRender()` (35 строк) смешивает IPC, `preview.innerHTML`, `enhanceTables`, `resolveLocalImages`, переиндексацию inspector и scrollsync. Понятий Document/Pane/View в репозитории нет вообще (grep ноль; `#panes` — просто flex-контейнер).

Три находки, которые прямо блокируют 2 панели:
1. `tables.ts` держит **модульные** `openMenu`, `outsideHandler`, `anchorSeq` + вешает меню фильтров в `document.body` → со вторым preview синглтон сломается.
2. `inspector.ts` и `scrollsync.ts` **независимо** строят одни и те же `buildUnitMaps`/`collectBlocks` из одного markdown.
3. E2E захардкодили `#editor`/`#preview`, `.md-block[data-md]`, `.table-enhanced*`, `.inspect-*`, дебаунс 120 мс, `ECHO_MS=100`, стартовый текст «Добро пожаловать в mdedit», `window.__errors`/`__xss` — это контракт, id-а должны выжить.

## Целевая модель

### Идентификаторы — строковые, newtype-брендированные

```ts
// src/core/ids.ts
type Brand<T, K extends string> = T & { readonly __b: K };
export type DocumentId = Brand<string, "doc">;
export type PaneId     = Brand<string, "pane">;
export type ViewId     = Brand<string, "view">;   // экземпляр вью внутри панели
```
Строки, а не числа: JSON-RPC/JSON-RPC-подобные манифесты плагинов operируют строковыми ключами, плагину нельзя доверять генерацию уникальных чисел. На Rust — `#[serde(transparent)] pub struct DocumentId(String)`.

### Кто чем владеет (главное решение)

| | Владелец | Почему |
|---|---|---|
| текст, rev, id↔path, кэш рендера | **Rust** `DocumentStore` | плагин (wasmi/stdio) никогда не увидит DOM — единственный общий знаменатель для контента это Rust-ядро; плюс туда же переезжает кэш |
| dirty, selection, scroll, фокус, layout, pane | **TS** | нужно синхронно на каждое нажатие; иначе IPC на клавишу |
| HTML документа | **Rust** (уже: `sanitize_html`) | тот же путь для плагина |

Правило: TS-`DocumentStore` — **проекция** (зеркало) Rust-стора, а не второй источник истины. Иначе получим рассинхрон.

### Layout — дерево с ограничением глубины

```ts
// src/core/layout.ts
export interface Pane  { kind: "pane"; id: PaneId; doc: DocumentId; view: ViewKind }
export interface Split { kind: "split"; id: string; dir: "row" | "column";
                         children: [LayoutNode, LayoutNode] }
export type LayoutNode = Pane | Split;

const MAX_PANES = 2;                      // единственное ограничение v1
// валидатор: все children сплита —Pane (глубина 1), countPanes <= MAX_PANES
export type LayoutOp =
  | { t: "split";  pane: PaneId; doc: DocumentId; view: ViewKind }
  | { t: "close";  pane: PaneId }                       // parent схлопывается в сиблинга
  | { t: "setView"; pane: PaneId; view: ViewKind }
  | { t: "setActive"; pane: PaneId };
```
Чистая функция `(layout, op) => layout | ValidationError` — без DOM. DOM-рендер дерева — 30 строк рекурсии, каждый хост получает `data-pane="<PaneId>"`.

### ViewProvider — два тира, и это суть «обкатки контракта»

Ключевая идея: **не один интерфейс, а два**. Иначе «обкатка» окажется обкаткой невозможного контракта.

```ts
// src/core/viewProvider.ts
export type ViewKind = string;                      // "editor" | "preview" | позже "acme.chart"
export type Json = string | number | boolean | null | Json[] | { [k: string]: Json };

/** Тир 1 — plugin-safe: только JSON, только HTML. Ровно то, что сможет wasmi/stdio-плагин. */
export interface HtmlViewProvider {
  readonly kind: ViewKind;
  readonly title: string;                           // для заголовка панели (→ манифест плагина)
  createView(ctx: ViewContext, opts: Json): HtmlView;
}
export interface HtmlView {
  render(doc: DocumentSnapshot): Promise<void>;     // получатель HTML; innerHTML — ТОЛЬКО здесь
  dispose(): void;
}

/** Тир 2 — built-in only: полный DOM (редактор, Excel-таблицы, инспектор). */
export interface DomViewProvider { readonly kind: ViewKind; readonly title: string;
  createView(ctx: ViewContext, host: HTMLElement, opts: Json): DomView }
export interface DomView { activate(): void; deactivate(): void; dispose(): void }

/** Единственная «песочница»: узкий фасад вместо произвольного доступа к хосту. */
export interface ViewContext {
  readonly paneId: PaneId; readonly viewId: ViewId;
  document(): DocumentSnapshot | null;
  edit(text: string): void;                          // правка документа (editor view)
  render(text: string, mapped: boolean): Promise<RenderResult>;   // единственный путь в md-core
  status(msg: string): void;
  openExternal(url: string): void;
  onDocument(cb: (d: DocumentSnapshot) => void): () => void;     // → unsubscribe
}
```

Что именно это обкатывает уже сейчас, без WASM:
- `PreviewView` реализуется **только** через тир 1 (`HtmlView`): асинхронный вход, HTML-строка на выходе, `opts: Json`, `dispose()`. То есть завтра `createView` становится вызовом `view.create {paneId, viewId, opts}`, а `render` — `view.render`, и интерфейс не меняется.
- HTML плагина пойдёт через **тот же** `sanitize_html`, что и `render_markdown` (санитайзер v2 уже есть, 63 теста) — симметрия контракта, а не новая дыра.
- `ViewContext` заведомо уже, чем «всё, что есть в main.ts»: сегодня мы *можем* дать плагину живые объекты, но не даём — чтобы миграция на wasmi была заменой транспорта, а не переразделом.

### Rust-стор

```rust
// crates/app/src-tauri/src/state.rs   ← НЕ в md-core (README: ядро не знает про GUI)
pub struct DocumentStore { docs: HashMap<DocumentId, Document>, order: Vec<DocumentId> }
struct Document { id: DocumentId, path: Option<PathBuf>, text: String,
                  rev: u64, cached: Option<(bool, u64, String)> } // (mapped, rev, html)
// app.manage(Mutex<DocumentStore>::default())
```

Команды (→ будущие JSON-RPC методы, 1:1):

| команда | сигнатура | заменяет |
|---|---|---|
| `new_document` | `(text?) -> DocMeta` | `newFile()` |
| `open_document` | `(path) -> DocMeta` | `read_file` + `currentPath` |
| `update_document` | `(id, text, mapped) -> RenderResult{html, rev, changed}` | `render_markdown` + `lastRenderedHtml` + `renderSeq` |
| `render_document` | `(id, mapped) -> RenderResult` | повторный рендер при вкл/выкл инспектора |
| `save_document` | `(id, path?) -> DocMeta` | `write_file` |
| `close_document` | `(id) -> ()` | — (появляется вместе с 2 панелями) |

`changed: false` при том же `rev` — это переезд `lastRenderedHtml` в Rust: сбрасывать кэш при смене документа (`resetRenderState()`) больше не нужно, кэш и так ключуется документом и ревизией. IPC-нагрузка не растёт: текст и так ехал в `render_markdown` на каждый дебаунс.

Ошибки: `String` → `{ code, message }` (3–4 кода: `NotFound`, `Io`, `TooLarge`, `NotUtf8`). Текст `message` оставляем **байт-в-байт** текущий — на него смотрит статус-бар и один e2e про «МБ».

## Риски

- **Нативный undo textarea.** Программный `value = ...` при смене документа ломает Undo — это уже так сегодня (`newFile`/`openFile`). Фаза 3 не ухудшает, но и не чинит; чинить — отдельная задача (свой undo-стек на документе).
- **Двойная истина о тексте.** Если TS-стор начнёт сам менять текст, а не только проецировать Rust — поплывёт `data-md` (байтовые смещения привязаны к конкретной ревизии). Защита: `RenderIndex` несёт `rev`, inspector/scrollsync отбрасывают индекс, если `rev` не совпал.
- **Глобальный DOM-мусор.** Меню фильтров в `document.body` + `attachMenuAutoClose` — при 2 панелях обязательна per-view подписка и `dispose()`, иначе утечка и «чужое» меню поверх активной панели.
- **E2E-контракты id.** Рекомендация: `id="editor"`/`id="preview"` остаются на элементах *первичной* панели, плюс новые `data-pane`/`data-view` — существующие шаги проходят без правок.
