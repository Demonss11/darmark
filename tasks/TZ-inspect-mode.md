# Техническое задание: режим инспектора (Inspect) для mdedit

**Версия:** 1.0
**Дата:** 04.10.2026
**Целевая аудитория:** разработчик фичи (реализация), ревьюер (проверка объёма и приёмки)

---

## 1. Постановка задачи

### 1.1. Пользовательская история

> Как автор markdown-документа, я хочу включить режим инспектора (как «DevTools → Inspect element» в браузере), чтобы при наведении мыши на участок предпросмотра соответствующий фрагмент исходного markdown подсвечивался в редакторе — и наоборот: при движении курсора по редактору подсвечивался соответствующий блок в предпросмотре.

### 1.2. Ожидаемое поведение (acceptance criteria)

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| AC-1 | Клик по кнопке «Инспектор» в тулбаре (или `Ctrl+I`) | Режим включается: кнопка визуально «нажата», в статусной строке появляется индикатор |
| AC-2 | Наведение мыши на любой блок предпросмотра (заголовок, абзац, список, таблицу, цитату, код, `<hr>`…) | Блок подсвечивается рамкой/фоном; в редакторе выделяется точный диапазон исходного markdown этого блока; прокрутка к блоку только если он вне видимой области |
| AC-3 | Переход мыши с одного блока предпросмотра на другой (в т.ч. с вложенного элемента, например `<strong>` внутри `<p>`) | Подсветка мгновенно (без задержки >50 мс) переключается на новый блок; старая снимается; выделение в редакторе перемещается |
| AC-4 | Наведение на неиндексируемые элементы (обёртки `.table-enhanced`, панель фильтров, футнот-ссылки вне индексированных блоков) | Никакой реакции, предыдущая подсветка сохраняется до входа в индексированный блок |
| AC-5 | Движение каретки / выделение текста в редакторе при включённом режиме | Находится топ-блок, чей диапазон содержит позицию каретки; он подсвечивается в предпросмотре |
| AC-6 | Клик по блоку предпросмотра в режиме инспектора | Диапазон блока выделяется в редакторе, фокус передаётся редактору; клик не ломает сортировку/фильтры таблиц |
| AC-7 | Редактирование текста в редакторе при включённом режиме | После debounce-перерендера маппинг обновляется; активная подсветка сбрасывается (нет «висячих» диапазонов) |
| AC-8 | Повторный клик по кнопке / `Ctrl+I` / `Esc` | Режим выключается: вся подсветка снимается, DOM предпросмотра возвращается к «чистому» HTML без обёрток блоков |
| AC-9 | Выключенный режим | Приложение ведёт себя ровно как сейчас: никаких оверхедов, слушатели сняты, hot-path не затронут |
| AC-10 | Кириллический текст, эмодзи, CRLF | Границы выделения в редакторе корректны (учёт UTF-16-индексации textarea и байтовой индексации pulldown-cmark) |

## 2. Контекст проекта (актуальное состояние кода)

Монорепозиторий Cargo workspace (`/workspace`):

```
crates/
  md-core/          # чистое ядро Markdown → HTML (pulldown-cmark 0.13)
    src/lib.rs      # to_html(), to_html_with(), DEFAULT_OPTIONS
  app/              # Tauri 2 + vanilla TS/Vite
    src/main.ts     # состояние документа, debounce-рендер (120 мс), статусная строка, хоткеи
    src/tauri.ts    # типизированные обёртки IPC: renderMarkdown/readFile/writeFile
    src/tables.ts   # Excel-подобные сортировка/фильтры <table> в предпросмотре (WeakMap-реестр)
    src/style.css   # CSS-переменные, light/dark через prefers-color-scheme
    index.html      # тулбар (#toolbar с кнопками), #editor (textarea), #preview (article)
    src-tauri/src/lib.rs  # команды: read_file, write_file, render_markdown
```

Ключевые факты, определяющие дизайн:

1. Рендер идёт **на Rust-стороне**: `render_markdown(markdown: String) -> String` вызывает `md_core::to_html`. Фронтенд вставляет HTML в `preview.innerHTML` и не имеет собственного парсера.
2. `main.ts` хранит `lastRenderedHtml` и пропускает запись в DOM, если HTML не изменился (защита состояния таблиц). Любые атрибуты маппинга должны быть частью детерминированного вывода рендера.
3. `tables.ts` после каждого рендера оборачивает `<table>` в `.table-enhanced` (панель инструментов + скролл-обёртка) — то есть **мутрует DOM предпросмотра**. Это учтено в §4.3 (T-14).
4. Editor — обычный `<textarea>`: выделение только через `setSelectionRange(start, end)`; индексы — **UTF-16 code units**, тогда как `OffsetIter` pulldown-cmark отдаёт **байтовые смещения**.
5. Хоткеи обрабатываются на `window` (`keydown`, Ctrl-комбо). `Ctrl+I` свободен.

## 3. Архитектура решения

Три слоя изменений, от ядра к UI:

```
┌─────────────────────────────────────────────────────────────┐
│ md-core: to_html_mapped(md) -> String                       │
│   OffsetIter → ranges топ-блоков → рендер каждого блока      │
│   отдельно → <div class="md-block" data-md="s,e">…</div>     │
├─────────────────────────────────────────────────────────────┤
│ IPC: render_markdown(markdown, mapped: bool) -> String      │
├─────────────────────────────────────────────────────────────┤
│ Frontend: inspector.ts                                      │
│   toggle-состояние, mouseover/mouseout в preview,            │
│   selectionchange в editor, двусторонняя подсветка,          │
│   байт↔UTF-16 конвертация, scroll-into-view                  │
└─────────────────────────────────────────────────────────────┘
```

### 3.1. Поток данных

```
[включение режима]
   → doRender(mapped=true) → HTML c data-md → innerHTML → enhanceTables
[hover в preview]
   → closest('[data-md]') → "s,e" (байты) → bytesToUtf16() →
   → setHighlight(previewEl) + editor.setSelectionRange(s..e)
[selection в editor]
   → selectionStart (UTF-16) → utf16ToBytes() → поиск блока s<=pos<e →
   → setHighlight(blockEl)
[input в editor]
   → clearHighlight() → scheduleRender(mapped=true)
```

## 4. Детальные требования

### 4.1. Слой `md-core` (Rust)

**T-1. Новая публичная функция** в `crates/md-core/src/lib.rs`:

```rust
/// Рендерит markdown с пометкой топ-блоков: каждый блок оборачивается в
/// <div class="md-block" data-md="{start},{end}">, где start/end — байтовые
/// смещения блока в исходном markdown (inclusive start, exclusive end).
pub fn to_html_mapped(markdown: &str) -> String
```

**T-2. Алгоритм:**
1. `Parser::new_ext(md, DEFAULT_OPTIONS).into_offset_iter()` — собрать ranges событий `Event::Start(_)` **верхнего уровня** (игнорировать вложенные, пока глубина > 0; `FootnoteDefinition` включать целиком).
2. Границы топ-блоков: следующий `Start` верхнего уровня ограничивает предыдущий блок; конец документа = `md.len()`.
3. Для каждого блока вырезать исходник `md[a..b]`, сделать `trim_end()` (не включать хвостовые пустые строки), прорендерить кусок тем же набором опций: `html::push_html(&mut out, Parser::new_ext(slice, opts))`.
4. Оборачивать результат в `<div class="md-block" data-md="{a},{a+len(trimmed)}">`. Смещения указывают на trimmed-диапазон в оригинале, чтобы подсветка не захватывала пустые строки между блоками.
5. Пустые блоки не создавать.

**T-3. Инварианты:**
- `to_html_mapped` детерминирована: одинаковый вход → одинаковый выход (важно для `lastRenderedHtml`).
- В обычном режиме вывод побайтово совпадает с текущим `to_html` (никаких обёрток) — регрессионный тест.
- Атрибут `data-md` содержит только `[0-9,]` — безопасен для HTML.
- Экранирование содержимого блоков не меняется (ответственность pulldown-cmark).

**T-4. Обработка частых случаев (юнит-тесты):**

| Кейс | Ожидаемо |
|------|----------|
| `# H\n\ntext` | 2 блока, границы точно по символам |
| Таблица GFM | один блок на всю таблицу, включая строку разделителя |
| Вложенный список с tasklist | один блок на весь список |
| Цитата с вложенным списком | один блок `<blockquote>` |
| Кодовый блок ``` … ``` | один блок; внутренние `#` не режут блок |
| Footnote-def `[^1]: …` | отдельный блок |
| Setext-заголовок (`Title\n=====`) | range включает обе строки |
| CRLF | байтовые смещения по исходному массиву байт; trim удаляет `\r` справа |
| Эмодзи/кириллица | границы всегда на UTF-8 char-boundary (гарантия OffsetIter) |

**T-5. Тесты в `md-core`:** минимум 8 тестов из таблицы T-4 + тест «обычный вывод идентичен прежнему» + property-тест: объединение всех `data-md`-диапазонов покрывает все непустые строки документа без наложений.

### 4.2. IPC-слой (Rust, `src-tauri/src/lib.rs`)

**T-6.** Расширить команду (обратная совместимость через default):

```rust
#[tauri::command]
fn render_markdown(markdown: String, #[serde(default)] mapped: bool) -> String {
    if mapped { md_core::to_html_mapped(&markdown) } else { md_core::to_html(&markdown) }
}
```

Альтернатива — отдельная команда `render_markdown_mapped`; решение по умолчанию: T-6 (меньше дублирования, OQ-1).

**T-7.** `crates/app/src/tauri.ts`:

```ts
export function renderMarkdown(markdown: string, mapped = false): Promise<string> {
  return invoke<string>("render_markdown", { markdown, mapped });
}
```

### 4.3. Фронтенд: новый модуль `crates/app/src/inspector.ts`

**T-8. API модуля** (main.ts знает только это):

```ts
export function createInspector(opts: {
  editor: HTMLTextAreaElement;
  preview: HTMLElement;
  statusEl: HTMLElement;      // индикатор в статус-баре
}): {
  isActive(): boolean;
  enable(): void;    // вешает слушатели; вызывающий обязан сделать re-render с mapped=true
  disable(): void;   // снимает слушатели, чистит подсветку, восстанавливает selection/focus
  onRendered(): void; // сброс активной подсветки после замены innerHTML
};
```

**T-9. Индексация и конвертация единиц:**
- Хранить префиксную карту байт→UTF-16 (Int32Array), пересчитывать лениво при каждом успешном mapped-рендере (один проход по `editor.value`, O(n)).
- `bytesToUnits(b)`: бинарный поиск; гарантировать попадание на границу UTF-16-суррогатной пары (не разорвать эмодзи).
- `unitsToBytes(u)`: обратный бинарный поиск.
- **Карта строится именно по `editor.value`**, а не по тексту файла: WebView может нормализовать CRLF в value (см. риск §5.2).

**T-10. Preview → Editor (hover):**
- Слушатель `mouseover` (делегирование) на `preview`: `const el = (e.target as Element).closest("[data-md]")`.
- Если найден и отличается от текущего: снять класс `.inspect-active` со старого, поставить на новый; разобрать `data-md`, сконвертировать единицы, `editor.setSelectionRange(s, e)`.
- `mouseout` с проверкой `relatedTarget` — снимать подсветку только при выходе за пределы всей preview-панели.
- Отзывчивость: переключение блоков — синхронно в обработчике, без debounce; `scrollIntoView({ block: "nearest" })` — throttle 100 мс, не скроллит, если блок уже виден.

**T-11. Editor → Preview (selection):**
- Слушать `document`-ный `selectionchange` (fire'ится для focused textarea в WebView2) + продублировать на `keyup`/`click` (частично уже навешаны в main.ts для updateStatus — переиспользовать единый хук, не плодя лишних слушателей).
- Поиск блока: линейный/бинарный по отсортированному массиву ranges (топ-блоков обычно < 10³).
- Каретка вне любого блока (пустая строка) → снять подсветку.
- **Не** ставить зеркальное выделение диапазона в textarea при движении каретки (это мешало бы печати); выделение в редакторе ставится только в направлении hover (T-10) и по клику (T-12).

**T-12. Клик по превью (AC-6):**
- Включённый режим перехватывает `click` в `preview` в capture-фазе: если цель внутри `[data-md]` — выделить диапазон, `editor.focus()`, `preventDefault()+stopPropagation()`.
- **Кроме** кликов по интерактиве таблиц: если `e.target.closest("button, input, select, a, .col-filter-menu")` — не перехватывать, дать tables.ts отработать (сортировка по th, воронка фильтра).

**T-13. Фокус и выделение textarea:**
- При hover из превью временно `editor.focus({ preventScroll: true })`; исходный `document.activeElement` запомнить и восстановить при disable/выходе мыши из превью.
- На enable сохранить `(selectionStart, selectionEnd, scrollTop)` textarea; на disable восстановить (OQ-3).

**T-14. Совместимость с `enhanceTables` и ре-рендером:**
- `enhanceTables` перемещает `<table>` внутрь `.table-enhanced` — поэтому `data-md` и класс подсветки живут на **внешнем div-обёртке блока** (созданном md-core): перенос таблицы внутрь обёртки сохраняет атрибут. Регрессия: hover над `<td>` подсвечивает весь табличный блок.
- При `input` в редакторе — сразу `onRendered()`-сброс подсветки; после установки нового `innerHTML` ничего не подсвечивать до следующего hover/selection (иначе stale-узлы).

**T-15. UI:**
- `index.html`: в тулбар добавить `<button id="btn-inspect" title="Инспектор (Ctrl+I)">⌕ Инспектор</button>` (placement — сразу за `#file-label`, чтобы не ломать `margin-left:auto` у `#toggle-preview`).
- Активное состояние: класс `.active` на кнопке (filled accent-фон).
- Статус-бар: отдельный span `#stat-inspect` с постоянной меткой `Режим инспектора` (не конфликтует с flash()).
- Хоткеи: `Ctrl+I` — toggle (в существующем switch); `Esc` — выход, если активен и нет открытого меню фильтра колонки (OQ-2).

**T-16. Стили подсветки (`style.css`):**
```css
.inspect-active {
  outline: 2px solid var(--accent);
  outline-offset: 2px;
  background: color-mix(in srgb, var(--accent) 12%, transparent);
  border-radius: 2px;
}
```
`outline`, а не `border` — не сдвигает layout. Dark mode работает через те же переменные.

**T-17. Изменения `main.ts` (минимальные):**
1. Импортировать `createInspector`, создать экземпляр после получения DOM-ссылок.
2. `doRender()` → `renderMarkdown(editor.value, inspector.isActive())`.
3. При enable/disable — принудительный ре-рендер (`lastRenderedHtml = ""; void doRender();`), чтобы HTML получил/потерял обёртки.
4. В `input`-хендлере — `inspector.onRendered()` перед `scheduleRender()`.
5. keydown: `Ctrl+I` → toggle; `Esc` → disable (с учётом OQ-2).
6. После успешной установки `preview.innerHTML` в mapped-режиме — `inspector.onRendered()`.

### 4.4. Производительность

**T-18.** Бюджеты:
- Рендер mapped не медленнее обычного более чем на ~30% на документе 50 КБ (линейный проход + N вызовов парсера, N = число топ-блоков). Если замер превысит бюджет — оптимизировать до одного общего прохода `into_offset_iter` с вырезанием HTML-подстрок.
- Hover-переключение < 16 мс (один кадр).
- Память: карта byte↔utf16 — Int32Array, ок для документов до ~1 МБ.
- Режим выключен → ноль дополнительной работы (mapped=false, слушатели сняты).

## 5. Ограничения, риски, открытые вопросы

### 5.1. Ограничения дизайна (зафиксировать в README)
- Гранулярность — **топ-блок**. Подсветка отдельных inline-элементов (`**bold**` внутри абзаца) — вне объёма v1 (требовало бы поуровневого маппинга всех Event'ов и сопоставления с HTML-DOM; сложность несопоставима).
- Подсветка в редакторе — стандартное выделение textarea; overlay-декорации (как в VS Code) — v2.

### 5.2. Риски

| Риск | Вероятность | Митигция |
|------|-------------|----------|
| `enhanceTables` перестраивает DOM и теряет `data-md` | высокая | T-14: атрибут на внешней обёртке блока; E2E-проверка на таблицу |
| Конфликт click-inspect с фильтрами/сортировкой таблиц | высокая | правило `closest(интерактив)` из T-12 |
| UTF-16/байтовый сдвиг на кириллице/эмодзи | средняя | T-9 + юнит-тесты конвертера; AC-10 |
| Разрыв границ из-за CRLF (textarea/WebView нормализует `\r\n`) | средняя | карта строится по `editor.value` (T-9); тест с CRLF-файлом |
| `selectionchange` не fire'ится в целевом WebView | низкая | дублирующие keyup/click (T-11) |
| Дерганье подсветки при быстром mousemove через границы блоков | средняя | игнорировать события, если `closest` даёт тот же блок (гистерезис) |
| Рост IPC-payload из-за обёрток (~+15% HTML) | низкая | приемлемо; бюджет T-18 |

### 5.3. Открытые вопросы (OQ) — решить до начала реализации
- **OQ-1.** Параметр `mapped` vs отдельная IPC-команда. Предлагаем: параметр (T-6).
- **OQ-2.** Кто обрабатывает `Esc` при открытом меню фильтра колонки. Предлагаем: инспектор игнорирует Esc, когда в DOM есть открытый `.col-filter-menu`.
- **OQ-3.** Восстановление выделения/скролла textarea при выходе из режима. Предлагаем: сохранять на enable, восстанавливать на disable (T-13).
- **OQ-4.** Автостарт режима по флагу запуска. Предлагаем: нет, v1 только вручную.

## 8. Приёмочное тестирование (чеклист)

**Ручные сценарии:**
1. Прогнать AC-1…AC-10 из §1.2 последовательно (скринкаст).
2. Документ только из кириллицы + эмодзи: границы выделения точные (AC-10).
3. Файл с CRLF: открыть с диска, hover — выделения корректны.
4. Таблица: hover над `<td>` → подсвечен весь табличный блок; клик по `td` ≠ сортировка; клик по `th` = сортировка работает; после сортировки/фильтра hover всё ещё работает.
5. Быстрое проведение мышью по всем блокам сверху вниз — ни одной «залипшей» `.inspect-active`.
6. Выключить инспектор → DOM предпросмотра без `.md-block`; дальнейшее поведение как до фичи.
7. Ctrl+P (скрыть предпросмотр) при активном инспекторе — не падает; направление editor→preview молчит.
8. Большой документ (~500 строк): hover-lag незаметен; время mapped-рендера зафиксировать (`console.time`).

**Автоматические:**
- `cargo test -p md-core` зелёный, новые тесты T-4 покрыты.
- `npm run build` (vite/tsc) без ошибок типов.

## 9. Что сознательно НЕ входит в v1

- Inline-гранулярность (подсветка слов/ссылок внутри абзаца).
- Overlay-подсветка поверх textarea (decorations в стиле VS Code).
- Множественные курсоры / rect-selection в редакторе.
- Тултип с именем тега/типом блока при hover (дешёвое улучшение, можно в v1.1).
- Сохранение состояния инспектора между сессиями.
