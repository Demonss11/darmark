# TZ-proto-lua-host — измерительный стенд Lua-плагинного хоста

> **Ветка:** `proto/lua-plugin-host` (от `main`, `604da5c`).
> **Тип:** прототип/спайк. **Код в `main` не мёржится.** Переносятся выводы.
> **Основание:** `docs/DESIGN_DOC.md` D11 и §0.
> **Цель:** проверить D1–D16 на практике **до** написания ADR.
> **Версия Lua:** только **5.5** (D13). Сравнение с 5.4 исключено.
> **Ревизия 06.10.2026:** учтены спайки (`docs/proto/FINDINGS.md` F1–F25). Главное:
> **`panic="abort"` — доминирующая переменная** (F9); лимит инструкций под `abort` требует
> нативного C-hook (F11) и safe-`pcall` (F13); цель M6 (≤ +20%) недостижима (F14); поддержан
> вариант C — Lua в отдельном процессе (F16–F25), фаза P9. Все проверки лимитов — **в release-профиле**.

## 1. Зачем прототип, а не сразу код продукта

DESIGN_DOC содержит 21 решение. Часть опирается на предположения, а не на замеры. По итогам
спайков статус такой (полная таблица — `docs/proto/FINDINGS.md`):

| Предположение | Где записано | Чем рискуем, если неверно | Факт |
|---|---|---|---|
| `mlua` + vendored Lua 5.5 даёт +0.3–0.5 МБ | §14 | бюджет 6 МБ трещит → пересмотр D1/D6 | подтверждено (F3: ≈326 КиБ) |
| `Lua::set_hook` доступен для `lua55` | §10.1 | нет защиты от `while true do end` | доступен (F2), **но под `panic="abort"` не спасает: ошибка из Rust-callback абортит процесс (F9)** |
| `set_memory_limit` даёт управляемый `MemoryError` | §10.1 | плагин роняет приложение → нужен отдельный процесс | подтверждено (F8) |
| Урезанный `StdLib` реально закрывает `os`/`io`/`require` | §6.1 | дыра в песочнице | подтверждено (F6) |
| Внешние строки 5.5 убирают копирование текста в Lua-кучу | §10.1, §6.1.1 | лимит памяти не покрывает документ | **не проверено (P6)** |
| Vendored Lua 5.5 собирается под MSVC без правок | §6.1 | блокер на Windows | подтверждено (F1) |
| **`panic="abort"` не мешает ловить ошибки плагина** | (не заявлено) | **любая ошибка из Rust-callback роняет приложение** | **опровергнуто (F9)** — новая доминирующая переменная |
| Ошибки плагина можно надёжно гасить в процессе | §10.2, §11.4 | мнимая отказоустойчивость | **опровергнуто для `abort`**; надёжно — только граница процесса (F18, F25) |

ADR на таких предположениях — фиксация догадок. Сначала замер, потом решение (D11).

## 2. Границы

### 2.1. Входит
- Новый крейт `crates/lua-proto` (bin) — изолированный CLI, без Tauri.
- Загрузка `.lua`-файла с диска, вызов `on_activate`/`on_deactivate`.
- Минимальный набор host-функций (§6.3 DESIGN_DOC) на **заглушках**: документ — строка в памяти, view — отсутствует.
- Проверка sandbox, лимитов, permissions, карантина.
- Замеры размера, памяти, времени.
- Документ `docs/proto/FINDINGS.md` **в форме таблицы** (D15).

### 2.2. Не входит (сознательно)
- Tauri, IPC, фронтенд, DOM.
- Document/View/Pane, layout, панели.
- UI менеджера плагинов.
- Манифест с `contributes` (views/toolbar/statusbar/keybindings).
- Событийная шина, обратная маршрутизация тир-1.
- Реальный файловый доступ, сеть, настройки.
- Санитайзер, SVG, `data-p-*`.
- **`json`-модуль** (`json.encode`/`json.decode`) — предмет H2, в прототипе сериализовать нечего (D14).
- **Сравнение `lua54` / `lua55`** — версия зафиксирована (D13).

Всё перечисленное — предмет H1–H2, и его проверка в прототипе бессмысленна: она требует UI и данных, которых ещё нет.

### 2.3. Расширение объёма (ревизия 06.10.2026)

Спайк in-process (вариант B) вскрыл F9 и по построению не мог ответить на вопрос о выборе
рантайма. Поэтому объём расширен **отдельным** спайком процесс-изоляции (вариант C):
`crates/lua-rpc-spike` — Lua в дочернем процессе, bidirectional RPC по stdio. Это осознанное
исключение из §2.2 («Tauri, IPC» исключались для исходного объёма). Итоги — FINDINGS
F16–F25, фаза P9.

## 3. Структура крейта (план)

```
crates/lua-proto/
├── Cargo.toml          # mlua 0.12, features = ["lua55", "vendored"]; build-dep cc
├── build.rs            # сборка C-модуля
├── src/
│   ├── main.rs         # CLI: --plugin <path> [--limit-mem <mb>] [--limit-insns <n>] [--c-hook] [--hook-step <n>]
│   ├── host.rs         # регистрация host-функций
│   ├── sandbox.rs      # Lua::new_with + чистка BASE
│   ├── limits.rs       # set_memory_limit, used_memory; RAII-гвард лимита инструкций
│   ├── proto_hook.c    # нативный C-hook + scoped safe-pcall/xpcall (нужны под panic="abort")
│   └── permissions.rs  # (P5) таблица разрешений + проверка перед вызовом
└── plugins/            # тестовые фикстуры (см. §5)
```

Под `panic="abort"` штатный `Lua::set_hook` непригоден (F9): лимит инструкций ставится нативным
C-hook (F11) и дополняется scoped safe-`pcall` (F13). `permissions.rs` отложен до P5.

Крейт добавляется в `[workspace] members` корневого `Cargo.toml` **только в ветке прототипа**; в `main` не переносится.
Отдельный крейт `crates/lua-rpc-spike` (parent+child) — артефакт расширения §2.3.

### 4.1. Детализация P9 (метрики и гейты)

P9 отвечает на три вопроса, без которых ADR по D16 нельзя писать честно (основание: FINDINGS F21, F23, F24, §6 «Очередь»).

| # | Метрика | Как измеряем | Гейт |
|---|---|---|---|
| **M10** | stdio в GUI-конфигурации (F21/N7) | GUI-parent (`windows_subsystem="windows"`, subsystem 2) + child; явные пайпы + `bInheritHandles=TRUE`; кадр 10 МБ + обрыв child'а | round-trip работает без консоли; при обрыве parent **видит закрытие границы** и не блокируется навечно. Если GUI-parent с пайпами не работает — **смена транспорта** и эскалация в ADR |
| **M11** | Job Object для child'а (N5) | child в Job Object с `JOB_OBJECT_LIMIT_*` (RSS/CPU/time); нагрузки `spin.lua`, `hog.lua` | `spin`/`hog` убиваются **Job'ом**, parent жив; **память — детерминированно (F28)**, **CPU/время — грубый ОС-backstop, секунды (F29)**; при жёстком бюджете — watchdog |
| **M12** | Модель процессов (F23/N8) | фикстуры в двух конфигурациях: **один общий child** vs **child на плагин** (N штук). RSS: пустой child, child с 10 МБ, N×child; реакция на `crash`/`spin` одного плагина | таблица RSS + времени активации для обеих моделей + вывод: при общем child один `crash`/`spin` валит/блокирует **все** плагины. **Выбор модели зафиксирован** для ADR (D16) |

**P9 сознательно НЕ делает:** оптимизацию range/delta под **латентность** N1 (F22 — на рабочих размерах 50–200 КБ не доминирует), деградацию на реальных Tauri-документах (требует продукта). При этом **сам API под дельты нужен по памяти** при модели «child на плагин» + крупный документ (F30, см. ниже).

**Что P9 меняет по итогам:** уточняет D16 (stdio подтверждён/нет в GUI; выбранная модель процессов; RSS как продуктовая метрика §14) — правки в DESIGN_DOC §7.1, §14, §16 (строка 21).

**Что P9 вскрыл дополнительно (синхронизировано с FINDINGS):**
- **M11:** детерминирована только **память** (F28); **CPU/время — грубый backstop** (F29: секунды, разброс).
- **F32 — UI-freeze:** зацикленный внутри host-вызова плагин блокирует host на `read` до срабатывания Job'а (секунды). Обязателен **per-call wall-clock watchdog** (`TerminateJobObject`) и/или **async host-вызовы**; иначе «изоляция отказов» есть, а «UI не зависнет» — нет.
- **F22 пересмотрена для «child на плагин»:** при полном документе каждый процесс держит копию (F30: 10 МБ → 20.7 МиБ ×N), поэтому **range/delta-API обязателен по памяти**, а не как «аккуратность».

## 6. Метрики (что именно фиксируем в FINDINGS)

| # | Метрика | Как измеряем | Порог/ожидание |
|---|---|---|---|
| M1 | Размер exe, `--release` + `strip` | `cargo build --release` + размер файла | baseline без mlua vs с `lua55`; прирост ≤ 0.5 МБ |
| M2 | Время старта плагина | `std::time::Instant` вокруг `load` + `on_activate` | < 50 мс |
| M3 | Память пустого Lua-состояния | `used_memory()` сразу после `new_with` | < 1 МБ |
| M4 | Срабатывание лимита памяти | `set_memory_limit(8 МБ)` + `hog.lua` | `MemoryError`, процесс жив |
| M5 | Срабатывание лимита инструкций | нативный C-hook (в release) + `spin.lua` | прерывание, процесс жив; `pcall`-обход закрыт (F13) |
| M6 | Оверхед hook | `count.lua` с hook и без | **цель ≤ +20% недостижима (F14: ~×2 на tight-loop, шаг N не влияет)** — замерить фактически и выбрать механизм |
| M7 | Изоляция глобалов | два инстанса, один пишет `x = 1` | второй не видит `x` |
| M8 | Доступность API под `lua55` | компиляция: `set_hook`, `set_memory_limit`, внешние строки | компилируется без `ffi` (F2); **поведение `set_hook` под `abort` непригодно — F9** |
| M9 | Внешние строки: отсутствие копии | `used_memory()` до/после `get_document_text` на 10 МБ документе | рост существенно меньше размера документа |

**Ключевая переменная — `panic`-стратегия, а не M8.** `set_hook` компилируется (F2), но под
`panic="abort"` ошибка из Rust-callback абортит процесс (F9): поэтому лимит ставится нативным
C-hook (F11), а не `set_hook`. Это меняет §10.1 DESIGN_DOC.

## 7. Риски прототипа

| Риск | Вероятность | Что делаем |
|---|---|---|
| Vendored Lua 5.5 не собирается под MSVC | низкая (не подтвердился, F1) | зафиксировано; fallback `lua54` не нужен |
| `set_hook` недоступен для `lua55` | низкая (не подтвердился, F2) | не требуется; см. следующий пункт |
| **`panic="abort"` делает ошибки плагина неуловимыми** | **высокая (подтверждено, F9)** | лимит — нативный C-hook (F11) + safe-`pcall` (F13); host-функции — ошибки значением; либо граница процесса (P9) |
| Прирост размера > 0.5 МБ | низкая для `lua-proto` (F3); **высокая для `unwind` на продукте** (F10: +3.2 МБ) | `abort` без mlua в базе; вынос Lua в процесс (вариант C) |
| `set_memory_limit` не покрывает Rust-аллокации host-функций | высокая (известно из API) | проверяем внешние строки 5.5 (M9/P6); иначе — принять ограничение или Job Object (P9) |
| Тестовый плагин падает и роняет процесс | **высокая (подтверждено, F9)** | под `abort` падение host-кода не ловится; надёжно — процесс-изоляция (F18) |

## 11. Решение по D16 (принято 06.10.2026)

**Выбран вариант C** — Lua-плагин в отдельном процессе. Полное обоснование —
`docs/adr/0021-plugin-isolation-process.md`.

Ключевое:
- **Рантайм:** child-процесс на Lua 5.5; GUI-хост без `mlua`, остаётся на `panic="abort"` (D6 не под угрозой).
- **Транспорт:** stdio (подтверждён в GUI-конфигурации, F26/F27).
- **Модель:** «child на плагин» (F31) — только она даёт изоляцию отказов.
- **Лимиты:** Job Object — память точно (F28), CPU/время — backstop (F29).
- **Изоляция — отказов, не данных** (§11.4/F25).

**Обязательные требования до H2 (не «аккуратность»):**
1. [x] **Прогресс-таймаут watchdog** (`TerminateJobObject`) — зацикленный без host-вызовов плагин снимается за бюджет (F33, `run-d16.ps1`);
   [x] **абсолютный дедлайн на invocation** (F35): chatty-плагин (прогресс есть, конца нет) снимается по дедлайну (≈1500 мс при 1500 мс, `run-d16.ps1`);
