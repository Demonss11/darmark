## 0. Контекст и текущее состояние

MVP синхронизации уже реализован (`crates/app/src/scrollsync.ts`):

- вертикальный скролл синхронизируется в обе стороны **пропорционально** — доля
  `scrollTop/scrollMax` редактора переносится на ту же долю предпросмотра и наоборот;
- переключатель «синхронно» в тулбаре (`#chk-sync`), включён по умолчанию;
- защита от обратной связи — флаг `syncing`, снимаемый через `requestAnimationFrame`.

Ревью v1.1 фиксирует как v2: **точную анкорную привязку через `data-md`** (неоднородные
документы: таблицы, код-блоки, картинки) и **сглаживание**. Пропорция остаётся fallback.

Этот документ описывает v2 поверх существующего MVP, не переписывая его с нуля.

## 1. Постановка задачи

### 1.1. Пользовательская история

> При прокрутке одной панели я хочу, чтобы вторая выравнивалась по **содержанию** (к
> соответствующему блоку), а не по проценту длины документа — в документе, где таблица занимает
> пол-экрана, а дальше идут сто коротких абзацев, пропорция уводит предпросмотр мимо нужного
> места.

### 1.2. Acceptance criteria

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| AC-1 | Прокрутка редактора при включённом режиме инспектора | Предпросмотр выравнивается по блоку, содержащему верхнюю видимую строку редактора |
| AC-2 | Прокрутка предпросмотра при включённом режиме инспектора | Редактор выравнивается по строке начала верхнего видимого блока |
| AC-3 | Прокрутка при выключенном инспекторе | Работает прежняя пропорциональная синхронизация (fallback) |
| AC-4 | Быстрая прокрутка колесом/полосой | Нет «драки» панелей: скролл не дёргается, обратная связь не возникает |
| AC-5 | Hover/каретка в режиме инспектора тянет `scrollIntoView` | Синхронизация не перетаскивает вторую панель от этого программного скролла |
| AC-6 | Документ с таблицей (внутренний `.table-scroll`) и код-блоком | Скролл внутри таблицы не считается прокруткой панели; анкор не ломается |
| AC-7 | Тумблер «синхронно» | Выключение немедленно останавливает любую синхронизацию, включение — выравнивает панели |
| AC-8 | Редактирование текста | После перерендера анкорные карты обновлены; между вводом и рендером — только пропорция (stale-данные не используются) |
| AC-9 | Панель предпросмотра скрыта (`Ctrl+P`) | Никаких действий, ошибок нет |
| AC-10 | Кириллица, эмодзи, CRLF | Анкорные границы корректны (байты ↔ UTF-16, те же гарантии, что у инспектора) |
| AC-11 | Длинный абзац (одна логическая строка) при включённом инспекторе | Привязка не расходится: `scrollTop/lineH` соответствует логической строке, `findBlockContaining` возвращает правильный блок |

## 2. Решения по открытым вопросам ревью

| OQ | Решение | Обоснование |
|----|---------|-------------|
| Где переключатель, состояние по умолчанию | Уже в тулбаре (`#chk-sync`), включён по умолчанию. Оставляем как есть | Менять нечего |
| Опираться на `data-md` или пропорцию | **Гибрид.** Анкорная привязка, когда в DOM есть `[data-md]`; иначе — пропорция (существующая `syncPair`) | Анкоры есть ровно тогда, когда включён инспектор (mapped-рендер). Точность нужна в первую очередь в связке с инспектором |
| Запрашивать ли mapped-рендер ради sync | **Нет.** Синхронизация не управляет рендером | Mapped-рендер переключил бы HTML (`lastRenderedHtml`), пересоздал бы DOM и сбросил состояние таблиц при каждом включении тумблера. Неприемлемо без отдельного согласования |
| Сглаживание | `requestAnimationFrame` + throttle на установку `scrollTop`; плюс окно игнорирования эха WebView2 | Без анимации/инерции — только стабильность |
| Конфликт с инспектором | Инспектор сообщает sync о своём `scrollIntoView` через колбэк; sync гасится на кадр | Иначе hover потянет вторую панель (зафиксировано в ревью) |

**Принято:** точная привязка доступна только при включённом инспекторе (когда в DOM есть
`data-md`). Если позже понадобится точность без инспектора — отдельная задача на mapped-рендер,
управляемый тумблером sync (и на сохранение состояния таблиц при переключении).

**Принято (2), UX-изменение:** мягкий перенос редактора отключается (`wrap="off"` +
`white-space: pre; overflow-x: auto` на `#editor`). Это устраняет расхождение «логическая строка
vs визуальная строка» целиком (§4.5) и делает формулу `scrollTop/lineH ↔ lineStarts` точной.
Горизонтальный скролл длинных абзацев — в духе Notepad++ (моноширинный редактор). Альтернатива
(визуальные строки через `measureText` при сохранённом переносе) — вне объёма, см. §9.

## 3. Архитектура

Три модуля фронтенда, разделение ответственности:

```
src/mapping.ts     # чистая логика: byte↔UTF-16, начала строк, поиск блока (без DOM)
src/scrollsync.ts  # v2: анкорная привязка + пропорция-fallback + сглаживание + suspend
src/inspector.ts   # тонкая связка: передаёт свой scrollIntoView в sync через колбэк
src/main.ts        # оркестратор: проброс markdown в onRendered, сброс на input, связка колбэка
```

Принципы (из `codebase-design`):

- `mapping.ts` — «глубокий» модуль: чистые функции, тестируемая поверхность без DOM/UI.
  Позже покроется vitest, когда тот появится в проекте (сейчас фронт-тестов нет).
- `scrollsync.ts` — единственный владелец прокрутки; `main.ts`/`inspector.ts` только передают
  данные и сигналы, сами `scrollTop` не трогают.
- Карты byte↔UTF-16 строятся **по тексту, ушедшему в рендер** (тот же инвариант, что в
  `inspector.ts`: `data-md` посчитан по этому тексту, а `editor.value` мог измениться за время
  асинхронного рендера).

## 4. Детальные требования

### 4.1. Новый модуль `crates/app/src/mapping.ts`

Вынести из `inspector.ts` общую логику, чтобы inspector и scrollsync не дублировали её.

Интерфейс (публичный, ≤5 сущностей):

```ts
export interface Block {
  start: number; // байтовый offset (inclusive)
  end: number;   // байтовый offset (exclusive)
  el: HTMLElement;
}

export interface UnitMaps {
  b2u: Int32Array; // байтовый индекс → UTF-16 code units
  u2b: Int32Array; // UTF-16 code units → байтовый индекс
}

export function buildUnitMaps(text: string): UnitMaps;
export function bytesToUnits(maps: UnitMaps, b: number): number;
export function unitsToBytes(maps: UnitMaps, u: number): number;
export function buildLineStarts(text: string): Int32Array; // UTF-16 индексы начал строк
export function collectBlocks(root: ParentNode): Block[];   // отсортировано по start
```

- `buildUnitMaps`/`bytesToUnits`/`unitsToBytes` — переносятся из `inspector.ts` без изменений
  логики (включая зажим индексов `Math.min/Math.max` — уже сделан в inspector).
- `buildLineStarts` — префиксный массив: `lineStarts[i]` = UTF-16 индекс первого символа строки
  `i` (начинается с 0; на каждом `\n` добавляется индекс следующего символа). Построение O(n).
- `collectBlocks` — переносится из `inspector.ts` (`querySelectorAll("[data-md]")` + `parseRange`
  + сортировка по `start`). DOM-зависимая часть изолирована здесь.
- `findBlockContaining` / `nextBlockAfter` — чистые функции над `Block[]`, реализуются в
  `scrollsync.ts` либо выносятся сюда; место — по итогам первого прохода (см. этап 1).

`inspector.ts` после выноса импортирует эти функции и удаляет свои дубликаты. Поведение
инспектора не меняется.

### 4.2. Переработка `crates/app/src/scrollsync.ts`

API:

```ts
export interface ScrollSync {
  isEnabled(): boolean;
  setEnabled(enabled: boolean): void;
  /** markdown — текст рендера: по нему строятся карты/блоки.
   *  Без аргумента — сброс анкорных данных (fallback на пропорцию). */
  onRendered(markdown?: string): void;
  /** Гасит синхронизацию на короткое время: программная прокрутка
   *  инспектора не должна тянуть вторую панель. */
  suspend(): void;
}
```

Внутреннее состояние:

```ts
let enabled = true;
let syncing = false;          // поднят на время программной записи scrollTop
let rafId = 0;
let lastWriteAt = 0;          // timestamp последней программной записи (для окна игнорирования)
let blocks: Block[] | null = null;
let maps: UnitMaps | null = null;
let lineStarts: Int32Array | null = null;
let lineH = 0;                // измеренная высота строки редактора, px
```

- `onRendered(markdown)` при `markdown !== undefined`: пересчитывает `maps`, `lineStarts`,
  `blocks = collectBlocks(preview)`, замеряет `lineH`; затем сразу
  выравнивает (как сейчас).
- `onRendered()` без аргумента: сбрасывает `blocks/maps/lineStarts` в `null` (stale после `input`),
  выравнивание — пропорцией.
- `lineH` измеряется из `getComputedStyle(editor).lineHeight`; при `"normal"`/нечисловом —
  fallback `fontSize * 1.2`. Это замер один раз на рендер. Значение стабильно только при
  отключённом переносе (§4.5): при включённом переносе визуальные строки ≠ логические, и
  формула `scrollTop/lineH` теряет смысл.

### 4.3. Минимальные правки `crates/app/src/inspector.ts`

- Вынести `buildMaps/bytesToUnits/unitsToBytes/collectBlocks/parseRange/findBlock` в `mapping.ts`
  и импортировать.
- В `createInspector` добавить опцию `beforeScrollIntoView?: () => void`. Вызывать её в
  `scrollIntoViewIfNeeded` непосредственно перед `el.scrollIntoView(...)` (когда блок реально
  вне видимой области). Больше ничего в инспекторе не меняется.

### 4.4. Минимальные правки `crates/app/src/main.ts`

- `scrollSync.onRendered(source)` в `doRender` вместо без-аргументного вызова.
- В `input`-хендлере редактора добавить `scrollSync.onRendered();` (сброс анкоров до перерендера),
  рядом с уже существующим `inspector.onRendered();`.
- При создании инспектора пробросить колбэк: `beforeScrollIntoView: () => scrollSync.suspend()`.

### 4.5. `style.css` и `index.html`

`index.html` — без изменений (тумблер `#chk-sync` и статус уже есть).

`style.css` — **отключить мягкий перенос редактора** (обязательно для точности привязки):

```css
#editor {
  white-space: pre;     /* было: перенос по словам */
  overflow-x: auto;     /* было: только vertical через resize: none */
  /* overflow-y остаётся штатным */
}
```

Плюс в `index.html` — атрибут `wrap="off"` у `<textarea id="editor">`. Причина: `lineStarts`
считает логические строки по `\n`, а `scrollTop/lineH` — визуальные. При включённом переносе
длинный абзац даёт несколько визуальных строк на одну логическую, и `topLine`/`findBlockContaining`
уводят анкор. `white-space: pre` + `wrap="off"` делают эти понятия тождественными.

Совпадение с эталоном инспектора: у `collectBlocks` корень — `preview`; при выключенном
инспекторе `[data-md]` в DOM нет → `blocks` пуст → гарантированный fallback на пропорцию (§4.2).

Если `.md-block`-обёртки дадут смещение `offsetTop` из-за `margin` — точечный CSS-сброс только
при необходимости.

## 5. Алгоритмы привязки

### 5.1. Редактор → предпросмотр

```
onEditorScroll():
  1. если !enabled или syncing → return
  2. если нет blocks/maps → syncPair(editor, preview) и return       // пропорция
  3. topLine = clamp(floor(editor.scrollTop / lineH), 0, lines-1)
  4. unitPos = lineStarts[topLine]
  5. bytePos = unitsToBytes(maps, unitPos)
  6. block = findBlockContaining(blocks, bytePos)
            ?? nextBlockAfter(blocks, bytePos)                        // каретка в «воздухе»
  7. если block == null → syncPair и return
  8. target = scrollTop, при котором block.el.top == preview.top + topOffset
     (topOffset = padding-top предпросмотра, сейчас 12px)
  9. записать preview.scrollTop = target с throttle/rAF + флаг syncing
```

`target` считается через разность координат, а не через `offsetTop`-цепочку (надёжнее при
вложенности и sticky-заголовках):

```ts
const pr = preview.getBoundingClientRect();
const br = block.el.getBoundingClientRect();
const delta = br.top - pr.top;            // может быть отрицательным
const target = preview.scrollTop + delta - topOffset;
```

### 5.2. Предпросмотр → редактор

```
onPreviewScroll():
  1. если !enabled или syncing → return
  2. если нет blocks/maps → syncPair(preview, editor) и return       // пропорция
  3. prTop = preview.getBoundingClientRect().top
  4. block = первый блок, у которого block.el.getBoundingClientRect().bottom >= prTop
     (верхний видимый блок; при пустом списке — последний)
  5. bytePos = block.start
  6. unitPos = bytesToUnits(maps, bytePos)
  7. line = номер строки, содержащей unitPos (бинарный поиск по lineStarts)
  8. записать editor.scrollTop = clamp(line * lineH, 0, editor.scrollMax)
     с throttle/rAF + флаг syncing
```

Обратимость формул — обязательный инвариант: таргет §5.2 подобран так, чтобы его читала
§5.1. В редакторе строка `line` отстоит от верха видимой области на
`padTop + line*lineH − scrollTop`; при `scrollTop = 0` первая строка стоит на `padTop`.
Тот же отступ для строки `line` даёт `scrollTop = line*lineH` (без вычитания padding), и
тогда `floor(scrollTop / lineH) = line`, то есть обе стороны сходятся на одной строке.

> **Исправлено относительно черновика v1.0.** В первой редакции здесь стояло
> `line*lineH − editorPadTop`. Это давало отступ `2*padTop` (24px вместо 12px) и
> необратимость: §5.1 читала бы `floor((line*lineH − padTop)/lineH) = line − 1`, и
> направления расходились на одну строку. Вычитание убрано, `editorPadTop` больше не
> замеряется; регресс закрыт E2E-сценарием «Обратимость» (`scrollsync.feature`).

### 5.3. Защита от обратной связи

Двухуровневая (MVP-флаг оставлен, добавляется окно времени):

1. **Инвариант: `syncing = true` поднимается ДО записи `scrollTop`**, снимается в
   `requestAnimationFrame` — гасит синхронное эхо «запись → scroll-событие». Текущий MVP
   пишет `to.scrollTop` в `syncPair` до поднятия флага (§0) и полагается только на асинхронность
   доставки события — в v2 это окно гонки закрывается порядком «флаг → запись».
2. `lastWriteAt = performance.now()` при каждой программной записи; scroll-обработчики
   игнорируют события из той же панели, если `now - lastWriteAt < 80..120 мс` — гасит
   инерцию WebView2, которая доставляет scroll-события после снятия rAF-флага.

Порог окна подбирается на ручном прогоне (WebView2 доставляет эхо с задержкой), стартовое
значение — 100 мс.

### 5.4. Сглаживание

- Установка `scrollTop` — только через `requestAnimationFrame` (один отложенный кадр), не
  напрямую в обработчике scroll.
- Throttle на направление: повторная запись в ту же панель не чаще ~16 мс (следующий кадр).
- Анимация/плавное «доезжание» — вне объёма (см. §9). Скролл остаётся мгновенным, но стабильным.

### 5.5. Взаимодействие с инспектором и таблицами

- Инспектор при `scrollIntoViewIfNeeded` вызывает `beforeScrollIntoView()` → `scrollSync.suspend()`:
  программная прокрутка preview не порождает обратный скролл редактора.
- `suspend()` поднимает `syncing` + обновляет `lastWriteAt` на стандартное окно (без записи
  `scrollTop` — только гасит реакцию).
- Слушатели `scroll` остаются только на `editor` и `preview`, без `capture`; проверка
  `e.target === editor/preview`. Скролл внутри `.table-scroll` (вертикальный скролл таблицы) не
  поднимается к preview и не считается прокруткой панели — AC-6 выполняется штатно.
- `attachMenuAutoClose` по-прежнему закрывает меню фильтра при скролле preview; программный
  скролл от sync тоже закрывает меню — поведение не меняем.

## 7. Риски

| Риск | Вероятность | Митигция |
|------|-------------|----------|
| Мягкий перенос: визуальные строки ≠ логические | критична без меры | отключение переноса (§2, §4.5, AC-11) |
| `lineHeight` возвращает `"normal"` | низкая | fallback `fontSize * 1.2`; при `font: 14px/1.5` вернётся `21px` (§4.2) |
| Инерция WebView2 даёт scroll-эхо после rAF-флага | высокая | окно игнорирования `lastWriteAt` (§5.3) |
| Смещение анкора на таблицах (sticky-шапка, `.table-scroll`) | средняя | расчёт через `getBoundingClientRect`-разность; ручной сценарий AC-6 |
| Stale `data-md` между `input` и рендером | высокая | `onRendered()` без аргумента сбрасывает анкоры (§4.2/§4.4) |
| CRLF/нормализация WebView | средняя | карты и `lineStarts` строятся по тексту рендера, как в инспекторе (AC-10) |
| Лишние DOM-обёртки `.md-block` влияют на `offsetTop` | низкая | разность координат не зависит от `offsetTop`; при нужде — CSS-сброс |
