# TZ-proto-lua-host — измерительный стенд Lua-плагинного хоста

> **Ветка:** `proto/lua-plugin-host` (от `main`, `604da5c`).
> **Тип:** прототип/спайк. **Код в `main` не мёржится.** Переносятся выводы.
> **Основание:** `docs/DESIGN_DOC.md` D11 и §15.0.
> **Цель:** проверить D1–D15 на практике **до** написания ADR.
> **Версия Lua:** только **5.5** (D13). Сравнение с 5.4 исключено.

---

## 1. Зачем прототип, а не сразу код продукта

DESIGN_DOC содержит 20 решений, из которых минимум **шесть опираются на предположения, а не на замеры**:

| Предположение | Где записано | Чем рискуем, если неверно |
|---|---|---|
| `mlua` + vendored Lua 5.5 даёт +0.3–0.5 МБ | §14 | бюджет 6 МБ трещит → пересмотр D1/D6 |
| `Lua::set_hook` доступен для `lua55` | §10.1 | нет защиты от `while true do end` → нужен `ffi::lua_sethook` или смена рантайма |
| `set_memory_limit` даёт управляемый `MemoryError` | §10.1 | плагин роняет приложение → нужен отдельный процесс |
| Урезанный `StdLib` реально закрывает `os`/`io`/`require` | §6.1 | дыра в песочнице |
| Внешние строки 5.5 убирают копирование текста в Lua-кучу | §10.1, §6.1.1 | лимит памяти не покрывает документ → остаётся открытая проблема |
| Vendored Lua 5.5 собирается под MSVC без правок | §6.1 | блокер на Windows |

ADR на таких предположениях — фиксация догадок. Сначала замер, потом решение (D11).

## 2. Границы

### 2.1. Входит
- Новый крейт `crates/lua-proto` (bin) — изолированный CLI, без Tauri.
- Загрузка `.lua`-файла с диска, вызов `on_activate`/`on_deactivate`.
- Минимальный набор host-функций (§6.3 DESIGN_DOC) на **заглушках**: документ — строка в памяти, view — отсутствует.
- Проверка sandbox, лимитов, permissions, карантина.
- Замеры размера, памяти, времени.
- Документ `docs/proto/FINDINGS.md` **в форме таблицы** (D15).

### 2.2. Не входит (сознательно)
- Tauri, IPC, фронтенд, DOM.
- Document/View/Pane, layout, панели.
- UI менеджера плагинов.
- Манифест с `contributes` (views/toolbar/statusbar/keybindings).
- Событийная шина, обратная маршрутизация тир-1.
- Реальный файловый доступ, сеть, настройки.
- Санитайзер, SVG, `data-p-*`.
- **`json`-модуль** (`json.encode`/`json.decode`) — предмет H2, в прототипе сериализовать нечего (D14).
- **Сравнение `lua54` / `lua55`** — версия зафиксирована (D13).

Всё перечисленное — предмет H1–H2, и его проверка в прототипе бессмысленна: она требует UI и данных, которых ещё нет.

## 3. Структура крейта (план)

```
crates/lua-proto/
├── Cargo.toml          # mlua 0.12, features = ["lua55", "vendored"]
├── src/
│   ├── main.rs         # CLI: --plugin <path> [--limit-mem <mb>] [--limit-insns <n>]
│   ├── host.rs         # регистрация host-функций
│   ├── sandbox.rs      # Lua::new_with + чистка BASE
│   ├── limits.rs       # set_memory_limit, set_hook, used_memory
│   └── permissions.rs  # таблица разрешений + проверка перед вызовом
└── plugins/            # тестовые фикстуры (см. §5)
```

Крейт добавляется в `[workspace] members` корневого `Cargo.toml` **только в ветке прототипа**; в `main` не переносится.

## 4. Фазы

| Фаза | Содержание | Гейт | Оценка |
|---|---|---|---|
| **P0** | Это ТЗ: цель, рамки, гипотезы, метрики | документ согласован | — |

| **P3** | Лимиты: `set_memory_limit` → `MemoryError`; `used_memory`; `set_hook` + `every_nth_instruction` → прерывание `while true do end` | бесконечный цикл прерывается, процесс жив | 1 день |

| **P5** | host-функции на заглушке + permissions: `get_document_text`, `apply_edit` с permission и без | без permission → ошибка с кодом, не исключение Lua | 1 день |
| **P6** | Lua 5.5 на практике: `global x` (ловит ли опечатку), `table.create`, **внешние строки** для передачи текста без копирования | подтверждение 5.5 + список ограничений для API-референса | 0.5 дня |
| **P7** | Отказоустойчивость: синтаксическая ошибка; плагин, падающий 3 раза → карантин | приложение работает, плагин отключается | 0.5 дня |

**Итого: ~5.5 дней.** Порядок обязателен: P1 блокирует всё, P2/P3 независимы друг от друга.

## 5. Тестовые фикстуры (плагины)

| Файл | Назначение | Ожидаемое |
|---|---|---|
| `hello.lua` | минимальный плагин: `on_activate` → `host.log("info", "hello")` | вывод в лог, код 0 |
| `count.lua` | считает слова в заглушке-документе через `host.get_document_text` | вывод количества |
| `edit.lua` | `host.apply_edit` **с** `document:write` | правка применена к строке в памяти |
| `edit-denied.lua` | `host.apply_edit` **без** `document:write` | ошибка `permission_denied`, процесс жив |
| `spin.lua` | `while true do end` | прерывание по лимиту инструкций |
| `hog.lua` | аллокация больших таблиц в цикле | `MemoryError` до исчерпания RAM |
| `escape.lua` | попытки `os.time()`, `io.open()`, `require()`, `load()`, `coroutine.create()` | каждая — ошибка |
| `broken.lua` | синтаксическая ошибка | плагин помечен `failed`, процесс жив |
| `crasher.lua` | падает на каждом вызове | карантин после 3 падений |
| `typed.lua` | опечатка в глобале под `global`-декларацией (5.5) | ошибка компиляции, не тихий `nil` |
| `external.lua` | получение текста документа внешней строкой (5.5) | нет копирования в Lua-кучу, `used_memory` не растёт |

## 6. Метрики (что именно фиксируем в FINDINGS)

| # | Метрика | Как измеряем | Порог/ожидание |
|---|---|---|---|
| M1 | Размер exe, `--release` + `strip` | `cargo build --release` + размер файла | baseline без mlua vs с `lua55`; прирост ≤ 0.5 МБ |
| M2 | Время старта плагина | `std::time::Instant` вокруг `load` + `on_activate` | < 50 мс |
| M3 | Память пустого Lua-состояния | `used_memory()` сразу после `new_with` | < 1 МБ |
| M4 | Срабатывание лимита памяти | `set_memory_limit(8 МБ)` + `hog.lua` | `MemoryError`, процесс жив |
| M5 | Срабатывание лимита инструкций | `set_hook(every_nth_instruction(N))` + `spin.lua` | прерывание, процесс жив; N подобрать |
| M6 | Оверхед hook | `count.lua` с hook и без | не более +20% |
| M7 | Изоляция глобалов | два инстанса, один пишет `x = 1` | второй не видит `x` |
| M8 | Доступность API под `lua55` | компиляция: `set_hook`, `set_memory_limit`, внешние строки | компилируется без `ffi` |
| M9 | Внешние строки: отсутствие копии | `used_memory()` до/после `get_document_text` на 10 МБ документе | рост существенно меньше размера документа |

**M8 — ключевая метрика.** Если `set_hook` под `lua55` не компилируется, это меняет §10.1 DESIGN_DOC и требует `mlua::ffi::lua_sethook`.

## 7. Риски прототипа

| Риск | Вероятность | Что делаем |
|---|---|---|
| Vendored Lua 5.5 не собирается под MSVC | средняя | фиксируем в FINDINGS; аварийный fallback — `lua54` (D13), эскалация в ADR |
| `set_hook` недоступен для `lua55` | низкая (аннотация mlua читается как «все, кроме Luau») | `mlua::ffi::lua_sethook` + запись в FINDINGS |
| Прирост размера > 0.5 МБ | средняя | пересмотр D6 (бюджет) или D1 (рантайм) |
| `set_memory_limit` не покрывает Rust-аллокации host-функций | **высокая** (известно из API) | проверяем внешние строки 5.5 (M9/P6); если не помогает — принять ограничение |
| Тестовый плагин падает и роняет процесс | средняя | именно это и проверяем (P7); паника в host-функции не должна пробиваться |

## 8. Что НЕ является критерием готовности прототипа

- Красивый код, готовый к мёржу.
- Полный API плагинов.
- Производительность на реальных документах.
- Совместимость с Tauri.
- Функциональность Excel-таблиц — **не развивается** (D12), `tables.ts` заморожен в текущем виде.

Прототип одноразовый. Его ценность — **таблица замеров и список опровергнутых предположений**.

## 9. Выход прототипа

1. `docs/proto/FINDINGS.md` — **таблица** «гипотеза → замер → вывод» + список опровергнутого (D15).
2. Правки `docs/DESIGN_DOC.md` по фактам (в первую очередь §14 размер, §10.1 лимиты, §6.1.1 Lua 5.5).
3. `docs/adr/NNNN-*.md` — 20 ADR **по факту** (§16 DESIGN_DOC), с числами из FINDINGS.
4. Решение по ветке: `main` не трогаем, ветку архивируем (код в продуктовую кодовую базу не идёт).
