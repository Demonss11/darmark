## 3. Вариант A (рекомендуемый) — удалить и слить

### Шаг 1. Слить уникальное в `CREATE_PLUGIN_PROMPT`

Заменить строку про `view_id`/`set_view_content` (`mod.rs:69-72`) на:

```
- Вкладка (view): объяви в contributes.views [{"kind": "<kind>", "title": "…", "tier": 1}] (ровно эти поля),
  permission view:create; содержимое пиши через host.set_view_content(VIEW_ID, html) (нужен view:modify), где
  VIEW_ID = "<id плагина>:<kind>": <id плагина> — это поле id из этого же JSON, <kind> — из contributes.views.
  HTML санитизируется на хосте: скрипты, javascript:, on* вырезаются.
  Клик по элементу с data-p-<plugin_id>-action="foo" (и опциональным data-p-<plugin_id>-payload="…")
  в HTML view → on_action(view_id, "foo", payload).
```

по решению владельца (16.10.2026, TASK-008 вариант A) — промт остаётся в одном источнике (`mod.rs`).

### Что теряется и чем компенсируется

Теряется discoverability: новичку «Добавить вкладку» понятнее, чем «Создать плагин».
Компенсация — не второй промт, а **режим в UI**: чип выбора цели у кнопки
(`вкладка | статусбар | команда`) в `skillBar.ts`, который дописывает в `{{input}}` строку
«нужна собственная вкладка (view)». Это отдельная мелкая правка фронта, промт не трогает.
