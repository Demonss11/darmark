## 1. Решение: скилл ОСТАВИТЬ

Формально пересекается с секцией 3 «Разметка» скилла `explain`, но отвечает на другой вопрос:
**какие элементы использованы** против **правильно ли они использованы**. Совпадение тем, не функций.

| | `explain` §3 «Разметка» | «Разбор разметки» |
|---|---|---|
| Вопрос | какие элементы и что они дают | правильно ли они использованы |
| Пример | «использованы таблицы, код, YAML-шапка» | сколько уровней заголовков, корректна ли вложенность; выровнены ли таблицы; не сломано ли открытие/закрытие блока кода; корректен ли синтаксис ссылок |
| Форма | свободный текст | 8 фиксированных секций, отсутствующие пропускаются |
| Роль | разбор | **диагностика** |

Основания:

1. Промт проверяет **дефекты** («корректна ли вложенность», «не сломано ли открытие/закрытие»),
   а `explain` этого не делает — он по правилу «не выдумывай» только описывает.
2. Правило «если тип элементов отсутствует — пропускай пункт» — поведение **проверяющего**, а не
   разборщика.
3. **Другого валидатора разметки в приложении нет:** `crates/md-core/src` содержит только `lib.rs`
   и `frontmatter.rs` — рендера и линта нет. Скилл — единственный способ узнать, что в документе
   сломан блок кода или криво вложены заголовки.
4. Дублируется не промт, а тема: 8 секций с конкретными дефектами не повторяются нигде.

## 2. Проблема, которую это создаёт

Название вводит в заблуждение: «Разбор разметки» читается как синоним секции внутри
«Объяснить файл». Обе кнопки с той же иконкой `▤`, обе работают с `{{doc}}`, обе «про разметку» —
пользователь не отличает «что тут написано» от «правильно ли это». Функция полезна, вход в неё
неочевиден.

---

## 3. Правка: переименовать в «Проверить разметку»

Название передаёт проверку корректности, а не описание, и не пересекается по смыслу со словом
«разбор» в названии «Объяснить файл».

- [ ] `crates/app/src-tauri/src/ai/skills/mod.rs:268` (`explain-syntax` → title) —
      `"Разбор разметки"` → `"Проверить разметку"`
- [ ] `mod.rs:271-272` (`description`) — добавить слово о проверке корректности:
      `"Разобрать синтаксис Markdown по фрагментам (заголовки, списки, таблицы, код)"`
      → `"Проверить, правильно ли использован Markdown: вложенность заголовков, блоки кода, ссылки"`
- [ ] `mod.rs:132-135` — док-комментарий константы: первая строка `Разбор **разметки** по
      фрагментам` → `Проверка корректности **разметки** по фрагментам`; пояснение «в отличие от
      `explain`…» оставить — оно и фиксирует различие
- [ ] `mod.rs:3-4` — в перечне скиллов ничего не меняется: перечень хранит **id**, а не title;
      `explain-syntax` остаётся и после TASK-004/005 (набор 7 → 5: уходят `add-view` и `summarize`)
- [ ] `crates/app/e2e/features/ai.feature:116` — `есть боевой скилл "Разбор разметки"`
      → `"Проверить разметку"` (номер — по состоянию до TASK-004/005: они сдвигают строку, поэтому
      искать по тексту)
- [ ] `cd crates/app; npm run build` — tsl strict зелёный
- [ ] `cargo test -p darmark ai::tests::skills` — зелёный (тест проверяет непустоту title/description,
      не конкретные строки — правки текста его не ломают)

**id скилла (`explain-syntax`) не менять:** он не в `PLUGIN_SKILL_IDS` (`skillBar.ts:14`), нигде
не используется как ключ и только упоминается в E2E-комментарии (`ai.feature:111`).

## 4. Чего не делать

- **Не удалять скилл.** Потеря единственной проверки корректности Markdown в приложении.
- **Не сливать с `explain`.** Смешение превратит разбор в перечисление с оговорками «а заодно
  проверим ещё вложенность» — качество обоих упадёт, а объяснение станет длиннее.
- **Не выносить линтер в md-core.** Отдельная задача (настоящая проверка в Rust с позициями
  строк); этот скилл — LLM-эвристика по документу, нормативным источником дефектов не является.
- **Не переносить правку в `skills.ts`** — фолбэк `FALLBACK_SKILLS` **удаляется** (решение
  владельца 16.10.2026, TASK-008 вариант A): единственный источник промтов — `ai/skills/mod.rs`,
  второго места для правки нет и не будет.
