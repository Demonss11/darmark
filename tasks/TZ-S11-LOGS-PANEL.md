## 1. Целевая картина

Панель «Журнал» — инструмент **best-effort наблюдаемости** для пользователя и разработчика
плагинов. Закрывает пробел: ошибки плагинов, карантины и действия с документами происходят
незаметно, причины отказов не диагностируются без внешних инструментов.

**Гипотеза:** читаемая история событий сокращает диагностику с «угадывания по статусбару»
до «прочтения последних записей».

**Аудитория:** плагин-разработчик (основной), продвинутый пользователь, бета-тестировщик.

### Текущее состояние

- `#sb-logs` (`index.html:244`) по клику показывает флеш «Журнал — скоро» (`shell.ts:81`).
- Бейдж `#log-badge` (`index.html:250`, `hidden`) не используется (ADR-0024).
- События уже существуют (`plugins-changed`, `plugin-views-changed`, `plugin-message`,
  `document-updated`), но с пустым/неполным payload.

### Принцип

Best-effort observability: потеря записей не критична (не audit log), но падение плагина или
ошибка команды обязаны быть видны. Рендер записей — только `textContent` (CSP/XSS).

## 2. Scope S11

### В scope

1. **Панель-консоль «Журнал»** — сворачивающаяся панель на всю ширину над `#statusbar`,
   **внутри layout** (сжимает рабочую область, не перекрывает контент). Свёртка/разворот, resize.
2. **Лента событий** — ring buffer на 200 записей, автопрокрутка с заморозкой.
3. **Источники событий** — существующие Tauri-события + новые Rust-события (обогащение payload).
4. **Бейдж `#log-badge`** — счётчик непрочитанных, цвет по уровню.
5. **Фильтр из двух кнопок** — «Все» / «Ошибки».
6. **Очистка журнала** — кнопка-иконка без подтверждения.
7. **Группировка по дате** — «Сегодня» / «Вчера» / «11 октября».
8. **Доступность** — ARIA, клавиатура, `aria-live`.

### Вне scope (отдельные задачи)

| Задача | Обоснование |
|--------|-------------|
| **IDEA-012** — полный мониторинг ресурсов (ОЗУ/CPU по плагинам) | Другой источник (WinAPI), спайк, ADR, отдельная задача. В S11 — только зарезервированная компактная строка памяти (см. §6.8). |
| Персистентность на диск | Нужен формат/ретеншен/приватность; для беты достаточно in-memory истории сессии. |
| Экспорт лога, поиск по журналу | Для 200 записей не критично. |
| Настройки уровня логирования | Отдельная задача (настройки приложения). |
| Полноценная панель журнала (H3) | ADR-0024 §3: S11 наполняет слот `#sb-logs`, а не строит H3-панель. |

## 3. Пользовательские сценарии

### Сценарий 1: Диагностика отказа плагина
> **Как** пользователь, у которого перестал работать плагин, **я хочу** открыть журнал и увидеть
> последние события по нему, **чтобы** понять, где сбой.

**Приёмка:** Given плагин `word-count` в статусе `failed`; When клик по `#sb-logs`;
Then в ленте есть запись `[ошибка] Плагин word-count: <текст>`.

### Сценарий 2: Отслеживание карантина
**Приёмка:** Given плагин в `quarantined`; When открыт журнал; Then в ленте серия ошибок и
финальная запись `[система] Плагин X: карантин (3 падения подряд)`.

### Сценарий 3: Проверка перезагрузки после правки `.lua`
**Приёмка:** Given разработчик нажал Ctrl+R; When открыт журнал; Then запись
`[плагин] Плагин Y: перезагружен`.

### Сценарий 4: Отслеживание действий с документом
**Приёмка:** Given плагин вызвал `apply_edit`; When открыт журнал; Then запись
`[документ] Документ обновлён (rev=N)`.

### Сценарий 5: Бейдж как сигнал
**Приёмка:** Given панель закрыта; When произошло 5 событий; Then `#log-badge` показывает «5»;
When пользователь открывает панель; Then бейдж сбрасывается.

## 4. Архитектурные решения

### 4.1. Размещение кода

- **Новый файл** `crates/app/src/logPanel.ts` — буфер + подписка + рендер.
- `shell.ts` — заменить заглушку на `logPanel.toggle()`.
- `main.ts` — создать экземпляр, передать в `createShell`.
- `index.html` — разметка панели между рабочей областью и `#statusbar`.
- `style.css` — стили панели (токены, записи, фильтр, бейдж).

### 4.2. Модель данных

```ts
interface LogEntry {
  id: number;                              // монотонный счётчик на фронте
  ts: number;                              // Date.now()
  level: "info" | "warn" | "error";        // тяжесть записи
  category: "plugin" | "document" | "system"; // цвет точки
  message: string;                         // человекочитаемый текст (не HTML)
  detail?: string;                         // необязательный хвост: версия, rev, имя файла
}
```

**Решение по категориям.** Категория **остаётся в модели** (один маленький enum на запись),
но **фильтры сокращены до двух**. Обоснование: `category` уже бесплатна и нужна для цвета точки
и приоритета бейджа; отдельные вкладки «Плагины/Документы/Система» при 200 записях дают мало
пользы и добавляют хрома. Практически ценно только «показать проблемы» → фильтр «Ошибки»
(`level` = `warn`/`error`). Рендер — только `textContent`; цвет/иконка — через CSS-классы.

### 4.3. Ring buffer

- `LogEntry[]`, лимит **200** (FIFO). Переполнение — молчаливое удаление старших (без строки-предупреждения).
- Перерисовка — по `requestAnimationFrame`, не на каждое событие.
- Коалесинг частых `document-event` (save/edit) — не чаще 1 раза в N секунд.

### 4.4. Доставка событий

- **Push:** Rust эмитит через `app.emit(...)`, фронт слушает `listen(...)` и добавляет запись.
- **Pull при открытии** не нужен — буфер копится с запуска.
- **Гарантии:** best-effort, FIFO в пределах источника, потеря при закрытии окна допустима.

### 4.5. Состояния панели

- **Развёрнута:** высота `--h-logs: 220px`; рабочая область сжимается.
- **Свёрнута:** полоса-шапка `--h-logs-bar: 28px` (тело скрыто).
- **Скрыта:** панель отсутствует (`hidden`) — состояние до первого открытия.
- **Resize:** drag-handle `#logs-resize`; высота клампится 28–520px.
- **Разворот/свёртка:** клик `#sb-logs` (получает `aria-expanded` и `.active`), шеврон
  `#logs-collapse` в шапке, Esc при фокусе в панели. Взаимоисключение с дровером плагинов
  и палитрой не требуется — панель не перекрывает контент.

### 4.6. Приватность и безопасность

- Не писать содержимое документов, полные пути (только имена), секреты, стектрейсы.
- Рендер записей — только `textContent`.

## 5. Источники событий

### 5.1. Существующие (переиспользуем)

| Событие | Эмиттер | Payload | Запись в журнале |
|---------|---------|---------|------------------|
| `plugin-message` | `services.rs: show_message` | `{plugin_id, text}` | `[плагин] Плагин «X»: <text>` |
| `document-updated` | `services.rs: apply_edit` | `{doc_id, rev}` | `[документ] Документ обновлён (rev=N)` |
| `plugins-changed` | `host.rs: notify_plugins()` | `()` | `[плагин] Плагины: обновлён список/статус` |
| `plugin-views-changed` | `services.rs: set_view_content` | `()` | `[система] Представления обновлены` |

### 5.2. Новые (Rust)

| Событие | Эмиттер | Payload | Зачем |
|---------|---------|---------|-------|
| `plugin-status-changed` | `host.rs` в точках смены статуса (`set_enabled`, `reload`, `remove`, `set_permissions`, `pump`/`start_enabled` при ошибке) | `{plugin_id, old_state, new_state, message?}` | «плагин X: active → failed», «карантин (N=3)» |
| `document-event` | `lib.rs` в `new_document`/`open_document`/`save_document`/`close_document` | `{type, path?, rev?}` | «Открыт файл …», «Сохранён …» |
| `log-entry` | Новый `LogSink` в `services.rs`, подключаемый в `setup_plugins` (как `StatusSink`/`DocumentSink`) | `{level, category, message}` | Сообщения `host.log` из Lua + ошибки IPC |

`plugins-changed` оставляем как есть (пустой payload, обратная совместимость); детали несёт
`plugin-status-changed` (принцип S2 — разделение сигналов).

## 6. UI-спецификация

### 6.1. Размещение

- Панель на всю ширину **внутри layout**, в flex-колонке между рабочей областью и `#statusbar`
  (не `position:fixed`, не overlay). Раскрытие сжимает рабочую область.
- Высоты: развёрнута `--h-logs: 220px`, свёрнута `--h-logs-bar: 28px`, скрыта — `hidden`.
- Resize: drag-handle `#logs-resize` сверху, высота клампится 28–520px.
- Анимация смены высоты — `transition: height 0.18s` (гасится `prefers-reduced-motion`).

### 6.2. Структура DOM

```html
<section class="logs-panel" id="logs-panel" role="region" aria-label="Журнал событий" aria-labelledby="logs-title" hidden>
  <div class="logs-resize" id="logs-resize" role="separator" aria-orientation="horizontal" aria-label="Изменить высоту журнала"></div>
  <div class="logs-head">
    <button class="logs-caret" id="logs-collapse" aria-expanded="true" aria-controls="logs-body" aria-label="Свернуть журнал">▾</button>
    <span class="logs-title" id="logs-title">Журнал</span>
    <span class="logs-count" id="logs-count">0</span>
    <div class="logs-filter" role="group" aria-label="Фильтр событий">
      <button class="filter-btn active" data-filter="all" type="button" aria-pressed="true">Все</button>
      <button class="filter-btn" data-filter="error" type="button" aria-pressed="false">Ошибки</button>
    </div>
    <span class="logs-head-spacer"></span>
    <span class="logs-resources" id="logs-resources" role="note" aria-label="Потребление памяти"><!-- IDEA-012, §6.8 --></span>
    <button class="logs-clear" id="logs-clear" type="button" title="Очистить журнал" aria-label="Очистить журнал"><!-- иконка корзины --></button>
  </div>
  <div class="logs-body" id="logs-body">
    <div class="logs-list" id="logs-list" role="log" aria-live="polite" aria-relevant="additions">
      <!-- .log-item -->
    </div>
  </div>
</section>
```

> Замороженные id — `#statusbar`, `#editor`, `#preview`, `#sb-logs`, `#log-badge` — не трогаем.
> `#logs-panel`, `#logs-resize`, `#logs-collapse`, `#logs-list`, `#logs-clear` — id панели из этого ТЗ.

### 6.3. Запись журнала

```html
<div class="log-item" data-category="plugin">
  <span class="log-dot" aria-hidden="true"></span>
  <span class="log-time">12:34:56</span>
  <span class="log-msg">Плагин «word-count» включён</span>
  <span class="log-detail">версия 1.0.0</span>
</div>
```

- **Точка** (`.log-dot`): 5px, `opacity: .7`, цвет категории; при `level=error` — `--error` и `opacity:1`.
- **Время** (`.log-time`): моно, `--fg-mute`, `tabular-nums`.
- **Сообщение** (`.log-msg`): `--fg` — **единственный яркий текст** в строке.
- **Детали** (`.log-detail`): `--fg-dim`, 11px, обрезка по `max-width: 40%`.

**Цвет точки по категории:** plugin `--accent`, document `--accent-2`, system `--fg-mute`;
уровень `warn` → `--amber`, `error` → `--error` (перекрывают категорию).

### 6.4. «Больше воздуха» (обязательные визуальные правила)

Правила упрощения, по которым проверяется реализация:

- **Строки лога без рамок** — разделяются отступами (`padding: 7px 14px`, `gap: 10px`), не линиями.
- **Тихий hover** — `background: var(--bg-1)`, без ярких подложек; непрочитанные — лёгкая
  подкраска `color-mix(in srgb, var(--accent) 4%, transparent)`.
- **Точки категорий** — 5px, `opacity: .7` (не «светофор»).
- **Разделители дат без линий** — только отступ и приглушённый uppercase-заголовок.
- **Границы** — `--line-soft`, минимально (только `border-top` панели и разделение тело/шапка).
- **Drag-handle тонкий** — 3px, проявляется (акцентная 1px-полоса, `opacity .6`) только при hover/resize.
- **Шапка** — `--bg-1`, высота 28px; «Очистить» и шеврон — 22px иконочные tbtn, `--fg-mute`.
- **Время приглушено** (`--fg-mute`), **сообщение — единственный яркий текст**.
- Сообщение обрезается/переносится (`overflow-wrap: break-word`), строка не растягивает панель.

### 6.5. Бейдж `#log-badge`

- Виден при непрочитанных > 0, `hidden` при 0; сбрасывается при разворачивании панели.
- Цвет: `--bg-3` (по умолчанию), `--error` (есть непрочитанные ошибки), `--warning` (есть
  предупреждения без ошибок).
- `aria-label="Непрочитанных событий: N"`.

### 6.6. Пустая лента

- Единственное реальное состояние (журнал пуст до первых событий): `.log-empty` —
  «Событий пока нет» + подсказка «События появятся при работе плагинов и документов».
- Отдельные демо-состояния «переполнение», «нет по фильтру», «норма» не описываются:
  фильтр «Ошибки» без результатов показывает ту же `.log-empty`; переполнение — FIFO без строки-предупреждения (см. §4.3).

### 6.7. Группировка по дате

- `.log-date-separator` — липкая шапка группы («Сегодня», «Вчера», «11 октября»),
  приглушённый uppercase, **без линии-разделителя**.

### 6.8. Строка памяти (IDEA-012, зарезервировано)

> **Статус:** в S11 **не реализуется**; здесь фиксируется только место и вид, реализация —
> отдельная задача IDEA-012 (спайк + ADR + TZ).

- Одна приглушённая строка в правой части шапки: `darmark 156 МБ`
  (`.logs-resources`, `--fg-mute`, моно, `tabular-nums`, без яркости и прогресс-баров).
- Полный мониторинг (по плагинам, CPU, пороги, crash/kill) — вне S11; критерии и пороги
  принадлежат задаче IDEA-012.
- При нереализованной IDEA-012 `#logs-resources` пуст (не занимает заметного места).

## 7. Доступность (a11y)

- Панель: `role="region"`, `aria-labelledby="logs-title"`.
- Лента: `role="log"`, `aria-live="polite"`, `aria-relevant="additions"`.
- Фильтр: `role="group"`, кнопки с `aria-pressed="true|false"`.
- Бейдж: `aria-label="Непрочитанных событий: N"`.
- Клавиатура: `Tab`, `Enter`/`Пробел` (фильтры/кнопки), `Esc` (свернуть). Записи ленты —
  только для чтения, без tab-стопов; навигация по записям (roving tabindex) — Фаза 3.
- Фокус: при открытии — на фильтр/ленту; при закрытии — возврат на `#sb-logs`.
- `prefers-reduced-motion` отключает анимацию высоты и автоскролл.

## 9. План реализации

**Фаза 1 — каркас (MVP).**
1. `logPanel.ts`: тип `LogEntry`, ring buffer (200), контроллер.
2. Разметка панели в `index.html` между рабочей областью и `#statusbar`.
3. `shell.ts`: заменить заглушку на `logPanel.toggle()`.
4. Подписка на существующие события, бейдж `#log-badge`.

**Фаза 2 — обогащение событий (Rust).**
5. `plugin-status-changed` в `host.rs`; `document-event` в `lib.rs`; `LogSink` + `log-entry` в `services.rs`.
6. Подключить события во фронте; тесты в `plugins/tests.rs`.

## 10. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Дублирование `listen()` может сломать существующие контроллеры | Среднее | Оставить подписки в `pluginManager.ts`/`pluginViews.ts` и продублировать в `logPanel.ts` (события идемпотентны) |
| Панель съедает вертикаль на маленьком экране | Низкое | Свёртка до полосы, resize, дефолт 220px |
| XSS через сообщения плагинов | Высокое | Только `textContent` |
| Раздувание памяти при интенсивных событиях | Низкое | Лимит 200 + коалесинг |
| Drag-resize конфликтует с выделением текста | Низкое | `user-select: none` на драге, pointer capture |
