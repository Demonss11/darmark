# ТЗ на доработку mdedit

**Версия:** 1.0 · **Дата:** 03.10.2026 · **Основание:** аудит кода (безопасность, надёжность, производительность)

---

## 1. Цель

Устранить критические дыры безопасности и узкие места, найденные при аудите, не меняя продуктовую концепцию (лёгкий Markdown-редактор Notepad++-style, Tauri + md-core).

**Критерий готовности релиза:** ни одна из задач P0 не остаётся открытой; все новые проверки покрыты тестами.

---

## 2. Задачи P0 — Безопасность (обязательно)

### P0.1. Реальное ограничение путей файлового доступа

**Проблема:** `check_path_allowed` (crates/app/src-tauri/src/lib.rs) проверяет только расширение; комментарий обещает несуществующий scope `file-md`. Фронтенд может читать/перезаписывать любой `.md`/`.txt` в файловой системе.

**Требования:**

1. Удалить/исправить вводящий в заблуждение комментарий.
2. Добавить в Rust-команды `read_file`/`write_file` реальную валидацию:
   - `path.canonicalize()` (для write — канонализация существующего родителя), отклонять симлинки, выходящие за пределы разрешённых директорий;
   - белый список корней: `Document`, `Desktop`, `Downloads` (получать через `tauri::path::PathResolver`, плюс явно добавленные диалогом пути — см. P2.2);
   - проверка, что канонический путь начинается с разрешённого корня;
   - сохранение проверки расширений `ALLOWED_EXTS`.
3. Ограничить размер чтения: до `read_to_string` — `metadata().len() <= MAX_FILE_SIZE` (константа, 10 МБ), иначе понятная ошибка.
4. Перевести `read_file`/`write_file` в `async fn` + `spawn_blocking` (синхронный I/O сейчас блокирует main-поток Tauri).

**Критерии приёмки:**

- юнит-тесты `check_path_allowed` / `validate_path`: разрешённый корень ✅, `..\`-traversal ❌, симлинк наружу ❌, запрещённое расширение ❌, большой файл ❌;
- ручной тест: попытка invoke `read_file` с путём вне белых директорий возвращает ошибку.

### P0.2. Защита XSS-поверхности предпросмотра

**Проблема:** `preview.innerHTML = html` + пропуск сырого inline-HTML из CommonMark; единственная защита — CSP (хрупко).

**Требования (выбрать и зафиксировать одну стратегию):**

- **Вариант A (рекомендуемый, без новых зависимостей):** в `md-core` добавить опцию «безопасного режима» — постобработка/конфиг, при которой сырой HTML вырезается (фильтрация событий `Html` у pulldown-cmark либо crate `ammonia` как новая зависимость md-core с feature `sanitize`, включённой в приложении). Ссылки `javascript:` — удалять/нейтрализовать.
- **Вариант B:** оставить raw-HTML, но добавить DOMPurify на фронтенде перед `innerHTML`.

Дополнительно (в обоих вариантах):

- CSP в `tauri.conf.json`: убрать `http:` из `img-src` (оставить `https:` + `data:`); явно прописать `script-src 'self'`;
- ссылки наружу (`<a href="http(s):">`) — открывать системным браузером (tauri-plugin-opener / shell), а не в WebView.

**Критерии приёмки:**

- тест md-core: `<img src=x onerror=alert(1)>` в markdown → в HTML нет `onerror`/`<script>`; `javascript:`-href нейтрализован;
- ручной: клик по http-ссылке в предпросмотре открывает внешний браузер.

### P0.3. Тесты на IPC-слой

**Проблема:** ни одного теста на команды Rust, где дыра.

**Требования:** модульные тесты на `read_file`/`write_file` (через вызов внутренних функций с `TempDir`, dev-зависимость `tempfile`): happy path, запрещённое расширение, путь вне корней, превышение размера.

## 3. Задачи P1 — Надёжность и UX

### P1.1. Сброс состояния рендера при смене документа

В `newFile`/`openFile`: `clearTimeout(debounceTimer)`, инкремент `renderSeq`, сброс `lastRenderedHtml` — исключить «эхо»-рендер старого ввода в новом документе.

### P1.2. Обработка ошибок в `enhanceTables`

Обернуть вызов в `try/catch` внутри `doRender`: при исключении — `flash()` с сообщением, предпросмотр остаётся читаемым (HTML без улучшений таблиц лучше полу-сломанного DOM).

### P1.3. Корректный цикл закрытия окна

В `onCloseRequested`: после подтверждения заменить `destroy()` на снятие `dirty` + повторный `close()` (graceful-путь Tauri); `destroy` оставить как fallback по таймауту.

### P1.4. Фикс `setAll` в мини-поиске фильтра (tables.ts)

`syncFromCheckboxes` должен учитывать состояние видимых и скрытых чекбоксов согласованно с Excel-семантикой: «Ничего» при активном мини-поиске снимает галки только с видимых — это ок, но счётчик «все выбраны = фильтр снят» должен считаться по фактическому набору. Зафиксировать поведение тестом-сценарием (можно ручной чек-лист в README).

### P1.5. Символьный счётчик

`statSize`: считать code points (`[...str].length`) вместо UTF-16 единиц; подпись «симв.» становится честной.

## 4. Задачи P2 — Производительность и качество

### P2.1. Кеширование типов колонок таблиц

Вычислить `kinds` один раз в `enhance()` (и при повторном открытии файла), передавать в `apply()`; убрать O(N×M) с regex на каждый клик. Целевая метрика: клик по сортировке таблицы 1000×8 < 16 мс.

### P2.2. Разрешение произвольных папок через диалог

Чтобы не ломать UX (открыть файл не из docs/desktop/downloads): после успешного `open()`/`save()` диалогом — «запоминать» родительскую директорию как разрешённую на сессию (Rust-side: `Mutex<HashSet<PathBuf>>` в managed state). Валидация P0.1 продолжает применяться ко всем invoke-вызовам.

### P2.3. Мелочи

- `md-core`: `Options::empty().union(...)` → цепочка `|` (читаемость);
- удалить ложный комментарий про capability (часть P0.1);
- README: задокументировать модель угроз (что защищено, чем).

**Риски:**

- белые списки папок могут заблокировать легитимные сценарии — компенсируется P2.2;
- `spawn_blocking` меняет сигнатуры команд — синхронизировать с `tauri.ts` (вызовы уже `Promise`, фронтенд не пострадает).
