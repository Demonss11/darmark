## 1. Целевая картина

AI-ассистент — **встроенная подсистема хоста** (как `DocumentStore` или `RenderCache`), которая снижает порог входа в работу с Markdown и создание Lua-плагинов. Пользователь описывает задачу на естественном языке, ассистент предлагает правки документа или генерирует код плагина, пользователь проверяет и применяет.

**Ключевой принцип:** AI — **помощник, а не замена**. Пользователь всегда контролирует, что применять, а что отклонить. Все действия ассистента проходят через существующие механизмы (DocumentStore, песочница плагинов, permissions).

### Проблема

1. **Порог входа в Markdown** — пользователь не знает синтаксис, не может структурировать документ.
2. **Порог входа в Lua-плагины** — пользователь не знает host-API, модели permissions, песочницы.

### Целевая аудитория

| Персона | Болевая точка |
|---------|---------------|
| **«Писатель»** | Нужна помощь в структурировании, конспектировании, форматировании Markdown |
| **«Расширитель»** | Хочет создать плагин, но не знает Lua/host-API |
| **«Разработчик плагинов»** | Нужен инструмент для быстрого прототипирования и отладки |

### Текущее состояние

- AI-ассистент отсутствует. Пользователь работает с документом и плагинами вручную.
- Плагинная система (H2) реализована: песочница, permissions, валидация манифеста, `plugin-host --self-test`.
- `DocumentStore` (D5) — владелец текста и undo-стека; правки через `apply_edit`.

### Принципы

- **Best-effort observability** — как журнал (S11), потеря ответа LLM не критична.
- **CSP `default-src 'self'`** — все сетевые вызовы только с Rust-стороны.
- **D6 (≤6 МБ)** — AI-клиент не должен раздувать базу.
- **D16 (изоляция плагинов)** — плагины, созданные AI, проходят ту же песочница.
- **D5 (владелец текста — Rust)** — правки документа идут через `DocumentStore.apply_edit`.
- **Приватность** — пользователь должен явно согласиться на отправку содержимого документа в LLM.

## 2. Scope

**Принцип баланса (11.10.2026):** AI-ассистент — **дополнительный** функционал лёгкого текстового редактора, а не основной. MVP намеренно минимален и не перенагружается (два скилла, история в памяти, без телеметрии); при этом ассистент остаётся **информативным** — понятные состояния, показ `usage`/токенов, читаемые ошибки.

### В scope (MVP/Фаза 1 + Фаза 2 — тот же релиз)

1. **AI-панель** — режим `AI` нижнего дока (`#logs-panel`, ADR-0030) с чатом, кнопки «AI» в тулбаре (`#tb-ai`) и статусбаре (`#sb-ai`).
2. **Провайдер LLM — OpenAI-совместимый API** (ADR-0032): протокол OpenAI (`POST /chat/completions`,
   `Authorization: Bearer <key>`, формат `messages`/`choices[].message.content`), базовая точка
   `https://routerai.ru/api/v1`, модель по умолчанию `deepseek/deepseek-v4.1-flash` — как **единственный
   реализуемый в MVP**. Клиент — любой OpenAI-совместимый; интерфейс провайдера держим расширяемым
   (Anthropic и пр. — позже), локальная LLM — вне scope (см. ниже).
3. **Настройки AI** — ввод и хранение **API-ключа** локально в `%APPDATA%/darmark/config.json` (секция `ai`, поле `api_key`; существующий `SettingsStore`, D11) и **выбор модели** в UI (`#ai-settings-pop`); **очистка ключа** — пустой строкой через `ai_set_api_key("")` (после `trim` → `api_key = None`, §3.2/§9.1).
4. **Rust-сетевой слой** — HTTP-клиент на Rust-стороне, обход CSP.
5. **Библиотека скиллов — ровно 2 готовых промта в MVP:** «Объяснить файл» (`explain`) и «Создать плагин» (`create-plugin`). Остальные (переструктурировать, конспект, отладить плагин, добавить view, объяснить синтаксис) — Фаза 3/«позже».
6. **Harness для документа (Фаза 2, тот же релиз)** — предложение диффов с предпросмотром и применением через `apply_edit`.
7. **Harness для плагинов (Фаза 2, тот же релиз)** — создание/редактирование/удаление Lua-плагинов с валидацией песочницы;
   делегирование `plugin-cli` (`darmark-plugin init` / `test <dir> --json`) с fallback (§6, ADR-0034 §2.4).
8. **Согласие пользователя** — явный диалог перед первой отправкой содержимого в облачный сервис routerai.ru.
9. **История диалога** — **только в памяти на сессию** (без персистентности в MVP).
10. **Логирование** — метаданные запросов (timestamp, model, token count) без содержимого. **Телеметрия/аналитика — вне MVP.**
11. **Размещение AI-рантайма (ADR-0034)** — **в процессе GUI** (`src-tauri/src/ai/`), отдельный
    бинарник/сайдкар `darmark-ai.exe` **отложен**. Закладывается **шов `AiBackend`/`AiTransport`**
    (точка «вызов провайдера + передача текста»), чтобы будущий сайдкар стал **drop-in** — замена
    реализации трейта **без переделки UI и IPC-контрактов** фронта.
12. **Включаемость без бинарника (ADR-0034)** — флаг **`ai.enabled`** в `config.json` (секция `ai`,
    settings-store D11) + **ленивая инициализация**; состояния «**выкл / нет ключа / нет согласия /
    офлайн**» и индикатор `#ai-dot`. При `ai.enabled = false` панель показывает **заглушку**
    (либо скрыта), **запросов нет**. **По умолчанию `enabled = false` — opt-in** (§3.2/§8.1):
    свежая установка не делает сетевых запросов, пока пользователь явно не включит AI.
13. **Стриминг ответов (SSE) — в MVP (Фаза 1).** Ответ приходит потоково: события `ai:chunk`
    (инкрементальный дельта-текст), `ai:done` (финальный `usage`), `ai:error` (§9.2); механизм —
    SSE (`stream: true`, `Response::chunk()`; ADR-0033).

### Вне scope (отдельные задачи)

| Задача | Обоснование |
|--------|-------------|
| **Локальная LLM** (Ollama/llama.cpp) | **Отложена на неопределённый срок** (вне scope, ADR-0032); при возврате — отдельный ADR/спайк. Локальный провайдер усложняет онбординг и медленный на CPU |
| **Anthropic API** | Возможное расширение провайдера позже за той же абстракцией; в MVP реализуется только OpenAI-совместимый API (routerai.ru, ADR-0032) |
| **Пользовательские скиллы** | Расширяемость промтов пользователем/плагинами |
| **AI как плагин** | Противоречит архитектуре: AI нужен Rust-сетевой слой |
| **Модель доверия шире документа/плагинов** | AI не получает доступ к ФС, сети или другим подсистемам |
| **Мультимодальность** | Изображения, аудио — не в scope |
| **Редактирование скиллов пользователем** | Отдельный UI для создания/редактирования промтов |
| **Интеграция с облачными хранилищами** | Google Drive, OneDrive |
| **Автоматический запуск плагинов** | Без явного подтверждения |
| **Расширенная аналитика** | Статистика использования AI |
| **MCP (inbound-сервер внешних клиентов)** | **Вне MVP (ADR-0034 §2.5).** MCP — отделённая граница доверия (внешние клиенты вызывают нас), качественно иная, чем outbound-запрос к провайдеру; при появлении кейса — отдельный ADR |
| **Сайдкар `darmark-ai.exe`** | **Отложен (ADR-0034).** В MVP — в процессе GUI; шов `AiBackend`/`AiTransport` держит выделение в child рефактором без правок UI/IPC (триггеры пересмотра — в ADR-0034 §2.6, в ТЗ не описываются) |

### 3.2. Провайдер LLM

**Решение (ADR-0032): в MVP реализуется только OpenAI-совместимый API (облако, точка `routerai.ru`); локальная LLM отложена на неопределённый срок.**

| Вариант | Плюсы | Минусы | Совместимость с CSP/D6 |
|---------|-------|--------|------------------------|
| **OpenAI-совместимый API (routerai.ru)** — **выбран** | Работает «из коробки» (нужен только ключ); протокол OpenAI → переносимый клиент; быстрый отклик; выбор моделей через роутер | Данные уходят в облако через **сторонний роутер** `routerai.ru` (а далее — к выбранной модели); нужны ключи; сетевые вызовы; стоимость/лимиты роутера | Только Rust-сторона; ключ локально в `config.json` (AppData) |
| **Локальный (Ollama)** — **отложен** | Приватность; нет вызовов наружу | Требует запущенного сервера и загрузки моделей (онбординг); медленно на CPU | CSP не нарушен; размер модели вне процесса |
| **Гибрид (выбор пользователя)** — отклонён сейчас | Максимальная гибкость | Сложнее конфигурация; локальной ветки нет | Оба варианта допустимы |

**Вывод:** выбран **OpenAI-совместимый API** (точка `routerai.ru`, модель по умолчанию
`deepseek/deepseek-v4.1-flash`); локальный провайдер и гибрид — вне scope (при возврате — отдельный
ADR/спайк).

**Протокол и точка.** Протокол — **OpenAI-совместимый** (`POST /chat/completions`, Bearer-токен, формат
`messages`/`choices[].message.content`), поэтому клиент может быть любым OpenAI-совместимым. Базовая
точка — **`https://routerai.ru/api/v1`** (сторонний роутер; далее запрос уходит к выбранной модели).
Референс-фрагмент — `ideas/openai_deepseek.txt`.

**Конфигурация провайдера** (в `%APPDATA%/darmark/config.json` — существующий settings-store D11,
секция `ai`):

```json
{
  "plugins": {},
  "recent_files": [],
  "ai": {
    "enabled": false,
    "provider": "openai-compatible",
    "base_url": "https://routerai.ru/api/v1",
    "model": "deepseek/deepseek-v4.1-flash",
    "api_key": "<секрет, локально>",
    "consent_document_send": false,
    "max_tokens": 4096,
    "temperature": 0.7
  }
}
```

`enabled` — включаемость без бинарника (ADR-0034); **по умолчанию `false` (opt-in)**: до явного
включения пользователем сетевых запросов нет. `consent_document_send` — согласие на отправку
содержимого документа (§4.2), по умолчанию `false`; отдельные команды согласия **не вводятся** —
поле читается/пишется через `ai_get_settings`/`ai_set_settings` (§9.1). `base_url` и `model`
настраиваемы; API-ключ хранится в той же секции `ai` (`api_key`), локально.

**Хранение API-ключа (секрет):**

- Ключ хранится **локально в `%APPDATA%/darmark/config.json`**, в секции `ai`, поле `api_key` — том же
  каталоге, что настройки и плагины (`%APPDATA%/darmark/`), через существующий `SettingsStore` (D11).
- **Отклонено:** Windows Credential Manager / DPAPI — **избыточно для локального лёгкого редактора**
  (лишняя зависимость и сложность при том, что каталог уже хранит настройки и плагины).
- **Trade-off (принятый компромисс):** секрет лежит на диске в открытом виде; для простого локального
  лёгкого редактора это осознанный выбор «простота важнее». Митигации: маскирование в UI, ключ
  **не логируется**, права каталога `%APPDATA%/darmark/` — пользовательские (как у остального конфига).
- Ключ **не попадает** в TS-код, логи, снапшоты и события (кроме маскированного отображения в UI).
- Ввод — в UI (`#ai-key`, `type="password"`); наружу (в TS) уходит только факт `has_key` — в UI показывается **маска-заглушка** (само значение не отдаётся).
- **Очистка ключа:** `ai_set_api_key("")` (пустая строка, в т.ч. из пробелов, после `trim`) записывает `api_key = None` — секрет удаляется из `config.json`; команда не возвращает значение (наружу — только `has_key = false`).

### 3.3. Правки документа

- **Где:** Через существующий `DocumentStore.apply_edit` (D5).
- **Почему:** Единая точка правки, undo-стек, инвалидация кэша.
- **Как:** AI предлагает дифф (байтовые диапазоны UTF-8), TS показывает предпросмотр, применяет через `apply_edit`.

### 3.4. Плагины

- **Где:** Через существующий цикл валидация (`plugin-host --self-test`).
- **Почему:** Плагины, созданные AI, должны проходить ту же песочница (D16, ADR-0021).
- **Как:** Запись файлов → валидация манифеста → прогон в песочнице → регистрация.

### 3.5. AI-панель

- **Где:** Тело режима `AI` нижнего дока (ADR-0030), по образцу `logPanel.ts` (тело режима «Журнал»).
- **Почему:** AI-чат — подсистема оболочки (как журнал), а не представление документа; чат глобален и переживает переключение панелей.
- **Как:** Модуль-оболочка `aiPanel.ts` монтируется `bottomDock` в контейнер `#logs-panel` (режим `AI`); **не** view и **не** pane — `viewRegistry.ts`/`paneHost.ts` не задействуются.
- **Размещение (ADR-0034):** AI-рантайм — **в процессе GUI** (`src-tauri/src/ai/`), сайдкар отложен; вызов провайдера и передача текста инкапсулированы за швом **`AiBackend`/`AiTransport`** (будущий сайдкар — drop-in без правок UI/IPC).

### 3.6. Сборка промпта скилла

- **Промпт скилла собирает фронт** (TS): подставляет `{{doc}}` текстом текущего документа
  (с **обрезкой до 100 КБ**, §10.1) либо `{{input}}` из поля чата, и отправляет уже готовый
  массив `messages` в `ai_chat` (§9.1).
- **Rust проверяет** перед запросом: `ai.enabled`, наличие ключа и `consent_document_send`;
  промпт не «додумывает» и содержимое документа дополнительно не читает.
- Причина: единая точка сбора промта на фронте (там же текст документа и выбор скилла), а
  Rust-сторона остаётся тонким сетевым фасадом; будущий сайдкар (ADR-0034) не меняет этот контракт.

## 4. Сеть и безопасность

### 4.1. Требования к сетевому слою

| Требование | Реализация |
|------------|------------|
| **Только Rust-сторона** | Все HTTP-вызовы в `src-tauri/src/ai/`, не в TS |
| **Провайдер и эндпоинт** | OpenAI-совместимый API: `POST https://routerai.ru/api/v1/chat/completions` (ADR-0032) |
| **HTTP-клиент** | `reqwest` (`default-features = false`, `features = ["native-tls","json","stream"]`) — async-нативно на tokio Tauri; стриминг через `Response::chunk()` (ADR-0033) |
| **TLS** | Системный **SChannel** (Windows; не rustls, без OpenSSL) — самый лёгкий стек по спайку (F55/F56, ADR-0033) |
| **Авторизация** | Bearer-токен в заголовке `Authorization`; ключ берётся из `config.json` (AppData, D11) и не логируется |
| **Согласие на отправку** | Проверка поля `consent_document_send` перед каждым запросом (§4.2) |
| **Лимиты** | Максимум 1 запрос в секунду; максимум 100 КБ текста документа за запрос |
| **Логирование** | Только метаданные (timestamp, model, token count) без содержимого |
| **Таймаут** | 30 секунд на запрос |
| **Маппинг ошибок (OpenAI-совместимый)** | `401` — неверный/отсутствующий ключ; `429` — rate limit/quota (+ `Retry-After`); `400` (context length exceeded) — запрос длиннее контекста модели → предложить фрагмент/сокращение; `5xx` — транзиентные, ретрай с backoff (ограниченное число попыток); сеть/таймаут — понятная офлайн-ошибка без падения приложения. **Примечание:** сторонний роутер `routerai.ru` может отдавать собственные коды/сообщения о квотах и лимитах — обрабатывать их устойчиво (не падать на незнакомом теле/коде, показывать текст роутера, если распознать не удалось) |
| **Обработка ошибок** | Сетевые ошибки, ошибки API, ошибки парсинга — все показываются в чате |

> **Hardening — реализовано (ревью кода).** В `crates/app/src-tauri/src/ai/`: запрет редиректов
> (`Policy::none` — тело не уходит на хост, не названный в согласии); лимит накопленного ответа
> (`MAX_RESPONSE_BYTES ≈8 МиБ`) и буфера SSE (`MAX_BUFFER_BYTES ≈1 МиБ`); bounded-read тела ошибки
> (`MAX_ERROR_BODY_BYTES ≈64 КиБ`); `stream_options.include_usage = true` (иначе `usage` при стриминге
> не приходит); валидация `base_url` (`https://` всегда; `http://` — только loopback; иначе код
> **`ai_bad_settings`**). Секрет не попадает в `{:?}` (ручной `Debug` с `<redacted>`); ретрай/rate-limit
> — `tokio::time::sleep` (без блокировки воркера).

### 4.2. Модель согласия

```
Пользователь открывает режим AI дока (#sb-ai / #tb-ai)
  ↓
При первой отправке: модальный диалог согласия «AI-ассистент может отправлять содержимое документа и историю чата в облачный сервис routerai.ru (для запроса к модели deepseek/deepseek-v4.1-flash). Разрешить?»
  ├─ «Разрешить» → consent_document_send = true
  └─ «Не разрешать» → consent_document_send = false (запросы не отправляются, отказ)
  ↓
При каждом запросе: проверка consent_document_send
  ├─ true → запрос уходит
  └─ false → ошибка «Согласие не дано»
```

**Путь данных при согласии:** `darmark` (Rust-сторона) → `routerai.ru` (сторонний роутер) → выбранная
модель (`deepseek/deepseek-v4.1-flash`). Согласие явно называет **routerai.ru** как получателя
содержимого.

**Хранение согласия:** поле **`consent_document_send`** в секции `ai` настроек (`config.json`,
D11); читается/пишется через `ai_get_settings`/`ai_set_settings` (§9.1) — **отдельных команд
`ai_get_consent`/`ai_set_consent` нет**. Проверка согласия — на Rust-стороне перед каждым запросом
(внутренняя проверка поля `consent_document_send`, не IPC-команда).

### 4.3. Границы доверия

| Действие | Требует согласия | Механизм |
|----------|-----------------|----------|
| Чтение текущего документа | Да, явное | Диалог согласия при первом использовании |
| Отправка текста документа и истории чата в облако | Да, явное | Диалог согласия + настройка «не отправлять»; без согласия запрос не уходит |
| Исходящий сетевой трафик в облако (routerai.ru) | Да, явное | Только Rust-сторона; только при наличии согласия и заданного ключа |
| Хранение и использование API-ключа | Нет (локальный секрет) | Локально в `config.json` (AppData, D11); ключ не в TS/логах (кроме маскированного отображения в UI) |
| Применение правки к документу | Да, явное | Предпросмотр диффа + кнопка «Применить» |
| Создание/редактирование плагина | Да, явное | Предпросмотр файлов + кнопка «Сохранить» |
| Удаление плагина | Да, явное | Диалог подтверждения |
| Запуск плагина в песочнице | Нет (безопасно) | `plugin-host --self-test` в child-процессе |
| Проверка соединения (`ai_test_connection`, `GET /models`) | Нет (содержимое документа не отправляется) | Только Rust-сторона; проверяются `ai.enabled` и наличие ключа; согласие — про содержимое документа, а не про проверку ключа (§4.2/§9.1) |

## 5. Harness для документов

> **Замечание о фазах:** harness правки документа — **Фаза 2** (тот же релиз, после Фазы 1, §12).
> В MVP-скиллах Фазы 1 только `explain` читает документ (и **не** предлагает правок);
> `create-plugin` работает с плагинами. Поэтому поток правки ниже — **задел** под документные
> скиллы Фазы 3 (переструктурировать/конспект). В Фазе 2 harness реализуется, но не активируется
> скиллом Фазы 1; AC-3–AC-5 проверяются на техническом уровне (прямой вызов `ai_apply_edit`).

### 5.1. Поток правки документа

```
Пользователь выбирает скилл «Переструктурировать документ»
  ↓
AI-ассистент запрашивает текущий текст документа (get_document_text)
  ↓
Отправляет текст + промт скилла в LLM
  ↓
LLM возвращает новый текст (или дифф)
  ↓
AI-ассистент вычисляет дифф (minimal_diff в Rust)
  ↓
Показывает предпросмотр диффа в чате (зелёный/красный)
  ↓
Пользователь нажимает «Применить»
  ↓
AI-ассистент вызывает apply_edit (через DocumentStore)
  ↓
DocumentStore обновляет текст, rev++, undo-стек
  ↓
TS-слой получает document:changed, перерисовывает превью
```

### 5.2. Интеграция с существующим API

| Существующий контракт | Как используется |
|----------------------|------------------|
| `DocumentStore::apply_edit` | Применение правки (байтовые смещения UTF-8) |
| `DocumentStore::undo/redo` | Отмена правки ассистента |
| `DocumentSnapshot` | Получение текущего текста документа |
| `document:changed` (событие) | Уведомление TS-слоя об изменении |
| `RenderResult.changed` | Инвалидация кэша рендера |

### 5.3. Предпросмотр диффа

```typescript
interface AiDiff {
  original: string;
  modified: string;
  ops: Array<{ start: number; end: number; text: string }>;
}
```

Отображается как:
- **Зелёные строки** — добавленные.
- **Красные строки** — удалённые.
- **Кнопки:** «Применить», «Отклонить», «Отменить» (после применения — через `undo_document`).

### 5.4. Защита от гонок

Перед применением диффа проверяется `rev` документа: если пользователь успел отредактировать текст, дифф помечается как **устаревший** и предлагается пересмотр.

## 6. Harness для Lua-плагинов

> **Фаза:** harness плагинов — **Фаза 2** (тот же релиз, после Фазы 1; §12). Команды и события
> harness'а помечены в §9 как «Фаза 2».

### 6.1. Поток создания плагина

> **Harness — инструмент, не рантайм (ADR-0034 §2.4).** Сеть и вызов LLM живут в AI-модуле
> (`src-tauri/src/ai/`), а **не** в `plugin-cli`. CLI `darmark-plugin` используется как
> **dev-инструмент** (скаффолд + валидация), сеть в него не вводится.

```
Пользователь выбирает скилл «Создать плагин»
  ↓
AI-ассистент запрашивает описание плагина (из чата)
  ↓
Отправляет промт + описание в LLM (сеть/LLM — в AI-модуле, не в plugin-cli)
  ↓
LLM возвращает код main.lua + plugin.json
  ↓
Показывает предпросмотр файлов в чате
  ↓
Пользователь нажимает «Сохранить»
  ↓
[1] Запись: darmark-plugin init <dir> (скаффолд) либо запись сгенерированных файлов
  ↓
[2] Валидация: darmark-plugin test <dir> --json (манифест + entry + песочница)
     ├─ CLI доступен → версионированный JSON-отчёт (schema_version)
     └─ CLI недоступен/отчёт невалиден → fallback: plugin_core::manifest + plugin-host --self-test
  ↓
[3] Регистрация: PluginManager::load_plugins — ТОЛЬКО при ok=true
  ↓
Показывает результат проверки в чате
  ↓
Если успешно — плагин появляется в менеджере плагинов
```

### 6.2. Делегирование `plugin-cli` и fallback

Harness **делегирует** существующему CLI `darmark-plugin` (ADR-0034 §2.4):

| Операция harness | Команда CLI | Назначение |
|------------------|-------------|------------|
| Скаффолд | `darmark-plugin init <dir> [--id <id>] [--name <name>]` | Создать `plugin.json` + `main.lua` + `README.md` из шаблона (заготовка, которую далее наполняет LLM) |
| Валидация | `darmark-plugin test <dir> --json` | Манифест + entry + прогон в песочнице; **версионированный JSON-отчёт** |
| Каталог (опц., вне MVP-обязательного потока) | `darmark-plugin list/install/link/remove/update` | Локальный каталог `plugins/index.json` (`schema_version: 1`) |

- **Версионированный JSON-отчёт:** корневое поле **`schema_version`** (аддитивные поля — без мажора).
  MVP-поля: `path`, `ok`, `checks[]` (`name`/`status`/`message`), `sandbox_logs[]`. Отсутствие
  `schema_version` или неизвестный мажор → harness **не доверяет** отчёту и уходит в fallback.
- **Fallback** (CLI недоступен либо отчёт невалиден) — **прямая валидация в GUI-хосте** тем же
  контрактом проверки: `plugin_core::manifest` (манифест) + прогон `plugin-host --self-test <path>`
  в child-процессе (изоляция `mlua`, D6/ADR-0021). Результат приводится к тому же виду, что и отчёт CLI.
- **Таймаут — на стороне хоста:** запуск CLI/`--self-test` ограничен **host-side** таймаутом
  (запрос LLM — 30 с, §10.1; прогон песочницы — по бюджету watchdog, ADR-0023); при превышении —
  отчёт `ok=false`, причина показывается в чате.
- **Безопасные id/пути:** id плагина и путь проверяются **до записи** (допустимые символы id,
  отсутствие `..`/абсолютных выходов за `plugins/`, запрет symlink-эскейпа) — как в
  `plugin_core::manifest` и `scan.rs`; небезопасный id/путь → отказ без записи.
- **Порядок строго:** **запись → валидация → регистрация.** `PluginManager::load_plugins`
  вызывается **только** при `ok=true`; неуспешная валидация оставляет плагин вне реестра.

### 6.3. Интеграция с плагинной подсистемой

| Существующий контракт | Как используется |
|----------------------|------------------|
| `darmark-plugin init` (`plugin-cli`) | Скаффолд `plugin.json` + `main.lua` + `README.md` |
| `darmark-plugin test <dir> --json` (`plugin-cli`) | Валидация: манифест + entry + песочница; версионированный JSON-отчёт |
| `plugin_core::manifest::Manifest` | Валидация `plugin.json` (fallback, если CLI недоступен) |
| `plugin_core::scan::scan_plugins` | Сканирование каталога плагинов |
| `plugin-host --self-test` | Прогон плагина в песочнице (fallback; в CLI — `plugin_host::selftest`) |
| `PluginManager::load_plugins` | Загрузка нового плагина (только при `ok=true`) |
| `PluginManager::reload_plugin` | Перезагрузка после редактирования |

### 6.4. Валидация (единый контракт: CLI `test --json` либо fallback)

Источник отчёта — `darmark-plugin test <dir> --json` (при недоступности — fallback §6.2). Проверки:
1. **Манифест** — `plugin_core::manifest` (id, version, `api_version`, permissions).
2. **Entry** — наличие и размер entry-файла (`main.lua`), `MAX_PLUGIN_SOURCE_BYTES`.
3. **Песочница** — реальный load + `on_activate`/`on_deactivate` в child-процессе
   (`plugin-host --self-test`; в CLI — `plugin_host::selftest`).

CLI-отчёт и fallback дают **один и тот же контракт проверки** — `checks[]` с `manifest`/`entry`/`sandbox`;
расхождение трактуется как ошибка harness (в чат — понятная причина, регистрации нет).

### 6.5. Редактирование существующего плагина

```
Пользователь выбирает плагин в менеджере → «Редактировать с AI»
  ↓
AI-ассистент читает текущий main.lua + plugin.json
  ↓
Отправляет в LLM с промтом изменения
  ↓
LLM возвращает обновлённые файлы
  ↓
Пользователь применяет изменения
  ↓
AI-ассистент перезаписывает файлы
  ↓
Повторная валидация (darmark-plugin test <dir> --json / fallback, §6.2)
  ↓
PluginManager::reload_plugin (перезагрузка без перезапуска приложения) — только при ok=true
```

### 8.7. Доступность (a11y)

- Док: `role="region"`; тело режима AI — `role="tabpanel"`.
- Сегмент режимов: `role="tablist"` + `role="tab"`/`aria-selected`/`aria-controls` (`#mode-logs-btn` → `#logs-body`, `#mode-ai-btn` → `#ai-mode`).
- Триггеры `#sb-ai`/`#tb-ai`: `aria-expanded` (состояние дока в своём режиме).
- Чат: `role="log"`, `aria-live="polite"`, `aria-relevant="additions"`.
- Сообщения: `role="article"`, `aria-label="Сообщение пользователя/ассистента"`.
- Карточка диффа: `role="group"`, `aria-label="Предлагаемая правка"`.
- Карточка плагина: `role="group"`, `aria-label="Плагин {{name}} версии {{version}}"`.
- Скиллы: `role="button"`, `aria-label="{{title}}: {{description}}"`.
- Клавиатура: `Ctrl+Shift+A` — открыть/свернуть режим AI; `Enter` — отправить (в поле ввода), `Shift+Enter` — перенос строки; `Esc` — свернуть док / закрыть поповер настроек.
- Фокус: при открытии режима AI — в поле ввода; при сворачивании дока — на триггер **активного** режима (`#sb-ai`/`#sb-logs`).

```rust
#[tauri::command]
fn ai_get_settings(state: State<'_, AiState>) -> AiSettingsView   // синхронная, БЕЗ Result

fn ai_set_settings(settings: AiSettingsInput, state: State<'_, AiState>) -> Result<(), CommandError>

async fn ai_chat(app: tauri::AppHandle, messages: Vec<AiMessage>, state: State<'_, AiState>) -> Result<AiResponse, CommandError>

// Tauri требует Result для async-команд; Err НЕ порождается — исход проверки всегда в AiTestResult.
// Гейт: ai.enabled + наличие ключа (согласие НЕ требуется — содержимое не отправляется, §4.3).
#[tauri::command]
```

**Фаза 2 (harness — тот же релиз, после Фазы 1; §5/§6):**

```rust

#[tauri::command]
async fn ai_update_plugin(app: tauri::AppHandle, id: String, manifest: serde_json::Value, source: String) -> Result<PluginInfo, CommandError>
```

**Согласие — без отдельных команд.** Поле `consent_document_send` входит в `AiSettingsView`/
`AiSettingsInput` и читается/пишется через `ai_get_settings`/`ai_set_settings` (§4.2); команды
`ai_get_consent`/`ai_set_consent` **не вводятся**.

**Ключ не логируется** (не в события/логи, не в снапшоты). `ai_set_api_key` пишет ключ в `config.json` (секция `ai`) и **не возвращает** его; **пустая строка (после `trim`) очищает ключ** (`api_key = None`). `ai_get_settings` возвращает **только `has_key: bool`** — полное значение наружу (в TS) не уходит, UI показывает маску-заглушку.

**Размещение и шов (ADR-0034):** команды `ai_*` остаются **IPC-фасадом** над AI-модулем; вызов
провайдера и передача текста инкапсулированы за трейтом **`AiBackend`/`AiTransport`** (в MVP — одна
реализация «в процессе GUI»). Выделение в сайдкар — замена реализации трейта **без изменения сигнатур
команд/событий** и id фронта. Флаг включаемости `ai.enabled` входит в `AiSettingsView` (`enabled`).

### 9.2. События (EventBus)

**Фаза 1 (MVP) — стриминг ответа:**

| Событие | Полезная нагрузка | Когда эмитится |
|---------|-------------------|----------------|
| `ai:chunk` | `{ message_id, delta }` | Инкрементальный чанк ответа (SSE `choices[].delta.content`) |
| `ai:done` | `{ message_id, usage }` | Завершение ответа; финальный `usage` (`prompt_tokens`/`completion_tokens`) |
| `ai:error` | `{ code, message }` | При ошибке (сеть/API/парсинг) |

**Фаза 2 (harness — тот же релиз):**

| Событие | Полезная нагрузка | Когда эмитится |
|---------|-------------------|----------------|
| `ai:edit_proposed` | `{ doc_id, diff }` | Когда AI предлагает правку |
| `ai:edit_applied` | `{ doc_id, rev }` | Когда правка применена |
| `ai:plugin_created` | `{ plugin_id }` | Когда плагин создан |
| `ai:plugin_updated` | `{ plugin_id }` | Когда плагин обновлён |
| `ai:plugin_deleted` | `{ plugin_id }` | Когда плагин удалён |

> Событие `ai:message` (показать готовое сообщение) **не вводится**: чат ассистента собирается из
> `ai:chunk` + `ai:done`, сообщения пользователя рисует фронт локально.

### 9.3. Структуры данных

```rust
// src-tauri/src/ai/types.rs

// --- Фаза 1 (MVP) ---

#[derive(Clone, Debug, serde::Serialize, serde::Deserialize)]
pub struct AiMessage {
    pub role: String,  // "user" | "assistant" | "system"
    pub content: String,
}

#[derive(Clone, Debug, serde::Serialize)]
pub struct AiResponse {
    pub message: AiMessage,          // итоговое (собранное из ai:chunk) сообщение
    pub usage: Option<AiUsage>,
}

#[derive(Clone, Debug, serde::Serialize)]
pub struct AiUsage {
    pub prompt_tokens: u32,
    pub completion_tokens: u32,
}

#[derive(Clone, Debug, serde::Serialize)]
pub struct AiSkill {
    pub id: String,                  // "explain" | "create-plugin" (2 шт. в MVP)
    pub title: String,
    pub description: String,
    pub prompt_template: String,     // {{doc}} / {{input}} — подставляет фронт (§3.6)
    pub category: String,            // "document" | "plugins"
}

// Настройки для UI: БЕЗ ключа; секрет не отдаётся, только факт его наличия.
#[derive(Clone, Debug, serde::Serialize)]
pub struct AiSettingsView {
    pub enabled: bool,               // ai.enabled — включаемость без бинарника (ADR-0034); default false
    pub provider: String,            // "openai-compatible"
    pub base_url: String,            // "https://routerai.ru/api/v1"
    pub model: String,               // по умолчанию "deepseek/deepseek-v4.1-flash"
    pub max_tokens: u32,             // 4096
    pub temperature: f32,
    pub consent_document_send: bool, // согласие на отправку документа (§4.2); default false
    pub has_key: bool,               // ключ задан; само значение не возвращается
}

// Вход ai_set_settings: без ключа (секрет — только через ai_set_api_key).
#[derive(Clone, Debug, serde::Serialize, serde::Deserialize)]
pub struct AiSettingsInput {
    pub enabled: bool,
    pub provider: String,
    pub base_url: String,
    pub model: String,
    pub max_tokens: u32,
    pub temperature: f32,
    pub consent_document_send: bool,
}

#[derive(Clone, Debug, serde::Serialize)]
pub struct AiTestResult {
    pub ok: bool,
    pub model: Option<String>,   // имя модели из `GET /models` (если ответ распознан)
    pub error: Option<String>,   // понятное сообщение при сбое (ключ/сеть/статус); None при успехе
}

// --- Фаза 2 (harness) ---

#[derive(Clone, Debug, serde::Serialize, serde::Deserialize)]
pub struct AiEditOp {
    pub start: usize,
    pub end: usize,
    pub text: String,
}

#[derive(Clone, Debug, serde::Serialize)]
pub struct AiValidationResult {
    pub valid: bool,
    pub errors: Vec<String>,
}
```

> Согласие — **не отдельный тип**: поле `consent_document_send` в `AiSettingsView`/`AiSettingsInput`
> (§4.2). Тип `AiConsent` и команды `ai_get_consent`/`ai_set_consent` **не вводятся**.

## 10. Ограничения

### 10.1. Производительность

> **Принято PM (11.10.2026):** лимиты ниже — нормативные для MVP (без изменений).

| Ограничение | Значение | Обоснование |
|-------------|----------|-------------|
| Таймаут LLM-запроса | 30 секунд | Не блокировать UI дольше |
| Rate limit | 1 запрос/сек | Не спамить API |
| Максимум токенов | 4096 | Контроль стоимости |
| Лимит стоимости/токенов | показ `usage` (prompt + completion) из ответа | Контроль расходов (routerai.ru/модель); предсказуемость счёта |
| Максимум текста документа | 100 КБ | Не отправлять весь документ целиком |
| Размер диффа | 10 000 строк | Защита от огромных правок |

### 10.2. Безопасность

| Ограничение | Реализация |
|-------------|------------|
| Сетевые вызовы только с Rust | Все HTTP в `src-tauri/src/ai/`; TLS — системный SChannel (`native-tls`, ADR-0033) |
| Согласие на отправку | Проверка поля `consent_document_send` перед запросом (§4.2) |
| Проверка соединения без согласия | `ai_test_connection` (`GET /models`) шлёт запрос **без** содержимого документа и **без** согласия — согласие относится к отправке содержимого, не к проверке ключа (§4.3) |
| Ключ локально в `config.json` (AppData) | **Не** в TS, **не** в логах; в UI маскируется; каталог `%APPDATA%/darmark/` — пользовательский (как остальной конфиг) |
| Логирование без содержимого | Только метаданные (timestamp, model, tokens); текст документа/чата и ключ не логируются |
| Плагины в песочнице | `plugin-host --self-test` в child-процессе |
| Нет выполнения произвольного кода | Только через плагинную систему |

### 10.3. Бюджет размера (D6)

| Компонент | Оценка размера |
|-----------|----------------|
| HTTP+TLS стек (`reqwest` + системный SChannel; ADR-0033, F55) | ~0.71 МиБ standalone; в дереве `darmark` уже есть `tokio`/`url`/`http`/`serde_json`, поэтому маргинальный прирост **меньше** (F58) |
| AI-модуль (команды, типы, клиент, доступ к `config.json`) | ~0.2 МиБ |
| **Итого (AI-клиент)** | **≤1.0 МиБ** |

**Пояснение к бюджету:** исходный ориентир «AI-клиент ≤0.5 МБ» (HTTP+TLS ~300–500 КБ) **недостижим** — ни один `rustls`-вариант не укладывается (минимум ≈1.15 МиБ: `ureq`+rustls), а «дешёвый» TLS-стек возможен только системный. По спайку (F55/F56) выбран **`reqwest`+native-tls (SChannel)** — самый лёгкий по размеру (0.71 МиБ standalone, вклад TLS всего +0.07 МиБ, крипто и корни сертификатов — ОС); новый ориентир — **≤1.0 МиБ** маргинально.

**Вывод:** укладывается в D6 (≤ 6 МБ); общий size-gate (release-exe ≤6 МБ) сохраняется и проверяется в CI.

### 10.4. Объём документа

| Сценарий | Поведение |
|----------|-----------|
| Документ < 100 КБ | Отправляется целиком |
| Документ 100 КБ – 1 МБ | Отправляется первые 100 КБ + предупреждение |
| Документ > 1 МБ | Отправляются только выбранный пользователем фрагмент |

## 12. План реализации

### Фаза 1: MVP (2 недели)

1. Нижний док, режим AI (чат, поле ввода) — расширение дока журнала (ADR-0030); порядок режимов —
   «**Журнал | Мониторинг | AI-ассистент**».
2. Rust-сетевой слой: OpenAI-совместимый `POST /chat/completions` (routerai.ru) через **`reqwest` + native-tls (системный SChannel)**, Bearer; + настройка ключа (локально в `config.json`/AppData) и выбор модели. **Клиент — `reqwest`+native-tls, не `reqwest`+rustls** (ADR-0033).
3. **Стриминг ответа (SSE) — в Фазе 1:** `stream: true`, `Response::chunk()`; события `ai:chunk`/`ai:done`, `ai:error` (ADR-0033, §9.2).
4. Согласие (диалог; поле `consent_document_send` в `config.json`, секция `ai`) — без отдельных команд (§4.2/§9.1).
5. **2 скилла MVP:** «Объяснить файл» (`explain`) и «Создать плагин» (`create-plugin`); промт собирает **фронт** (§3.6).
6. Команды Фазы 1: `ai_get_settings`, `ai_set_settings`, `ai_set_api_key`, `ai_list_skills`, `ai_chat`, `ai_test_connection` (§9.1); ответ AI рендерится `textContent` (§8.3).
7. История чата — в памяти на сессию; `ai.enabled` по умолчанию **`false` (opt-in)** + ленивая инициализация.

**Размещение и включаемость (ADR-0034):** AI-рантайм — **в процессе GUI** (`src-tauri/src/ai/`),
сайдкар `darmark-ai.exe` **отложен**; закладывается шов **`AiBackend`/`AiTransport`** (будущий
сайдкар — **drop-in** без правок UI/IPC). Включаемость — флаг **`ai.enabled`** (default `false`) +
**ленивая инициализация** + состояния «**выкл / нет ключа / нет согласия / офлайн**» (`#ai-dot`).
**MCP — вне MVP** (отдельный ADR при появлении кейса внешних клиентов). Триггеры перехода к сайдкару
описаны в ADR-0034 §2.6 — **в этом ТЗ не дублируются**.

### Фаза 2: Harness (тот же релиз, после Фазы 1)

**Принято PM (11.10.2026): Фаза 2 выходит в том же релизе, что и Фаза 1.**

8. Harness правки документа: предпросмотр диффа (зелёный/красный), диффы на Rust (minimal diff); применение через `apply_edit`; отмена через undo-стек; защита от гонок по `rev` (§5).
9. Генерация Lua-плагинов.
10. Валидация через `darmark-plugin test <dir> --json` (версионированный отчёт, `schema_version`) с **fallback** на `plugin_core::manifest` + `plugin-host --self-test` (§6).
11. Редактирование существующих плагинов.
12. Удаление плагинов.
13. Остальные скиллы (переструктурировать, конспект, отладить плагин, добавить view, объяснить синтаксис).

### Фаза 3: Улучшения (по результатам)

14. Пользовательские скиллы; редактор скиллов.
15. Другие провайдеры (опционально: Anthropic и пр. за той же абстракцией); **локальная LLM — отложена на неопределённый срок** (ADR-0032).
16. Персистентность истории чата; телеметрия/аналитика; Rust-санитайзер Markdown для ответа AI (§8.3).

## 13. Риски

| Риск | Влияние | Митигация |
|------|---------|-----------|
| Размер AI-клиента превысит бюджет | Среднее | Бюджет пересмотрен: **≤1.0 МиБ** (ADR-0033, F55); выбран самый лёгкий вариант — `reqwest`+native-tls/SChannel (0.71 МиБ standalone); проверка в CI (size-gate ≤6 МБ) |
| Сборка TLS-провайдера (rustls/`aws-lc-rs`: `cmake`/`nasm`) | Низкое | **Снят выбором SChannel** (ADR-0033): системный TLS Windows, без OpenSSL и без сборки криптостека — новых build-зависимостей нет (обоснование выбора) |
| Качество генерируемых плагинов будет низким | Среднее | Валидация песочницы, итеративное исправление |
| Пользователи не доверяют AI с документами | Среднее | Явное облачное согласие, отключаемость, отсутствие логирования содержимого |
| Ключ на диске (секрет в открытом виде) | Среднее | Принятый компромисс: ключ локально в `config.json` (AppData, D11); митигации — маскирование в UI, не логировать, права каталога `%APPDATA%/darmark/` (как у остального конфига) |
| Недоступность routerai.ru/офлайн | Среднее | **Без fallback** (резервной модели/точки нет): честная понятная офлайн-ошибка в чате + кнопка «Повторить»; ретрай с backoff для `5xx` |
| Непредсказуемая стоимость | Среднее | `max_tokens`, выбор модели, показ `usage`, клиентский rate limit |
| Лимиты 429 | Среднее | Учёт `Retry-After`, сообщение о лимите, повтор по кнопке |
| Задержка LLM ухудшит UX | Среднее | **Стриминг (SSE)** — ответ виден по мере генерации; индикатор загрузки, таймауты |
| Гонки при применении диффа | Среднее | Проверка `rev` перед применением |
| Дистрибутив физически содержит сетевой AI-код даже при `ai.enabled=false` | Низкое | Принято (ADR-0034): «поставка без AI» — триггер пересмотра к сайдкару (ADR-0034 §2.6); в MVP `ai.enabled` гасит фичу без пересборки |
| Шов `AiBackend`/`AiTransport` — риск преждевременной абстракции | Низкое | Одна реализация в MVP (сознательно ради обратимости); расширение — только по триггерам ADR-0034 §2.6 |
| Соблазн втянуть MCP/внешних клиентов в MVP | Низкое | **MCP — вне MVP** (ADR-0034 §2.5): отделённая граница доверия (inbound); при кейсе — отдельный ADR |
