# H3 — Экосистема (отдельная задача)

> **Статус:** Фазы 1–2 закрыты (Фаза 1 — `init`/`test`; Фаза 2 — 2a локальный каталог сделан, 2b
> отложена на неопределённый срок). Фазы 3–4 не начаты; параллельно идёт стабилизация H1+H2.
> **Приоритет:** Низкий
> **Зависимости:** Стабильная работа H1 + H2

## Контекст

H1 (ядро приложения) и H2 (плагинная система) реализованы. Перед началом H3 необходимо:
- Отладить существующий функционал
- Провести E2E-тестирование
- Убедиться в стабильности плагинной системы

## Задачи

### 1. Реестр плагинов (Фаза 2 — закрыта)

**2a. Локальный каталог — сделано** (ADR-0026):
- [x] Каталог `plugins/index.json` (`schema_version: 1`)
- [x] Команда `darmark-plugin list`
- [x] Команда `darmark-plugin install <id>` (копирование)
- [x] Команда `darmark-plugin link <id>` (junction/symlink — разработка «на лету»)
- [x] Команда `darmark-plugin update [<id>]`
- [x] Команда `darmark-plugin remove <id>`

**2b. Удалённый подписанный реестр — отложено на неопределённый срок:**
- [ ] Git-репозиторий с `index.json` (сетевой источник)
- [ ] Подпись Ed25519 для верификации
- [ ] `install/update/remove` из сети (отдельный ADR, номер по назначению)

### 2. Template-репозиторий плагина (Фаза 1 — `darmark-plugin init`)
- [x] Создать шаблон для `darmark plugin init`
- [x] Структура: `plugin.json`, `main.lua`, `README.md`
- [x] Минимальный пример с `on_activate` + `host.show_message`

### 3. Тестирование плагинов (Фаза 1 — `darmark-plugin test`)
- [x] Команда `darmark plugin test <path>`
- [x] Запуск в изолированной среде (песочница `plugin-host`)
- [x] Проверка манифеста, точек входа, permissions
- [x] Отчёт о найденных проблемах (текст/JSON)

### 4. Расширение API (итеративно, не отдельная фаза)

> Расширение идёт по мере разработки плагинов, а не отдельным этапом. Внешней обратной связи пока
> нет (только эталонные плагины в `plugins/`). Перед публичным распространением зафиксировать
> политику совместимости `HOST_API_VERSION`.

- [ ] Добавлять host-функции по конкретным потребностям плагинов (итеративно)
- [ ] Политика совместимости/депрекации `HOST_API_VERSION` (до распространения)

### 5. Опциональные улучшения
- [ ] Rust-undo (D5) — стек отмены/повтора в Rust `Document`; **планируется** после стабилизации,
      нужен дизайн/ADR (rev-семантика). Не «опция» — решение D5 уже принято.
- Подсветка синтаксиса — перенесена в идеи (`ideas/UI-IDEAS.md` IDEA-014), когда-нибудь; требует ADR.
