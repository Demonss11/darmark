# TASK-003 — «Отладить плагин»: инструмент `plugin_read` + правило промта

> **Статус:** к исполнению
> **Дата создания:** 16.10.2026 (переписан 16.10: скилл `debug-plugin` уже существует; решение C8 — без Tauri-команды авто-подстановки)
> **Источник:** анализ возможностей ассистента (сабагент rust-developer)
> **Зависит от:** TASK-004 (состав скиллов); шаг 2 (TASK-003b) опирается на шаг 1 (TASK-003a, инструмент `plugin_read`)
> **Независим от:** TASK-002 (правится промт `debug-plugin`, а не `create-plugin`; шаг 1 не зависит от промтов вовсе)
> **Оценка:** ~100–120 строк Rust (инструмент и тесты) + правило промта; **логи в объём не входят**
> **Решение C8 (16.10.2026):** исходник плагина отладке отдаёт MCP-инструмент `plugin_read`, который промт вызывает **первым ходом**. Отдельная Tauri-команда авто-подстановки (`ai_read_plugin`) **не вводится** — ни регистрации в `generate_handler!`, ни правок `ai/types.rs` и `skillBar.ts`.

---

## 1. Актуальное состояние (проверено по коду)

Скилл **`debug-plugin` уже реализован** — `crates/app/src-tauri/src/ai/skills/mod.rs:160-187`,
регистрация `:286-293`. Промт содержит чек-лист причин отказа и принимает `{{input}}`.

**Чего не хватает:**

- **Ассистент не может прочитать код плагина.** Инструменты: `plugin_validate`, `plugin_test`,
  `plugin_catalog_list`, `markdown_render` — ни один не отдаёт исходник. MCP-ресурс
  `darmark://plugins/{id}/manifest` отдаёт манифест из каталога `plugin-catalog`, а не
  установленного плагина, и ассистенту resources не видны (цикл объявляет только tools).
  IPC-команд чтения кода нет; `PluginHost` держит `source` в памяти
  (`plugins/manager/runtime.rs`), но наружу отдаёт только `PluginInfo { id, name, version,
  permissions, status }`.
- **Значит пользователь обязан сам вставлять код плагина в чат.** Это и есть главный дефект:
  отладка работает, только если пользователь скопировал `main.lua` руками.
- **Логи рантайма недоступны принципиально.** Child стартует с `.stderr(Stdio::null())`
  (`plugins/supervisor/mod.rs:112`); `host.log`/`print` → `LogSink` (`plugins/services/mod.rs:62`)
  → Tauri-событие `log-entry` → журнал фронта. Кольцевого буфера в Rust нет.
  `plugin_test` возвращает логи самотеста, но там host-call'ы отклоняются и подписки не срабатывают.
- **`ai_validate_plugin` проверяет реально:** манифест + загрузка Lua + прогон `on_activate`
  в песочнице (fallback: статика + `--self-test`). Не проверяет host-call'ы, события, permissions
  в рантайме.
- **Блокер формата:** все MCP-tools принимают `path`, модель знает только `id`.

**Вывод:** скилл есть и промт хороший — нужен инструмент чтения кода, который промт зовёт сам.

## 2. Шаг 1 (TASK-003a) — MCP-инструмент `plugin_read` (минимальный вариант)

~100–120 строк, 3 файла кода + 2 файла тестов. Фронт не трогаем.

| Файл | Правка |
|---|---|
| `src-tauri/src/mcp/adapters/tools.rs` | рядом с `PluginValidateTool` (после `:69`) — `PluginReadTool { sink }`: `name "plugin_read"`, схема **`{ id }`** (только `id`, произвольный путь не принимается); порядок: `validate_plugin_id(id)` → `plugins_root()?.join(id)` → `ensure_plugin_path_allowed` (`ai/plugin_harness/paths.rs:82`); чтение `plugin.json` + `main.lua` с проверкой `plugin_core::manifest::validate_source_len`; санайтизация путей в ответе тем же `sanitize_*`, что у соседей; ошибки — `ToolError::invalid_params/internal` |
| `src-tauri/src/mcp/adapters/mod.rs` | импорт + `registry.register_tool(...)` рядом с `:38-54` |
| `ai/plugin_harness/tests/mcp.rs` | 2 теста по образцу `call_plugin_test`/`temp_plugin` (`:48-108`): happy path по `id`; отказ на `../` и несуществующем id |
| `tests/mcp_contract.rs:106` | `expected_tools()` += `"plugin_read"` — иначе упадёт `tools_list_declares_inventory_with_usable_schemas` |

Принимает `id` — это же снимает блокер «модель не знает путь»: путь строится на стороне Rust
из доверенного корня, а не приходит от модели.

**Вердикт вызова — не поле обработчика.** `plugin_read` **не** инструмент-верификатор: его
«успех» означает «выполнилось», а не «проверка прошла». Поэтому его payload обязан быть **без**
поля `isError` — правило ADR-0041 §2.2 п.15 (`markdown_render`/`plugin_catalog_list` того же
класса). `isError` появляется только у `plugin_validate`/`plugin_test` (класс A) и у `Err`
(`plugin_catalog_list` с битым `index.json`).

- [ ] тест: happy path по `id` → манифест + исходник
- [ ] тест: `id = "../x"` и несуществующий id → отказ, без чтения файлов (путь не покидает `plugins_root()`)
- [ ] тест: payload `plugin_read` не содержит поля `isError` (ADR-0041 §2.2 п.15)
- [ ] `cargo test -p darmark` — зелёный

## 3. Шаг 2 (TASK-003b) — правило промта: промт сам зовёт `plugin_read`

Решение C8 (16.10.2026): отдельная Tauri-команда авто-подстановки (`ai_read_plugin`) **не
вводится**. Источник кода для отладки — MCP-инструмент `plugin_read`, который промт
`DEBUG_PLUGIN_PROMPT` вызывает **первым ходом**. Правка ограничена промтом: без новых команд,
без регистрации в `generate_handler!`, без правок `ai/types.rs` и `panels/aiPanel/skillBar.ts`.

| Файл | Правка |
|---|---|
| `ai/skills/mod.rs` (`DEBUG_PLUGIN_PROMPT:160-187`) | добавить инструкцию: **первым ходом** вызвать `plugin_read` с `id` плагина и дальше вести диагностику по полученному `source` |
| `ai/skills/mod.rs` (`DEBUG_PLUGIN_PROMPT`) | **fallback-чеклист**: если исходник не получен (инструмент недоступен, `id` неизвестен, пользователь не назвал плагин) — попросить пользователя вставить `main.lua` и `plugin.json` в чат |

**Размен.** Гарантия UX ниже, чем у Tauri-команды: успех зависит от того, вызовет ли модель
инструмент — промт даёт инструкцию и fallback, но не принуждает. Взамен — нет новой команды,
её контракта, реэкспорта макросов и правок фронта; дифф ограничен одним промтом. **При провале
эвалов отладки** (модель не зовёт `plugin_read` даже с fallback-правилом) решение
**пересматривается на Tauri-команду авто-подстановки** — вариант с `ai_read_plugin` остаётся
запасным и описан в §5 «Отклонено в этой итерации».

- [ ] `DEBUG_PLUGIN_PROMPT` содержит правило «первым ходом вызвать `plugin_read`»
- [ ] `DEBUG_PLUGIN_PROMPT` содержит fallback-чеклист (код не получен → попросить вставить)
- [ ] `cargo test -p darmark` — зелёный (промт — Rust-константа, `npm run build` не требуется)

## 4. Шаг 3 — дополнение промта отладки

В `DEBUG_PLUGIN_PROMPT` (`mod.rs:160-187`) добавить отсутствующие классы ошибок (источник
промтов теперь один — копии-фолбэка `FALLBACK_SKILLS` нет, см. TASK-008):

- **«ничего не происходит»:** подписки не сняты / `on_activate` сделал работу вместо обработчика /
  нет события, на которое подписан.
- **watchdog и карантин:** `PROGRESS_TIMEOUT_MS` = 400 мс, `DEADLINE_MS` = 1500 мс,
  3 падения подряд → карантин, включить вручную.
- **разрешения в рантайме:** `permission_denied` приходит **значением** `(nil, {code, message})`,
  не исключением; `permissions` в манифесте не совпадают с реально вызываемыми функциями.
- **формат ответа:** сейчас симптом/причина/исправление текстом; если в чат попадает diff —
  развести парсинг в `pluginProposal.ts` (он ищет карточку по ```json). Решение: карточку плагина
  рисовать только если ответ содержит **полный** `source` (иначе — обычный текст с инструкцией).
  `pluginProposal.ts:54-55` уже отбрасывает объект без `source` (`if (!id || !source) return null;`),
  но это поведение сейчас **не проверяется** — закрепить его в приёмке (§7).

## 5. Логи — вне объёма

Хвост runtime-логов = **не минимальный дифф**: кольцевой буфер ~200 строк в
`DocumentServices.with_log_sink` / `setup/plugins.rs:215` + команда `ai_plugin_log_tail` + правка
`PluginState`. Отдельная задача, если подтвердится, что без логов отладка не работает.
Текущий обходной путь — `plugin_test` возвращает логи самотеста (полезно для ошибок загрузки).

**Отклонено в этой итерации.** Tauri-команда `ai_read_plugin(id) -> {manifest, source}` с
подстановкой в `{{input}}` (`ai/plugin_harness/commands.rs`, `ai/types.rs`, регистрация в
`lib.rs`, правка `skillBar.ts:85-96`) — запасной вариант шага 2, отложен до провала эвалов
(§3). Не минимальный дифф: команда, контракт, реэкспорт `__cmd__*`/`__tauri_command_name_*`
(ADR-0039), правка фронта.

## 6. Риски и ограничения

1. **Ограничение задачи — исходящая передача кода.** Ответ `plugin_read` (исходник плагина)
   уходит LLM-провайдеру: тот же класс данных, что `{{doc}}` в скилле «Объяснить файл». Граница
   доверия — ADR-0035 §2.7 (согласие привязано к активному хосту) и ADR-0029 (приватность):
   содержимое плагина покидает машину в теле запроса. **Решение владельца (16.10.2026):** исходник
   может уходить; отдельная формулировка в согласии/privacy **не требуется** — согласие на
   отправку уже покрывает пользовательский контент.
2. **Обход белого списка.** Схема принимает только `id` через `validate_plugin_id` →
   `plugins_root()/id` → `ensure_plugin_path_allowed`. **Произвольный путь не принимается** — ни
   отдельным параметром `path`, ни внутри `id`.
3. **Ответ — только `plugin.json` + `main.lua`.** Никаких `settings` (могут содержать
   пользовательские значения), никакого документа.
4. **Ложная «отладка».** Без `plugin_read` модель чинит по коду, которого не видела.
5. **Модель не вызывает инструмент.** Смягчение — инструкция «первым ходом» + fallback-чеклист
   (§3); при провале эвалов — пересмотр на Tauri-команду.
