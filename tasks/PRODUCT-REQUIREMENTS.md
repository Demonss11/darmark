> **Статус:** действующий продуктовый слой поверх задач; источник истины для «зачем»

## 1. Назначение и рамки

Продукт — лёгкий Markdown-редактор/вьюер (аналог Notepad++ для Markdown): редактор слева,
HTML-предпросмотр справа, таблицы, инспектор, синхронная прокрутка. Расширяется
**пользовательскими Lua-плагинами без пересборки** — это главная продуктовая фича по
`docs/DESIGN_DOC.md` §1.2.

**Рамки этого документа — AI-подсистема и плагинный UX**, которые затрагивает текущий срез работ
(TASK-001…009). Архитектура, контракты host ↔ плагин и визуальная идентичность здесь **не**
переопределяются: норма — `docs/DESIGN_DOC.md`, `DESIGN.md`, `docs/adr/`. Изменения host-API идут
через ADR (`docs/adr/0042-*.md`, TASK-001), а не через этот документ.

**Вне рамок:** платформенный pivot «Host/Engine» и «тонкий host» (EPIC E — отложены, P3);
кроссплатформенность (продукт — только Windows); CodeMirror, CPU-тяжёлые плагины
(`DESIGN_DOC.md` §1.3).

## 4. Эпики и user stories

Формат: эпик → приоритет → задача(-и) → user story → критерии приёмки (сжато; детали — в файле
задачи). Все критерии проверяемы командой или E2E-сценарием.

### EPIC A — Сохранность документа при AI-правках (P0)

**Задача:** TASK-006.
**Проблема:** `truncateDoc` режет `{{doc}}` до 100 КБ в лог, а не в чат; для пишущего скилла
(`restructure`) это потеря хвоста документа, которую пользователь замечает по исчезнувшему тексту.

**US-A1.** Как автор документа, я хочу быть **остановлен** при риске потери текста, чтобы правка
ассистента не удалила часть документа молча.

**AC-A1** (источник — TASK-006 §4, §6):
- пишущий скилл при усечении **не отправляет** запрос; в чате — видимое предупреждение, а не
  только запись в лог-панель (TASK-006 §4 шаги 3–4);
- непишущий скилл отправляет запрос, но с заметкой о неполном разборе;
- **обязательный E2E-сценарий** «Усечение документа останавливает пишущий скилл…» зелёный, без
  `@manual` (TASK-006 §6);
- `npm run build`, `npm run lint`, `npm run knip` зелёные.

**US-A2.** Как автор документа, я хочу, чтобы подсказка называла **конкретный** скилл, чтобы понять,
что делать (дописать `{{input}}` или разбить документ).

**AC-A2:** сообщение «нужно описание в поле ввода» содержит title текущего скилла, а не
захардкоженное «Создать плагин» (TASK-006 §4 шаг 4, §7).

### EPIC B — Понятный ряд AI-скиллов (P1)

**Задачи:** TASK-007 (переименование), TASK-004 (удаление `add-view`), TASK-005 (удаление
`summarize`), TASK-009 (чип цели), подсказка из TASK-006.
**Проблема:** ряд из 7 кнопок с пересекающимися темами (`explain`↔`summarize`,
`create-plugin`↔`add-view`, `explain`↔`explain-syntax`) — шум; после прореживания новичок теряет
вход в сценарий «вкладка».

**US-B1.** Как автор документа, я хочу отличать «объяснить» от «проверить», чтобы нажимать нужный
скилл.

**AC-B1:** кнопка `explain-syntax` называется «Проверить разметку», description говорит о проверке
корректности; ряд содержит **5** боевых скиллов; `explain` не тронут (TASK-007 §3, §5).

**US-B2.** Как автор плагинов-новичок, я хочу найти вход «вкладка» через чип цели, чтобы не искать
удалённую кнопку «Добавить вкладку».

**AC-B2:** чип цели (`вкладка | статусбар | команда`) виден рядом с «Создать плагин»; выбранная
цель доезжает до отправляемого запроса строкой вида «нужна собственная вкладка (view)»;
E2E-сценарий выбора цели зелёный (TASK-009 §5, §7).

**AC-B3** (состав ряда, источник TASK-004 §5, TASK-005 §6):
- `add-view` и `summarize` отсутствуют в коде и ряду; `builtin_skills()` возвращает 5;
- E2E `ai.feature` и unit-тесты скиллов обновлены и зелёные;
- `PLUGIN_SKILL_IDS` = `["create-plugin", "debug-plugin"]`.

### EPIC C — Единый источник промтов (P1, enabler)

**Задачи:** TASK-002, TASK-004, TASK-005, TASK-008, TASK-001.
**Проблема:** API-блок промта (`create-plugin` × `mod.rs`/фолбэк, `add-view` × 2 копии) продублирован
дословно; каждая правка нормы обязана попасть в несколько мест, иначе копии разъезжаются молча.

**US-C1.** Как сопровождающий, я хочу править API-блок промта в **одном** месте, чтобы копии не
разъезжались.

**AC-C1:** фолбэк `FALLBACK_SKILLS` удалён; `rg "FALLBACK_SKILLS"` пусто; в `skillBar.ts` нет
тернарника/`.catch`, подставляющего другой набор (TASK-008 §5, §6).

**US-C2.** Как автор плагинов, я хочу, чтобы промт «Создать плагин» был самодостаточен (манифест,
точки входа, лимит окна, цикл окон), чтобы не искать внешний документ.

**AC-C2:** правки A–D внесены в `CREATE_PLUGIN_PROMPT`; промт вырос ≤10 строк; `docs/PLUGIN_API.md`
удалён, нормативность перенесена в ADR-0042 §2.1 (два промта — `create-plugin`, `debug-plugin`) и
док-комментарии кода (TASK-002 §6, TASK-001 §2/§6).

### EPIC D — Отладка Lua-плагина без копипаста (P1, фича)

**Задача:** TASK-003 (`debug-plugin` уже существует; не хватает инструмента чтения кода).
**Проблема:** ни один MCP-инструмент и ни одна IPC-команда не отдают исходник установленного
плагина; пользователь вставляет `main.lua` в чат руками.

**US-D1.** Как автор плагина, я хочу, чтобы ассистент сам прочитал код моего плагина, чтобы не
копировать его в чат.

**AC-D1** (источник — TASK-003 §2/§3, §7):
- MCP-инструмент `plugin_read` объявлен в `tools/list`, схема — только `id`; путь строится из
  доверенного корня, произвольный путь не принимается;
- промт `DEBUG_PLUGIN_PROMPT` зовёт `plugin_read` **первым ходом** и содержит fallback-чеклист
  (код не получен → попросить вставить);
- payload без поля `isError` (не инструмент-верификатор, ADR-0041 §2.2 п.15);
- ответ содержит только `plugin.json` + `main.lua`; `tests/mcp_contract.rs` обновлён; `cargo test
  -p darmark` зелёный.

### EPIC E — Платформа: Host/Engine + тонкий host (P3, отложено)

**Идеи:** `tasks/IDEA-002-SPIKE-DISCUSSION.md` (разделение Host / Engine),
`tasks/IDEA-004-SPIKE-DISCUSSION.md` (тонкий host + адаптеры/провайдеры).
**Продуктовая цель:** перестать быть приложением, «умеющим Markdown», и стать редактором,
подключающим движки; host максимально тонкий, функциональность дают адаптеры и провайдеры.

**US-E1.** Как сопровождающий-архитектор, я хочу, чтобы граница между host и движком была
зафиксирована, чтобы подключение движка было одной точкой, а не правкой семи мест.

**AC-E1:** до старта спайков **обязателен ADR**, фиксирующий общий шов «граница Host ↔ Engine»
(единый для IDEA-002 и IDEA-004, см. IDEA-002 §3.3). Спайк не начинается без утверждённого ADR;
продуктовые метрики EPIC A–D от него не зависят.

> **Статус P3:** условие старта — закрытие вехи H2 (закрыта) и решение владельца по агентам/
> приоритету; до этого идеи живут как документы-обсуждения, кода не трогают.
