# План реализации H3 — Экосистема плагинов

## Обзор задачи

H3 — экосистема плагинов, включающая 5 направлений:
1. Реестр плагинов (install/update/remove, Ed25519)
2. Template-репозиторий плагина
3. Тестирование плагинов
4. Расширение API
5. Опциональные улучшения

> **Текущий статус:** Фаза 1 — **сделана**; Фаза 2 — **закрыта** (2a сделана, 2b отложена
> на неопределённый срок); Фаза 3 — **не отдельная фаза** (расширение API идёт итеративно,
> по конкретным потребностям плагинов); Фаза 4 — **разобрана** (подсветка → идеи IDEA-014;
> Rust-undo — планируется после стабилизации).

## Приоритизация и последовательность

Предлагаю разбить на фазы с учётом зависимостей:

### Фаза 1: Основа (без реестра) - **СДЕЛАНО**
**2. Template-репозиторий плагина** — `plugin.json`, `main.lua`, `README.md`, минимальный пример.
**3. Тестирование плагинов** — `plugin test <path>` с проверкой манифеста/точек входа/permissions.

*Почему первым:* не зависят от реестра, нужны для обратной связи и расширения API.

### Фаза 2: Реестр — **ЗАКРЫТА** (2a сделана; 2b отложена)
**2a. Локальный каталог плагинов — СДЕЛАНО.** `plugins/index.json` (`schema_version: 1`,
`{id, path, description}`; метаданные из `plugin.json`) + CLI `darmark-plugin list/install/link/remove/update`
(ADR-0026). Без сети и подписи.

**2b. Удалённый подписанный реестр — ОТЛОЖЕНА НА НЕОПРЕДЕЛЁННЫЙ СРОК.** Git-репозиторий +
Ed25519 + `install/update/remove` из сети; отдельный ADR (номер по назначению) и только при реальной потребности.

*Почему так:* локальный каталог закрывает discoverability/установку без сети и ключей; удалённый
реестр — тяжёлая инфраструктура (сеть, ротация ключей, доверие, CI/CD), преждевременная до
стабилизации продукта.

### Фаза 3: Расширение API — **НЕ ОТДЕЛЬНАЯ ФАЗА (итеративно)**
Расширение API идёт **итеративно**, по конкретным потребностям реальных плагинов, а не отдельным
этапом: у «фазы» нет входных данных (обратной связи), пока продукт не распространён. Добавление
host-функций — обычные задачи по мере необходимости, с обновлением `docs/PLUGIN_API.md`.

**Единственное, что стоит зафиксировать заранее** (дёшево сейчас, дорого после публикации):
политика совместимости `HOST_API_VERSION` — когда поднимать мажор, обещание не ломать плагины,
депрекация. Оформить как ADR/раздел перед первым публичным распространением.

### Фаза 4: Опциональные — **РАЗОБРАНА**
**Подсветка синтаксиса — В ИДЕИ.** Сейчас не нужна; перенесена в бэклог — `ideas/UI-IDEAS.md`
IDEA-014 («когда-нибудь»; требует отдельного ADR).

**Rust-undo (D5) — ПЛАНИРУЕТСЯ (не «опция»).** Владелец текста и undo-стека — Rust `Document`
(D5, §4.2) — **уже принятое решение**, а не опция. Текущее ограничение зафиксировано
(`formatActions.ts`: программная правка сбрасывает нативную историю `textarea`). Делать **после
стабилизации**, с отдельным дизайном/ADR: меняет семантику `rev`/`DocumentStore`, затрагивает
`editorView`/`formatActions`/`apply_edit` плагинов и объединяет правки в единый стек с ревизиями.

## Ключевые вопросы для обсуждения

### 1. Реестр плагинов
- **2a (локальный каталог) — решено:** формат `index.json` и команды зафиксированы в ADR-0026
  (`schema_version` + `{id, path, description}`, метаданные — из `plugin.json`).
- **2b (удалённый, Ed25519) — отложено на неопределённый срок:** хранение подписей (отдельный файл
  или внутри `index.json`), источник репозитория (GitHub Releases / отдельный Git-репозиторий),
  публичные ключи и их ротация — к моменту возобновления, отдельным ADR (номер по назначению).

### 2. Тестирование плагинов
- **Формат отчёта:** текст, JSON, интерактивный?
- **Объём проверок:** только статический анализ или запуск в песочнице?
- **Интеграция с CI:** нужна ли для реестра?

### 3. Расширение API — итеративно
- **Какие плагины уже написаны?** Пока только эталонные в `plugins/`; внешней обратной связи нет.
- **Какие host-функции запрашиваются?** Определяется по мере появления реальных плагинов.
- **Что зафиксировать заранее:** политика совместимости `HOST_API_VERSION` (до публичного распространения).

### 4. Опциональные улучшения
- **Rust-undo (D5):** планируется (решение D5 уже принято), после стабилизации; влияет на
  `DocumentStore`/`rev`-семантику — нужен дизайн/ADR.
- **Подсветка синтаксиса:** перенесена в идеи (`IDEA-014`), когда-нибудь; требует ADR.

## Риски

1. **Ed25519-подпись** — *(отложено с 2b)* ротация ключей, доверие к реестру.
2. **Реестр** — *(2a закрыт локальным каталогом)* удалённая инфраструктура/CI-CD — при возобновлении 2b.
3. **Обратная совместимость** — изменения в API могут сломать существующие плагины; снимается политикой `HOST_API_VERSION` (Фаза 3, зафиксировать до публичного распространения).
