## 0. Контекст и текущее состояние

Ревью v1.1 §2 зафиксировало, что инспектор (`tasks/TZ-inspect-mode.md`) подсвечивает
исключительно **топ-блок** `.md-block`, а не вложенные элементы. Для таблиц это означает:
наведение на `<td>`/`<tr>`/`<th>` подсвечивает всю таблицу, а не ячейку/строку/столбец.

Этот документ **частично закрывает** Проблему 1 **только для таблиц**. Полный поуровневый
маппинг всех inline-`Event`'ов (жирный/курсив внутри абзаца) остаётся вне объёма — для
таблиц сложность принципиально ниже: у них жёсткая DOM-структура, а `pulldown-cmark`
отдаёт точные байтовые диапазоны строк и ячеек.

**Проверено фактически** (`into_offset_iter` на GFM-таблице):

```
20..32  Start(TableRow)    "| a1 | b1 |\n"
21..25  Start(TableCell)   " a1 "
```

— диапазоны `TableRow`/`TableCell` пригодны для `data-md`.

Текущий `to_html_mapped` (`md-core/src/lib.rs:54`) группирует события по топ-блокам и
размечает `data-md` только на обёртке `.md-block`. Санитайзер (`GLOBAL_ATTRS`, строка 246)
**не пропускает** `data-*`, поэтому разметку вложенных элементов можно добавлять только
**после** `sanitize_html`.

На фронте `inspector.ts:110` делает `closest("[data-md]")` — расширение атрибута на
`tr`/`td`/`th` автоматически даст более глубокую гранулярность. Но тот же атрибут читают
`mapping.ts::collectBlocks` (инспектор + синхронизация скролла + E2E-хелперы), поэтому
селектор блочного уровня нужно **сузить до `.md-block[data-md]`**.

## 1. Постановка задачи

### 1.1. Пользовательская история

> Как читатель markdown-документа с таблицей, я хочу, чтобы в режиме инспектора наведение
> на ячейку подсвечивало в редакторе именно эту ячейку, на строку — строку целиком, а на
> заголовок столбца — заголовок и весь столбец. Тогда я вижу точное соответствие
> «значение ↔ исходник», а не всю таблицу.

### 1.2. Решения по UX-развилкам (согласованы)

| Вопрос | Решение |
|--------|---------|
| Что делает «интерактивность» | **Только подсветка источника** (в редакторе) + визуальная подсветка в предпросмотре. Действий выделения/копирования нет |
| Где считать маппинг | **Расширить `md-core`**: `data-md` на `<tr>`, `<th>`, `<td>` |
| Столбец в редакторе | Выделяется **фрагмент заголовка** (`<th>`) источника; весь столбец подсвечивается визуально в предпросмотре |
| Триггер уровня | **Вложенность + модификаторы**: обычный hover по ячейке → ячейка; `Shift+hover` → строка; hover по `<th>` → столбец |

### 1.3. Acceptance criteria

| # | Сценарий | Ожидаемый результат |
|---|----------|---------------------|
| AC-1 | Наведение на `<td>` | Ячейка подсвечена в предпросмотре; в редакторе выделен ровно исходный фрагмент этой ячейки |
| AC-2 | `Shift` + наведение на `<td>` | Подсвечена строка (`<tr>`); в редакторе выделена исходная строка таблицы целиком (`| a | b |`) |

## 3. Детальные требования

### 3.1. `md-core`: структурные диапазоны и инъекция

**S-1. Сбор диапазонов.** При группировке событий в `to_html_mapped`, если первое событие
блока — `Event::Start(Tag::Table(_))`, пройти события группы и собрать
`Vec<StructRange>` **в порядке следования HTML-тегов**:

```rust
enum StructTag { Row, Th, Td }
struct StructRange { tag: StructTag, start: usize, end: usize }
```

- `in_head` переключается на `Start/End(TableHead)`.
- `Start(TableCell)` → тег `Th` при `in_head`, иначе `Td`.
- `Start(TableRow)` → тег `Row`, **только вне head** (строка `<thead><tr>` не размечается:
  для столбца интерактивен `<th>`, а строка-заголовок отдельно не нужна — это снимает
  неоднозначность «есть ли `TableRow` внутри `TableHead`» между версиями pulldown).
- Диапазон ячейки обрезается до содержимого (`first_non_ws` / `last_non_ws_end`); если
  после обрезки пусто (ячейка из пробелов) — берётся исходный диапазон парсера.
- Диапазон строки: `start = range.start`, `end = trim_end_ws(...)` (убирает `\n`/`\r`).

**S-2. Инъекция.** Новая чистая функция
`fn inject_structural_data_md(html: &str, ranges: &[StructRange]) -> String`, вызывается
для блока-таблицы **после** `sanitize_html` (иначе санитайзер срежет `data-*`).

- Проход по HTML с определением открывающих тегов `<tr`/`<th`/`<td`, с учётом кавычек
  внутри тега (`style="text-align: right"`).
- Состояние: `in_head` (по `<thead>`/`</thead>`/`<tbody>`) и `cell_depth` (инкремент при
  `<th`/`<td`, декремент при `</th`/`</td>`).
- Инъекция **только при `cell_depth == 0`** и **только** в структурные теги:
  - `<th>` → следующий `StructTag::Th`;
  - `<td>` → следующий `StructTag::Td`;
  - `<tr>` вне head → следующий `StructTag::Row`; `<tr>` в head — пропуск.
    Тоггл `in_head` учитывается только при `cell_depth == 0` (защита от сырой
    вложенной таблицы внутри ячейки).
- Атрибут вставляется перед закрывающей `>`: ` data-md="start,end"`. Порядок и число
  тегов и диапазонов совпадают; при несовпадении типа — тег пропускается без сдвига
  курсора диапазонов (defensive).
- Обёртка `.md-block` с `data-md` остаётся как раньше (инъекция в неё не входит).

**S-3. Документация и инварианты.** Обновить doc-комментарий `to_html_mapped`:
инвариант «содержимое без обёрток байтово совпадает с `to_html`» заменяется на
«содержимое **без всех `data-md`-атрибутов** байтово совпадает с `to_html`»; добавить
описание вложенной разметки `tr`/`th`/`td` и правила тримминга.

### 3.2. `crates/app/src/mapping.ts`

**F-1.** `collectBlocks` меняет селектор `"[data-md]"` → `".md-block[data-md]"`.
Комментарий: селектор сужен намеренно — ячейки/строки тоже несут `data-md` (для гранулярности
инспектора), но блочные потребители (каретка, синхронизация скролла) обязаны видеть только
топ-блоки.

**F-2.** `parseRange` не меняется. Иных правок в `mapping.ts` нет.

### 3.3. `crates/app/src/inspector.ts`

**F-3. Разрешение цели `resolveTarget(e: MouseEvent)`:**

```
t = e.target as Element
th = t.closest("th[data-md]")            → { el: th, mode: "col" }
tr = t.closest("tr[data-md]")
td = t.closest("td[data-md]")
если td && !e.shiftKey                    → { el: td, mode: "cell" }
если tr                                   → { el: tr, mode: "row" }
если td                                   → { el: td, mode: "cell" }
block = t.closest(".md-block[data-md]")   → { el: block, mode: "block" }
иначе null
```

Приоритет `<th>` выше `Shift` (столбец не переопределяется модификатором).

**F-4. Подсветка цели `applyTarget(target, focus, force)`:**
- `applyBlock(target.el, focus, force)` — существующая логика (диапазон из `data-md`,
  `setSelectionRange`, `scrollIntoViewIfNeeded`).
- `clearBands()` перед установкой новой.
- `mode === "col"`: вычислить `col = th.cellIndex`; для всех `table.rows` навесить
  `.inspect-col` на ячейку с тем же `cellIndex` (учесть, что `cellIndex` сохраняется после
  переупорядочивания строк `tables.ts`); запомнить список для очистки.
- `mode === "row"`: навесить `.inspect-row` на `<tr>`.
- `mode === "cell"`/`"block"`: бэндов нет.

**F-5. Слушатели.**
- `mouseover` → `const t = resolveTarget(e); if (t) applyTarget(t, true)`.
- `mouseout` (за пределы preview) → `clearBlockHighlight()` + `clearBands()` + `restoreSavedFocus()`.
- `click` (capture): сохранить проверку `INTERACTIVE_SELECTOR` (в т.ч. `th`, `button` —
  сортировка/воронка `tables.ts`); затем `resolveTarget(e)`, `preventDefault`/`stopPropagation`,
  `applyTarget(t, true, true)`.
- `keydown`/`keyup` (только пока инспектор активен): при изменении состояния `Shift`
  пересчитать уровень для **последней наведённой** цели (сохранять `{el, shiftKey}` в
  `lastHover`; сбрасывать на `mouseout`) и вызвать `applyTarget` (AC-5).

**F-6.** `clearBands()` считается частью `clearBlockHighlight`-цикла; `disable()` и
`onRendered()` обязаны снимать и бэнды, и подсветку (идемпотентно; классы на удалённых
узлах безвредны).

### 3.4. `crates/app/src/style.css`

**F-7. Бэнды строки/столбца** (фон, не `outline`; `outline` остаётся за `.inspect-active`):


перекрывает фон — допускается добавить точечное правило с `!important` для `.inspect-col`,
зафиксировав в комментарии причину.

## 4. Алгоритмы

### 4.1. Инъекция (ядро)

```
fn inject_structural_data_md(html, ranges):
    out = ""; cursor = 0; cell_depth = 0; in_head = false
    пройти html, находя открывающие и закрывающие теги:
        </th> / </td>        → cell_depth = max(0, cell_depth-1)
        <thead>              → if cell_depth==0: in_head = true
        </thead> / <tbody>   → if cell_depth==0: in_head = false
        <th ...>  если cell_depth==0 и cursor<len и ranges[cursor].tag==Th:
                                 out += тег с " data-md=\"s,e\""; cursor++; cell_depth++
                                 иначе: out += тег; cell_depth++ (не структурный)
        <td ...>  аналогично для Td
        <tr ...>  если cell_depth==0 и !in_head и tag==Row: инъекция + cursor++
        прочее — как есть
```

### 4.2. Уровень при наведении (фронт)

```
resolveTarget(e):
    th → col
    td & !shift → cell
    tr → row            // Shift+td сюда же; либо курсор на промежутке строки
    td → cell           // без data-md на tr (страховка)
    .md-block → block
```

`Shift` пересчитывается на `keydown`/`keyup` через `lastHover` (AC-5). `col` требует
`th.cellIndex`; бэнд ставится на все строки таблицы.

## 6. Риски

| Риск | Вероятность | Митигция |
|------|-------------|----------|
| Санитайзер срезает `data-md` | высокая | инъекция строго после `sanitize_html` (§3.1 S-2) |
| Сырой HTML (`<td>`) внутри ячейки ломает парность тегов | низкая | инъекция только при `cell_depth == 0` (§4.1) |
| Ячейки/строки попадают в блочные списки (sync/каретка) | высокая | `collectBlocks` → `.md-block[data-md]` (§3.2) |
| E2E-хелперы выбирают ячейку вместо блока | высокая | сужение селекторов E-1 + новые хелперы E-2 |
| Бэнды перекрыты зеброй/sticky-столбцом `tables.ts` | средняя | специфичность/id; при нужде `!important` (§3.4) |
| `Shift` без движения мыши не пересчитывается | средняя | `keydown`/`keyup` + `lastHover` (§3.3 F-5) |
| Раздувание HTML на больших таблицах | низкая | AC-14; инъекция O(n) без DOM |
| Вложенная таблица внутри цитаты/списка | низкая | тест T-4 |

## 8. Что сознательно НЕ входит

- Поуровневый маппинг inline-элементов (жирный/курсив/код внутри абзаца) — по-прежнему
  вне объёма (Проблема 1 закрыта частично, только таблицы).
- Выделение/копирование столбца или строки (действия) — только подсветка источника.
- Отдельный «гуттер» с номерами строк (Excel-модель) — не вводится: строка выбирается
  `Shift`; номера строк остаются задачей `TZ-excel-tables.md` (T-14).
- Столбец в редакторе — только заголовок; множественных диапазонов (`setSelectionRange`
  их не поддерживает) нет.
- Каретка редактора → предпросмотр (`onEditorSelection`) остаётся на уровне топ-блока.
- Изменения `tables.ts`/`main.ts`/`src-tauri` — не требуются.
- Юнит-тесты фронтенда (vitest не установлен); логика `resolveTarget` покрывается E2E.
