### 9.2. Ключевой инвариант: `.pl-item-body` всегда в DOM

### 9.5. Риски тестирования (панель плагинов)

- **Скрытый клик ≠ видимость:** synth-click обходит `display:none`, поэтому для аккордеона обязана быть отдельная проверка `getComputedStyle`.
- **`replaceChildren` после каждого действия:** состояние раскрытия — только вне DOM (`Set`), иначе все проверки аккордеона станут flaky.
- **Строгий `strict: true` в WDIO:** неопределённый шаг валит прогон — объявлять до запуска.
- **Асинхронность `plugins-changed`:** ждать через `browser.waitUntil`, не паузами.
- **Недостижимые состояния в E2E:** `failed`/`quarantined` (нет crash-фикстуры), пустой каталог — не гоняться, помечать `@manual`.
- **Не трогать `pluginStatusBar.ts`** — его селекторы `.ps-item[data-plugin]` проверяются той же фичей, вне scope задачи.

## 11. Info-кнопка плагина — ключевые решения

> Перенесено из `ideas/UI-INFO-BUTTON.md` (удалён после реализации).

### 11.1. Обоснование выбора Popover

- **Tooltip** не подходит: не управляется с клавиатуры, не удерживается открытым при переводе фокуса.
- **Dialog** — overkill для информационного текста без действий (тяжёлая модалка с `inert`, focus-trap, `aria-modal`).
- **Popover** — лёгкий, не модальный, 1–2 абзаца текста, управление с клавиатуры (Enter/Space/Escape).

### 11.2. ARIA-паттерн

- Кнопка: `aria-expanded="true|false"`, `aria-controls="<id поповера>"`, `aria-label="Информация о границах изоляции плагина <id>"`.
- Поповер: `role="tooltip"`, `id` уникален (`pl-info-pop-<plugin_id>`), `aria-hidden="true|false"`.
- Поповер **не** захватывает фокус — фокус остаётся на кнопке.

### 11.3. Решения по рискам

- **Hit-area**: `inset: -10px -6px` — зона нажатия не заходит на `.pl-toggle` (устраняет мисклики).
- **Цвет текста**: `.pl-info-pop .pl-notice { color: inherit; }` — информационный текст не выглядит янтарным «предупреждением».
- **Вертикальный клиппинг**: принят как известное ограничение (`.pl-panel { overflow-y: auto }`). Горизонтальное вылезание за узкий sidebar снято `right: 0`. Если станет проблемой — решать порталом (`position: fixed` + JS-расчёт) отдельным шагом.
