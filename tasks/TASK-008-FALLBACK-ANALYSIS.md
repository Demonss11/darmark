## 1. Решение

`FALLBACK_SKILLS` (`crates/app/src/panels/aiPanel/skills.ts`, 84 строки) **удаляется**.

Единственный источник промтов встроенных скиллов — `crates/app/src-tauri/src/ai/skills/mod.rs`
(`builtin_skills()`); он же отдаёт наружу командой `ai_list_skills`. Если команда недоступна, ряд
скиллов показывает **честное состояние «недоступно»** с подсказкой перезапустить приложение, а не
подставляет другой набор.

Обоснование в одну строку: фолбэк не страхует от пустого списка (такого списка не бывает, §2.1) —
он маскирует отказ IPC подстановкой устаревшего набора из двух скиллов вместо пяти.

## 2. Ответы на исходные вопросы (сверено с кодом 16.10.2026)

### 2.1 Достижим ли пустой список — нет, ветка фолбэка мёртвая

Цепочка вызовов:

| Слой | Файл:строки | Что делает |
|---|---|---|
| TS-обёртка | `crates/app/src/core/tauri/ai.ts:132-134` | `aiListSkills()` → `invoke<AiSkill[]>("ai_list_skills")` |
| команда | `crates/app/src-tauri/src/ai/commands/mod.rs:52-56` | `ai_list_skills() -> Vec<AiSkill>` — **без `Result`**, тело `skills::skills()` |
| домен | `crates/app/src-tauri/src/ai/skills/mod.rs:305-308` | `skills()` → `builtin_skills()` |
| источник | `crates/app/src-tauri/src/ai/skills/mod.rs:245-303` | `Vec` из семи констант (`EXPLAIN_PROMPT:14`, `CREATE_PLUGIN_PROMPT:40`, `RESTRUCTURE_PROMPT:96`, `SUMMARIZE_PROMPT:116`, `EXPLAIN_SYNTAX_PROMPT:136`, `DEBUG_PLUGIN_PROMPT:160`, `ADD_VIEW_PROMPT:193`) |

Ни БД, ни I/O, ни fallible-операций в цепочке нет: команда не может упасть и не может вернуть пусто.
Следовательно в `skillBar.ts:41` тернарник `list.length > 0 ? list : FALLBACK_SKILLS` — **мёртвая
ветка**: левая часть истинна всегда.

`FALLBACK_SKILLS` достижим ровно одним путём — `.catch` в `skillBar.ts:43-50`, то есть **исключение
IPC**: команда не зарегистрирована или фронт загружен вне Tauri (рассинхрон бинаря и ассетов).

**Вывод:** фолбэк — не страховка на пустой список, а маска отказа. Подставить вместо отказа два
устаревших скилла значит скрыть поломку и дать пользователю кнопку, которая работает по старому
промту.

Побочная находка (не в объёме решения, но чинится рядом): док-комментарий
`commands/mod.rs:52` «Возвращает встроенную библиотеку скиллов MVP (ровно 2, ADR-0032)» устарел —
скиллов 7 (после TASK-004 → 6, после TASK-005 → 5).

> Правка ожидания к исходной формулировке §2.1: обёртка лежит в `core/tauri/ai.ts`, а не в
> `core/tauri/plugins.ts` — файл `plugins.ts` к скиллам отношения не имеет.

### 2.2 Кто источник правды — `mod.rs`; копия `create-plugin` пока идентична

- **Посимвольная сверка `create-plugin`: копии совпадают.** Извлечены обе строки и сравнены:
  по 3224 байта каждая, расхождений 0. Различается только экранирование обратных кавычек —
  TS template literal (`\`\`\``, 11 вхождений) против Rust raw-string `r#"…"#`; после разэкранирования
  строки равны.
- Значит **накопленного расхождения по `create-plugin` нет** — риск проспективный: следующая правка
  промта в `mod.rs` (TASK-002, TASK-004) молча разъедет копию, и при отказе IPC пользователь получит
  устаревший промт, не узнав об этом.
- **Расхождение по составу есть и оно накапливающееся:** фолбэк содержит только `explain` и
  `create-plugin`; нет `restructure`, `summarize`, `explain-syntax`, `debug-plugin`, `add-view`.
  После TASK-004 + TASK-005 в норме остаётся 5 боевых скиллов, фолбэк отстаёт ровно на 3.
- **Источник правды — `crates/app/src-tauri/src/ai/skills/mod.rs`:** он формирует и команду
  `ai_list_skills`, и норму, которую видят пользователи и модель. Фронтовая копия — не источник,
  а страховка, которая эту роль не выполняет.

### 2.3 Что видит пользователь при пустом списке — пустой ряд без пояснения

- `renderSkills` (`skillBar.ts:58-76`): обнуляет `dom.skillsRow.textContent = ""` (`:59`) и рисует
  кнопки в цикле по `state.skills` (`:60`). При `state.skills = []` тело цикла не выполняется —
  остаётся пустой контейнер, **заглушки нет**.
- Разметка: `crates/app/index.html:297` — `<div class="ai-skills" id="ai-skills" role="toolbar"
  aria-label="Готовые скиллы">`. Пустой `role="toolbar"` без потомков и без пояснения: скринридер
  сообщает «пустая панель инструментов», причина неизвестна.
- Стили `.ai-skills` (`crates/app/src/styles/ai.css:34-43`): `padding: 7px 14px`, правила `:empty`
  нет — остаётся визуально пустая полоса ~14 px, похожая на недогрузившийся UI.
- Ряд скрывается только при выключенном AI (`indicator.ts:73`, `dom.skillsRow.hidden = !enabled`).
  Состояние «AI включён, а ряд пуст» ничем не объяснено.
- То же пустое состояние существует и в норме: `renderSkills()` вызывается на монтировании
  (`index.ts:303`), когда `state.skills` ещё `[]` (`state.ts:173`). Значит подсказку «недоступно»
  нельзя рисовать на любом пустом списке — её нужно отличать от состояния «ещё грузится» (например,
  рисовать только при `state.skillsLoaded`).

**Вывод по §2.3:** вместо подстановки чужого набора нужен один неинтерактивный узел-подсказка
(«Скиллы недоступны — перезапустите ПЕНАЛ»), который не выглядит кнопкой и доступен скринридеру.

## 3. Почему вариант A, а не B или C

| | Вариант | Вердикт | Почему |
|---|---|---|---|
| **A** | Убрать фолбэк | **принят** | источник промтов один; дублирование закрыто; отказ виден пользователю |
| **B** | Актуализировать фолбэк | отклонён | копия API-блока возвращается в `skills.ts`: каждая правка промта снова в двух местах; рассинхрон вернётся молча, без CI-гейта |
| **C** | Оставить как есть | отклонён | пользователь получает 2 кнопки вместо 5 без объяснения; правка промта обязана быть продублирована в `skills.ts` |

Промежуточный вопрос «правило синхронизации копий в ADR-0042 §2.1 п.2» снимается вместе с копиями:
после удаления фолбэка синхронизировать нечего. Правило в ADR-0042 не заносится (следствие: TASK-002
правит промт в одном месте).

**Побочный эффект решения:** исчезает аргумент за синхронизацию копий и упрощается ADR-0042 §2.1 —
перечень промтов фиксируется как два (`create-plugin`, `debug-plugin` после TASK-004).

Отдельный ADR по фолбэку **не нужен**: изменение чисто фронтовое, контракт host ↔ плагин
(ADR-0023, ADR-0027) и перечень скиллов (ADR-0032) не затрагиваются. Открытый вопрос
`tasks/BACKLOG.md` §6 «нужен ли отдельный ADR?» закрывается этим решением; правку BACKLOG выполняет
исполнитель при закрытии задач.

## 4. Что теряется и чем компенсируется

Теряется единственное: при отказе IPC вместо двух кнопок пользователь не получит ничего рабочего.
Компенсация — честная подсказка в журнал (`state.log`) и в самом ряду: скиллы появятся после
перезапуска. Это осознанный размен: «две кнопки из устаревшего набора» — не диагностика, а шум.
